# 本体工作台与 Palantir 能力对照表

核对日期：2026-09-15  
项目：`wiz_kq_builder_v2`

本文以 Palantir Foundry 的概念与能力为主线，对照当前工作台的代码与页面入口。用于明确已有能力和差距，不代表本次要新增所有功能，也不代表已完成逐项运行验收。

**核心区别：我们将“通用本体定义”和“具体项目映射”分为两个工作区；Palantir 的完整 Ontology 同时关联真实数据与业务操作。因此，比较时要区分定义维护、项目配置和实际运行能力。**

## 完整对照表

“基础已实现”表示已有对应的基础建模功能，不表示达到 Foundry 的完整能力；“部分实现”表示只有部分定义或配置能力；“旧功能保留”表示代码和入口仍在，但不属于当前主流程。

| 层次 | Palantir 内容分类 | Palantir 的作用 | 储能场景示例（本文举例） | 我们当前入口／实现 | 当前程度 | 主要差距或边界 |
|---|---|---|---|---|---|---|
| 基础建模 | **对象类型 Object Types** [1] | 定义业务实体或事件的结构 | 储能簇、储能设备、检修工单 | 本体区 → 对象建模；可维护名称、业务定义，通过列表和画布操作 | **基础已实现** | 使用自有模型协议，不是 Foundry 原生格式；通用类型定义与项目实例识别分开维护 |
| 基础建模 | **属性 Properties** [1] | 定义对象具有哪些特征 | 名称、额定容量、额定功率、SOC | 对象建模 → 对象属性；维护名称、业务定义、数据类型、显示格式 | **基础已实现** | 当前采用简化的数据类型与维护流程；属性定义保存不代表已经能读取实际属性值 |
| 基础建模 | **链接类型 Link Types** [2] | 定义对象类型之间的关系 | 储能簇「所属」储能设备 | 对象建模中维护链接；项目区配置来源表及关联字段 | **基础已实现** | 已有关系定义与映射配置；尚不能等同于 Foundry 的对象关系查询和运行服务 |
| 属性能力 | **时间序列属性 Time series properties** [3] | 将随时间变化的数据关联到对象属性 | 储能簇 SOC 的历史采样记录 | 数据类型选择“时间序列”，再选择观测值类型；项目区配置时间字段、值字段或采样取值规则 | **定义与配置已实现** | 我们的 `timeSeries` 是自有表达；不等同于 Foundry 的 Time series reference 实现。采样规则目前保存配置，未执行真实数据库查询 |
| 属性能力 | **值格式化 Value formatting** [4] | 控制原始属性值在应用中的显示方式 | 功率显示为带单位的数值、时间显示为年月日时分秒 | 属性选填 → 显示格式；有常见格式及自定义／自然语言格式化配置 | **部分实现** | 显示格式不替代数值换算或数据口径；自然语言格式化是我们的扩展方案，不是 Foundry 格式化机制的原样实现 |
| 定义复用 | **共享属性 Shared Properties** [5] | 集中维护多种对象共用的属性定义和元数据 | 储能设备与储能簇共用“资产编码”的定义 | 本体区 → 共享属性库；支持引用、查看引用位置、复制为私有、解除共享引用 | **核心思路已对齐** | 共享的是定义，不是对象实例的值；复制或解除引用后不再跟随共享定义更新 |
| 定义复用 | **接口 Interfaces** [6] | 约定不同对象类型共有的结构与能力，使它们可按共同接口使用 | “可维护资产”由储能设备、光伏逆变器实现 | 更多工具 → 接口定义；选择必需共享属性和实现接口的对象类型，并检查缺失属性 | **部分实现** | 目前仅覆盖共享属性契约；接口链接、动作约束等未实现。它不是 HTTP 接口，也不是此前计算契约的别名 |
| 分类管理 | **对象类型组 Object Type Groups** [7] | 对对象类型分类，便于搜索与浏览 | “储能”组下包含系统、设备、簇等对象类型 | 无独立对象类型组管理功能 | **未实现** | 新建多个本体是管理不同模型，不等同于同一本体内的对象类型分组；类型组也不是实例集合 |
| 类型复用 | **值类型 Value Types** [8] | 基于基础类型定义可复用的语义与约束 | 定义百分数类型及允许范围 | 更多工具 → 值类型管理；保留约束维护、样本检验、引用位置功能 | **旧功能保留** | 属性主表单已不提供值类型引用选择，但旧管理入口仍存在；当前主流程与历史功能需要进一步统一。约束不会自动修正错误计算结果 |
| 结构化建模 | **结构体 Structs** [9] | 用多个字段组成结构化属性值 | 设备地址包含省、市、详细地址 | 底层保留结构体数据类型，旧值类型页面支持结构体字段约束 | **有限支持** | 尚无与 Foundry 相当的完整结构体定义、编辑和映射流程；不是创建几个普通属性即可视为完整实现 |
| 业务行为 | **行动类型 Action Types** [10] | 定义一次操作对对象、属性、链接产生的修改，以及参数、提交条件和副作用 | 创建检修记录，同时更新设备维护状态 | 更多工具 → 动作定义；可填写参数、效果、条件、权限要求、验收案例；部分内置实现可模拟预览 | **部分实现** | 主要是定义记录和演示；未形成通用真实动作执行、身份权限校验与外部系统写入机制。权限文字说明不等于权限控制 |
| 计算与运行 | **函数 Functions** [1] | 接收输入、执行逻辑并返回结果，可与对象、动作和应用集成 | 输入储能簇和时间范围，计算平均 SOC | 更多工具保留旧计算契约；项目区 → 取值规则库，保留历史实现维护能力 | **部分实现** | 计算契约描述和取值配置不等于可执行函数；当前没有完整的通用函数部署、调用和运行管理体系 |
| 数据与运行 | **数据源绑定与对象数据更新** [2][11] | 将数据源关联到对象和关系，让应用使用实际数据 | 簇表提供实例及额定容量；采样数据提供 SOC 序列 | 项目区 → 数据连接、对象映射；支持连接测试、目录读取、实例识别、属性取值、链接映射 | **配置能力已实现，运行能力有限** | 连接探测与目录读取是真实操作；不能据此推断所有属性取值已可执行。通用数据接入、索引、持续更新及查询服务尚不完整 |
| 安全治理 | **本体资源与对象数据权限** [1][12] | 控制谁可以维护定义、访问数据、执行操作 | 运维可查看设备；资产管理员可调整归属 | 本地服务已有请求边界、连接密码保护等技术防护；动作可记录权限要求 | **业务权限未实现** | 没有完整的用户、角色、对象数据授权及操作授权体系；本地技术防护与业务访问权限属于不同能力 |
| 变更治理 | **本体变更管理** [11] | 管理定义修改、审查与历史变更 | 审查 SOC 数据类型变更对下游使用方的影响 | 本体与项目独立草稿、校验、不可变发布快照；项目固定引用本体版本，可比较和切换引用 | **已有自有版本机制** | 尚无完整的多人分支协作与提案审核；我们的本体／项目双发布线是自身架构设计，不声称与 Foundry 机制完全一致 |
| 应用使用 | **对象视图 Object Views** [1] | 汇集一个对象的属性、关系、分析和相关业务操作 | 打开某个储能簇，查看名称、SOC 曲线、所属设备和检修记录 | 更多工具中的对象数据浏览、实例与计算预览；对象建模中有类型级列表和画布 | **有限演示支持** | 类型画布不是实例详情应用；尚无完整连接真实数据和业务动作的可配置对象视图 |

上述“层次”是为本次对照整理的阅读分组，不是 Palantir 官方规定的固定分类或实施步骤。时间序列、格式化是属性相关能力；函数、数据接入、权限和对象视图也不应全部作为与对象类型平级的必填建模项。表格覆盖本次本体建设讨论涉及的主要领域，不是整个 Foundry 产品功能清单。

## 对当前工作台的判断

1. **当前主流程已经覆盖对象、属性、链接和共享属性。** 本体区主导航为工作概览、对象建模、共享属性库、本体校验与发布。
2. **动作、接口、值类型不是完全没有代码，而是旧功能保留或部分实现。** “更多工具”仍有入口，不能将“已移出主流程”描述为“已全部删除”。
3. **最大的运行差距是从定义、配置到真实执行。** 能保存映射、测试连接、查看目录，不代表已完成属性查询、时序读取和动作执行。
4. **我们的取值规则库属于项目实现层。** 固定的采样取值规则通过表名、属性名、实例主键等参数复用；这是一种项目适配设计，不是 Palantir 单独规定的一类本体元素。
5. **建议下一步先确定接口、行动类型的建设范围。** 类型组用于组织管理，可按规模增加；值类型和结构体按实际需求完善，无需为了凑齐菜单全部加入业务专家必填流程。
