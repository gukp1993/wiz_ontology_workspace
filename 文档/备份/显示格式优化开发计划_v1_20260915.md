# 显示格式优化开发计划 v1

本计划只覆盖 [显示格式优化需求](显示格式优化需求_v1_20260915.md)，不包含架构重构、项目映射改造、数据源查询或新模型接入。

## 1. 当前实现与改动点

| 位置 | 当前情况 | 本轮任务 |
|---|---|---|
| `frontend/src/ontology/PropertyFormatting.vue` | 三种 mode；已有较多数值／日期样式；序列按观测值的标量类型处理 | mode 改二选一；按类型联动；增加模板、映射、复杂类型预览；历史兼容；简化小数位字段 |
| `frontend/src/ontology/PropertyManager.vue` | 属性本地表单；共享属性只读／解除；格式配置在托管键中 | 尽量不改，核对保存和类型切换；未改格式不能丢旧键；共享引用保持 |
| `frontend/src/ontology/api.ts` | 统一 formatPreview 请求入口 | 原路径复用，必要时补请求类型，不另写 fetch |
| `workbench/formatter_runtime.cjs` | 常用格式和历史代码执行；标量／数组／结构体分支 | 补文本模板和映射、复杂类型格式；可提取小型纯格式化函数以复用，不创建插件框架 |
| `workbench/formatting.py` | 自然语言调用、Node 预览与限制 | 空值先处理；保持密钥保护、超时、输入输出限制；支持序列预览请求 |
| `workbench/model_routes.py` | 已有 format-preview 路由处理 | 核对允许传入的新 dataType／配置；尽可能复用接口 |
| `tests/` | 本轮需增加针对性覆盖 | 运行时语义、前端联动与历史往返、隔离保存验证 |

## 2. 执行顺序与任务边界

### 阶段 0：确认基线及协议（负责人串行完成）

1. 阅读根 AGENTS.md、需求与相关文件；检查当前修改，保留他人改动。
2. 确定旧配置 fixture：builtin、natural、code、未知键、不同小数位、旧文本／日期样式。
3. 将需求第 6 节键名与默认值冻结为小型示例；不要全仓探索，也不要重复设计一套属性 schema。
4. 检查新字段是否可被现有 JSON 透传；只有确有边界限制才改协议层，两端同步。

交付：一份在实施记录中的最终配置示例及文件负责人表。

### 阶段 1：按无重叠文件并行

| 任务 | 文件所有权 | 必须交付 | 依赖 |
|---|---|---|---|
| A：前端编辑器 | PropertyFormatting.vue，确需的最小前端辅助文件 | 两项模式、常用格式联动、历史只读提示、自然语言、样本、异步失效保护 | 阶段 0 |
| B：预览执行 | formatting.py、formatter_runtime.cjs，确需的 model_routes.py 改动 | 各类型格式化及边界错误、空值处理、兼容旧格式 | 阶段 0 |
| C：独立验证 | 新增格式化测试文件及测试 fixture | 依据需求写期望，测试新旧格式、复杂类型和持久化；先编写 fixture，等待 A/B 后执行 | 阶段 0，完成依赖 A/B |

最多三个实现／测试子任务即可；GLM 即使支持 50 并发，也不要让多人同时修改同一组件或协议文件。无多 agent 能力时按相同边界顺序执行。

### 阶段 2：负责人集成

- 检查 UI 实际配置与运行时消费字段一致，所有新样式均有实际执行逻辑。
- 检查序列与标量类型判断，避免继续只读 rdfs:range 忽略时间序列标记。
- 检查空自然语言规则的“未配置”语义、无配置打开不脏、恢复原样仅随属性保存生效。
- 检查历史格式摘要不能改变 mode，切换时不能误丢其他属性字段。
- 仅必要时调整 PropertyManager.vue；保留 form-save、form-guard 和既有保存队列。

### 阶段 3：验证与交付

1. 运行定向单元测试，覆盖 A4—A10；自然语言请求用 mock，默认不调用真实模型。
2. 用实际组件测试／浏览器检查 A1—A3、A11—A12。涉及保存的浏览器测试使用临时项目数据目录和独立端口。
3. 执行 `cd frontend && npm run build`；构建自带类型检查，无新原因不用重复跑一次 typecheck。
4. 若触及项目校验或保存协调器，再按 AGENTS.md 运行对应金样／队列回归；未触及则不要扩大到无关全量套件。
5. 生成 `文档/交付物/显示格式优化实施记录_20260915.md`：改动文件、协议样例、A1—A14 结果、未完成项、人工检查路径。
6. 前端静态产物须可被现有服务读取；若修改后端需要生效，通过 start.sh 管理现有服务，不另起占用生产端口的进程。

## 3. 最小测试矩阵

| 测试组 | 核心样例 |
|---|---|
| 数值 | 两种百分比口径、0、负数、小数补零、科学计数、非法精度 |
| 文本／布尔／空值 | 模板、映射未匹配与重复、true/false、null、空字符串 |
| 日期／时间 | 纯日期、时区转换、分钟／秒精度、无效日期、相对时间固定时钟 |
| 复杂类型 | 数组超量与元素格式、结构体字段顺序与缺失、时间序列时间和值分别格式化 |
| 兼容 | code、旧样式、min/max 不等、未知键，无修改保存不丢失 |
| 请求状态 | 自然语言只请求一次、失败、切换后的旧响应丢弃、关闭表单后的响应失效 |
| 持久化 | 临时根保存重载、取消、共享属性引用，样本不入库 |

## 4. 防止范围膨胀

不换 Vue、不加 UI 框架、不重构保存队列、不增加新菜单、不做时间序列图表、不改查询规则库、不做单位换算、不批量迁移用户数据、不删除历史函数运行兼容。不为每种格式增加一个页面或独立 API。

这是前端表单与已有预览运行时的定向迭代。完成常用格式全部范围的工作量高于只删一个下拉项；可按 A/B/C 并行，但协议确认和集成必须串行。每完成一个阶段汇报结果和剩余项，不承诺没有实测依据的固定分钟数。
