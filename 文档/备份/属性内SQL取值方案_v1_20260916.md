# 属性内 SQL 取值方案 V1

日期：2026-09-16。状态：待开发。仅项目映射功能，不修改本体属性定义。

## 1. 目标和范围

简单计算直接在属性映射页写 SQL，无需创建命名规则。复杂、可复用、多步骤查询继续引用规则库。

入口：项目映射 → 对象映射 → 属性取值 → 配置属性 → 调用取值规则 / 函数。

该入口内增加两种方式：
- 直接编写 SQL：仅当前项目、当前对象、当前属性的匿名取值定义。
- 引用已有规则：保持现有 SQL 步骤规则和旧实现的选择与绑定。

不新增顶层取值策略卡片，不恢复关联聚合入口，不自动新建规则库记录。不修改现有已保存来源；旧聚合仅只读兼容，由用户选择新来源并保存后替换。

首期仅单条 SELECT 模板，不执行 SQL、不新增试运行接口，不支持 WITH 起始、多语句、存储过程、动态表字段和步骤间引用。需要动态标识或多步时，提示使用已有规则方式。JOIN、SUM、表达式和子查询可写在单条 SELECT 内，保存不意味着完整 SQL 验证。

## 2. 页面

选中“调用取值规则 / 函数”后，用现有 AppSelect 或分段按钮展示“直接编写 SQL / 引用已有规则”。新配置默认直接 SQL；旧配置按原方式回显，不擅自转换。

直接 SQL 页面只展示：
1. 数据连接（必填）：当前项目已配置 MySQL 连接下拉。
2. SQL 模板（必填）：等宽编辑框，保留换行缩进。
3. 参数绑定：识别 SQL 中 :参数 后按需展示；没有参数则不显示参数表。
4. 输出说明（只读）：继承当前项目固定引用版本的属性类型，不重复让用户选类型、结果列、规则名称。

普通属性约定返回一行，输出列名 value；时间序列属性约定返回多行，列名 timestamp 和 value，SQL 应写 ORDER BY 时间升序。SQL 类型与真实返回行数只能在未来执行时验证，当前显示“输出约定，尚未执行验证”。不把任意非空 SQL 标成验证成功。

点击保存直接进入项目草稿；取消放弃表单修改。保存后列表摘要：“直接 SQL · 连接名称”，修改重开原文和参数完整。

两种方式切换只影响本地草稿；建议各自保留本次未提交内容，切回不用重填。落盘仅一种生效方式。保留已有 409、撤销、离页守卫，不新建保存流程。

## 3. 储能系统额定功率示例

以下为示意模板，park_id_column 不是确认过的真实字段，严禁自动写入业务配置：

```sql
SELECT SUM(rated_power) AS value
FROM m_storage_phase
WHERE park_id_column = :park_id;
```

park_id 绑定当前项目参数或固定园区编号；若系统范围还需其他条件，用户自行写入 WHERE/JOIN。储能系统实例编号不等于园区编号，不能默认互换。

若用户已明确整张表都属于该系统，可以自己填写无 WHERE 的 SUM；不要系统自动生成整表汇总。字段需使用相同单位，显示格式不自动换算。SUM 的空集、NULL 语义按 SQL 保留，不自动补 COALESCE、不补零。需要排除逻辑删除、去重或缺失处理时，由 SQL 作者明确描述。

名称、表、归属字段未核实时，示例只作提示，不自动保存。截图若是额定容量，需使用实际容量列，不能误把额定功率规则绑定过去。

## 4. 参数绑定

仅识别字符串、反引号标识符、行／块注释外的 :参数名；名称允许英文字母／下划线起始，后续数字。重复参数只显示一行。

| 来源 | 用户操作 | 存储示意 |
| --- | --- | --- |
| 固定值 | 选择文本／数值／是非／日期时间，填写值 | {from:"constant",dataType:"string",value:"42"} |
| 项目参数 | 从当前项目已有参数选择 | {from:"projectParameter",key:"park_id"} |
| 当前实例编号 | 仅实例身份已配置时选择 | {from:"instanceId"} |

第一版不新增其他属性依赖或身份表字段读取。需要进一步定位可在 SQL 中 JOIN，或使用规则库。项目登记对象也能用固定值和项目参数，不能被“没有来源表”阻挡。

项目参数选择需适配现有 parameters 实际结构，按项目既有 key 引用；不允许自行假设字段路径。实例来源主键、登记实例编号均按现有身份机制解析。

SQL 改动后：保留仍存在的参数绑定，新增参数显示待绑定，移除的参数不进最终生效配置；不能因重新识别清空全部绑定。空字符串、0、false 和未填写须区分；常量明确填写空字符串是有效值。项目参数失效或引用不存在需提示。

## 5. 数据格式（本轮约定）

沿用 kind=computed，内部分支互斥，不增加顶层 kind。

```json
{
  "kind": "computed",
  "mode": "inlineSql",
  "inlineSql": {
    "version": 1,
    "connection": "existing-connection-id",
    "sql": "SELECT SUM(rated_power) AS value FROM m_storage_phase WHERE park_id_column = :park_id;",
    "params": {
      "park_id": {"from": "projectParameter", "key": "park_id"}
    }
  }
}
```

引用已有规则保持原格式 `{kind:"computed", implementation:"稳定ID", output:"稳定输出键", inputs:{...}}`，不强制批量补 mode。

- inlineSql 与 implementation/output/inputs 不可作为双生效配置同时写入。
- 不存冗余输出类型，按当前项目引用的属性定义推导；本体升级检查按新目标属性重新校验／提示，不假定 SQL 自动适配。
- 存在对象绑定的 properties[属性稳定键] 中，复用现有项目草稿和发布序列化。不要写本体文件，不追加 implementations。
- bindingModel.propertyView/commitProperty 必须先识别 mode=inlineSql；当前 computed 适配器只取 implementation/output，会丢掉 inlineSql，必须改前后端及相关显示分支。
- 不支持的 inlineSql.version、mode 或未知字段按项目现有未知结构保留机制处理，不能当空计算规则重存导致数据丢失。
- 后端校验 computed 先区分 inlineSql 和命名规则；内联分支不要报“实现不存在”。禁止把内联模板送进 demo 执行器；merged() 仍只放行直接字段映射。

## 6. 校验与边界

前后端一致检查：合法结构版本、可用连接、SQL 非空、单条 SELECT 模板、占位符格式、每个参数已绑定、绑定来源合法且存在、分支互斥。SQL 中明确的 WITH、多语句、步骤引用、动态标识给出可理解的限制提示。

扫描复用现有工具并修复必要词法边界：MySQL 字符串转义、注释和反引号，不宣称正则即可安全执行 SQL。可以尽力提取显式输出别名辅助提示；复杂 SELECT 无法可靠推导时标记未验证，不假造列存在性、类型、行数验证。

连接密码不进项目数据／日志。当前无执行路由、无调用 LLM、无网络查询，不改 dbdrivers 安全边界。

## 7. 验收

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| A1 | 进入属性的计算取值 | 两种方式可选，未新增关联聚合或其他顶层策略 |
| A2 | 配置一个无参数 SUM | 只需连接和 SQL；保存重开原文一致，implementations 数量不变 |
| A3 | SQL 使用 :park_id | 自动显示一行，可绑定项目参数；保存重开绑定不丢失 |
| A4 | 重复、增加、移除参数 | 去重；保留已有项；新项待填写；删除项不写生效参数 |
| A5 | 参数取值 0/false/空字符串 | 明确填写的常量有效；真正未绑定拦截 |
| A6 | 项目登记的储能系统 | 不要求有来源表也能配置 SQL 和项目参数 |
| A7 | 普通／时序属性 | 展示对应输出约定，不增加重复填写字段 |
| A8 | 原规则绑定编辑 | 原方式正常回显，V2/V3/V4 入参和输出兼容 |
| A9 | 两种方式切换／取消 | 保存前不覆盖现有配置，取消无修订写入；保存只保留一种生效结构 |
| A10 | 未知版本或结构 | 原样保留，不能静默清空；错误明确 |
| A11 | 保存／发布／重开 | 正确序列化内联内容，不报缺少命名实现，不进本体或 demo |
| A12 | 参数失效、非法连接、缺绑定 | 配置校验发现问题，错误指向属性和参数 |
| A13 | 注释和字符串含 :fake、分号 | 不误识别参数或多语句；动态表／步骤引用明确提示去规则库 |
| A14 | 本体引用升级 | 新属性类型输出说明同步，SQL 未执行事实明确，不能宣称自动兼容 |
| A15 | 测试隔离 | 不改用户 ontology，不执行 SQL；相关回归及 build 通过 |
