# 显示格式优化需求 v1

日期：2026-09-15  
状态：供开发实施；本次仅产出文档，未修改代码。  
范围：本体属性和共享属性的“显示格式”配置、持久化与样本预览。

## 1. 已确认的产品方向

1. “显示格式”仍在属性选填区，默认折叠。
2. “格式化方式”下拉仅保留 **常用格式、自然语言**，不再提供新建 JavaScript 自定义函数的入口。
3. “常用格式”按当前属性的数据类型联动展示，覆盖本文字段；不再要求用户重新选择属性数据类型。
4. 自然语言规则接收属性值，输出显示文本，通过已有大模型预览链路处理。
5. 保留现有默认偏好：新配置的格式化方式为自然语言。打开未配置属性时不创建配置、不触发保存或模型请求；未填写自然语言规则时按未配置处理。
6. 本次借鉴 Palantir 的按类型配置及预览思路，字段是工作台自己的产品设计，不宣称与 Foundry 协议完全兼容。

## 2. 固定交互

属性编辑 → 展开“显示格式” → 格式化方式二选一。

| 选择 | 展示内容 |
|---|---|
| 常用格式 | 当前类型的显示样式、该样式必要参数、空值显示、样本预览 |
| 自然语言 | 自然语言格式规则、空值显示、样本预览 |

- 格式化方式使用现有 AppSelect / EditorField，风格与管理后台一致。
- 默认只展示相关字段；切换样式后不展示无关配置。
- 不增加向导、额外保存步骤、独立格式管理菜单或单位管理页面。
- 沿用属性表单保存：编辑只改本地草稿，保存一次持久化，取消不落盘。
- 明确提供“恢复原样显示”操作：仅在本地表单中清除显示格式，用户保存属性后生效。无配置时直接显示原值。
- 格式化方式和样式来回切换时，当前表单内已填写内容尽量保留；只有当前方式／样式参与预览。
- 历史格式不能静默重置，规则见第 7 节。

## 3. 按类型展示的常用格式

以下为本轮要实现的范围。整数、精确小数等历史数值类型复用数值表单，日期与时间戳保留原类型，不能因编辑格式而改写属性类型。

| 属性类型 | 显示样式 | 样式参数 | 示例 |
|---|---|---|---|
| 文本 | 原样、模板、值映射 | 模板填写“显示模板”，使用 `{value}`；值映射用多行键值表维护“原始值 → 显示文字” | `ESS-{value}`；`running → 运行中` |
| 数值 | 普通数字、百分比、货币、科学计数 | 小数位数、千位分隔、显示前缀、显示后缀；百分比增加原值口径；货币增加币种 | `1234.5 → 1,234.50 kW` |
| 是／否 | 默认、自定义文字 | 自定义文字时填写 true 显示文字、false 显示文字；默认分别为“是”“否” | `true → 启用` |
| 日期 | 仅日期、自定义格式 | 仅日期展示到年／月／日；自定义格式填写格式模板 | `2026`、`2026-09`、`2026-09-15` |
| 时间戳 | 仅日期、日期时间、仅时间、相对时间、自定义格式 | 日期时间／仅时间可选择到分钟／秒；仅日期可选择到年／月／日；支持显示时区；自定义格式填写格式模板 | `2026-09-15 14:30`、`14:30:25` |
| 数组 | 列表、分隔文本 | 最多显示项数；分隔文本增加分隔符；可选展开“元素格式” | 列表逐项换行；文本 `A、B、C…` |
| 结构体 | 字段列表、模板 | 字段列表维护展示字段及顺序；模板填写显示模板，字段以 `{字段名}` 引用 | `{manufacturer} / {model}` |
| 时间序列 | 时间和值 | 时间格式、观测值格式分别复用对应常用格式配置；不再选择观测值类型 | `2026-09-15 14:30  70.5%` |

### 3.1 数值规则

- 小数位数：0—20 的整数；不填则使用原有默认数值精度行为。填写后表示固定小数位，最少和最多小数位一致。
- 千位分隔：默认开启；科学计数样式不展示该项。
- 百分比口径：必须明确选“0—1（0.7 → 70%）”或“0—100（70 → 70%）”；无历史配置时不替用户猜测，未选时提示补选。
- 币种：CNY、USD、EUR 常用选项，允许输入有效货币代码；默认 CNY。
- 后缀就是显示文字，不隐含单位换算；输入 1000 后添加 kV 后缀，不能自动除以 1000。页面提供一句简短提示。
- 普通格式不改变底层属性值，不改变计算、筛选、排序口径。

### 3.2 文本与空值规则

- 文本模板只替换 `{value}`，不执行代码；映射按原始文本精确匹配，不匹配时保留原值。
- 映射行允许添加／移除；重复原始值提示错误，禁止用后行静默覆盖前行。
- 共用“空值显示”默认 `—`。仅 null／缺失值算空值，0、false、空字符串不自动等同 null。
- 自然语言模式也采用这一空值策略：空值在本地返回占位文字，不发起大模型请求。
- 格式中不加入颜色、告警阈值等条件格式能力。

### 3.3 日期与时间规则

- 纯日期没有时区设置，禁止通过格式补出时分秒。
- 时间戳时区提供“Asia/Shanghai”“UTC”和可输入的 IANA 时区；默认沿用 Asia/Shanghai。
- 本轮不引入浏览器自动推断时区，保证预览结果可复现。
- 自定义模板支持 `YYYY`、`MM`、`DD`、`HH`、`mm`、`ss`，其余文字按原样显示。
- 相对时间沿用当前运行时规则；示例结果依赖预览时刻。测试固定时钟，不断言会随时间漂移的文本。

### 3.4 数组、结构体和时间序列

- 数组最多显示项数默认 10，允许 1—100，超出后显示省略提示；不截断真实数组。
- 元素格式默认原样；有元素类型元数据时自动使用。缺失元数据时，仅在用户主动配置元素格式时选择元素解释类型；不据此修改本体数据类型，不根据第一个样本自动推断。
- 数组元素格式本轮仅支持文本、数值、布尔、日期／时间的常用格式，不支持无限嵌套或逐元素调用模型。
- 结构体展示字段按用户排序输出；未配置字段清单时按输入字段顺序展示。可使用简单可排序字段行，不要求引入拖拽库。
- 结构体模板本轮仅支持顶层字段，字段缺失使用空值占位；不执行表达式，不开放任意属性路径。
- 时间序列预览采用规范样本 `[{"timestamp":"2026-09-15T14:30:00+08:00","value":70.56}]`；输入提示写明形态。
- 时间序列的时间和值分别格式化，一条记录一行；空数组显示“暂无记录”。本轮不画曲线，不查询数据、不计算平均值、不改变采样周期、不补点。
- 时间序列选择自然语言时，整份受大小限制的样本作为一次输入；不逐条调用模型。

## 4. 自然语言模式

- 展示“自然语言格式规则”，必填后才可预览／保存为有效自然语言配置。
- 示例随类型变化，例如数值：“输入为 0—100 的 SOC，保留一位小数并添加百分号，只输出结果。”
- 保留现有大模型配置与服务端请求路径，不新增模型选择、密钥填写或代码生成页面。
- 点击预览才发请求；说明样本和规则会发送到已配置模型。没有模型配置时明确提示，允许保存已填写的规则。
- 失败显示实际可理解错误，不显示假结果，不自动改用另一种格式方式。
- 不要求大模型生成或执行代码，只输出显示文本。

## 5. 预览、保存与共享属性

- 样本和预览结果是临时状态，不保存为对象属性值，也不写入模型配置。
- 所有输入支持 null 样本；文本与日期仍支持直接输入，需明确 null 的输入说明。
- 修改样本、格式、属性或关闭编辑器后，旧异步响应不得覆盖新状态。
- 预览输出以文本安全渲染，不使用 v-html；保留输入大小、输出长度和超时限制。
- 共享属性沿用当前引用和解除引用机制；修改共享格式时保留现有影响提示，不能把共享引用静默复制为私有。

## 6. 存储与实现边界

- 继续使用属性的 `mg:formatting` JSON 配置；API 边界仍使用现有 `formatting` 字段，不新增散落的单位／小数位顶层字段。
- 新配置 mode 仅为 `builtin` 或 `natural`；历史 `code` 可兼容读取与预览，但不作为新建选项。
- 优先复用既有 style、minDecimals、maxDecimals、percentInput、currency、prefix、suffix、timezone、pattern、trueText、falseText、separator、emptyText、instruction 等键。
- 本轮新增键建议冻结为：`template`（文本／结构体模板）、`mappings`（文本映射行数组，元素为 `{from,to}`）、`maxItems`、`elementType`、`elementFormat`、`fields`（结构体字段名顺序数组）、`timeFormat`、`valueFormat`。
- 新样式可复用／扩展为 template、mapping、list、join、pairs、series；数值科学计数仍用 notation=scientific；时间精度可通过现有 pattern／style 表达，不重复存储互相矛盾的精度字段。
- 时间序列预览的 dataType 可扩展为 timeSeries；不改动本体已有 `{type:'timeSeries',valueType:...}` 语义。
- 若需改变上述命名，先在实施记录中说明原因并同步所有消费者；不得前后端各自设计协议。

## 7. 历史兼容

- 旧 code 配置：显示“历史 JavaScript 格式（兼容保留）”提示和只读内容；下拉仍只有两项，未切换前保持历史配置，不能伪装成自然语言。允许显式选择新方式替换，不自动转换代码为自然语言。
- 旧 upper／lower／trim／mask／truncate、count／json、compact／engineering、ISO 等样式不主动删除、不静默改成原样。用“历史样式：…”只读摘要保留，显式选择新样式后才替换。
- 旧最少与最多小数位不同：保留原结果；表单提示原范围，用户填写新的“小数位数”后才统一为固定精度。
- 未修改格式时，打开、预览、修改其他属性字段再保存，旧配置及未知扩展键必须保留。
- 不批量重写 ontology/，不修改已发布快照，不自动升级项目引用。
