# 通用属性来源配置需求说明 V1

日期：2026-09-14  
用途：工作台增量开发交接。本文件描述待实现需求，不表示当前已具备这些能力。  
配套：[GLM 开发指令](../交付物/GLM开发指令_通用属性来源配置_20260914.md)

## 1. 要解决的问题

当前属性来源中的“字段所在来源”，只能选择当前对象的实例来源和已登记的数据库补充来源。每个字段映射最终返回一个值，多条记录只能取最新、求和或平均。

这不能完整表达以下业务：储能簇由台账表识别，但 SOC 历史数据在一个同时存储多类对象、多种指标的采样表中，需要按对象和指标定位记录，再返回“时间＋值”的序列。

改造目标：**属性来源不再受对象已登记表的范围限制，统一描述“从哪里取、如何找到当前实例的数据、如何组成属性结果”。**

不能仅把取值字段改成多选框：多个字段还需要说明各自角色，多条记录也需要明确返回规则。

这是本项目自有配置方案，借鉴本体语义与项目实现分离的思路，不是 Palantir 官方配置格式，也不宣称已实现 Foundry 的时间序列服务。

## 2. 范围与既有文档关系

在现有 Vue3 管理后台上增量修改，沿用 AppSelect、对象列表＋详情、局部编辑草稿，以及本体／项目独立保存发布机制。

相对于《项目映射与数据连接需求说明_20260914.md》，本文件更新以下规则：

| 原规则 | 本轮规则 |
| --- | --- |
| 属性字段只能选对象已登记来源 | 可直接选当前项目连接下目录中可见的表／视图；已登记来源仍可快捷复用 |
| Redis 必须先登记为对象补充来源 | 可直接选择当前项目 Redis 连接；兼容旧来源引用 |
| 属性映射只返回单值 | 支持单值与时间序列，按目标属性的结果形态配置 |
| 采样序列不在范围内 | 本轮包含时间序列的定义、映射、配置校验与保存发布；不含真实业务数据执行 |

继续保留：连接测试、服务端表结构目录、对象实例识别、已有补充来源、两端来源下拉的链接映射、计算实现页。

本轮不做：任意 SQL 编辑执行、多表可视化查询编排、跨库查询引擎、ES 适配器、真实 Redis 业务 Key 读取、函数执行、任意结构体／数组建模器、公共来源模板库。已有结构体／数组和旧配置须保持可读且不丢失，不展示尚未实现的新配置入口。

## 3. 三个概念及职责

| 概念 | 作用 | 储能簇示例 | 维护人 |
| --- | --- | --- | --- |
| 本体属性 | 定义业务含义、值的数据类型、结果形态与单位 | 额定功率：数值单值；SOC 采样序列：带时间的数值序列 | 业务专家 |
| 实例识别来源 | 确定有哪些对象实例、实例的唯一标识 | m_storage_cluster_phase.id | 开发／实施 |
| 属性来源 | 为当前实例取得符合属性定义的结果 | 台账字段、Redis Key、公共采样表或项目函数输出 | 开发／实施 |

对象实例来源不是其全部属性的来源白名单。公共采样表也不必因为给储能簇供数而成为储能簇的实例来源。

数据库主键、查询匹配用的编码等技术字段，可以用于项目参数绑定，不要求先创建为本体业务属性。

## 4. 用户操作流程

进入项目 → 对象与链接绑定 → 储能簇 → 属性来源 → 选择某一属性“配置”。

列表显示：属性名称、目标结果形态、取值方式、来源摘要、配置状态。详情按以下顺序展开：

1. **属性要求**：只读显示名称、业务定义、数据类型、单值／时间序列、单位，来自项目引用的本体发布版本。
2. **数据来源**：数据库取值／Redis 查询／函数结果，单选一种。
3. **记录定位或输入绑定**：根据来源显示匹配条件、Key 参数或函数输入说明。
4. **结果映射**：把来源字段或输出对应到属性要求的结果角色。
5. **配置摘要**：用可读文本说明取值过程；保存配置／取消。

每个属性只有一份有效来源配置。切换方式只影响局部草稿；保存整体替换，取消恢复原配置。列表“已配置”不等于“已验证”。

必填字段直接显示，带具体填写示例；有明确默认行为的异常处理放在最后，默认折叠。稳定标识由系统管理，不要求用户填写。

## 5. 本体侧最小补充：结果形态

项目映射必须遵守本体属性的结果形态，不能在项目侧把一个数值属性随意改成数组。

| 结果形态 | 含义 | 配置时需要映射 |
| --- | --- | --- |
| 单值 | 当前实例的一个文本、数值、是／否或日期值 | 一个值字段／一个兼容的输出 |
| 时间序列 | 当前实例按时间排列的一组观测点 | 每个点的时间和值 |

本轮在属性管理增加“结果形态”，默认单值；选择时间序列后，“数据类型”表示每个观测值的类型，时间部分由序列结构自带，不再要求另建一个时间属性。已有普通属性保持原义，不能根据名称含“采样”自动转换。

实现建议使用独立协议字段 `valueShape: scalar | timeSeries`，与 `dataType.type` 分开；JSON-LD 侧使用自有命名空间对应字段。缺省按单值解释。具体编码由开发在实施说明中固定，前后端必须镜像、无损往返。

新字段必须进入共享属性继承／复制／解除引用、契约属性引用的类型检查、变更分类及项目升级预检。单值改为时间序列属于破坏性变更；缺省单值与显式单值应视为等价，避免旧版本误报。

同一个共享属性定义包含完整类型要求。SOC 单值与 SOC 时间序列不能直接引用同一份完整共享定义。两者可以填写一致的 SOC 含义和单位，本轮不另做指标语义库。

若需要“单个带时标的观测点”，它在概念上也是时间和值的组合；本轮不额外引入第三种形态。数值单值不会因为多选了时间字段就变为对象。已有标量实时 SOC 保持标量；需要对外返回其采集时间时，应另行明确契约或结构定义。

## 6. 数据库取值

### 6.1 来源选择

选择当前项目已配置的 MySQL 连接 → 搜索表／视图 → 选择字段。范围是该连接配置数据库的可见目录，不是任意服务器或任意手输表名。

提供“使用实例来源”“使用已登记补充来源”快捷操作，自动带入连接、表及已有匹配规则；同时支持直接搜索其他表，不要求返回对象来源页登记。

直接选表的配置保存在当前属性绑定中，不自动增删对象 `sources[]`。它不会改变链接映射的来源范围。

表、字段仍用可搜索下拉，不支持自由填写。目录缺失时就地引导刷新；刷新失败保留当前配置，显示原因。换连接／换表，清除局部草稿中不再有效的字段、条件、排序，提示重新选择，不能带着旧字段保存。

### 6.2 定位当前实例的记录

条件编辑器采用“来源字段＋操作符＋比较值来源”。首期支持多条件 AND，不做嵌套 OR 查询设计器。

| 比较值来源 | 示例 | 要求 |
| --- | --- | --- |
| 当前实例主键 | sample.object_id = 当前储能簇实例主键 | 自动使用实例识别配置，禁止让用户逐实例填写 ID |
| 当前实例身份表字段 | sample.asset_code = 当前身份记录.asset_code | 从身份表目录选择，不要求建为业务属性 |
| 当前对象已映射的单值属性 | sample.device_code = 当前对象的设备编码 | 稳定属性引用、检查依赖循环和类型；不能依赖本属性或序列 |
| 常量 | sample.object_type = storage_cluster；sample.metric_code = soc | 常量按字段类型填写；不是自由 SQL |
| 项目参数 | sample.site_code = 项目站点编码 | 选择已存在参数，检查是否能得到单值 |

实例匹配首期使用等值条件，至少一条条件绑定当前实例。常量、项目参数只能补充筛选，不能代替对象关联。身份表本行取值自动按主键定位，无需重复填写。

类型不兼容不能用隐式字符串转换掩盖。需要转换的复杂匹配交给已有数据库视图或项目函数，本轮不增加任意表达式编辑器。

重复条件、空条件和失效引用有就地提示。不能仅写一句“按当前对象过滤”就声称已形成可校验配置。

### 6.3 结果映射与多行处理

| 目标形态 | 必填内容 | 多行处理 |
| --- | --- | --- |
| 单值 | 值字段 | 默认预期零或一条，超过一条报错；可明确按时间取最新 |
| 时间序列 | 值字段、时间字段 | 返回所有匹配观测点，按时间升序；不要求取最新或汇总成单值 |

保留已有求和／平均配置及入口，仅对兼容数值且业务口径允许时使用；本轮不扩展新的聚合运算。排序时间不能当作求平均等聚合输出的采样时间。

时间序列默认时间窗口来自调用上下文 `startTime`、`endTime`，采用 `[startTime, endTime)`：映射定义保存参数角色，调用时提供具体时间，不把某次日期写死在属性定义中。无执行器时仅配置、校验及展示这份约定。未来执行器须有范围／点数上限和截断说明，本轮不把全历史无界查询包装成可运行功能。

时间字段支持日期时间或数值时间戳。前者必须明确来源时区（可用项目时区默认值并展示），后者必须选秒／毫秒；输出统一使用带时区的 ISO 8601 时间。仅有日期、没有一天内时刻的字段不能直接用于五分钟采样序列。

同一实例同一指标同一时刻出现多个值，默认报数据冲突；可配置基于明确次级排序的取舍，不能静默随机保留。按时间取最新遇到并列且无确定性取舍规则，同样报冲突。元数据不能证明实际记录唯一。

高级处理默认：单值无记录为 null；序列无记录为空列表；序列中值为空保留 null（不补零）；无效时标或转换失败报错误。页面显示这些默认行为，不以缺失代替错误；未来运行时必须遵守。

多个字段按“值、时间”等角色映射，不提供不说明用途的任意字段多选。结构体、列表可以沿相同输出映射机制扩展，但不在本轮新增支持范围。

## 7. 三个储能示例

以下表名／字段用于说明，除用户明确给出的内容外均为示例，开发只能写入隔离测试数据。

| 项目属性 | 来源 | 实例定位／输入 | 结果 |
| --- | --- | --- | --- |
| 储能簇额定功率 | MySQL：m_storage_cluster_phase.rated_power | 身份表本行，按 id 自动定位 | 数值单值，单位按本体定义 |
| 储能簇实时 SOC | Redis GET：m_storage_cluster-{id}-soc | id 绑定当前实例主键 | 转为数值；缺失不是 0 |
| 储能簇 SOC 采样序列 | MySQL 公共表 telemetry_sample | object_id=当前实例主键，object_type=storage_cluster，metric_code=soc | sampled_at→时间，value→值；按调用时间范围返回序列 |
| 储能簇采样功率计算结果 | 已有项目计算实现 | 当前对象、契约声明的时间输入等 | 选择兼容输出；若声明为序列，输出须满足时间＋值结构 |

公共采样表宽表形式也使用相同配置：例如 `sampled_at` 为时间、`soc` 为值、`cluster_id` 为实例匹配字段，不需要额外“宽表策略”。长表中的 `metric_code=soc` 是过滤条件，也不需要额外“长表策略”。

SOC 序列的结果示意：

```json
[
  {"timestamp": "2026-09-14T10:00:00+08:00", "value": 68.5},
  {"timestamp": "2026-09-14T10:05:00+08:00", "value": 68.2}
]
```

五分钟是该项目的数据采样配置，不自动等于五分钟平均值，也不强制其他项目按同样频率采样。

## 8. Redis 与函数的统一边界

统一的是“输入绑定＋结果要求”，来源编辑器保留不同表单：

- Redis：直接选当前项目 Redis 连接，配置 GET／HGET、Key 模板、参数、结果转换。旧对象 Redis 来源仍可读取和快捷复用。增加当前身份表字段参数绑定，与数据库匹配使用同一参数表示。
- 函数：选择项目实现与其输出，输入继续在实现页维护，属性页可查看并跳转，不复制实现规则。
- 数据库：选择表、定位记录、映射输出字段。

Redis 简单读取不强制创建本体计算契约。GET／HGET 的普通数值输出不能绑定时间序列；本轮不引入 Redis 历史序列协议或 JSON 路径解析器。复杂结果使用声明了兼容输出的项目函数，并标明尚未执行。

函数输出引用目标属性时，应解析该属性的有效结果形态和数据类型；只比较“都是数值”不足以认定单值与序列兼容。

## 9. 配置结构与文件职责

采用来源、定位、结果三个独立部分。以下是逻辑结构，开发需结合现有适配层确定版本标记和字段名，不可把示意 ID 写入真实项目：

```yaml
# 概念示例：某个 SOC 序列属性的一份绑定，不是可直接导入文件
source:
  kind: database
  connectionId: <项目连接稳定ID>
  table: telemetry_sample
lookup:
  match:
    - field: object_id
      operator: eq
      value: {kind: currentIdentity}
    - field: object_type
      operator: eq
      value: {kind: constant, value: storage_cluster}
    - field: metric_code
      operator: eq
      value: {kind: constant, value: soc}
  timeRange:
    field: sampled_at
    start: {kind: context, name: startTime}
    end: {kind: context, name: endTime}
    bounds: '[start,end)'
result:
  valueField: value
  timestampField: sampled_at
  timestampEncoding: datetime
  timezone: Asia/Shanghai
  order: ascending
  duplicateTimestamp: error
```

结果形态以引用版本的本体属性为准，不在绑定里另存一份可任意改变的声明。保留“已登记来源引用”和“直接连接＋表定位”两种表示时，必须明确互斥，不能出现两份表名谁生效不清楚的问题。

| 内容 | 文件／存储职责 |
| --- | --- |
| 业务定义、数据类型、结果形态、共享属性 | 本体 ontology.json，经本体 API 保存到本体草稿修订和发布版本 |
| 实例来源、属性来源／匹配／输出映射、链接映射 | 项目 bindings.yaml，经项目 API 保存 |
| 函数处理规则、输入绑定、输出声明 | 项目 implementations.yaml |
| 连接配置与凭据引用 | 项目 connections.yaml；密码由 vault 单独管理 |
| 项目时区等参数（如使用） | 项目 parameters.yaml，不重复写进本体 |
| 项目身份、引用的本体版本 | 项目 project.yaml |
| 表结构目录 | 现有服务端 ontology/catalogs/projects 缓存；不进草稿、快照或修订哈希 |

项目编辑不能直接改变本体定义。需要新增序列属性时，先通过本体页面保存发布，再让项目执行升级预检；不能自动改写用户已发布版本。

## 10. 兼容、校验与状态

1. 旧字符串字段映射、related_sources、field／redis／computed 配置仍可读取、展示、保存及发布；无用户编辑时不能暗改其语义。
2. 新结构通过明确版本或结构分支识别。不能把未知 kind 默认解释成函数结果；不能把所有 field 都按单字段旧模型序列化，导致时间或过滤条件丢失。
3. 只有确实等价于旧身份表直接字段的映射，才允许编码为字符串。任何新增过滤、时间、缺失策略等信息都不能在压缩时丢失。
4. 旧 many 来源的 latest／sum／average 保持原规则；新字段直接选表的配置不依赖对象补充来源基数。
5. 后端重复校验引用归属、连接类型、条件输入、结果角色、类型／形态、循环依赖，不能只靠前端禁用按钮。
6. 目录缺失或过期标明“元数据待核对”，保留旧配置；当前目录明确显示字段不存在或类型不匹配时提示具体位置。结构性错误阻止生效和发布；可按现有项目机制保存待修复草稿，不能标为配置通过。
7. 连接删除／改类型检查直接属性引用与旧来源引用；被引用时阻止删除并定位。属性、来源、参数、实现的变更须检查影响，不能静默删除其他配置。
8. 本体形态改变后，项目固定引用旧版本不受影响；主动升级时报告受影响映射与契约实现。引用失效不得人工改为兼容绕过。
9. 状态至少区分未配置、配置有误、元数据待核对、配置校验通过／未执行验证。连接成功不能提升为属性执行成功。
10. 演示合并仅向旧执行器传递其确实支持的身份表字符串字段，其他来源必须过滤并清楚显示未支持，不能伪装执行成功。

| A6 | 序列漏时间字段、匹配缺当前实例、类型不兼容 | 就地报错，后端同样拒绝认定有效 |

| A8 | 秒／毫秒与无时区日期时间 | 必须明确编码与时区；无效时标和重复时刻处理能保存校验 |
| A9 | Redis 未登记为对象来源 | 可直接选项目连接，Key 参数绑定身份主键／身份字段 |
| A10 | 标量函数输出绑定序列属性 | 类型／形态校验不通过 |
| A11 | 换来源后取消；保存后重载 | 取消保留旧配置；保存仅保留一种有效配置且全部字段往返完整 |
| A12 | 新形态发布、共享引用、项目升级 | 形态继承正确；变化识别为破坏性；旧项目版本不自动升级 |
| A13 | 大目录刷新、读取失败与切换连接并发 | 目录不进保存请求／快照／revision；失败不清旧值，旧响应不覆盖新选择 |
| A14 | 旧修订保存、跨项目引用、删除被引用连接 | 409、归属校验和引用保护正常 |
