# 通用属性来源配置 实施说明

日期：2026-09-14。配套：[需求说明 v1](../文档/通用属性来源配置需求说明_v1_20260914.md)、[开发指令](./GLM开发指令_通用属性来源配置_20260914.md)、[数据契约与实施设计](./通用属性来源配置_数据契约与实施设计_20260914.md)（内部设计底稿，含最终协议全貌）。

## 1. 交付范围

- 本体侧新增属性「结果形态」`valueShape: scalar | timeSeries`，默认单值；项目侧属性来源新增「数据库直选表（database）」与「Redis 直连」两种结构，支持多条件 AND 记录定位、单值/时间序列结果映射；computed 函数输出增加形态声明。仅配置与校验，无业务执行 API。
- 兼容：旧字符串直取、field/related/redis/computed 全部原语义保留；未知结构零丢失。

## 2. 最终协议（摘要，全文见设计底稿）

### 2.1 本体 valueShape

- schema 字段 `valueShape` ↔ JSON-LD `mg:valueShape`（普通字面量，两端 FIELDS 镜像）；**单值不落盘**，只有 timeSeries 才写 `'timeSeries'`；`dataType` 为 array/struct 时禁止 timeSeries。缺省单值与显式单值等价（classify 规范化）。
- 共享属性继承（properties.py FIELDS / propertyModel.ts metadataKeys）自动携带；对象属性引用共享定义时形态跟随共享定义，不可本地覆盖（既有校验自动生效——SOC 单值与 SOC 序列必须使用不同共享定义）。
- `STRUCTURAL_FIELDS` 增加 valueShape：单值↔序列互改 = 破坏性变更。

### 2.2 项目属性来源新结构

- `{kind:'database', connection, table, lookup:{match[], timeRange?}, result:{...}}`：直选项目 MySQL 连接目录中的表/视图；match 首期仅 `eq`，比较值来源五类（identityKey/identityField/property/constant/parameter），至少一条绑定当前实例（身份表本行同连接同表豁免）；timeRange 仅 timeSeries 目标（`[startTime,end)` 上下文约定）；result 按 scalar/timeSeries 分支（详见设计底稿 §2.2）。
- redis kind 扩展 `connection`（与 `source` 互斥）＝直连；params 新增 `{from:'identityField', field}`；普通 GET/HGET 不得绑定 timeSeries 目标。
- computed：`outputDeclarations[]` 增加可选 `valueShape`（缺省 scalar），与目标属性形态不一致即校验失败。
- **压缩规则**：database 草稿等价于旧身份表直取时（同连接同表、无条件、无时间、scalar、result 仅 valueField）编码为字符串；其余完整落盘。timeSeries 目标仅接受 database 或声明序列的 computed。
- 循环依赖：同对象内 database 经 `{kind:'property'}` 依赖图 DFS 检环。

## 5. 运行边界（未实现，界面已如实标注）

- 本轮只有连接测试与目录读取是真实网络访问；业务 SQL、Redis Key、函数与时间序列查询仅配置校验，无执行 API。列表状态「配置校验通过 · 未执行验证」即此含义；演示执行器仍只接收身份表字符串映射，其他来源显示「未支持」。
- Redis 无表结构目录（引擎限制）；match 仅等值 AND；无嵌套 OR 设计器；时间序列执行器（范围/点数上限）留待后续。
