## 1. 保存协调器协议（P01 实现，文件 `frontend/src/saveCoordinator.ts` 新增）

```ts
export type SaveStatus='saved'|'dirty'|'saving'|'error'|'conflict'
export interface Saver{
  status:Ref<SaveStatus>; error:Ref<string>; lastSavedAt:Ref<string>
  working:Ref<any>            // 当前工作副本（App 的 state/projectState 即此对象的 .value）
  revision:Ref<string>
  commitNow():Promise<void>   // 立即持久化当前 working（表单保存按钮/撤销重做/图操作结束调用；取消 pending debounce）
  touch():void                // changed() 入口：dirty + debounce 900ms 自动保存（连续编辑合并）
  flush():Promise<void>       // 切换本体/项目/版本/页面离开前 await（保存中则等待完成）
  reload():Promise<void>      // 放弃本地修改，重新 GET（conflict/用户显式操作）
  retryFromLocal():Promise<void> // conflict 时：refetch 最新 revision 后以当前 working 内容重提交（UI 需用户点击确认，非自动）
  retry():Promise<void>       // error（网络/5xx）时重试上次未成功快照
}
export function createSaver(label:string, load:()=>Promise<{state:any;revision:string}>,
  submit:(state:any,revision:string)=>Promise<{revision:string}>):Saver
```

行为细则：
1. **串行**：同一 Saver 同时最多一个在途请求；入队项携带"入队瞬间的 working 深快照 + 当时 revision"。
2. **成功合并**：响应 revision 写回；若入队后 working 又被修改（代数变化）→ 状态回 dirty 并继续下一轮；无后续修改 → saved。
3. **失败**：网络/5xx → error（保留 working，可 retry）；409 → conflict（后端响应将带 `currentRevision`，retryFromLocal 用它 refetch 最新 state 重新载入为基线后，把本地 working 内容带新 revision 提交一次——用户显式点击，非自动覆盖）。注意 refetch 会覆盖 working：retryFromLocal 先把本地 working 深拷贝暂存，载入服务端最新后**逐键合并不可行**，故 retryFromLocal 语义=「以我屏幕上的内容为准重试」，UI 文案必须写明将覆盖服务端较新草稿，需二次确认。
4. **beforeunload**：dirty/saving/conflict 时拦截。
5. 快照/撤销钩子保留 App.vue 现有 pushUndo 机制（before-change 时快照）；undo/redo 应用后调用 commitNow()（产生新修订，不回写旧修订）。
6. **画布 zoom/pan 不得触发保存**（现 App.vue L146 的 zoom/pan→changed 要降级为仅 captureLayout，不 dirty）。
7. 本体区 POST /api/save 响应 `{revision,errors}`——errors 非空时仍算保存成功（草稿允许带错误），状态条显示 saved 但提示"N 项校验问题"。
8. 本体 /api/validate 不走保存队列（只读校验）。

## 5. 表单提交协议（全部组件统一）

- 组件保持 props/emits 不变；内部局部 draft 机制保留（编辑副本→取消丢弃→保存提交）。
- **表单"保存"按钮**：校验→mutate 写入 working→`inject('commit-now')()`（App provide，调 saver.commitNow）→按钮进入 saving 态→成功显示"已保存"。失败不关表单，保留输入，显示错误。
- **即时编辑型控件**（字段/列表增删/开关）：行为不变（mutate+emit changed），由 App 的 touch() 自动持久化（900ms 合并）。
- **取消**：仅还原局部 draft，不触碰 working 已有内容。
- 离开保护：dirty 时切换本体/项目/版本（App 内 flush 后放行，flush 失败 confirm）；表单内部切换对象/属性若 draft 有未保存修改，组件内 confirm（P05/P07 表单型组件实现；提示"继续编辑/放弃"）。

## 7. 组件间接口（冻结）

- ObjectCanvas：见 §2。P03 只消费，不改该文件。
- provide/inject：`'commit-now': () => Promise<void>`（App provide；P05/P07/P08 表单保存按钮调用；调用前组件已 mutate）。
- ProjectBinding props 不变（project-state, ref-state, focus-type, report）。
- ImplementationManager 新增可选 prop `focusImpl?:string`（watch 定位并高亮对应实现；P06）。
- navigate 事件签名统一：`emit('navigate', view:string, focus?:object)`；App 接住转内部导航。
- 发布动作：OntologyRelease/ProjectValidation 内部完成发布对话框与 API 调用；成功后 emit('published')，App 收到后刷新版本相关数据（不再负责发布逻辑）。
