## 任务顺序

### T1：检查基线并锁定协议

阅读当前文件：
- frontend/src/project/QueryRuleManager.vue
- frontend/src/project/QueryRuleImplementation.vue
- frontend/src/project/queryRules.ts
- frontend/src/project/sqlTemplates.ts
- frontend/src/project/PropertySources.vue
- workbench/query_rules.py、sql_templates.py、project_validation.py
- tests/query_rules.test.mjs、sql_templates.test.mjs、test_query_rules.py、test_sql_templates.py

先确认现状；已有并发修改必须保留。建立 V4 sqlSteps 协议，明确稳定 id/key、inputs、steps[].sql、result.step。不要只改页面不改后端校验和属性绑定支持。

### T2：旧格式适配和校验

实现 V1/V2/V3 结构化规则、V3 sqlTemplate → V4 卡片的内存转换。成功转换必须无损；失败保留旧原文和编辑回退。保留 implementation ID、output 稳定键、未知扩展字段。打开不自动保存。

双端校验参数／前向引用／唯一记录／返回类型；扫描 SQL 时正确处理注释、字符串、分号。不能用正则黑名单声称实现了安全 SQL 执行。

### T3：卡片 UI

基本信息和参数区复用。每张卡片仅步骤名、只读技术名、SQL 编辑框、one/many、上移下移删除、插入引用。新增步骤不修改已有步骤语义。插入引用定位光标并保留文本；仅列出前面 one 步骤。输出选择独立，不强制最后一步。

使用现有 Vue/TypeScript、AppSelect 和后台样式。不要引入流程图引擎、全站状态库、大型 SQL 编辑器或跨库连接配置。

### T4：保存与绑定集成

沿用 form-save、form-guard、保存协调器及 revision；不要自写 fetch 或保存队列。V4 规则能在属性取值中选择，输入参数按声明填写，返回类型与本体属性校验相容。修改规则后应提示已有引用需要检查。

### T5：验证与交付

测试一律使用临时 WIZ_WORKBENCH_ROOT 和独立 WIZ_WORKBENCH_PORT；不得为演示写用户 ontology/。覆盖 SQL 卡片保存重开、输入引用、步骤移动失效、one/many、返回步骤、旧格式转换失败回退、属性绑定兼容。修改项目校验则按 AGENTS 加金样，不把无关失败覆盖进预期。

执行相关测试与 `cd frontend && npm run build`。浏览器验证至少覆盖三步采样卡片、插入引用、重排后错误提示、取消；保存往返用隔离实例。测试未通过不能宣称完成，说明已有失败和新增失败。
