## 2. 协议样例（冻结实现）

```yaml
identity: {kind: registered, instances: [{id: CZYEQ-ESS-001, label: 创智园二期储能系统}]}
properties:
  sysname: {kind: registered, field: label}
  cap: {kind: aggregate, relation: l_contains, property: devcap,
        operator: sum, empty: 'null', missing: incomplete, inputUnitConfirmed: true}
relations:
  - kind: membership
    relation: l_contains
    target_type: dev
    rules:
      - sourceInstance: CZYEQ-ESS-001
        scope: filtered
        conditions: [{field: park, operator: eq, value: CZY}, {field: del_flag, operator: eq, value: 0}]
```

## 4. 支持范围与明确不支持

支持：登记对象 → 一跳 membership 链接（一对多/多对多）→ MySQL 身份表直接数值字段 → SUM；registered 属性（id/label）。
不支持（显式报错，不隐式执行）：AVG/MIN/MAX、Redis/时序聚合、跨库 JOIN、递归聚合、多对一/一对一链接成员规则、补充表字段聚合、scope 缺省整表。

## 9. 扩展（20260916）：集合端按端判定，支持入向多对一链接

用户裁决：判定应基于链接数量关系而非方向——多对一链接的"一"端对象即可聚合。实施为"集合端按端判定"：

- **规则**（前后端同一来源）：持有者在 domain 侧（出向）须 one-to-many/many-to-many，成员=range；持有者在 range 侧（入向）须 many-to-one/many-to-many，成员=domain。共享助手 `project_mapping.member_side_of`。
- **后端**：`project_validation.py`（聚合与 membership 校验改按端判定，消息更新）、`project_property_reader.py`（成员解析按端判定；入向 many-to-one 归一化为集合端一对多参与归属核对）。
- **前端**：`PropertySources.vue`（aggregateLinkOptions 触及本对象的链接全列出，入向标注"（入向）"；成员端取 member 侧）、`LinkMappings.vue`（添加链接纳入入向多对一/多对多；成员编辑器方向感知展示"设备 — 属于系统 → 系统（入向 · 成员=设备）· 多对一"；入向只读区排除可配置项）。
- **协议不变**：membership 仍挂集合端绑定，target_type=成员端对象；入向时成员=domain 侧。旧出向配置零影响。
- **金样受控更新**：样例 46 两处消息变化（belongsToStation 无端定义链接 → "两端都不是当前对象"；systemAlias 一对一消息细化），test_validation_split 同步；test_registered_validation 更新 3 处消息并新增入向正反用例。
- **新测试**：`tests/test_incoming_aggregate.py`（8 步，端口 18950）：入向本体发布→membership 挂系统绑定→校验通过→预览 **500**（他园排除）→成员预览→反例（数量关系不满足判定为空）。
- **浏览器端到端**（18900"入向链接UI验证项目"）：添加链接列出"属于系统（入向 · 储能设备 → 本对象）"→成员条件 park=CZY→聚合选"属于系统（入向） → 储能设备"+额定容量→保存回显→预览 **1000**（A200+B300+已删除500，park 条件未含 del_flag 故已删除计入属预期语义；他园 400 排除）。
