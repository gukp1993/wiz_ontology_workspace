# 工作台整体交互迭代 实施说明

日期：2026-09-14。配套：[开发指令](./GLM开发指令_工作台整体交互迭代_20260914.md)、[交互方案 v1](../文档/工作台整体交互迭代交互方案_v1_20260914.md)、[并行任务板（接口冻结稿）](./工作台整体交互迭代_并行任务板.md)。执行方式：总协调者 + 11 个按文件所有权划分的并行工作包（P01–P11，实际峰值 8 并发），四阶段推进（并行检查→接口冻结→并行实施→集成验收）。

## 1. 保存机制（本轮核心）

**表单保存一次直通持久化，顶部不再有"保存草稿/发布"按钮。**

- 新增 `frontend/src/saveCoordinator.ts`：每个工作区一个 Saver（本体/项目），串行队列（同时最多一个在途请求，入队携带深快照+当时 revision）、成功合并 revision、提交后又有修改自动续存、error/conflict 状态机、beforeunload 拦截、flush（切上下文前落盘）。
- 触发方式两级：即时编辑（字段/列表增删/画布完整操作）→ `touch()` 900ms 合并自动保存；表单"保存"按钮 → mutate 后 `inject('commit-now')` 立即持久化。三态按钮（保存/保存中…/已保存），失败不关表单保留输入。
- 顶部状态条五态：已保存（含时间）/未保存修改/保存中/保存失败（重试）/版本冲突（"放弃本地并重新加载"或"以当前内容重试"，后者需二次确认）。
- 409：后端响应新增 `currentRevision`（本体/项目两处），前端据此换基线重提或 refetch，不跳过 revision 检查。
- `projects.save_draft` 异常不再假报成功（返回 error → 500，并清理半写修订目录）。
- 撤销/重做保留：undo/redo 应用后 `commitNow()` 产生新修订，不回写旧修订。画布 zoom/pan 不再触发保存。
- 发布与保存分离：发布前先 `commit-now` 确保落盘，再读服务端最新草稿与 revision 提交发布（OntologyRelease/ProjectValidation 内置发布对话框），未确认的表单不借发布偷偷提交。

## 3. 属性来源三步表单（P05，复用上一轮全部协议）

属性来源编辑器重组为局部三步向导（选择来源 → 定位记录/绑定输入 → 映射结果与确认）：上一步/下一步只改步骤保留 draft，中间步骤不校验不提交，最终"保存"一次校验并经 commit-now 持久化；切换属性/对象时有未保存修改 confirm 保护。数据库直选表/Redis 直连/时间序列/压缩规则等协议零改动。

- 恢复快照成功后整页 reload 以跟进工作副本（与原行为一致）。
