# 通用储能本体工作台 —— 整体方案与架构梳理

> 梳理日期：2026-09-14 ｜ 对应代码现状：V3 双空间架构（本体空间 / 项目空间）
> 入口：`./start.sh start` → http://127.0.0.1:8765

---

## 1. 项目定位

面向**储能业务**的本地化本体建模与项目绑定工作台，产品理念参照 **Palantir Foundry Ontology**，但完全本地实现、零外部服务依赖：

- **本体层（What）**：业务专家定义"现实世界有什么"——对象类型、链接类型、属性、值类型、计算契约（输入/输出签名 + 业务约定），不含任何项目实现细节。
- **项目层（How）**：实施人员在具体项目中把本体"落地"——对象映射到数据表、属性绑定数据字段或计算实现、契约绑定项目处理规则（如 Redis key 模板）。
- **分离带来的价值**：同一个本体（如"储能簇 SOC"）在不同项目中可以有不同取数与计算方式；本体演进通过版本与变更分类管理，项目钉住（pin）某个已发布本体版本，升级前先做影响预检。

一句话概括：**本体定义"是什么、算什么"，项目实现"从哪取、怎么算"，两者各自草稿、各自发布、互不阻塞。**

## 2. 核心设计理念（对照 Palantir Foundry）

| Foundry 概念 | 本工作台对应 | 本地化取舍 |
|---|---|---|
| Object Type / Link Type | `owl:Class` / `owl:ObjectProperty`（起点/终点/数量关系） | JSON-LD 图模型存储，rdflib 校验 |
| Property（含 API name） | `owl:DatatypeProperty`（中文名 + 技术标识 apiName） | 一个属性定义，两套标识 |
| Shared Property | `mg:SharedProperty`（跨对象复用的属性定义） | 属性通过 `mg:sharedProperty` 继承 |
| Value Type + 约束 | `mg:ValueType`（数据类型 + 约束 + 单位后缀） | 正则/枚举/区间约束，安全校验 |
| Function / Action 类型（签名式） | **计算契约**（guide_version 3）：命名输入/输出 + 类型引用 + 业务约定 | 实现不在本体层，由项目绑定 |
| 时序属性 / last point | 一个 SOC 属性 + 两个查询契约（实时/采样） | 采样是纯快照前提下成立；若是 5 分钟平均则需另立属性 |
| Ontology 版本 / 重大变更 | 不可变版本目录 + 变更分类（breaking→主版本，compatible→次版本） | 发布前强制 `publish-check` 预检 |
| 项目绑定数据源 | 项目对象映射/属性来源/计算实现 | 密钥只存受保护配置，不进规则文本 |

## 3. 概念模型

### 3.1 本体层资源（五组 + 契约）

| 概念 | 存储 | 关键字段 |
|---|---|---|
| 对象类型 | `owl:Class` | 名称、别名、业务定义 |
| 链接类型 | `owl:ObjectProperty` | 起点、终点、数量关系（一对一/一对多/多对一/多对多）、反向名称 |
| 属性 | `owl:DatatypeProperty` | 所属对象、数据类型（文本/数值/是-否/时间/数组/结构体）、技术标识 apiName、可挂值类型 |
| 共享属性 | `mg:SharedProperty` | 跨对象复用的属性定义（数据类型、单位后缀、值类型） |
| 值类型 | `mg:ValueType` | 约束（正则/枚举/区间/嵌套结构）、单位后缀、小数位 |
| 计算契约 | `workflow.functions`（guide_version=3） | 命名输入/输出列表 + 类型引用 + 业务约定 + 适用对象 |

**契约签名的类型引用（ref）有三种**：
- `kind: 'object'` → 引用某个对象类型（如"储能簇"）
- `kind: 'property'` → 引用某个属性/共享属性（如"储能SOC"）
- `kind: 'base'` → 基础类型（string/double/integer/boolean/timestamp/array/struct）

签名条目带**稳定 id**（`in_xxx` / `out_xxx`），项目实现按 id 绑定，改 id 即破坏性变更。

**业务约定（conventions）**：自由文本，写"口径"而非"实现"。例："SOC 取值 0~1；采样周期 5 分钟；实时值允许滞后于最新采样值。"

### 3.2 项目层概念

| 概念 | 说明 | 示例 |
|---|---|---|
| 项目 | 独立管道，可先建、后绑本体 | 创智园二期 |
| 本体引用 | 钉住某个已发布本体版本（可后期补绑/升级） | 储能本体 1.0.0 |
| 对象映射 | 对象类型 → 数据表 + 主键 + 标题字段 | 储能簇 → `m_storage_cluster_phase`，主键 `id` |
| 属性来源 | 每个属性三选一：数据字段 / 计算来源 / （未配置） | 额定功率 → `rated_power`；储能SOC → 计算实现输出 |
| 链接映射 | 链接类型 → 存目标主键的字段 | 所属储能 → `storage_id` |
| 计算实现 | 对某契约的项目落地：每个输入绑来源、每个输出声明返回 + 项目处理规则 | 契约"查询储能SOC" → 规则"查 redis，模板key=m_storage_cluster_phase-soc-{id}" |
| 输入来源四种 | `object`（对象实例）、`field`（对象数据字段）、`constant`（常量）、`output`（另一实现的输出，自动做循环依赖检测） | |
| 数据连接 | 连接配置只读展示，凭据由实施配置，**不进入规则文本** | |

**两条铁律**：
1. **密码与密钥保存在受保护配置中，不写入自然语言规则**（规则文本只写取数逻辑，如 redis key 模板）。
2. **配置校验 ≠ 执行验证**：工作台第一阶段只做结构校验；真正跑通需要执行器（后续阶段）。发布 ≠ 上线。

## 4. 双空间交互模型（V3 最终形态）

```
┌────────────────────────────────────────────────────┐
│  左栏：[工作空间下拉：本体空间 / 项目空间]              │
│         [当前对象下拉：本体列表 / 项目列表]             │
│         （空间菜单，按状态门控）                       │
├────────────────────────────────────────────────────┤
│  本体空间（需先有本体，否则显示引导卡片）                │
│    1 · 对象类型   2 · 链接类型   3 · 属性管理           │
│    4 · 计算定义   校验与版本                           │
├────────────────────────────────────────────────────┤
│  项目空间                                           │
│    项目管理（始终显示）                                │
│    对象与链接绑定 / 项目校验（选中项目后才出现）          │
└────────────────────────────────────────────────────┘
```

- **并行管道**：没有本体也能新建项目（引用后补）；没有项目也不影响本体建模。只有"对象绑定 / 项目校验"两个菜单依赖"本体 + 项目"同时存在。
- **菜单门控**：`hasOntology` 为假时不渲染本体菜单，显示"从零开始"引导（创建第一个本体）；未选项目时项目菜单只剩"项目管理"。
- **空间记忆**：`localStorage['wiz-space']` 记住上次空间，刷新/重进自动恢复。
- **辅助页面**（画布、图谱导览、实例浏览等）不占主菜单，经各编辑页入口或 URL hash 进入。

## 5. 总体架构

```
浏览器 (Vue 3 SPA, frontend/dist 静态产物)
   │  fetch /api/* (JSON, ≤2MB)
   ▼
Python 标准库 HTTP 服务 (ThreadingHTTPServer, 127.0.0.1:8765)
   │  workbench/server.py —— 全部路由 + 安全边界
   ├── workbench/workspaces.py   本体注册表 + 多文件草稿
   ├── workbench/versions.py     不可变本体版本注册表
   ├── workbench/projects.py     项目存储 + 项目校验 + 升级预检
   ├── workbench/contracts.py    契约签名校验 + 变更分类
   ├── workbench/workflow.py     业务定义校验（含契约路由）
   ├── workbench/properties.py   属性继承/技术标识
   ├── workbench/value_types.py  值类型约束检查
   ├── workbench/model_format.py JSON schema ↔ RDF 图模型无损转换
   ├── workbench/explorer.py     实例快照（演示数据）
   ├── workbench/formatting.py   显示格式化
   ├── workbench/regex_constraints.py 正则安全
   └── service/  演示执行链（只读 json_fixture + 加权 SOC 示例）
   │
   ▼
文件系统（唯一持久层，无数据库）
   ontology/
     workspaces/<uuid>/workspace.json          本体登记
     drafts/models/<id>/{current.json, revisions/NNNN-hash/…}
     drafts/projects/<id>/{current.json, revisions/NNNN-hash/…}
     releases/models/<id>/{index.json, <semver>/…}
     releases/projects/<id>/vN/…
     models/storage/, projects/…               legacy 基础文件（仅初始化输入）
```

技术栈：后端 Python 3 标准库 + PyYAML + rdflib（仅两个第三方依赖）；前端 Vue 3.5 + TypeScript 5.9 + Vite 5 + cytoscape（画布）。构建时 `vue-tsc --noEmit` 强制类型检查。

## 6. 后端模块详解

### 6.1 `workbench/server.py`（396 行）— 唯一 HTTP 入口
- **启动即绑定 127.0.0.1:8765**，静态目录 `frontend/dist`，首页 no-store。
- **GET 路由**：`/api/ontologies`（本体列表，空库返回空数组）、`/api/state`（当前草稿+revision+最新版本号；`current()` 三级回退：草稿指针 → legacy 单文件草稿 → 空白种子 `blank_state()`，空白库也能自举）、`/api/versions`、`/api/version-state?version=`（读已发布版本内容）、`/api/releases`（legacy zip 列表）、`/api/projects`、`/api/project-state?project=`（含迁移待办 `migrationTodos`）、`/api/project-releases`、`/api/project-config`（legacy storage 项目只读配置）。
- **POST 白名单**（不在名单直接 404）：本体侧 `ontologies / save / validate / preview / publish-check / publish / restore / export / workflow-check / format-preview / value-type-check / function-preview / action-preview / demo-objects / explorer`；项目侧 `projects / project-save / project-validate / project-publish / project-upgrade-check`。
- **发布流程**：`/api/publish-check` 先算 `contracts.classify(上一版, 当前)` 给出建议类型与原因 → 前端弹窗让用户确认 → `/api/publish` 校验通过后写入草稿并调用 `versions.publish()`；**breaking 不允许被标记为 compatible（422 拒绝）**；pending 必须显式选择。
- **并发控制**：保存/发布/恢复前比对 revision 哈希，不一致返回 409"已有新版本，请刷新后重试"。
- **合并策略 `merged()`**：项目绑定注入演示引擎前，**过滤掉 computed 属性来源**（demo 引擎只认字符串字段映射），避免旧引擎崩在 dict 上。
- **快照**：`package()` 打 zip（模型+项目配置+学习记录+布局+manifest）；`restore_snapshot()` 校验 zip 归属本体、展开 ≤20MB、恢复前自动备份现有草稿，**项目部分不回灌**（项目草稿独立）。

### 6.2 `workbench/workspaces.py`（211 行）— 本体注册表 + 草稿存储
- 本体 id 只有两种合法形态：`storage`（legacy 默认）或规范 UUID；`clean_id()` 强校验，路径全部 `resolve().parent` 防穿越。
- **V3 多文件草稿**：每次保存 = 新建 `revisions/NNNN-<hash8>/` 目录写入全部文件（ontology.json / workflow.json / metrics.yaml / rules.yaml / layout.json，可选 learning.json / source-graph.json），完成后**原子替换 current.json 指针**；失败自动删目录，永不留半个草稿。
- `revision_of(state)`：`encode_state` 后全量 sha256，作为乐观锁令牌。
- `listing()`：空白工作台（无 legacy 草稿且无草稿指针）**不列出默认 storage**——"幽灵本体"就是这么消灭的。
- `legacy_draft_state()`：legacy 单文件草稿只作一次性初始化输入，读入时剥离 `bindings/parameters`（项目部分归项目区）。

### 6.3 `workbench/versions.py`（173 行）— 不可变版本注册表
- 目录 `ontology/releases/models/<id>/<semver>/`，文件集与草稿一致 + `manifest.yaml`（版本号、changeType、changeNote、reviewer、createdAt、revision、parentVersion、reasons）。
- `index.json` 记录版本链，**先写目录再原子更新索引**。
- `ensure_base_release()`：仅 storage，把 legacy 基础文件一次性登记为 1.0.0，让老项目可钉住。
- `_next_version()`：breaking → `major+1.0.0`，其余 → `major.minor+1.0`。
- **空内容不落盘**：metrics/rules 为空数组时不写对应 yaml（演示时每个文件都有用）。

### 6.4 `workbench/projects.py`（516 行）— 项目存储 + 校验（最重的模块）
**存储三区**（V3 设计第 7 节）：
```
ontology/projects/<id>/           基础文件（创建时写入，之后只读，legacy 兼容输入）
ontology/drafts/projects/<id>/    草稿修订（project/connections/bindings/implementations/parameters 五文件）
ontology/releases/projects/<id>/  已发布版本 v1、v2…（含 manifest）
```
项目 id 为 12 位 hex；`_state_from_files` 兼容 legacy 键名（ontology_id/model_version，缺 ontology 只带版本时回退 `storage`）。

**`validate_project(state, ontology_state)` — 项目配置校验**，逐项产出 `{kind, status: valid|unconfigured|invalid, issues}` 报告：
1. **对象映射**：类型存在于钉住版本、来源表/主键必填、标题属性必须有字段映射、`related_sources` 关联来源仅支持**同库一对一、多行必须报错**（当前阶段约束）。
2. **计算实现**：契约存在且已是 V3 契约；契约**每个输入都已绑来源**、**每个输出都已声明返回**（"可选声明、声明即必须"的落地）；四种输入来源逐一校验（object → 类型存在；field → 引用的对象已映射且字段在属性来源/主键/标题字段中；constant → 有值；output → 目标实现存在且输出已声明）；未填项目处理规则记 unconfigured。
3. **属性计算来源**：实现存在、所选输出已声明；输出 ref 指向另一个属性定义时给 warning（口径核对）。
4. **循环依赖**：实现间 output 引用做 DFS 环检测。
5. **引用未实现**：属性来源引用了契约但项目无实现 → warning。

**`upgrade_check(state, current, target)` — 升级预检**：把本体两版本间的 diff reasons **映射到本项目具体配置**（对象映射/属性映射/链接映射/实现/属性计算来源），breaking 且被项目引用 → blocking；未被引用的 breaking/pending 标注"本项目当前配置未直接引用"。前端展示影响清单，用户确认后才切换版本。

### 6.5 `workbench/contracts.py`（206 行）— 契约与变更分类
- `signature_errors()`：契约结构校验（稳定 id 唯一、名称必填、类型引用三种 kind 合法且目标存在、适用对象存在且不重复、至少一个输出、声明无输入则不能有输入）。
- `classify(old, new)` — **变更分类核心**：
  - 五组资源按 id 对比：**删除 = breaking**；新增 = compatible；同 id 改字段 → 命中 `STRUCTURAL_FIELDS`（如属性的 objectTypeId/dataType/apiName/sharedPropertyId/valueTypeId，链接的起点/终点/数量关系）= breaking，否则 = compatible（仅改名/说明）。
  - 契约：签名（输入/输出的 id+ref）变化 = breaking；仅名称/说明/业务约定变化 = compatible；legacy 定义变化 = pending（人工确认）。
  - 动作/接口/指标/规则变化 = pending（历史内容，人工确认）。
  - 汇总：有 breaking → breaking；否则有 pending → pending；否则 compatible。
  - **语义变化也算 breaking 的精神**：SOC 从 0~100 改为 0~1 即使只改描述文字，也必须人工选 breaking 发布。
- `value_source_todos()`：扫描钉住版本里 legacy `mg:valueSource` 函数式属性，生成迁移待办（提示搬进项目绑定）。

### 6.6 其余模块
- `workflow.py`：objective/functions/actions/interfaces 的定义校验；guide_version 3 自动路由到契约校验；readiness() 就绪度。
- `properties.py`：`effective()` 属性合并共享属性定义、`api_name()` 技术标识、属性结构校验。
- `value_types.py`：值类型约束（正则/枚举/区间/嵌套 struct/array）+ 样例检查。
- `model_format.py`：**自有 JSON schema（schemaVersion=1，五组资源+metadata+definitionOrder）↔ legacy RDF JSON-LD 图** 的无损双向转换；未知字段直接报错（必须放 extensions），保证不丢内容；"我们的 JSON 格式，受 Foundry 概念启发，不是 Foundry 导入格式"。
- `service/demo.py + calculations/soc.py`：只读演示执行链（json_fixture 适配器、版本一致性校验、加权 SOC 计算示例），不访问生产库、不执行配置内任意代码。

## 7. 前端架构

### 7.1 总体
- **无 vue-router、无 pinia**：`App.vue`（216 行）单状态树 + props down / events up；页面切换用 **hash 导航**（`#model`、`#binding`…）+ alias 兼容（validation→versions 等）。
- `space` ref（'ontology' | 'project'）驱动整个左栏与工具栏；本体态（state/revision/dirty/undo栈）与项目态（projectState/projectRevision/projectDirty/项目undo栈）**完全独立**，互不污染。
- 前后端**同构编解码**：`modelFormat.ts` 的 encode/decode 与后端 `model_format.py` 对应，草稿在传输线上是自有 JSON schema，进编辑器转图模型。
- 深链竞态已修：`onMounted` 先 `loadProject()` 再做 binding/pvalidation 视图守卫。

## 8. 数据存储架构

### 8.1 目录全景（写入规则）
```
ontology/
├── workspaces/<uuid>/workspace.json        # 本体登记（id/名称/创建时间）
├── drafts/
│   ├── models/<id>/
│   │   ├── current.json                    # {seq, revision, revisionDir, updatedAt} 原子指针
│   │   └── revisions/0013-edb8a218/        # 每次保存一个完整快照目录
│   │       ├── ontology.json  workflow.json  metrics.yaml  rules.yaml  layout.json
│   │       └── (learning.json  source-graph.json 可选)
│   └── projects/<id>/
│       ├── current.json
│       └── revisions/0012-b8c627a4/
│           └── project.yaml connections.yaml bindings.yaml implementations.yaml parameters.yaml
├── releases/
│   ├── models/<id>/
│   │   ├── index.json                      # 版本链（原子更新）
│   │   └── 1.0.0/                          # 不可变：五文件 + manifest.yaml（空 metrics/rules 不写）
│   └── projects/<id>/v1/                   # 不可变：五文件 + manifest.yaml
├── models/storage/                         # legacy 基础定义 —— 仅初始化输入，永不回写
├── projects/chuangzhi/, projects/9803ea…/  # 项目基础文件 —— 创建时写入，之后只读
└── (drafts/draft.json legacy 单文件草稿 —— 仅初始化输入)
```

**写入铁律**：
1. 草稿 = **整修订目录 + 原子指针**，失败不留半个草稿；
2. 发布目录 = **写临时目录再 rename**，不可变，永不改历史；
3. `models/`、`projects/<id>/` 基础目录**初始化后不再写**（legacy 兼容输入）；
4. 修订内容哈希 = 乐观锁令牌（保存/发布/恢复前比对，409 拒绝并发覆盖）。

## 9. 关键机制时序

### 9.1 本体发布（含变更分类）
```
编辑草稿 → 保存(/api/save, 409并发保护)
        → 发布前检查(/api/publish-check)
            classify(上一版, 当前) → suggested: breaking|compatible|pending + reasons
        → 弹窗确认变更类型
            breaking 不能改标 compatible（服务端再拦一次 422）
            pending 必须显式选择
        → /api/publish
            validate 全量校验 → 写草稿 → versions.publish()
            新版本号：breaking→2.0.0 / compatible→1.1.0
```

### 9.2 项目绑定与发布
```
创建项目（可暂不绑本体）→ /api/projects（绑定时校验版本存在）
    → 补绑/升级：/api/project-upgrade-check 预检影响清单 → 确认切换
    → 配置：对象映射 / 属性来源 / 计算实现（输入绑定 + 输出声明 + 规则）
    → /api/project-validate（结构校验，五类检查）
    → 保存草稿 /api/project-save（409并发保护）
    → 发布 /api/project-publish：校验必须通过 → releases/projects/<id>/vN（不可变）
```

### 9.3 升级预检（本体 1.0.0 → 1.1.0 时）
`classify` 的每条 reason 按区域（对象/属性/链接/契约）匹配项目配置 → 产出影响项（对象映射需核对 / 属性来源需核对 / 实现需重写…），被引用且 breaking → blocking，未引用 → 仅提示。**项目永远钉住具体版本，本体演进不自动影响项目。**

## 11. 安全边界（不可放宽）

1. **只绑定回环** `127.0.0.1:8765`，不对外网监听。
2. POST：**路径白名单** + **Origin 校验**（仅本机来源）+ **Content-Type 必须 JSON** + **请求体 ≤2MB**。
3. 所有文件路径 `resolve().parent` 校验，杜绝穿越；项目/本体 id 格式强校验。
4. 恢复 zip：展开总量 ≤20MB、只接受 `.zip` 单段名、**拒绝跨本体快照**、恢复前自动备份。
5. rdflib 解析 JSON-LD **只用本地 context，不解引用远程**；`@context` 与种子不一致直接报错。
6. 演示引擎只支持 json_fixture，不连生产库、不执行配置内代码。
7. **密钥不落规则文本**：connections.yaml 由实施在受保护配置中维护，界面只读展示 id/adapter/path。
8. 用户数据（ontology/ 下）是用户资产：清理、删除、重建必须用户明确确认。

## 13. 设计边界与已知限制

| 边界 | 说明 |
|---|---|
| 配置校验 ≠ 执行验证 | 第一阶段无执行器；项目发布仅代表结构正确，"发布不等于上线" |
| 演示引擎范围 | 仅 storage + chuangzhi legacy 数据；computed 来源会被过滤后进入演示 |
| 关联来源 | 当前只支持同库一对一（多行报错），跨库关联待执行阶段 |
| 采集时间口径 | "可选声明、声明即必须"；SOC 若是 5 分钟**平均**值则需新增口径属性，不能只叫采样 SOC |
| 单用户本地工具 | 乐观并发（409）而非锁；不做多人协同 |
| legacy 内容 | 旧计算定义只读展示 + 一键转契约；valueSource 函数式属性出现在迁移待办 |
