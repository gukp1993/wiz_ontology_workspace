## 一、最终数据协议

### 存储布局（第三条独立状态线）

```
ontology/drafts/flows/<flowId>/current.json                       原子指针（seq/revision/revisionDir/updatedAt）
ontology/drafts/flows/<flowId>/revisions/<seq>-<hash>/flow.json   整修订快照（JSON）
```

- 保存 = 先写完整修订目录、成功后原子替换 current.json；失败清理修订目录，绝不留半写状态。
- 修订号 revision 为内容 SHA-256（`_` 前缀字段与布局除外约定：布局参与哈希，缩放/平移只改内存不触发保存，落盘时随下一次内容修订一起写入）。
- 软删除：追加一条 `status:'deleted'` 修订；修订历史永不物理清除；列表默认隐藏，`?includeDeleted=1` 可见。
- 复制：服务端重新生成全部稳定 ID（编排/入口参数/输出/节点/输入/输出/逻辑连接/对象字段/布局键），并重映射所有引用；原编排任何字节不动，副本名自动去重（`-副本`、`-副本2`…）。
- 未知字段整体保留（零丢失）：读取时只取认识的键，从不重建整个状态。

### 状态结构（flow.json）

```jsonc
{
  "schemaVersion": 1,
  "flowId": "c5e705d2bd03",          // 12 位十六进制，服务端生成
  "name": "SOC 日采样计算流程",
  "description": "…",
  "status": "active | deleted",
  "inputs":  [ 入口参数 ],            // 编排输入边界节点的内容
  "outputs": [ 命名输出 ],            // 编排输出边界节点的内容
  "connections": [ 逻辑连接 ],
  "nodes":   [ 处理节点 ],            // 边界节点不在 nodes 中，由 inputs/outputs 派生（ID flow-input/flow-output 为保留字）
  "layout": { "positions": {节点ID:{x,y}}, "zoom": 1, "pan": {x,y} }   // 画布布局与业务分开管理
}
```

类型声明（递归，对象嵌套 ≤3 层，列表不占层）：
```jsonc
{ "type": "text|number|boolean|datetime|object|list",
  "fields":    [ { "id": 稳定ID, "name": 技术名, "label": 显示名, "type": 嵌套声明 } ],  // object
  "elementType": 嵌套声明 }                                                                              // list
```

入口参数 / 命名输出：
```jsonc
{ "id": 稳定ID, "name": 技术名(标识符规则), "label": 显示名, "type": 类型声明 }
// 命名输出额外： "binding": 来源（同输入来源，node/nodeField）
```

处理节点（python/sql 统一骨架）：
```jsonc
{ "id": 稳定ID, "kind": "python|sql", "name": 名称*, "description": 说明,
  "inputs":  [ { "id": 稳定ID, "name": 技术名, "label": 显示名, "type": 类型声明, "source": 来源|null } ],
  "outputs": [ { "id": 稳定ID, "name": 技术名, "label": 显示名, "type": 类型声明 } ],
  "implementation": { "language": "python", "code": "def main(...):…" }
                   | { "language": "sql", "sql": "SELECT … WHERE k = :param", "connectionId": 逻辑连接稳定ID } }
```

输入来源（唯一业务事实，四种；连线全部由此派生）：
```jsonc
null                                                        // 未绑定（区别于固定值 0/false/""）
{ "kind": "flowInput", "inputId": 入口参数稳定ID }
{ "kind": "fixed", "valueType": "text|number|boolean|datetime", "value": 0|false|""|… }
{ "kind": "node",       "nodeId": 节点ID, "outputId": 输出ID }                        // 完整输出（列表不展开）
{ "kind": "nodeField",  "nodeId": 节点ID, "outputId": 输出ID, "fieldPath": [字段ID…] } // 对象内字段（稳定ID 路径）
```

逻辑连接（仅名称+类型，无真实地址/账号/密码）：
```jsonc
{ "id": 稳定ID, "name": "业务数据库", "engine": "mysql" }
```

类型相容：类型名一致；对象按字段技术名逐一同名匹配且嵌套相容；列表递归元素类型。显示名不参与任何判断；稳定 ID 用于绑定路径，独立声明的同结构对象视为相容。

## 二、API（全部经 server.py 白名单表分派）

| 路由 | 方法 | 说明 |
| --- | --- | --- |
| `/api/flows?includeDeleted=` | GET | 列表：名称/说明/节点数/configStatus(passed|pending)/errorCount/updatedAt/status |
| `/api/flow-state?flow=` | GET | 草稿 + revision（不存在 404，非法标识 400） |
| `/api/flows` | POST | 新建 `{name, description?}`（同名 400；名称 1–80 字） |
| `/api/flow-save` | POST | `{state, revision}`；旧 revision → 409 + currentRevision；结构损坏 → 400；成功返回 `{revision, check}`（配置检查随保存返回，失败≠保存失败） |
| `/api/flow-check` | POST | 纯配置检查（不写盘、不持锁、不执行任何代码） |
| `/api/flow-copy` | POST | `{flowId, name?}` 复制并重映射（不存在 404） |
| `/api/flow-delete` | POST | 软删除（追加 deleted 修订） |

写操作持 `workbench.locking` 的同一把全局写锁；flow-check 与 GET 不持锁。安全边界（Origin 校验、2MB 上限、POST 白名单）由 server.py 统一承担，未做任何放宽。

配置检查项：必填与技术名唯一/合法、类型声明（深度/重复/缺 ID）、类型相容、失效引用（入口参数/节点/输出/字段路径/逻辑连接）、自引用与循环依赖（DFS 灰白黑）、SQL `:参数` 未声明/未引用、编排输出绑定完整、Python/SQL 正文非空、未绑定输入与未声明字段对象降为"待完善"warning。SQL 参数扫描复用 `query_rules.strip_sql_noise_mysql`（字符串/反引号/注释免疫）。不声称语法、业务正确性或执行安全验证；文案统一为"配置检查通过（未执行验证）"。

## 六.5 追加：Redis 节点（2026-09-16 同日迭代）

应用户场景（设备 SOC = Σ(簇SOC×簇容量)÷设备额定容量×100）新增 **Redis 节点**：

- 节点类型 `redis`：`implementation = {language:'redis', connectionId, keyTemplate}`；数据连接下拉列出项目"数据连接"菜单中 Redis 类型的连接（只引用 id，不存凭据）。
- Key 模板两种模式（互斥，混用报错）：
  - **行模式** `m_storage_cluster_phase-{{id}}-soc`：恰好一个输入且为列表类型，`{{字段}}` 引用列表元素对象的技术名字段；对列表每行各取一个 key，输出列表与输入顺序一一对应；输出建议声明为列表（否则提示）。
  - **单键模式** `m_storage_cluster_phase-${cluster_id}-soc`：`${参数}` 引用本节点输入参数，取单个 key。
- 校验：模板非空、字段/参数存在、连接存在且 engine=redis、行模式输入绑定来源；`{{}}`/`${}` 混用拒绝。
- 复制修正：项目数据连接引用（不在编排自带 connections 中的 connectionId）复制时保持原 id，不再被错误重映射。
- 废弃字段处理：编排自带 connections（旧机制）不再产生任何校验错误（界面无维护入口），仅作引用回退。
- 边界不变：Redis 节点同样是"配置 + 校验"，不连接 Redis、不执行任何读取；执行器属二期。

示例编排「设备SOC计算（Redis版）」（flowId 664381dde0b3，已建于正式环境并通过检查）：
编排输入 device_id → SQL 设备额定容量 + SQL 储能簇列表 → Redis 簇SOC（行模式）→ Python 计算设备SOC → 编排输出 soc。

1. 顶栏切到"项目映射"，侧栏点"函数编排"（或直接访问 `#f-home`）；不需要先选择项目或本体。
2. 编排列表 →"＋ 新建编排"（只填名称，说明选填）→ 进入编辑页。
3. 左栏"＋ Python / SQL / Redis 节点"添加处理节点。选中 SQL 节点：在右栏"SQL 模板"区块顶部选择"逻辑连接"（下拉）；点开下方"管理逻辑连接"折叠区可就地新建（新建后自动选中）、改名、删除（被引用时先确认）。逻辑连接是编排内共享的"具名数据源"占位：仅名称+类型（本期仅 MySQL），真实地址/账号在项目引用编排时再绑定。
4. 编排输入边界节点声明入口参数；在节点输入卡"来源绑定"选"编排入口参数"，画布自动出现连线（或用画布"↗ 连线"点两节点在对话框中绑定，取消不产生绑定）。
5. Python 节点：声明输入（如 列表<对象>，整体传入不展开）、输出与 `def main(...)` 正文（参数变化不覆盖正文；改技术名会提示检查代码）。
6. 编排输出边界节点：添加命名输出，绑定到 Python 输出（可"按来源推导类型"）。
7. 顶部"检查配置"查看结果并可"去处理"定位；顶栏状态条显示"已保存，配置待完善/配置检查通过（未执行验证）"。
