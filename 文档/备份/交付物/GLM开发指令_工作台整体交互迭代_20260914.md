## 三、最新确认：保存只做一次

这是本轮重点，不只是移除一个按钮。

1. 对象、属性、链接、契约、共享属性、连接、项目参数、来源映射、计算实现等表单点击“保存”，即调用所属区域的保存 API，写入持久化草稿。接口成功后显示“已保存”，刷新或重启后数据仍存在。
2. 删除顶部“保存草稿”按钮。顶部只展示实际状态：有未保存修改／保存中／已保存／保存失败／版本冲突，必要时显示重试或冲突处理操作。
3. “取消”放弃当前表单未提交的修改，保留已持久化草稿。未保存表单离开时提示继续编辑或放弃，不能因切换页签、对象、工作区或下拉上下文而静默丢失。
4. 表单使用局部编辑副本。发送保存时，基于最新已确认状态生成候选快照；成功才将响应与新 revision 合入已保存状态。失败保留用户输入，不关闭表单、不假报成功。
5. 现有保存接口可能提交整个工作区，而不是单个实体。可以复用完整修订保存，但必须保证只合并本次提交的编辑，不能顺带持久化其他尚未确认的表单，也不能覆盖期间已经保存的其他更改。
6. 同一本体／项目内保存请求串行化，按资源 ID 分别管理 revision、队列与状态。处理点击重复提交、快速连续编辑、保存过程中切换上下文和过期响应，不能让旧响应覆盖新内容。
7. 409 冲突保留本地输入，提供重新读取并核对后重试的路径；不得自动强制覆盖或跳过 revision 检查。网络失败可重试，状态要说明实际结果；结果不确定时先核对服务端修订，避免盲目重复提交。
8. 画布拖动、连线、删除、撤销／重做等没有独立表单的操作，在一次完整操作结束后保存草稿。拖动按结束事件保存，可以合并待发送操作；不按 mousemove 或每个字符生成修订。失败提示可恢复，不偷偷回滚用户操作。
9. 列表中直接新增、启用／停用、删除、复制／引用等确认即生效的操作，同样要持久化并检查引用。涉及多实体的修改在一个完整草稿修订中提交，不能写出半完成状态。
10. 保留撤销／重做和原有画布快捷键。撤销已保存操作产生新的草稿修订，不回写或删除旧修订。文本输入仍使用正常文字编辑行为。
11. 发布生成独立、不可变的版本，发布之前必须有已保存的完整修订。未提交的表单、失败的保存或正在执行的保存要明确处理，不借发布偷偷提交用户没确认的表单。
12. 数据连接保存与受保护凭据写入复用现有 API；只有本次必需步骤均成功才能显示整项已保存。部分失败须明确提示并可恢复；测试连接不自动保存表单。

## 四、本体建设：以对象为中心

- “对象建模”使用对象目录＋详情。对象详情内集中维护属性、链接和相关计算契约，避免反复切换一级菜单重新选择对象。
- 对象名称与业务定义直接展示；属性、契约等沿用已确认的必填内容，选填默认折叠、就地提供简短示例。不要重新加入已删除的业务专家技术标识表单。
- 对象列表和关系画布共用同一份模型。点击节点定位对象；修改名称、属性、链接后保持同步。复用现有 cytoscape 画布、拖拽、连线与快捷键，不能用原型的静态关系图替代编辑器。
- 原型把关系编辑放入对象详情，不代表丢弃全局链接查看和跨对象检索能力。旧 hash／深链应适配到新入口，并定位对应对象／属性。
- 属性支持单值／时间序列，类型协议及版本影响按通用属性来源需求实现。字段在前后端转换中无损往返，缺省单值与显式单值语义等价。
- 共享属性库支持复制为私有、引用共享、解除引用、查看并跳转引用位置。复制生成新的本地属性标识；共享引用跟随元数据。共享修改和解除引用检查契约、接口及项目影响，不能静默断链。
- 单值 SOC 与 SOC 序列不能引用同一个完整共享属性定义；共享引用的有效数据类型和结果形态必须一致。
- 全局计算契约入口保留多输入、多输出、无输入、无对象归属等现有能力，不照原型缩减成一个对象输入和一个属性输出。具体数据库与 Redis 规则留在项目实现。

## 五、项目映射：围绕对象配置来源

- 数据连接与全部计算实现各自保留一个主入口，移除重复嵌套页签；对象映射详情仅保留实例识别、属性取值、链接映射。

- 属性取值采用局部三步表单：选择来源 → 定位记录／绑定输入 → 映射结果。上一步／下一步保留局部内容，最终“保存”一次持久化整份来源配置；中间步骤不是独立提交。
- 直接身份表字段尽量自动带入连接、表、主键定位，减少重复填写。复杂来源继续使用完整三步，不能隐藏必要匹配条件。
- 按通用属性来源需求实现自由搜索项目连接下的表／视图、当前实例匹配、多条件 AND、时间和值角色、时间编码与时区、上下文时间范围、重复记录与缺失处理。
- 一个属性只有一种生效来源。Redis 直接选当前项目连接，不强制先登记对象来源或创建本体计算契约；函数则引用项目实现与兼容输出。
- 链接映射仍从两端对象已登记的表与字段中选择。不要因为属性来源放开选表，就同时改变链接映射的范围。
- 项目可以选择实际启用的对象与属性，不要求本体所有内容都实现；必需依赖、输入绑定、显示名称、引用关系按正式规则检查，不能通过“排除”绕过失效引用或启用功能的必需依赖。

执行 `cd frontend && npm run build`，完成有意义的后端保存／兼容性测试，并在隔离实例中做浏览器关键链路验收。类型检查不能代替浏览器交互验证；未完成的验证如实说明。

建议按“保存状态与持久化 → 两区导航和对象工作区 → 属性来源与类型能力 → 校验定位和版本 → 回归验收”推进，每阶段保持可构建。直接完成授权范围内的工作；确有架构冲突时说明具体冲突，不通过删用户配置、覆盖并发修改或缩减既有能力绕过。

## 九、并行开发编排（用户补充：GLM 可支持 50 并发）

用户希望尽可能并行推进。**按依赖和文件归属主动调度多个开发任务，不把全部工作串行交给一个任务。** 50 是可用并发上限，不是必须凑满的任务数；实际启动受当前工具能力限制，不能声称启动了工具并未启动的任务。

默认采用“一名总协调者＋下列独立工作包”。总协调者可以同时承担集成包，其余包在前置接口明确后尽量并行。执行时先核对真实文件分布，建立文件所有权清单，再派发任务。

### 9.1 第一批：并行检查，统一最小接口

同时开展四项只读检查：保存及撤销链路、前端导航与组件、后端数据兼容边界、验收和隔离环境。各任务输出发现、建议和需要的接口，不同时修改共享实现文件。

总协调者汇总后，在 `outputs/工作台整体交互迭代_并行任务板.md` 固定以下内容：

- 每个任务的目标、负责人、允许修改的文件、依赖、状态和验收标准。
- 表单提交协议：资源类型／ID、编辑基线、候选改动、返回 revision、失败／冲突状态、取消及离开保护。
- 对象定位和问题跳转协议：工作区、对象／属性／契约的稳定引用，不通过中文名称临时拼接。
- 后端错误、待核对项和发布状态的前端消费协议。
- 共享组件的 props／事件及作用域样式边界；复用实际已有类型，避免每组发明一套格式。

这里只冻结并行开发所需的最小接口，不先写一套全新架构。协议确认后立即派发第二批，测试准备无需等待页面开发完成。

### 9.3 文件冲突与集成规则

1. **同一文件同一时间只允许一个写入负责人。** 最容易冲突的文件是 App.vue、projects.py、bindingModel.ts、propertyModel.ts、modelFormat.ts、style.css，不能按“业务功能”把同一文件分给多人同时改。
2. P03/P07/P09 需要 App 挂载时，提供组件名、props、事件和接入说明，由 P01 集成；P01 不同时重写这些包负责的子组件。
3. 子任务需要他人文件变更时，提交准确需求给该文件负责人，不自行越界修改。阻塞只影响相关工作包，继续推进其他独立包。
4. 本目录当前非 Git 仓库。使用共享目录时依靠明确所有权和阶段快照，不使用 reset、clean 或覆盖目录“解决冲突”。若工具提供隔离工作副本，可使用不含真实 ontology/ 的代码副本并由协调者合入，不能擅自初始化 Git 或复制用户凭据。
5. 一个协调者负责阶段完整构建。共享目录中不要同时启动多份写同一 dist／缓存的构建；独立纯函数测试可并行，浏览器验收使用协调后的稳定构建。
6. 每个运行隔离服务的测试任务都使用不同临时根目录和不同端口。不得共享用户数据目录、凭据目录或浏览器会话，不互相关闭他人进程。
7. 提交契约、共享类型和 UI 接口改变后，通知受影响包；总协调者记录变更，必要时先做小范围同步再继续，禁止靠 any／跳过校验掩盖协议冲突。
8. 每个包结束时交付：已改文件、行为说明、验证结果、未完成项、集成要求。未提供证据的“完成”不算总体验收通过。

### 9.4 第三批：并行审查、集中修复与验收

可以继续并行派发只读审查任务：保存并发与取消、模型协议与共享继承、来源映射与类型、凭据与数据隔离、导航与无障碍、旧版本与演示兼容。审查报告交给原文件负责人修复，审查者不同时改同一文件。

总协调者按依赖逐批接入：保存基础 → 对象／项目页面 → 全链路校验与发布。每批执行一次完整构建和相关验证，全部包集成后执行跨页面浏览器验收。并行完成不代表集成完成，不能各组测试通过就直接宣告交付。

### 9.5 如何使用剩余并发

有明确独立任务时，可再拆分测试用例、只读兼容审查、交互审查或独立新组件。满足以下条件再加并发：文件归属不重叠、输入接口已明确、有独立验收、存在实际可推进的工作。没有条件时等待依赖或帮助审查，不为了用满 50 个并发重复实现同一功能。

执行平台若提供更少并发槽位，按上述工作包分批轮换，保持最大可用并行度；向用户说明实际运行数与待调度任务，不能把计划中的任务报告为已经启动。
