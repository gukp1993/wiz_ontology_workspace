# SQL 步骤编排需求 V1

日期：2026-09-16
状态：待开发。本文是本轮实现和验收依据，替代此前“大文本框中用 @step 分段”的编辑方案，不改变已有规则的取值含义。

## 1. 目标与范围

项目映射中的取值规则采用“每张步骤卡片写一段 SQL，后续引用前面步骤的结果”。开发／实施人员维护 SQL；属性绑定人员只选择规则并填写参数。本体定义不新增字段。

首期支持：同一数据库连接、顺序步骤、单条 SELECT 模板、参数引用、动态表／字段引用、单值或时间序列返回、规则创建／编辑／保存、旧格式兼容。

不做：真实 SQL 执行、试运行、数据库写操作、LLM 执行、拖拽流程画布、并行分支、循环、条件分支、跨连接编排、任意 SQL 的安全执行引擎。多条记录不能隐式取第一条或自动展开循环。

## 2. 页面及操作

入口仍为“项目映射 → 取值规则库”。列表提供新建规则、编辑规则和引用属性列表。采样规则作为可复用示例，不再强制全项目只有一条规则。

编辑页按以下顺序，全部同页：

| 区域 | 必填内容 | 交互 |
| --- | --- | --- |
| 基本信息 | 规则名称、数据连接 | 连接从当前项目已登记的 MySQL 连接下拉选择 |
| 输入参数 | 用到的参数名称、数据类型、传入方式 | 支持增加、删除；说明选填；无参数规则允许空列表 |
| 查询步骤 | 步骤名称、SQL、预期记录数 | 每张卡片一个 SQL 编辑框，默认展开 |
| 返回结果 | 输出步骤、返回类型、值类型、值列；序列另选时间列 | 列名可以使用发现的输出候选或明确填写 |
| 操作栏 | 保存、取消 | 直接保存项目草稿，无第二次保存步骤 |

不增加步骤级数据连接选择。参数类型沿用文本、数值、是／否、日期时间；传入方式为“属性绑定时填写”“查询时传入”。

### 步骤卡片

- 标题：步骤序号、可编辑中文名称、只读技术引用名。
- 正文：一个等宽 SQL 编辑框；不拆出条件字段、运算符、来源字段等表单。
- 辅助操作：插入引用、上移、下移、删除。
- 卡片下面显示“可供引用的输出列”以及本步骤校验错误。
- 增加步骤：默认空 SQL，不自动改写其他步骤的记录数或返回结果。
- 删除步骤／参数可先修改本地表单，立即标出受影响的引用；修复前禁止保存。取消恢复原配置。
- 上下移动后重新校验顺序。不得自动把前向引用改成别的步骤。
- 步骤中文名可以修改；内部 ID 和技术引用名稳定，不向用户提供随意改技术名的操作。
- SQL 编辑框支持滚动、等宽字体、保留缩进。复用现有组件或原生 textarea，不为本轮引入大型编辑器依赖。

## 3. SQL 模板语法

用户不必在每段 SQL 中写 @step，段落归属由卡片保存。

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `:参数名` | 输入值 | `:model_id` |
| `:步骤技术名.输出列` | 前步骤唯一记录中的值 | `:point.scada_id` |
| `{{步骤技术名.输出列}}` | 前步骤返回的动态表名／字段名 | `{{point.scada_table}}` |

值参数和动态标识是不同的引用种类。输入值占位符不得当作动态表名替换。未来执行器须参数化绑定值并验证动态标识；当前仅保存模板，不进行字符串拼接执行。

每步一条 SELECT，支持将 JOIN、聚合、表达式、子查询写在 SQL 内。本期不支持 WITH 起始语句或多语句片段；给出清晰提示，而不是宣称支持全部 SQL。

### 插入引用

点击后，在当前 SQL 光标位置插入，不覆盖其他内容，插入后恢复焦点。

- 输入参数：显示名称、说明，生成 `:参数名`。
- 前置步骤：只展示排在当前步骤之前、且预期“一条”的步骤。
- 选择输出列后，再选择“作为值”“作为表名／字段名”，生成对应语法。
- 不展示当前步骤、后续步骤或多条结果步骤作为直接引用来源。
- 输出候选尽量从显式 AS 别名或简单 SELECT 列名提取；无法可靠识别时允许明确填写输出列名，并标记“未验证”。不得为了列举候选访问真实业务数据。
- 不用脆弱正则宣称已经验证任意 SQL 的输出结构。字符串、注释中的伪占位符不得被当成有效引用。

## 4. 记录数与返回语义

| 配置 | 约定 |
| --- | --- |
| 一条 | 应返回唯一记录；缺失或多条按错误处理，不能隐式 LIMIT 1 |
| 多条 | 返回记录集合；无数据为空集合，不自动报错 |
| 单值返回 | 输出步骤必须为“一条”，指定值列 |
| 时间序列返回 | 输出步骤必须为“多条”，指定不同的时间列和值列 |

允许选择任一步骤作为输出步骤。整个配置仍按列表顺序描述；如输出步骤不是最后一步，显示“后续步骤不参与返回，建议删除无用步骤”，不要静默改变返回步骤。所有步骤仍参与配置校验。

时间序列要求作者在输出 SQL 中写清 ORDER BY 时间升序。UI 明确这是约定，未执行时不宣称时标类型、排序和数据正确。空值保留 null，不转零；不存在的字段不补零。

## 5. 储能 SOC 完整示例

规则名称：采样值查询；连接：当前项目数据库。

| 输入参数 | 类型 | 传入方式 | 属性绑定示例 |
| --- | --- | --- | --- |
| model_name | 文本 | 属性绑定 | m_storage_cluster_phase |
| attr_name | 文本 | 属性绑定 | soc |
| model_id | 文本或与主键相容的数值 | 属性绑定 | {id} |
| startTime | 日期时间 | 查询时传入 | 查询开始时间 |
| endTime | 日期时间 | 查询时传入 | 查询结束时间 |

### 卡片 1：定位测点（技术名 point，一条）

```sql
SELECT scada_table, scada_id
FROM s_attr_scada
WHERE model_name = :model_name
  AND attr_name = :attr_name
  AND model_id = :model_id;
```

### 卡片 2：定位采样存储（技术名 storage，一条）

```sql
SELECT sample_table_name, sample_field_name
FROM {{point.scada_table}}
WHERE id = :point.scada_id;
```

### 卡片 3：读取采样记录（技术名 samples，多条）

```sql
SELECT record_time AS timestamp,
       {{storage.sample_field_name}} AS value
FROM {{storage.sample_table_name}}
WHERE record_time >= :startTime
  AND record_time < :endTime
ORDER BY record_time ASC;
```

返回：samples、时间序列、数值、时间列 timestamp、值列 value。具体表名、属性名在属性绑定时填写；规则可复用于温度、功率，不为每个属性复制规则。

## 6. 保存协议与兼容

建议新增 `schemaVersion:4, mode:sqlSteps`，独立于现有 V3，前后端同步支持。继续使用 kind=queryRule、规则原 ID、connection、inputs。不得把新格式伪装成旧 sqlTemplate 模式。

示意（ID 仅示意，真实新增由系统生成）：

```json
{
  "kind": "queryRule", "schemaVersion": 4, "mode": "sqlSteps",
  "id": "existing-rule-id", "name": "采样值查询", "connection": "existing-connection-id",
  "inputs": [{"name":"model_id","type":"string","source":"binding"}],
  "steps": [{
    "id":"existing-or-generated-step-id", "key":"point", "name":"定位测点",
    "cardinality":"one", "sql":"SELECT scada_table, scada_id FROM s_attr_scada WHERE model_id = :model_id;"
  }],
  "result": {"step":"existing-or-generated-step-id","type":"scalar","valueType":"string","value":"scada_table"}
}
```

### 旧规则

1. V1/V2/V3 结构化步骤：用已有转换逻辑生成各步 SQL，保留 ID、技术引用、别名、参数、顺序、记录数、结果与扩展字段。不能擅自规范化别名破坏引用。
2. V3 大 SQL 模板：按 @step 边界转换成卡片。边界识别须避开字符串和块注释内的伪指令；不能使用无条件 split 造成静默截断。
3. 无法无损转换：保留完整原文，显示“旧格式待处理”及具体原因，提供旧模板编辑／查看回退；不能空白覆盖，也不能假装转换成功。
4. 打开不落盘；用户保存才写项目新修订。旧发布快照、初始化目录不回写。
5. `extensions` 未知内容保留；原实现留档时放 extensions，不能与新步骤同时作为生效来源。
6. 属性绑定保留已有 implementation ID 与 output 键（现有 series 键即使单值也不擅自替换），界面按真实类型显示。
7. 新输入／返回类型变化后，属性配置和项目校验检查影响；不凭空补默认业务值。

## 7. 校验和错误提示

前后端须一致：名称、连接、步骤 ID/key 唯一、参数声明、SQL 非空、单 SELECT 模板、有效引用、前置唯一结果限制、输出步骤存在、记录数和返回形态相容、返回列不空、时间和值不重名。

能够确定的错误阻止保存；不能确定的 SQL 输出列存在性、字段真实类型及业务查询正确性只提示未验证。需要词法扫描处理字符串、注释和分号；本轮不建设完整 SQL 解析器。

提示必须含步骤中文名与具体问题，例如“定位采样存储：引用 point.scada_id，但定位测点已被删除”。禁止只显示 UUID 或“配置无效”。

发布校验依然只代表配置检查，不代表执行成功。不得新增执行路由，不改 dbdrivers 的固定只读操作限制、不访问真实业务表。

## 9. 开发计划

1. 基线检查：阅读 AGENTS、当前 queryRules/sqlTemplates/QueryRuleManager、后端校验和属性绑定；记录已有测试失败，不顺手修其他模块。
2. 协议与转换：确定 V4、双端校验、旧格式无损转换、异常回退；先用内存 fixture 验证三个格式。估计工作量以现场代码为准，不承诺固定耗时。
3. 卡片编辑：替换大文本框；参数区复用；上下移、删除、光标插入、输出选择、错误定位。
4. 集成：属性绑定、保存队列、校验发布、只读展示；稳定引用和项目草稿往返测试。
5. 验收：相关回归、金样、前端构建、隔离页面测试，记录 A1—A15 证据。
