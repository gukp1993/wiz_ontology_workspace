# 无表对象与关联聚合设计方案 v1

日期：2026-09-15。本文为待开发设计，不代表工作台已实现或用户数据已变更。

## 1. 目标与业务基线

支持：在项目中登记“创智园二期储能系统”，不绑定虚构的数据库表；通过“系统包含设备”关系确定成员；系统额定容量由成员设备额定容量求和，并能只读预览实际结果。

当前项目 `9803ea198cbc` 引用储能本体 3.0.0。已有储能系统、储能设备、共享额定容量属性；设备容量映射为 `m_storage_phase.capacity`。缺少系统包含设备链接，系统项目绑定为空。详细基线见 [填写示例](创智园二期_储能系统容量映射填写示例_20260915.md)。

**保持本体与项目分离：**本体维护对象、属性和链接；项目维护实例、成员条件、取值算法及数据连接。不增加“虚拟对象”本体类别，也不创建假的数据库表。

## 2. 固定范围

本轮交付三项配置能力及一个受限只读查询闭环：

1. 对象实例来源新增“项目登记”。
2. 链接映射新增“按条件选择成员”。
3. 属性取值新增“关联聚合”，先支持 SUM。
4. 用已配置的数据库身份表直接字段，预览成员及聚合结果。

不做通用 ETL、任意 SQL、自动建表／建视图、Redis 聚合、时序聚合、跨库 JOIN、递归聚合、AVG/MIN/MAX、规则脚本、系统调控、定时计算或缓存平台。既有数据库来源、Redis 来源和采样规则继续保留。

本轮支持范围：登记对象 → 一跳关系 → MySQL 来源对象 → 身份表上的直接数值字段。其他组合保留原配置或明确提示“不支持此次聚合”，不得假装执行成功。

## 3. 交互设计

### 3.1 实例识别

保留“对象映射 → 选对象 → 实例识别”的入口，增加来源方式下拉：

| 方式 | 表单 |
|---|---|
| 数据库表／视图 | 沿用连接 → 表／视图 → 主键的现有联动 |
| 项目登记 | 实例列表；新增／编辑实例：实例编号、显示名称 |

项目登记可有多个实例，不能将整个对象类型硬编码为永远只有一个系统。实例编号在当前项目同一对象类型中唯一；编辑已有编号视为身份变更，第一版禁止直接修改，提供新建并处理旧引用的明确提示。

显示名称是便于管理实例的标签；本体已有显示名称属性时，可在属性取值中选择“登记信息 → 显示名称”。不能靠中文名称自动匹配属性。项目登记信息不要求新建本体标识属性，但也不禁止已有标识属性绑定登记编号。

切换来源方式时，展示受影响的属性／链接配置。若有不兼容引用，阻止切换并提供定位，不静默删除原映射。仍使用本地表单保存与取消机制。

### 3.2 链接映射

先选择本体已定义的链接，起终点对象由链接确定，不允许手填另一套类型。

- 旧“表字段关联”保持原交互。
- 起点为项目登记、终点为数据库来源时，提供“按条件选择成员”。
- 表单字段：起点实例下拉、终点对象只读、成员范围、条件列表、预览成员。
- 每个起点实例可单独保存一套成员条件；一个链接映射容纳多条起点实例规则，不重复建立同一链接定义。

条件字段从终点对象**已配置的身份表字段目录**选择；第一版只支持等于、不等于、属于列表、为空、不为空，条件用 AND 组合。值按字段数据类型校验，执行参数化查询；不开放任意表达式或 SQL。

范围选项：

1. 按条件选择（默认）：至少一条条件，例如园区字段等于项目园区编号、删除标识等于有效值。
2. 该来源表全部有效记录：仅在实施人员明确选择后允许，显示“将使用该表全部记录”的具体说明；表有逻辑删除等字段时不会自动猜其语义，仍需条件。不得默认为整表。

当前项目尚无已确认的园区编号，不能填写猜测值。工作台连接指向某数据库不构成项目范围过滤。预览列表显示设备标识、名称（已映射时）及用于范围过滤的字段，默认最多 20 条，并显示是否截断。

第一版新规则支持一对多或多对多链接。一对多时检查同一设备是否落入该链接多个起点实例，冲突应报错；不能靠去重掩盖跨系统归属冲突。一对一等暂不支持的数量关系提供明确提示。

### 3.3 属性取值

在现有属性取值单页增加“登记信息”和“关联聚合”来源，只对适用对象／类型展示。

| 来源 | 字段 |
|---|---|
| 登记信息 | 实例编号／显示名称；目标必须是兼容文本属性 |
| 关联聚合 | 关联链接、成员属性、聚合方式（本轮只显示求和）、容量单位确认说明 |

关联链接下拉只列当前对象的可用出向成员关系；成员属性下拉只列终点对象的数值属性。引用共享定义的属性应显示有效名称和类型，但绑定仍引用终点对象属性的稳定键。

第一版要求源属性已映射为身份表直接数值字段（包括可证明等价的旧字符串／field／database 表示），目标也是数值；其他映射不能退化成读取同名字段。

示例摘要：“沿【包含设备】关系，对成员设备的【额定容量】求和”。不让业务用户手写 SUM、稳定 ID、表名。

固定初始策略：成员按实例主键去重；没有成员返回 null；任何成员容量缺失返回 null 并标记“不完整”；重复主键且容量冲突报错，不能随便取一条。0 是合法容量值，不当成缺失。

容量不跨单位直接累加。第一版由实施人员确认输入值已采用同一单位口径；界面必须说明这不是自动验证或换算。不得从自然语言显示格式中解析单位，更不得从后缀猜测倍数。本例按现有说明为 kWh，真实来源尚需确认。

### 3.4 预览与查询

提供“预览关联取值”：先保存当前配置，保存成功后使用服务器最新确认 revision 发起只读预览；若保存失败，不能继续查询旧配置并展示成新结果。

结果包含：数值、状态、成员数量、缺失数量、计算说明、最多 20 条成员明细、执行时间。明确区分：配置有效、数据查询成功、结果不完整。

生产数据只读预览必须由用户点击触发，不在打字、页面打开或保存时执行。预览不保存聚合值、不发布数据、不触发模型、Action 或设备指令。

## 4. 数据协议（新增最小联合类型）

继续写项目 `bindings.yaml` 的 object_bindings，沿用现有草稿修订存储。以下是协议示意，尖括号为待解析稳定标识，不可直接写入用户数据。

```yaml
object_bindings:
  - object_type: <系统类型现有键>
    identity:
      kind: registered
      instances:
        - id: CZYEQ-ESS-001
          label: 创智园二期储能系统
    properties:
      <系统显示名称属性键>:
        kind: registered
        field: label
      <系统额定容量属性键>:
        kind: aggregate
        relation: <已发布的包含设备链接键>
        property: <设备额定容量属性键>
        operator: sum
        empty: 'null'
        missing: incomplete
        inputUnitConfirmed: true
    relations:
      - kind: membership
        relation: <已发布的包含设备链接键>
        target_type: <设备类型现有键>
        rules:
          - sourceInstance: CZYEQ-ESS-001
            scope: filtered
            conditions:
              - field: park
                operator: eq
                value: <需要用户确认的实际园区编号>
              - field: del_flag
                operator: eq
                value: 0
```

上述 park、del_flag 条件仅为填写结构示例，需先核对真实目录与业务含义。`inputUnitConfirmed` 表示实施人员确认口径，不代表系统验证了实际数据。

兼容规则：

- 没有 identity 的历史对象仍按旧 connection/table/primary_key 解释，不批量迁移旧数据。
- registered 对象不再要求连接／表／数据库主键；分支校验，不放宽 database 对象要求。
- 历史 relation 无 kind 时仍按原表字段关联解释。所有适配器、校验器、发布预检、摘要必须处理新的联合类型。
- 空策略固定存为字符串 `empty: 'null'`，表示空集合返回空结果；不可前端存字符串、后端按 YAML null 配置值理解。
- 未识别的 kind 和扩展字段继续保留并阻止无法解释的执行，不以默认类型覆盖。
- 登记实例也是用户项目数据；删除实例前检查成员规则、引用和预览选择状态。禁止隐式删除。
- 新 aggregate 限定一跳、直接字段输入，结构上拒绝自引用、聚合依赖聚合，避免递归循环。
- 本轮不新建单独的计算契约，聚合配置直接属于属性来源。

## 5. 只读执行边界

建议新增 `POST /api/project-property-preview`，请求只接收 projectId、revision、objectType、instanceId、property。服务器加载已保存项目及其固定本体版本，不接受客户端 SQL、连接密码、任意表名或任意配置替代。

1. 在短锁内读取并核对 revision，复制项目快照后释放锁；网络访问不持 LOCK。
2. 校验实例、链接、条件及映射，解析至已登记连接与目录；表／列标识仅允许目录匹配后安全引用，条件值全部参数化。
3. 独立只读执行模块处理业务查询；不把任意查询塞入仅负责探测的 dbdrivers。连接密码复用 vault，不能回传或记录。
4. 首版单次最多 10,000 条候选记录，超量直接提示缩小范围，不对截断记录求和；设置连接／读取超时，不自动无限重试。
5. 数据库范围权限之外再应用配置的成员条件。记录查询时间；结果是该次查询视图，不承诺持续实时一致性。
6. 新对象和新来源不得进入旧演示引擎造成崩溃：标记 unsupportedSources 或走新明确入口，不能静默伪造演示结果。
7. response 建议包含 `status: ok|empty|incomplete|error`、`value`、`memberCount`、`missingCount`、`membersPreview`、`evaluatedAt`、`message`；错误不得暴露密码或连接串。

本轮只读查询首版以项目草稿预览为入口，不声称已提供发布项目运行服务、AI 自动问答或外部应用 SDK；这些可基于相同执行器后续扩展。

## 6. 发布与项目初始化

缺少本体链接时，项目页提供“引用版本中尚无适用链接，请先在本体定义后发布”的定位提示。不能在项目保存时自动创建链接、发布本体或升级引用。

开发自动化用临时本体构造链接、登记系统和聚合配置。实际创智园二期项目的链接创建、版本发布、引用切换及成员条件填写属于单独的数据配置步骤；完成能力开发后报告待填写条件，不自行猜园区编号。

## 8. 尚需项目实施确认的事实
