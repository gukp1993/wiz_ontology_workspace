# 属性内 SQL 取值实施记录

日期：2026-09-16。依据《属性内SQL取值方案_v1_20260916.md》与《GLM执行指令_属性内SQL取值_20260916.md》完成。核心：属性取值「调用取值规则 / 函数」内新增「直接编写 SQL」与「引用已有规则」两种方式；直接 SQL 是属性私有匿名配置，不起规则名、不新增 implementations、不新增顶层取值策略、未恢复关联聚合入口。全程未执行任何 SQL。

## 1. 协议（computed/mode=inlineSql，冻结）

```json
{"kind":"computed","mode":"inlineSql",
 "inlineSql":{"version":1,"connection":"连接ID","sql":"单条SELECT模板",
              "params":{"参数名":{"from":"constant","dataType":"string|double|boolean|dateTime","value":...}
                                     |{"from":"projectParameter","key":"项目参数键"}
                                     |{"from":"instanceId"}}}}
```

- 与命名规则 `{kind:"computed",implementation,output,inputs}` 互斥（不作为双生效配置同时写入；后端校验同时出现报「内联 SQL 与命名规则取值不能同时配置」）。
- 引用已有规则保持原格式，不强制补 mode；旧数据零迁移。
- 不存冗余输出类型：输出说明按当前项目引用版本的属性定义推导（普通=一行 value；时序=多行 timestamp+value），并明示「输出约定，尚未执行验证」。
- 存于对象绑定 `properties[属性稳定键]`，复用项目草稿/发布序列化；不写本体、不追加 implementations。
- propertyView/commitProperty 先识别 mode=inlineSql；version≠1、mode 未来值或 inlineSql 含未知键 → `{kind:"unknown"}` 只读原样保留（零丢失），绝不当空计算规则重存。
- 演示执行器隔离：`merged()` 本就只放行字符串映射，内联配置计入 `bindings.unsupportedSources`（kind=computed），有测试锁定。

## 5. 未实现/边界（按方案即为不做）

不执行/试运行 SQL；无「提取为共享规则」；不支持 WITH、多语句、动态表字段、步骤间引用（明确提示改用规则库）；参数来源仅固定值/项目参数/实例编号三种（身份表字段等后续考虑）；输出列存在性与返回行数未验证（仅显示约定）；示例 park_id_column 为占位，未写入任何业务数据；未自动 SUM 整表、未加 COALESCE/单位换算；历史 aggregate 配置未做任何转换，仍只读兼容。
