# 工作台整体迭代交互方案 V1

日期：2026-09-14  
阶段：交互方向评审，尚未修改正式工作台。  
原型：[本体工作台整体迭代交互原型](../prototypes/本体工作台整体迭代交互原型_v1.html)

补充确认：每个表单点击“保存”即持久化当前草稿，删除顶部“保存草稿”按钮。HTML 原型尚保留旧的两层保存展示，实施时以本条及第 5 节为准。开发入口：[GLM 整体迭代指令](../交付物/GLM开发指令_工作台整体交互迭代_20260914.md)。

## 1. 本轮设计结论

保留两个独立工作区：**本体建设定义通用业务模型，项目映射为具体项目配置数据与实现。**

主要改变是把编辑组织方式从“逐个进入分类菜单”调整为“围绕当前对象完成工作”。对象、属性、链接仍是独立的模型定义，只在交互上集中呈现。

本方案是本项目的交互设计，不是 Palantir 官方菜单或官方固定建模流程。

## 2. 基于现有代码发现的问题

| 当前组织方式 | 用户遇到的困难 | 本轮调整 |
| --- | --- | --- |
| 对象、链接、属性分别作为主要入口 | 创建一个对象后，需要跨页寻找其属性和链接 | 合并为“对象建模”，对象详情内维护属性、链接与相关契约 |
| 项目绑定存在页面级页签，再叠加对象详情页签 | 连接、全部实现、对象来源的入口重复，定位成本高 | 连接和实现保留唯一主入口；对象映射只保留实例识别、属性取值、链接映射 |
| 页面顶部同时出现保存、校验、发布、撤销等操作 | 用户难以判断当前表单是否已保存，是否应发布 | 表单保存即持久化草稿，顶部只展示保存状态；校验与发布集中到独立页 |
| 建设流程按多类内容连续排列 | 容易理解为每类都必须填写，才能进入下一步 | 改为可跳转工作概览，计算契约和项目使用范围按需维护 |
| 属性来源依赖对象已登记表，字段最终返回单值 | 公共采样表与时间序列难以表达 | 沿用新需求：来源、记录定位、结果映射三个环节 |
| 项目是否绑定本体、引用哪个版本需要进入管理详情辨认 | 容易把本体草稿和项目引用版本混淆 | 项目页眉持续显示固定引用版本，升级独立展示比较与确认 |

这是交互层梳理，不主张因调整菜单删除底层定义、历史数据或现有能力。

## 3. 信息架构

顶部固定“本体建设／项目映射”，左侧选择当前本体或项目。两个区域各自保留当前编辑上下文。

| 本体建设 | 负责的工作 |
| --- | --- |
| 工作概览 | 明确接下来可以做什么，进入对象建模、契约或发布 |
| 对象建模 | 对象目录与关系画布切换；对象内维护属性、链接、相关契约 |
| 计算契约 | 维护通用输入输出和业务说明，包括不依附某个对象的契约 |
| 共享属性库 | 管理可共享定义，支持复制为私有、引用共享及查看影响 |
| 校验与发布 | 定位问题、检查差异、发布版本、查看历史 |

| 项目映射 | 负责的工作 |
| --- | --- |
| 项目概览 | 管理本体版本引用、项目参数、待处理事项与使用范围 |
| 数据连接 | 集中配置和测试连接、维护表结构目录 |
| 对象映射 | 按对象配置实例识别、属性取值和链接映射 |
| 计算实现 | 根据通用契约填写本项目的输入绑定和处理规则 |
| 校验与发布 | 定位配置问题、声明使用范围、发布配置快照 |

动作、接口、历史导览、实例预览等既有辅助能力不在本轮核心原型中展开；正式迭代前单独确定入口，不能直接删除其代码与数据。对象建模页中的“相关契约”只是筛选和快捷入口，不改变全局契约的独立性。

## 4. 三条核心交互链路

### 4.1 业务专家维护储能簇

选择本体 → 对象建模 → 储能簇 → 属性清单 → 编辑属性 → 保存本体草稿。

名称与业务定义直接展示。属性直接填写名称、业务定义、数据类型与单值／时间序列；单位和格式等附加设置默认折叠。对象的显示名称通过文本属性标记。原型的字段是本轮提案，不代表所有旧字段已决定删除。

关系画布和对象列表使用同一份定义，点击节点进入该对象。画布主要展示对象和链接，属性不默认变成节点。

共享属性库提供两种清楚命名的操作：复制后独立维护；引用则继承共享定义。完整类型不同的单值 SOC 和 SOC 序列不能直接引用同一个完整共享定义。

### 4.2 实施人员配置 SOC 采样序列

选择项目 → 对象映射 → 储能簇 → 属性取值 → SOC 采样序列 → 配置。

局部三步操作：

1. 选择来源：项目连接 → 搜索公共采样表，不要求先登记为对象来源。
2. 定位记录：当前实例主键对应 object_id，再按对象类型、指标代码筛选。
3. 映射结果：value 对应值、sampled_at 对应时间，明确时间编码和来源时区。

三个步骤属于一个属性的编辑表单，前后切换保留内容；保存后整体生效，取消不替换原绑定。单值、Redis 和函数展示各自需要的配置，不要求用户维护无关字段。

实例识别来源负责确定对象实例。属性可以来自公共采样表；链接映射仍从两端对象已配置的来源表选择关联字段。这两种范围不能混同。

### 4.3 从问题到发布

校验与发布 → 查看具体问题 → 点击“去处理” → 直接打开对应对象／属性的表单 → 保存 → 回到发布。

项目可明确排除暂不使用的属性，不把“整份本体全部映射”当作发布前提。实际必需属性、计算依赖、显示名称等仍应按正式校验规则处理，不能仅靠一个排除勾选绕过依赖。

本体与项目各自保存和发布。本体发布后项目不自动升级；项目先比较目标版本与配置影响，再切换草稿引用，既有发布快照保持不变。

## 5. 通用交互约定

- 页面始终显示正在维护的本体或项目、当前对象；项目额外显示引用的本体发布版本。
- 表单修改未保存时离开，提示继续编辑或放弃本次修改，不能静默覆盖旧配置。
- 每个表单点击“保存”，直接通过所属区域 API 持久化当前草稿，成功后才能显示“已保存”。删除顶部“保存草稿”，不再要求第二次保存。编辑期间显示“有未保存修改”，请求期间显示“保存中”，失败保留输入并允许重试。
- 表单“取消”只丢弃本次未提交修改。画布拖动、连线、删除、撤销／重做等没有独立表单的操作，在一次完整操作结束后自动持久化草稿，不按鼠标移动或每次按键生成修订。保存失败和冲突必须可见，不能静默丢弃修改。
- 发布独立于草稿保存：将已保存的完整草稿修订生成固定发布版本。存在未保存表单或保存失败时，引导先处理，不能把发布按钮当作隐式保存按钮。
- 只在有待办工作时显示引导，不用一排无意义的完成百分比制造强制流程。
- 表单旁提供一句填写提示，复杂规范按需展开；业务专家不用先读完整需求文档。
- 正式表和字段选择统一使用现有可搜索 AppSelect，换连接或换表后清理无效的局部依赖，并提示重新选择。
- 配置校验与执行验证分开。正式连接测试可以是真实操作，但连接成功不等于属性查询或函数执行成功。
- 图与列表是同一份数据的不同入口，不出现独立保存、相互不同步的两个模型。

## 6. 原型可以体验什么

已使用隔离的内存示例串联以下交互：两区切换、空白本体／项目创建、对象及属性编辑、关系画布、共享复制／引用、计算契约／实现、实例识别、公共采样表映射、Redis Key 配置、链接两端选择、连接配置、问题定位、模拟发布和主动版本引用切换。

原型内的储能簇、设备、系统与数据表用于演示，不代表读取或迁移了真实 ontology/ 内容。刷新页面后修改重置。

原型有意简化：目录为静态示例；连接测试与发布为模拟；版本对比不是完整语义差异分析；函数表单先示范一个对象输入与一个属性输出，正式版仍需保留现有多输入／多输出、无输入及无对象归属能力；补充来源示范一个编辑入口，正式版保持可配置零到多项；关系画布演示点击导航，不替代现有拖拽、连线及快捷键；筛选条件原型先展示当前实例和常量，正式字段范围见通用属性来源需求。

未声称已完成浏览器全链路验收或正式功能开发。后续实施须遵守 AGENTS.md、V3 存储边界和隔离测试要求。

## 7. 本轮先评审的三个决定

1. 是否接受“对象建模”集中维护属性和链接，减少独立一级菜单？建议接受，同时保留全局查找和跨对象入口。
2. 是否接受属性映射的三步局部表单？建议复杂来源采用三步，身份表直接字段在后续可提供快捷配置。
3. 是否接受“先配置范围，再检查发布”的方式，让项目不必实现整个本体？建议接受，保留必需依赖检查。

方向确认后，再把页面细节、状态机、数据结构变更和迁移步骤整理成正式迭代需求与开发任务，不直接照原型脚本改写生产工作台。

## 8. 实施事实（2026-09-14 迭代完成后补充）

本方案与《开发指令_工作台整体交互迭代》已实施完成，最终事实以 [工作台整体交互迭代实施说明](../交付物/工作台整体交互迭代实施说明_20260914.md) 为准。要点：

- 导航按第 2 节 5+5 落地，辅助能力归并"更多工具"，旧 hash 全量 alias 兼容。
- 保存规则按第 5 节及开发指令第三节加严版实现：表单"保存"一次直通持久化（串行队列 saveCoordinator），顶部无保存按钮，仅状态条（已保存/未保存修改/保存中/保存失败/版本冲突）；发布移入两区"校验与发布"页，发布前强制先落盘。
- 对象建模为目录+详情+关系画布三合一（复用现有 cytoscape 与快捷键）；属性编辑内嵌完整属性管理器；共享属性库独立页支持复制为私有/引用/解除/查看引用与形态一致性校验。
- 属性来源采用三步局部表单（选择来源→定位/绑定→映射确认），数据库直选表、Redis 直连、时间序列协议沿用上一轮实现，未重做。
- 校验页问题项"去处理"按结构化 kind/id 跳转定位；四态语义与"配置校验通过≠已执行验证"边界在页面明示。
- 本文档第 6 节所列原型简化（模拟连接测试、模拟发布、单一函数表单等）在生产实现中均不成立：连接测试与目录读取为真实 API，发布复用后端正式校验与分类，契约保留多输入/多输出/无归属，补充来源零到多项。
