## 当前计算契约怎么填写

1. **这个能力叫什么？** 例如“查询储能簇 SOC 采样记录”。
2. **它做什么？** 例如“返回指定储能簇在指定时间范围内的 SOC 采样记录”。
3. **使用时需要提供什么？** 搜索选择“对象 · 储能簇”；再添加两个“自定义内容 · 时间”，分别命名为开始时间、结束时间。确实不需要参数时勾选“不需要提供任何内容”。
4. **希望得到什么？** 搜索选择“储能簇 → SOC 采样序列”，沿用已有属性的定义与类型；也可返回对象或自行命名的数值、文本、时间序列等结果。支持多项返回。

已有对象和属性的名称自动带出；同类型内容需区分用途时，可展开“名称与补充说明”调整本次参数称呼。通用业务约定默认折叠。数据库、Redis Key 和执行步骤放在项目映射的计算实现中。

对象不必关联计算契约：所选输入输出只是让系统自动在相关对象详情展示这个能力，并不新增图上的链接或属性。单纯读取已映射属性不强制另建契约。

# 计算函数定义填写规范

## 当前工作台填写方式（以本节为准）

只填写五项：名称、业务说明、输入、计算规则、输出。输入、规则和输出都用自然语言描述，不再选择函数场景、不填写参数表、步骤表和属性绑定表。查询、公式、组合调用仅作为折叠的参考示例。

历史结构化内容会转为文字展示，编辑保存后采用五项文字定义；实际规则解析与执行尚需接入。以下为历史详细参考，不再作为界面必填要求。

---

适用范围：储能本体中的数据查询、公式计算和多个函数的组合调用。

本规范按照本次确认的“输入 → 函数主体 → 输出”方案制定，是本项目的填写约定，不是 Palantir 官方文件格式。工作台已支持输入、函数主体、输出、调用步骤和属性绑定维护，提供示例和缺项检查；编排仅保存为定义，尚不自动执行。

## 1. 用户需要填写什么

一个函数先填写以下五项，不要求业务专家编写代码：

| 内容 | 是否必填 | 怎么填写 | 示例 |
| --- | --- | --- | --- |
| 函数名称 | 是 | 动词＋业务对象＋结果，区分实时、历史等场景 | 查询储能簇实时 SOC |
| 业务说明 | 是 | 一句话说明用途和结果含义 | 获取指定储能簇最新上报的 SOC，70 表示 70% |
| 输入 | 是，可明确“无输入” | 列出调用者必须提供的参数 | 储能簇 ID |
| 函数主体 | 是 | 按顺序说明查什么、怎么算、调用谁 | 用簇 ID 拼接 Redis Key，读取数值 |
| 输出 | 是 | 说明返回值名称、数据类型、业务含义 | SOC，数值，百分数口径 |

“适用对象类型”不再与输入重复维护：对象归属由输入参数的对象关联和属性绑定表达。通用数值函数可以不关联对象类型。工作台已采用此方式，历史配置保留。

## 2. 输入怎么填写

每个输入参数是一行。

| 字段 | 是否必填 | 填写要求 | 示例 |
| --- | --- | --- | --- |
| 参数名称 | 是 | 用户看得懂的名称 | 储能簇 ID |
| 数据类型 | 是 | 文本、数值、是／否、时间、数组、结构体 | 文本 |
| 参数说明 | 是 | 指明哪个标识、什么时间或哪种单位 | 本体中储能簇实例的唯一标识 |
| 关联对象类型 | 对象标识参数填写 | 说明这个 ID 代表哪类对象 | 储能簇 |
| 示例值 | 选填 | 用虚构数据帮助理解 | cluster-001 |

约定：第一版填写的输入均为调用时必填，不另增“是否必填”开关。没有参数时明确写“无输入”。

参数名如 `cluster_id`、`at` 用于表达式和程序调用，由工具生成或开发／实施补充，业务专家不必自己设计稳定标识。

- 数值参数说明单位和口径，例如 kWh、0～100的SOC。
- 时间参数说明用途，例如“查询时刻”，时间戳应带时区。
- 数组说明元素类型；结构体说明字段及其类型。
- 对象标识与业务表主键不一致时，由项目映射提供转换，不默认二者相等。

## 3. 函数主体怎么填写

可以用自然语言、结构化步骤或由开发补充的代码描述。无论采用哪种形式，都要明确数据来源、参数对应和结果处理。

自然语言是规则描述，不等于已经可以运行。实际执行需要开发实现，或配置能解析并执行这些规则的受控执行器。仅有大模型文本输出，不能当作已经查询过 Redis 或数据库。

### 3.1 数据查询

按以下顺序写：

1. 从哪个逻辑数据源读取。
2. 用哪些输入定位数据。
3. 读取哪个字段或值，如何解释。
4. 返回什么；查询不到时怎么办。

示例：

> 从“实时遥测 Redis”读取储能簇实时 SOC。将输入的储能簇 ID 代入 Key 模板 `soc_{cluster_id}`。本例假设 Key 的值直接存放 SOC 数字文本，读取后转换为数值并返回，70 表示 70%。Key 不存在或内容不是数值时返回明确错误，不按 0 处理。

不要只写“查 Redis”，这不足以指导实施。

### 3.2 公式计算

写清每个数值从哪里来，再写公式和结果口径。

示例：

> 查询当前储能簇的额定能量，单位 kWh；调用“查询储能簇实时 SOC”。按“额定能量 × SOC ÷ 100”计算剩余电量，返回 kWh 数值。

不要只写“容量 × SOC”：需要区分额定容量是 Ah 还是 kWh，以及 SOC 是 0～1 还是 0～100。

### 3.3 函数编排

每一步写清“调用谁、传什么、结果交给谁”。推荐用表格：

| 步骤 | 操作／被调用函数 | 输入来自哪里 | 本步结果 |
| --- | --- | --- | --- |
| 1 | 查询设备下属储能簇 | 当前函数输入的设备 ID | 簇 ID 数组 |
| 2 | 对每个簇调用“计算储能簇剩余电量” | 步骤1中的每个簇 ID | 电量数组 |
| 3 | 对电量数组求和 | 步骤2的输出 | 设备剩余电量 |

自然语言可以说明步骤，但系统落地时应保存明确的函数引用和参数绑定，不能仅靠函数名称字符串猜测调用对象。

## 4. 输出怎么填写

第一版默认每个函数返回一个结果。需要返回多个字段时，使用结构体。

| 字段 | 是否必填 | 示例 |
| --- | --- | --- |
| 输出名称 | 是 | 实时 SOC |
| 数据类型 | 是 | 数值 |
| 结果说明 | 是 | 以0～100百分数表达，70表示70%，不附带百分号文本 |
| 示例值 | 选填 | 70 |

输出单位、口径写在结果说明中，不强制新增独立字段。数组和结构体需补充元素或字段说明。

计算函数返回原值：返回数值 `70`，而非显示文本 `"70%"`。单位后缀、小数位和自然语言显示处理放在属性的显示格式中。

## 5. 储能簇实时 SOC：完整填写示例

| 项目 | 填写内容 |
| --- | --- |
| 函数名称 | 查询储能簇实时 SOC |
| 业务说明 | 获取指定储能簇最新上报的荷电状态，结果为百分数口径 |
| 输入 | 储能簇 ID；文本；关联对象类型：储能簇；代表本体实例唯一标识 |
| 函数主体 | 从“实时遥测 Redis”读取 `soc_{cluster_id}`。本例为 Redis 字符串值，转换为数值返回。无数据、无法转成数值时返回错误，不补零 |
| 输出 | 实时 SOC；数值；70表示70%，原值不附带百分号 |
| 示例 | 输入 `cluster-001`，读取 `soc_cluster-001`，原始内容 `"70"`，返回数值 `70` |

以上 Redis 结构与 Key 是本次讨论的示例假设，尚不代表实际项目已经核对或接入。若实际存储为 Hash 或 JSON，实施人员需明确字段和解析路径。

## 6. 历史采样 SOC：与实时函数分开

| 项目 | 填写内容 |
| --- | --- |
| 函数名称 | 查询储能簇历史采样 SOC |
| 业务说明 | 获取指定簇、指定时刻对应的5分钟采样SOC |
| 输入 | 储能簇 ID：文本；查询时刻：时间 |
| 函数主体 | 从“历史遥测数据源”查询该簇采样记录。本例约定将查询时刻向下取整到5分钟边界，再查该采样点；缺失或重复记录返回错误，不以实时值替代 |
| 输出 | 采样 SOC；数值；0～100百分数口径 |

“向下取整”只是本示例明确选定的查询规则，需按业务确认；也可以采用精确匹配或最近点查询，但必须明确，不能由实施人员随意推断。

## 7. 设备实时 SOC：完整编排示例

先定义三个可复用函数：

| 函数 | 输入 | 主体 | 输出 |
| --- | --- | --- | --- |
| 计算储能簇剩余电量 | 簇 ID | 读取簇额定能量 × 调用簇实时SOC函数 ÷ 100 | 数值，kWh |
| 计算储能设备剩余电量 | 设备 ID | 沿设备与簇的归属关系取得下属簇，逐个调用簇剩余电量函数后求和 | 数值，kWh |
| 计算储能设备实时 SOC | 设备 ID | 调用设备剩余电量函数 ÷ 读取设备额定能量 × 100 | 数值，百分数口径 |

本例前提写入函数主体，不另设“成员范围”“异常处理”等独立必填页面：

- 额定能量统一为 kWh，SOC统一为0～100。
- 成员按明确的归属关系获取，每个簇只计一次；找不到成员时返回错误。
- 依赖函数失败或分母缺失、为0时，停止计算并返回原因，不填0、不忽略失败成员。
- 设备额定能量作为本例分母；是否应与下属簇额定能量之和一致，需业务确认。
- 本例读取最新值，不保证多个簇的采样时间一致；需要时间对齐时必须补充取样规则。

示例数据：两个簇额定能量分别100、200 kWh，SOC分别50、80；设备额定能量300 kWh。

- 簇剩余电量：50、160 kWh。
- 设备剩余电量：210 kWh。
- 设备 SOC：210 ÷ 300 × 100 = 70。

禁止函数直接或间接调用自身形成循环。嵌套调用不代表可以重复定义相同规则；能复用的函数应引用已有定义。

## 8. 属性如何关联函数

仅建立函数还不够：需要说明哪个属性由该函数提供，以及参数如何取得。

| 对象类型 | 属性 | 提供值的函数 | 参数绑定 |
| --- | --- | --- | --- |
| 储能簇 | 实时 SOC | 查询储能簇实时 SOC | 簇 ID ← 当前簇实例 ID |
| 储能簇 | 剩余电量 | 计算储能簇剩余电量 | 簇 ID ← 当前簇实例 ID |
| 储能设备 | 剩余电量 | 计算储能设备剩余电量 | 设备 ID ← 当前设备实例 ID |
| 储能设备 | 实时 SOC | 计算储能设备实时 SOC | 设备 ID ← 当前设备实例 ID |

历史采样SOC还有“查询时刻”输入，需要由查询页面或调用者提供，不能只凭当前对象ID得到唯一结果。应按带时间参数的查询调用，不默认当作无参数的实时属性。

额定能量等直接映射属性不必额外创建函数；公式主体可以引用这些已映射属性。

## 9. 业务专家与开发／实施的职责

| 内容 | 业务专家 | 开发／实施 |
| --- | --- | --- |
| 名称、业务说明 | 定义用途 | 协助消除歧义 |
| 输入、输出 | 确认业务含义、单位和时间口径 | 参数标识、技术类型及转换 |
| 函数主体 | 写查询规则、公式、调用步骤 | 实现查询、计算、编排与错误返回 |
| 属性关联函数 | 确认哪个属性由哪个函数提供 | 配置参数绑定与调用接口 |
| 数据源 | 确认数据含义和来源 | 配置连接、真实表字段、Key模板及凭据 |

项目配置边界：

- 函数引用逻辑数据源名称，例如“实时遥测 Redis”。
- Redis地址、端口、数据库和密钥属于项目连接配置，不写进函数主体或本体文件。
- Key模板、表名、字段名若随项目变化，由项目映射配置；函数描述中可以提供示例。
- 本文不新增或规定现有配置文件尚未支持的具体字段名，后续实现时同步确定文件结构。

## 属性与函数的简化关联入口

在属性管理的“对象属性”中选中属性，设置“值的来源”。数据映射可跳转到该对象的项目映射；函数计算需选择已有函数，并用一句话说明输入从哪里取得。共享属性的取值方式在各对象属性上独立配置。函数详情中可展开“使用此函数的属性”并跳回属性。

关联保存为对象属性的 valueSource，包含 kind、functionId、arguments；不会写入共享属性。选择函数仅建立定义关联，当前不自动执行查询、替代项目映射或写入实例值。
