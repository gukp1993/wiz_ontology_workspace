# 需求说明 — 模型设置简化改版（model_setting 需求变更）

- 版本：v1（2026-09-25，zcode 交付；同日用户审核原型并确认，原型升 v1.1）
- 关联：`交互原型_v1.html`（内容为 v1.1，已含审核修正：移除「查看文档」入口）、`开发计划.md`、`执行指令.md`（同目录）
- 变更对象：**model_setting worktree**（分支 `model_setting`，HEAD cdb5939）正在实施的《文档/v1/需求/20260922_模型供应商与模型管理改版》（交互 v4，已实施、未验收、未合并 main）。本需求**替代**其页面交互设计；v4 域层资产（内置目录、存储两表、端点）尽量复用。
- 状态：需求已确认，待开发指令。不得据此声称工作台已实现。

## 1. 背景与变更缘由

用户 2026-09-25 对 model_setting worktree 提出需求变更（附参考截图）：

1. 添加模型改为**单弹窗**：选供应商（预设目录 + 自定义）→ 输入 API Key（可测试连接）→ 选模型；自定义供应商手填接口地址与模型参数名；**不含高级配置**。
2. 设置页列表**只保留模型列表**：字段 = 模型名称、供应商、操作（测试连通、编辑、删除）。

v4 的「供应商 × 模型」两级管理界面（可用模型/供应商双 Tab、模板选择向导、供应商编辑弹窗）按此收敛为单层模型列表。交互原型经用户审核：「查看文档」入口删除，其余（含默认模型建议方案）确认。

## 2. 已确认需求（R 系列）

### R1 单层模型列表

- 入口不变：设置中心 → 基础设置 → 模型设置。页面主体为一张模型列表，**三列**：
  - **模型名称**（默认模型带「默认」徽标）
  - **供应商**（目录预设名，或「自定义」）
  - **操作**：测试连通 / 编辑 / 删除
- 不再有：供应商独立管理界面、启停列/开关、思考档位、超时/温度、「查看文档」链接。
- 行内「测试连通」：用**已存配置**发起最小真实探测（服务端不持全局锁），行内瞬时反馈成功（含耗时）/失败（错误摘要），不改页面数据。
- 删除：确认弹窗，文案含「正在引用它的节点配置检查会报错」；该供应商下**最后一个模型**删除后，其接入信息（含密钥）一并移除并提示；删除默认模型后默认置空（见 R4）。
- 空态文案：「还没有模型条目。点『＋ 添加模型』选择供应商并填写 API Key 后，函数编排的 Python / LLM 计算节点即可使用。」

### R2 添加模型弹窗（单弹窗）

- **供应商（仅支持 OpenAI 兼容协议 API）**：下拉带搜索框；选项 = 内置目录中 `openai-chat-completions` 协议模板 + 「其他」分组下的「自定义」；选中项带 ✓；已有密钥的供应商标「已存密钥」。展示顺序：智谱开放平台、Kimi（月之暗面）、MiniMax、深度求索、腾讯混元置顶，其余目录 openai 兼容模板随后（腾讯混元为本版新增目录条目）。
- **API Key**：密文输入 + 可见性切换（眼睛）；右侧「测试连接」按钮，用**当前临时填写**的配置探测、不落盘；供应商已有密钥时可留空（占位提示「留空即可沿用」）。
- **模型名称**：
  - 预设供应商 = 内置目录模型清单**下拉**（必选）。
  - 自定义 = **手填**模型参数值（如 `gpt-4o`、`openai/gpt-4o`），并手填**接口地址**（https URL，OpenAI 兼容 chat/completions）。
- **明确不含**（用户确认去除）：高级配置（工具调用/图片输入/思考模式/自定义协议）、输入/输出计价字段、「Auto」模型选项、「查看文档」链接。
- 校验：供应商必选；预设必选模型；自定义必填接口地址（https）与模型名；该供应商无已存密钥时 Key 必填。

### R3 编辑模型弹窗

- 与添加同弹窗预填；API Key 不回显，留空 = 沿用已保存密钥。
- 可更换供应商（换预设目录或自定义）：目标已有密钥可留空沿用，目标无密钥则必填新 Key。
- 含「设为默认模型」开关（R4）。

### R4 默认模型（机制沿用主干，交互经原型确认）

- 语义沿用主干：未明确指定模型的节点与本体构建使用默认模型。
- 交互：编辑弹窗「设为默认」开关 + 列表「默认」徽标 + 列表上方默认条（显示当前默认模型与供应商，不占表格列）。
- 默认**不再携带思考档位**；既有数据中的档位字段保留但不再展示、不修改。
- 删除默认模型 → 默认置空，默认条提示「未设置默认模型」及警告说明，**不自动改指**其他模型；引用该默认的节点按既有校验提示。

### R5 供应商目录（复用 v4 内置目录）

- 目录 = 仓库内置 `workbench/llm_catalog.json`（随版本分发）；弹窗仅展示 `apiType=openai-chat-completions` 模板 + 自定义模板；Anthropic 兼容等其余模板数据保留、不在弹窗展示。
- 本版**新增目录条目**：腾讯混元（openai 兼容；baseUrl/模型清单实施时按官方文档核对录入）。
- 目录内容（baseUrl、模型清单、名称）以实施时核对为准，原型中的条目为示意。
- Key 挂**供应商级**：同一供应商添加多个模型时，第二个起 Key 留空沿用；覆盖 Key 即更新该供应商密钥。「自定义」每条模型独立一套接入信息（接口地址 + Key），互不影响。
- 同一预设模板存在多个存量供应商时，添加模型复用第一个，不做合并迁移。

### R6 密钥与安全（沿用，不变）

- AES-256-GCM + AAD + 库外根密钥；**只写不读回**（接口只有 `keyConfigured` 标志）；测试连接/测试连通为真实网络探测、不持全局锁；密钥绝不进响应、日志与快照。

### R7 v4 范围收缩清单

- **废弃（UI 层）**：可用模型/供应商双 Tab、供应商模板选择页（两列向导）、供应商编辑弹窗、供应商与模型启停开关、思考档位选择、超时/温度 UI、从 /v1/models 拉取模型的入口、「查看文档」链接。
- **保留（域层，兼容不动）**：`wb_llm_providers`/`wb_llm_models` 两表与迁移 20260923_0006、`llm_catalog` 目录、现有 9 个 LLM 端点（见开发计划 §2）、消费端引用稳定 id 机制。

## 3. 数据与兼容约束

1. 接口契约流程不变：先改 `文档/接口文档/04-编排与LLM接口.md`（+05 速查、README 变更记录），再改代码，文档与代码同 commit。本轮目标形态为**零端点变更**（前端编排复用现有端点）；若实施核对后必须调整（如删除级联参数），按流程登记后再改。
2. 存储层**不做新迁移**（分支已含 0006）；`wb_model_configs` 旧表兼容策略维持 v4 冻结口径。
3. 存量映射：现有模型配置在新列表中每条一行，供应商列显示所属供应商名；非目录预设的存量供应商显示其名称，可经编辑改选目录预设。
4. 启停过滤语义变化：列表与消费端选择器**不再按 enabled 过滤**（字段保留；存量禁用数据升级后直接可见可用）。
5. 按账号（owner_user_id）完全隔离不变；跨账号按不存在处理。

## 4. 验收标准

1. 设置页仅单层模型列表（三列 + 操作），与原型 v1.1 一致；无供应商 Tab/模板选择页/供应商编辑弹窗。
2. 添加模型（预设）：选供应商 → 填 Key → 选模型 → 保存；列表新增「模型名 / 供应商名」行；密钥只写不读回（响应与日志无密钥）。
3. 添加模型（自定义）：接口地址 https 校验生效；模型名手填；保存后供应商列显示「自定义」。
4. 同供应商第二个模型：Key 留空可保存且沿用原密钥；覆盖 Key 后新密钥生效。
5. 弹窗「测试连接」用临时配置探测且不落盘；行内「测试连通」用已存配置；均真实探测、不持全局锁，失败展示不含密钥的错误摘要。
6. 编辑：换供应商、改模型名、覆盖 Key 均生效；「设为默认」全列表唯一，徽标与默认条同步；删除默认行后默认条显示未设置 + 警告。
7. 删除供应商下最后一个模型：接入信息一并移除（再添加同模板需重新填 Key）。
8. 消费端（编排节点、本体构建范围页）模型选择正常、旧引用不悬空、默认回退提示与单层语义一致。
9. 门禁：`python3 tests/run.py` 相关组全过；`npm run typecheck`/`lint`/`build` 通过；接口文档（04/05/README 变更记录）与实现、`server.py` 白名单一致。
10. 浏览器走查覆盖开发计划 §5 清单（隔离实例 + 测试账号）。

## 5. 非目标

- 高级配置（工具调用/图片输入/思考模式/自定义协议）、输入/输出计价、「Auto」选项、「查看文档」链接。
- 从 /v1/models 拉取模型列表的 UI（端点保留，不在弹窗暴露）。
- 供应商启停、思考档位、超时/温度的 UI 配置（域层字段保留，用契约默认值）。
- Anthropic 兼容模板的下拉展示、多模态能力、OAuth 账号体系、目录在线同步、存量同模板供应商合并工具。
