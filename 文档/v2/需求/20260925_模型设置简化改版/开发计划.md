## §1 总体方案

**存储与域层基本不动，前端单层化。**

1. 保留 v4 已建的 `wb_llm_providers` / `wb_llm_models` 两表、迁移 20260923_0006、`llm_catalog` 内置目录与 9 个端点；密钥 AAD（provider_id 绑定）零重加密。
2. 「供应商」从独立管理对象降级为模型条目的归属属性：列表 = 模型条目（join 供应商名）；添加模型 = 前端按 `templateId` **find-or-create** 供应商（复用 `POST /api/llm-provider-save`）→ 挂模型（`POST /api/llm-model-save`）；自定义 = 每条模型一个独立供应商实体（customTemplate）。
3. 设置页重写为单层列表 + 添加/编辑弹窗（原型 v1.1）；废弃双 Tab、模板选择向导、供应商编辑弹窗及其专用前端模块。
4. 消费端（编排节点、构建范围页）数据源不变（同 9 端点），仅按新语义微调（无启停过滤、默认无档位的提示文案）。

## §2 现状接口与目标形态（T1 冻结前的输入基线）

分支现有端点（`workbench/server.py` 白名单 + `flow_routes.py`）：

- `GET /api/llm-catalog`（目录）、`GET /api/llm-providers`（供应商视图 `{id,name,templateId,apiType,baseUrl,enabled,keyConfigured,…}` + 内嵌 models）
- `POST /api/llm-provider-save|delete|default|test`、`POST /api/llm-model-save|delete`、`POST /api/llm-models-fetch`

目标形态（推荐，T1 核对后冻结）：

1. **GET 侧零变更**：扁平模型列表由前端从 `GET /api/llm-providers` 派生（每 model 一行 + 所属供应商字段）。
2. **添加（预设）**：在 GET 响应中按 `templateId` 找既有供应商 → 有则复用（Key 留空沿用；填了 Key 则先 `provider-save` 更新）→ `model-save`；无则先 `provider-save`（模板预填）→ `model-save`。部分失败沿用 v4 草稿重试语义的简化版（供应商已建、模型未存时提示重试且不重复建供应商）。
3. **添加（自定义）**：`provider-save`（customTemplate，baseUrl）→ `model-save`；每条独立。
4. **默认**：`provider-default` 只下发 `{providerId, modelId}`（不带 reasoningLevel）；已有默认数据中的档位保留不展示。
5. **删除末模型清供应商**：优先前端编排（`model-delete` 后该供应商 models 为空则追加 `provider-delete`）；若 T1 核对认为需原子性，则冻结为 `llm-model-delete` 增加可选级联参数（走接口文档变更流程）。删除默认行后默认读为未设置 + 警告（核对现有悬空默认的读法，必要时在视图层兜底）。
6. **启停过滤移除**：列表与消费端不再按 `enabled` 过滤；字段保留不写入。
7. **测试**：弹窗 = `provider-test` 临时形态（模板/baseUrl/Key 不落盘）；行内 = `provider-test` 已存形态（按 providerId）；均不持全局锁。

## §5 浏览器走查清单（隔离实例 + 测试账号，T6 执行）

1. 列表三列渲染：模型名称（含默认徽标）/供应商/操作；默认条显示当前默认。
2. 添加模型（预设）：目录下拉搜索与 ✓ 选中；选 Key 未配置的供应商时 Key 必填校验。
3. 添加模型（自定义）：接口地址 https 校验、模型名手填；保存后供应商列显示「自定义」。
4. 同供应商第二个模型：Key 留空保存成功（占位提示「留空即可沿用」）；覆盖 Key 生效。
5. 弹窗「测试连接」：临时配置成功/失败两态；失败摘要不含密钥。
6. 行内「测试连通」：已存配置两态；瞬时反馈自动消失。
7. 编辑：换供应商（含换到已有密钥供应商留空沿用）、改模型名、覆盖 Key。
8. 设为默认：唯一默认、徽标与默认条同步；删除默认行后默认条「未设置默认模型」+ 警告。
9. 编排节点模型选择：级联正常、无启停过滤、默认提示为单层口径；旧节点（仅 providerId）不报错。
