## 2. 让当前会话立即执行交接规范

不论是否支持 Hook，都执行以下流程：

- 接到新任务，先 read --actor zcode，读取当前需求和版本。
- 每次实际开始实施及验收前重新核对上下文；同轮可用 --ticket <原ticket> 重读。
- 接手时或阶段结束写 in_progress；完成后写 implemented，列出真实测试与未测项。只有相应验证真的通过才写 verified。
- 用户改变需求时记录新的决定，不自动把正在执行的旧版改成新版本；存在冲突时明确提出。
- 最终回复前用 record 完成本轮交接。纯问答没有新决定用 no_change，不填造假的完成项。
- 已有其他工作的修改仍由原任务负责，本次不清理、不覆盖、不夹带提交。

命令格式（替换真实 ticket 和内容后执行）：

```bash
python3 .collaboration/context.py record <<'JSON'
{
  "ticket": "替换为本轮read返回的ticket",

JSON
```

## 3. 核实自动触发能力再接入

检查 zcode 当前版本、设置入口及真实文档，确定是否提供“收到用户消息前”“每轮回复完成前/后”事件，以及如何注入上下文、提醒继续工作、重载配置。

**支持兼容事件时：**

- 只设置本项目规则或 Hook，保留已有配置。
- 轮次开始调用 read，把摘要与 ticket 传给当前 AI；不能只是打印到用户通知区，AI 却读不到。
- 结束前核对本轮是否 record；漏写时最多提醒补写一次，第二次显示失败，不无限循环。
- 可复用 `context.py hook --actor zcode`，但须核实事件 payload 与输出协议兼容；否则写薄适配器转换字段及返回值，不更改共用存储格式。
- Codex 的 .codex/hooks.json 是参考，不代表 zcode 支持同名文件、Stop 事件或 decision:block；禁止凭空造配置后声称生效。
- 如存在工具自身信任确认，说明准确入口，让用户完成；不得绕过或伪造信任。

**没有对应事件或不能热重载时：**

- 将第 2 节写入 zcode 确实会读取的项目规则文件，注明来源为 AGENTS.md，避免维护冲突版本。
- 当前会话立即按命令执行；交付标注“规则驱动的主动交接，未接入自动 Hook”，不要声称后台已全自动。
- 不为补上自动化而监听完整聊天目录、运行无人看管的轮询或调用外部模型。
