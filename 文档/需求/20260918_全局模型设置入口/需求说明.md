# 全局设置中心、用户菜单与模型设置

版本 v2 · 2026-09-18 · 本次只交付方案，未修改工作台代码。

配套：[交互原型](交互原型_v1.html) · [开发计划](开发计划.md) · [执行指令](执行指令.md)。

## 1. 产品决定

“LLM 配置/LLM 设置”统一更名为 **模型设置**，属于当前工作台部署的全局配置。所有本体、项目及函数编排共享同一份可用模型配置；“全局”不是跨机器、跨部署或多租户账户的承诺。

入口调整为**左下角固定用户区：头像、用户名、齿轮**。悬停或键盘聚焦齿轮显示“设置”，点击进入独立的全局设置中心；点击头像/用户名弹出用户菜单。设置中心拥有自己的分类导航，本期先提供“模型设置”，后续其他设置作为同级分类接入。

本版根据用户新截图替代 v1“直接显示模型设置、保留业务Tab”的方案。沿用四份文件及原型文件名，当前四件套内容以 v2 为准。

- 在本体区、项目区、函数编排页面均可访问；尊重当前侧栏手动收起偏好，不自动切换收起状态。
- 未创建/未选择本体、未选择项目时可访问。
- 从本体的“更多工具”删除该入口，不删除模型配置本身，不移动其他工具。
- 本期只更改设置页面、入口及相应提示的产品名称；技术概念“LLM 推演”和内部 providerId/API 名称保留，不做全仓词语替换。

## 2. 当前实现依据

| 代码事实 | 需要解决的问题 |
|---|---|
| `tools/ToolsPage.vue` 将 llm 放在更多工具卡片中 | 全局能力被埋在本体辅助工具里 |
| `app/navigation.ts` 把非 projectSpaceViews 默认归为 ontology | 点击旧 llm 跳转会切换工作区语义 |
| `App.vue` 的 navigate/initialSpace/工作区 watcher、lastOntologyView 使用两区兜底 | 只移动菜单会继续出现回跳本体、污染上次本体页的问题 |
| 模型设置组件位于本体加载成功后的主内容分支 | 本体加载慢或失败时，独立的模型设置也被挡住 |
| activeSaver/撤销/发布提示按 flow 或 space 路由 | 模型设置容易显示无关的本体保存状态、撤销操作 |
| `llm_providers.py` 是部署级配置，路径为 DATA_ROOT 下的 ontology/vault/llm-providers | 路径里有 ontology 不代表属于某个 ontologyId；不需要迁移密钥或修改存储路径 |
| 当前元数据返回 endpoint/model/timeout/temperature，API Key 不回传 | 页面“密钥与接口地址都不回显”的旧提示不准确，要修正文案 |

基于当前代码审阅；本轮没有操作真实配置或执行模型连通测试。仓库中函数编排页面正在发生其他修改，后续实施需整合最新代码，不按旧快照覆盖。

## 3. 页面与入口交互

### 3.1 左下用户区与齿轮

```text
业务侧栏                          设置中心侧栏（替换业务侧栏）
本体工作台                        ← 返回工作区
[本体] [项目]                    全局设置
本体/项目选择器                   基础设置
业务菜单（独立滚动）              ▣ 模型设置
                                 （后续设置按需增加）
────────────────               ────────────────
[头像] 用户名          [齿轮]      [头像] 用户名        [齿轮]
```

- 用户区固定在侧栏底部，不随业务或设置分类列表滚走。头像+用户名组成同一个触发按钮，齿轮是独立按钮；点击齿轮不能同时弹用户菜单。
- 齿轮使用现有 SVG 图标规范；可点击区域至少 36×36 px。hover、focus 显示 tooltip“设置”；屏幕阅读器名称也是“设置”。不只依赖原生 title，移动端直接点击进入。
- 正常侧栏显示头像及用户名；长名称省略并可查看完整名。折叠侧栏保留头像和齿轮两个独立入口，用户名在头像 tooltip 中显示；不强制展开业务侧栏。小屏使用原导航抽屉，弹出菜单不得超出视口。
- 显示身份必须来自现有身份信息。当前代码未发现应用登录/个人账户 API，仅有数据库连接用户名；**数据库用户名不能当登录用户**。无身份信息时显示“本地用户”，默认头像为文字/通用头像。原型的“演示用户”不是实际账号。
- 本期不读取操作系统账号、不推断截图中的真实身份，不为展示用户名额外实现认证系统。

### 3.2 独立全局设置中心

- 点击齿轮进入全局设置中心，默认选中“模型设置”；将来有其他真实设置时，可记住最近有效分类，未实现分类不显示。
- 左侧整块切换为设置专用导航：顶部“返回工作区”，下方“全局设置”、分类分组与条目，底部仍保留用户区。**不再展示本体/项目Tab、资产选择器和业务菜单**。保留业务状态只是为了返回，不代表当前设置属于业务区。
- 首期分类为“基础设置 → 模型设置”。常规、外观、浏览器控制等截图条目仅作结构参考，不造空白页面或灰色的“敬请期待”。
- 右侧标题为当前设置分类“模型设置”，附全局范围说明。沿用模型配置列表与表单，不照搬订阅套餐、额度、厂商市场或“供应商下多个模型”的新数据结构。
- 设置专用侧栏建议 220–240 px，独立滚动；内容区域自适应。桌面进入设置时使用完整设置分类导航，不继承业务侧栏缩成64px而导致分类不可读；返回时恢复业务侧栏原收起偏好。窄屏设置导航使用抽屉。
- `space` 可保留上次业务空间供返回；通过独立 `globalViews` / `isGlobalView` 判定设置模式，不增加第三种业务资产Tab。
- 不显示本体/项目版本、发布、业务撤销重做及其保存状态。设置表单独立保存，不进入业务 Saver。
- 模型列表独立读取：加载中、失败重试、空态、新增。不因本体或项目读取失败而阻断。

### 3.2.1 用户弹出菜单

点击头像/用户名，在触发按钮上方弹出菜单，默认左对齐，宽约 280 px；空间不足时自动翻转/贴合视口。用户区与菜单不是两个账户来源。

```text
[头像] 本地用户
       当前工作台
────────────────────
[齿轮] 设置                 →
[退出] 退出登录
────────────────────
菜单外部点击或 Esc 关闭
```

头部展示用户名/头像及有依据的身份说明，本期头部是展示区，不暗示可编辑资料。菜单中的“设置”和旁边齿轮进入同一个设置中心，先关闭菜单再导航。已在设置中打开此菜单时，“设置”只关闭菜单并保持当前分类，不能覆盖最初的返回来源。

用户已确认菜单内容固定为：**用户信息展示 + 设置 + 退出登录**。不增加个人资料编辑、会员/额度、宠物、邀请好友、语音等条目。

**退出登录的状态与行为：**

- 菜单必须保留“退出登录”选项。有真实登录态时启用；当前项目没有应用账户API时使用“本地用户”展示，退出项显示“未登录”并禁用，提供可见说明“当前为本地模式，无登录会话”。不能靠假登录标志将它启用。
- 真实登录态下点击退出，先沿用所有相关编辑区域的未保存修改保护，再确认退出；确认调用认证服务的退出接口，成功后清理认证会话与账号相关的内存状态，进入已有登录页。不得删除本体/项目数据、vault、全部localStorage或全局模型配置。
- 退出失败留在原页面并显示可重试原因，不能展示已退出；取消不改会话与编辑状态。编辑器正在保存/有冲突时，按现有保护完成或明确处理，不能在未确认情况下丢掉输入。
- 当前未发现认证服务/登录页，**本期不顺带建立账户系统**。执行者核对若仍未接入认证，应如实交付本地模式的禁用态，在实施记录标明真实退出依赖；后续接入真实会话后启用相同菜单项。不要把这个依赖当成删除菜单项的理由。
- 原型用明确标识的演示会话展示“确认退出→已退出演示会话”；这是交互演示，不是已实现认证。额外提供本地模式场景供验收禁用态，不作为正式产品用户菜单条目。

交互要求：

- 二次点击触发器、点击外部、Esc关闭；点击菜单内部不提前关闭。
- Enter/Space打开，初始焦点到第一项；方向键在可操作项移动。Tab离开菜单时关闭但不抢回焦点；Esc返回头像按钮焦点。
- `aria-expanded`、`aria-controls`、`aria-haspopup="menu"` 与实际状态同步；tooltip与菜单分层，菜单不被侧栏overflow裁切。
- 只打开用户菜单不导航、不保存、不触发业务离开保护；真正进入设置才按原流程检查未保存内容。
- 切换页面/工作区时自动关闭菜单，不残留遮挡；关闭菜单不能清除编辑内容。

### 3.3 回到来源页面

| 进入方式 | 返回文案与行为 |
|---|---|
| 从本体页进入 | 返回原本体页面，保持所选对象与页签 |
| 从项目页进入 | 返回原项目页面，保持项目及编辑位置 |
| 从编排节点“前往模型设置”进入 | 返回编排，恢复编排 ID、节点、详情页签与画布视口 |
| 直接打开模型设置地址/新开页面 | 无可靠来源时显示“返回工作区”，回到最近有效工作区概览，不伪造上次节点 |

进入前沿用现有离开保护和保存流程：未提交表单不能默默丢失、保存失败不能假称成功。无需用户多点一次“保存草稿”。对于打开设置又返回的操作，优先保留原编辑组件或显式缓存最小 UI 状态；不能只恢复 hash 就声称恢复编辑现场。

模型保存成功后**留在设置页**，用户可继续配置或点击返回。回到编排时刷新可用模型列表；保留节点原有 providerId/“使用默认”，不自动给节点绑定新建配置。刷新失败与没有模型分开显示；配置改变后原检查结论标待重检，不自动执行节点。

返回缓存只包含页面/资产/节点/页签/视口标识，不持久化 API Key、模型设置表单或运行输入。浏览器刷新只保证设置路由可恢复，不承诺恢复内存里的未提交表单。

### 3.4 地址兼容

设置中心入口 `#settings`，本期默认归一到分类地址 `#settings-models`；旧 `#llm` 及旧内部 `navigate('llm')` 直达模型分类，保留兼容。后续分类使用独立的 settings-* 地址及统一注册表，避免每加一项重做侧栏。已在设置内点击齿轮/菜单设置保持当前分类。仅进入 settings 入口时采用最近有效分类或默认模型分类；业务节点“前往模型设置”始终定向模型分类。

首次深链、内部导航、hashchange、浏览器前进后退、返回工作区都要覆盖全局页判断。全局页不得写入 lastOntologyView，不能被工作区 watcher 自动改成 o-home/p-home。不要因此重写整个应用路由或引入路由框架。

## 4. 模型设置页面

### 4.1 列表

复用现有配置和稳定 providerId。术语用“模型配置”，以避免“提供方”和“模型名称”混淆；一条配置对应现有的接口地址、模型标识与密钥组合，不新增厂商目录。

| 列 | 内容 |
|---|---|
| 配置名称 | 例如“通用推理模型” |
| 模型标识 | 接口实际使用的 model 参数 |
| 默认 | “全局默认”标签；节点明确指定其他配置时不受此标签影响 |
| 密钥状态 | 已配置/未配置，不回显原值 |
| 连通性 | 未测试、测试中、最近一次成功/失败；不是持续健康监控 |
| 操作 | 测试连通、编辑、更多→删除 |

页面主按钮“新增模型配置”。列表无配置显示同一新增入口和简短引导，不要求创建本体。测试为用户主动点击，可能请求外部模型服务，不能在打开页面、保存或返回时自动测试。

### 4.2 新增/编辑表单

| 字段 | 展示 | 规则 |
|---|---|---|
| 配置名称 | 必填，默认展示 | 对应现有 name |
| 接口地址 | 必填，默认展示 | 当前支持的兼容接口完整 URL；按后端已返回的 endpoint 回显 |
| 模型标识 | 必填，默认展示 | 对应现有 model，不凭空新增模型枚举 |
| API Key | 新增必填；编辑可留空 | 密文输入；编辑留空沿用原值，不提供查看原密钥 |
| 设为全局默认 | 默认展示 | 第一条默认行为沿用现有后端；修改默认不会改写节点显式引用 |
| 超时、温度 | 高级设置，默认折叠 | 保留当前字段、限制与默认值，不更改推理策略 |

按钮“取消 / 保存配置”。失败保持表单与错误原因，允许重试；关闭有未提交改动时走丢弃确认。保存成功不代表连通测试成功；配置修改后以前的连通性结果应标过期或清空。

设置全局默认时说明：“未指定模型配置的节点将使用此默认配置；不影响已明确指定的配置。”删除确认说明引用可能失效；保留后端已有默认兜底行为。如删除默认后会改用其他配置，应在删除摘要中说明，不能伪装成无影响。**本期不新增全局引用扫描/精确引用数量，也不改默认解析规则。**

接口地址可回显；密钥不回显。不要把不准确的旧说明搬到新页面，也不能把密钥存进 localStorage、原型、文档、草稿或发布快照。

## 7. 原型范围

原型展示本体/项目/编排、左下用户菜单和齿轮提示、独立设置分类侧栏、模型配置弹窗、返回编辑现场。用户身份、退出会话、模型、地址和结果均为虚构；不读取、不保存、不请求任何服务。正式实现必须复用现有 API 与权限/离开保护，不复制原型样例状态。
