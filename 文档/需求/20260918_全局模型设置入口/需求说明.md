# 全局模型设置入口与导航方案

版本 v1 · 2026-09-18 · 本次只交付方案，未修改工作台代码。

配套：[交互原型](交互原型_v1.html) · [开发计划](开发计划.md) · [执行指令](执行指令.md)。

## 1. 产品决定

“LLM 配置/LLM 设置”统一更名为 **模型设置**，属于当前工作台部署的全局配置。所有本体、项目及函数编排共享同一份可用模型配置；“全局”不是跨机器、跨部署或多租户账户的承诺。

入口放在**应用侧栏底部固定区域**，与上方本体/项目业务菜单用分隔线隔开。直接显示“模型设置”，点击一步进入；本期只有这一项，不新增空的“系统设置”首页，也不增加第三个业务 Tab。

- 在本体区、项目区、函数编排专注模式均可访问。
- 未创建/未选择本体、未选择项目时可访问。
- 从本体的“更多工具”删除该入口，不删除模型配置本身，不移动其他工具。
- 本期只更改设置页面、入口及相应提示的产品名称；技术概念“LLM 推演”和内部 providerId/API 名称保留，不做全仓词语替换。

## 2. 当前实现依据

| 代码事实 | 需要解决的问题 |
|---|---|
| `tools/ToolsPage.vue` 将 llm 放在更多工具卡片中 | 全局能力被埋在本体辅助工具里 |
| `app/navigation.ts` 把非 projectSpaceViews 默认归为 ontology | 点击旧 llm 跳转会切换工作区语义 |
| `App.vue` 的 navigate/initialSpace/工作区 watcher、lastOntologyView 使用两区兜底 | 只移动菜单会继续出现回跳本体、污染上次本体页的问题 |
| 模型设置组件位于本体加载成功后的主内容分支 | 本体加载慢或失败时，独立的模型设置也被挡住 |
| activeSaver/撤销/发布提示按 flow 或 space 路由 | 模型设置容易显示无关的本体保存状态、撤销操作 |
| `llm_providers.py` 是部署级配置，路径为 DATA_ROOT 下的 ontology/vault/llm-providers | 路径里有 ontology 不代表属于某个 ontologyId；不需要迁移密钥或修改存储路径 |
| 当前元数据返回 endpoint/model/timeout/temperature，API Key 不回传 | 页面“密钥与接口地址都不回显”的旧提示不准确，要修正文案 |

基于当前代码审阅；本轮没有操作真实配置或执行模型连通测试。仓库中函数编排页面正在发生其他修改，后续实施需整合最新代码，不按旧快照覆盖。

## 3. 页面与入口交互

### 3.1 侧栏

```text
本体工作台
[本体] [项目]
当前本体/项目选择器
业务菜单……（此区滚动）
─────────────────
模型设置              全局（固定，不随菜单滚走）
```

折叠侧栏显示设置图标，hover/键盘焦点显示“模型设置（全局）”，有 aria-label。不能在函数编排专注模式中隐藏。小屏以现有应用导航抽屉提供同一入口，不叠加一个遮挡画布的悬浮按钮。

### 3.2 进入模型设置后

- 页眉为“全局设置 / 模型设置”，范围提示：“供当前工作台的本体、项目与函数编排共用。”
- 全局入口高亮，业务菜单均不高亮。保留两个工作区切换按钮，用于回到相应业务区；设置页不把任一业务 Tab 表现为当前配置归属。
- 当前本体/项目选择器及业务菜单暂时替换为“全局配置”说明和“返回工作区”；不是清除已选本体/项目。
- `space` 可保留上次业务空间供返回；页面归属用独立 `globalViews` / `isGlobalView` 判定，不必给业务 space 强加第三种可编辑资产类型。
- 不展示本体/项目版本、校验发布、业务撤销重做或它们的“已保存”状态。设置表单按自己的保存反馈显示结果，不进入本体/项目/编排 Saver。
- 模型设置独立加载：列表加载中、加载失败可重试、空配置可新增。无需等待本体或项目的成功读取。应用服务整体不可用时仍如实展示请求错误。

### 3.3 回到来源页面

| 进入方式 | 返回文案与行为 |
|---|---|
| 从本体页进入 | 返回原本体页面，保持所选对象与页签 |
| 从项目页进入 | 返回原项目页面，保持项目及编辑位置 |
| 从编排节点“前往模型设置”进入 | 返回编排，恢复编排 ID、节点、详情页签与画布视口 |
| 直接打开模型设置地址/新开页面 | 无可靠来源时显示“返回工作区”，回到最近有效工作区概览，不伪造上次节点 |

进入前沿用现有离开保护和保存流程：未提交表单不能默默丢失、保存失败不能假称成功。无需用户多点一次“保存草稿”。对于打开设置又返回的操作，优先保留原编辑组件或显式缓存最小 UI 状态；不能只恢复 hash 就声称恢复编辑现场。

模型保存成功后**留在设置页**，用户可继续配置或点击返回。回到编排时刷新可用模型列表；保留节点原有 providerId/“使用默认”，不自动给节点绑定新建配置。刷新失败与没有模型分开显示；配置改变后原检查结论标待重检，不自动执行节点。

返回缓存只包含页面/资产/节点/页签/视口标识，不持久化 API Key、模型设置表单或运行输入。浏览器刷新只保证设置路由可恢复，不承诺恢复内存里的未提交表单。

### 3.4 地址兼容

建议规范 hash：`#settings-models`。旧 `#llm` 及旧内部 `navigate('llm')` 归一到此页；兼容期保留别名，旧链接不能失效或落回本体。已有项目使用其他规范地址可等价落实，但只能有一个规范入口。

首次深链、内部导航、hashchange、浏览器前进后退、业务区切换都要覆盖全局页判断。全局页不得写入 lastOntologyView，不能被工作区 watcher 自动改成 o-home/p-home。不要因此重写整个应用路由或引入路由框架。

## 4. 模型设置页面

### 4.1 列表

复用现有配置和稳定 providerId。术语用“模型配置”，以避免“提供方”和“模型名称”混淆；一条配置对应现有的接口地址、模型标识与密钥组合，不新增厂商目录。

| 列 | 内容 |
|---|---|
| 配置名称 | 例如“通用推理模型” |
| 模型标识 | 接口实际使用的 model 参数 |
| 默认 | “全局默认”标签；节点明确指定其他配置时不受此标签影响 |
| 密钥状态 | 已配置/未配置，不回显原值 |
| 连通性 | 未测试、测试中、最近一次成功/失败；不是持续健康监控 |
| 操作 | 测试连通、编辑、更多→删除 |

页面主按钮“新增模型配置”。列表无配置显示同一新增入口和简短引导，不要求创建本体。测试为用户主动点击，可能请求外部模型服务，不能在打开页面、保存或返回时自动测试。

### 4.2 新增/编辑表单

| 字段 | 展示 | 规则 |
|---|---|---|
| 配置名称 | 必填，默认展示 | 对应现有 name |
| 接口地址 | 必填，默认展示 | 当前支持的兼容接口完整 URL；按后端已返回的 endpoint 回显 |
| 模型标识 | 必填，默认展示 | 对应现有 model，不凭空新增模型枚举 |
| API Key | 新增必填；编辑可留空 | 密文输入；编辑留空沿用原值，不提供查看原密钥 |
| 设为全局默认 | 默认展示 | 第一条默认行为沿用现有后端；修改默认不会改写节点显式引用 |
| 超时、温度 | 高级设置，默认折叠 | 保留当前字段、限制与默认值，不更改推理策略 |

按钮“取消 / 保存配置”。失败保持表单与错误原因，允许重试；关闭有未提交改动时走丢弃确认。保存成功不代表连通测试成功；配置修改后以前的连通性结果应标过期或清空。

设置全局默认时说明：“未指定模型配置的节点将使用此默认配置；不影响已明确指定的配置。”删除确认说明引用可能失效；保留后端已有默认兜底行为。如删除默认后会改用其他配置，应在删除摘要中说明，不能伪装成无影响。**本期不新增全局引用扫描/精确引用数量，也不改默认解析规则。**

接口地址可回显；密钥不回显。不要把不准确的旧说明搬到新页面，也不能把密钥存进 localStorage、原型、文档、草稿或发布快照。

## 6. 验收标准

| 编号 | 检查点 |
|---|---|
| G01 | 本体、项目、编排专注模式均有全局入口；菜单很长时入口仍可见 |
| G02 | 无本体、无项目、本体加载失败时可加载模型设置；失败仅反映模型 API 自己的状态 |
| G03 | 进入后面包屑/高亮/保存反馈显示全局语义，无本体名称、版本或业务撤销发布 |
| G04 | 新旧 hash、内部跳转、前进后退正常，不回跳本体、不污染 lastOntologyView |
| G05 | 进入前离开保护有效；返回恢复当前对象/节点/页签/画布，无草稿丢失 |
| G06 | 保存留在设置页；返回后刷新模型元数据，稳定引用不变，不自动重绑或执行 |
| G07 | 列表四态与表单错误明确；高级项折叠；编辑 API Key 留空沿用，endpoint 正常回显 |
| G08 | 模型设置不写入任何本体/项目/编排修订；现有 vault 与 API 协议不迁移 |
| G09 | 删除/默认变更影响说明准确；连通测试只经主动点击，配置更新后旧测试不过度宣称有效 |
| G10 | 1280×800、1366×768、窄屏/折叠侧栏可操作；弹窗键盘与脏输入关闭保护有效 |
| G11 | 更多工具删除模型入口，其余功能保持；Python 推演语义不变 |
| G12 | 自动化用隔离数据和模拟网络，真实配置、密钥及外部模型无改动无调用 |

## 7. 原型范围

原型展示本体/项目/编排入口切换、固定全局入口、独立全局页、配置弹窗、返回编辑现场。模型、地址和结果均为虚构；不读取、不保存、不请求任何服务。正式实现必须复用现有 API 与权限/离开保护，不复制原型样例状态。
