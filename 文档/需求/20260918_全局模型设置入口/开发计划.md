## 2. 技术边界

- 保留 `space: ontology|project` 作为上次业务空间；增加全局视图判断即可。所有把“非项目”视为“本体”的判断逐一审阅，包括导航、加载门槛、保存状态、撤销键盘、离开保护。
- 模型设置不调用 ontologySaver/projectSaver/flowSaver 保存配置；但**进入设置前**仍需处理来源编辑器的在途保存与未提交表单。不能为了全局页无Saver而绕过离开保护。
- 来源记录存储在父级内存，包括原view、资产ID、选中ID/页签/视口。优先复用现有focus/状态缓存；若组件卸载导致丢失，应保活该编辑组件或恢复必要状态，不能全局KeepAlive所有页面。
- 返回后可用配置列表重新读取；如果元数据或默认项变了，相关编排检查待重检。不得自动改变节点providerId。
- 独立读取 `/api/llm-providers`；保存、删除、测试继续现有 `/api/llm-provider-*`。不改 stable id、不搬vault、不增加新后端数据结构。
- 修正“接口地址不回显”提示：代码现状 endpoint 会返回；只有 API Key 不回传。不要读取真实 vault 核对内容。
- UI 对外命名“模型设置/模型配置”，内部文件名 LlmProviders、providerId 可保留，避免无收益全仓重命名。
- 模型设置表单的脏状态纳入现有注册式guard，成功保存后撤销guard；失败留在表单。测试按钮不自动保存未提交表单；本期沿用对已保存配置测试的流程。

## 3. 验证计划

1. 导航纯函数测试：新旧hash归一、全局页不改lastOntologyView、不被space watcher覆盖；新开深链与返回无来源兜底。
2. 页面测试：从三个来源进入、空本体/项目、本体读取失败、全局状态栏正确。模拟迟到响应确保不污染返回页。
3. 返回编排：选定节点输入页，修改后进入设置，保存一条模拟配置，返回同节点同页签；检查原providerId不改，选项刷新；保存失败/未提交输入保护继续有效。
4. 配置表单：新增必填、编辑留空密钥、高级默认折叠、取消无写入、错误保留、默认变更说明、测试不自动触发。所有请求用替身，真实外部服务不调用。
5. `cd frontend && npm run build`。仅运行与改动相关的既有测试及上述定向测试，不因改入口重跑无关执行引擎套件。
6. 浏览器四种情况：1280×800、1366×768、折叠侧栏、窄屏抽屉。截图记录固定入口和返回流程；原型DOM测试不能替代正式布局验收。
7. 自动化服务使用 WIZ_WORKBENCH_ROOT 临时目录与独立端口。确认真实 ontology、vault 零修改；提交仅本次文件。
