复用现有结构，不为每个阶段创建空抽象类。边界图：

```text
客户端保存当前编辑内容 → 导出预览API → 一致性读取配置和依赖
                                            ↓
                                安全包生成 / 冻结预览token → 下载
上传分片 → 私有暂存 → 结构/版本/引用预检 → 命名预览
                                            ↓
                         短事务：新ID + 全部新配置 + 索引 + 成功回执
                                            ↓
                               新资产列表 + 持久化待补项
```

## 4. T1：配置读取、依赖收集与导出

1. 建一致性读取边界：SQLite需显式读事务取得同一快照（不能假定多个无事务SELECT一致）；未来方言收口在storage层，不改在线数据库类型。
2. 根选择 → 当前+全部发布 → 项目本体版本依赖 → 编排+连接/凭据声明/模型/附件。只向依赖方向遍历，不沿“被谁引用”无限带走其他项目。
3. 从存储payload读取完整配置，按payloadFormat做已有适配；保留未显示的扩展，不从列表summary重建数据。
4. 识别同flow在不同project上下文的连接冲突，建立可复制分组；能共享时只复制一次。额外flow的运行上下文显式选择，不查同名猜测。
5. 安全元数据导出：不读取或解密vault；已知敏感header/URL值剥离，出具定位，不在日志输出原值。
6. 打包前断言闭包齐全、附件白名单、文件预算、版本可解码；未完成配置与破损依赖区别处理。
7. 冻结包与清单，token绑定账号和hash/时间。压缩在读事务释放后、写锁之外进行；下载只读取冻结内容。
8. 导出API不写任何草稿、不更新版本、不测连接；前端先用现有保存流程处理当前编辑。

完成条件：导出fixture完整，未选项目不进入包；预览后修改来源不改变已生成包；受管理凭据在任何成员文件中都不存在。

## 5. T2：暂存、安全解析与命名预检

1. JSON有界分片：begin总大小/hash，chunk按索引与hash可重传；同一索引不同数据409，乱序正确组装，缺块不进预检。base64严格解析并限制解码前后大小。
2. 暂存身份由服务器随机生成，绑定当前账号；不接受客户端路径。对并发分片、超时取消、重启遗留设清理策略与磁盘配额。
3. ZIP只检查允许成员，不extractall；限制数量/压缩解压体积/嵌套深度，拒绝穿越/重复/特殊项。逐文件hash与manifest核对。
4. 校验格式和能力，未知业务字段零丢失；不支持的可执行/引用能力阻止，不能忽略继续。
5. 预检计算计划但不写资产；强依赖缺失列阻断，待补密钥/未完成业务项列提醒。
6. 当前账号同类名字与包内名字一起分配后缀；长度按真实创建上限处理。预览可手改，后端权威复验。
7. 预览输出用业务名+路径定位、只读版本摘要，客户端用文本渲染。新文件/重传/改选择使旧预览失效，晚回包不能覆盖当前。

完成条件：坏包、跨账号token、超限、取消都零业务资产；有效包可看到完整清单和命名。

## 6. T3：ID转换与单事务写入（核心）

1. 先构造包内稳定映射：资产ID、定义ID、来源ID、flow节点/参数/输出/字段、模型及附件；业务常量不变。跨版本相同定义共用映射。
2. 转换必须纯函数化，可测试输入不变；结构字段/定义键/顺序数组/布局/manifest/索引同步。不要通过json字符串replace改SQL和说明。
3. 预先完成CPU重校验，短写事务内核对名称并生成最终写集。创建所有资产容器，再写本体发布，再项目引用，再相关索引/元数据/回执（实际FK顺序核对后冻结）。
4. 新资产所有者取auth.require_user_id；每次新ID，不以来源ID执行ensure_asset复用旧行。内部ID碰撞需重分配或拒绝，绝不能落到旧资产。
5. 直接使用接收conn的Repository辅助，不循环调用workspaces.create/projects.create/flows.copy等自行提交的公共函数。所有待补声明和模型元数据也在同事务。
6. 复制的发布快照仍不可变；不用versions.publish重新生成版本。保持来源version标签与顺序，目标新hash/IDs及origin信息。
7. 幂等键同账号+operation+requestId，hash包含包hash和最终命名/选项。并发同键唯一性与事务回执保护；失败无成功回执，重试同键可重新尝试；已成功且token过期先返回回执。
8. 账号归属、名称并发、回执冲突需覆盖；不能用全局packageHash去重，否则违反再次主动导入。
9. 导入后重建索引，验证新project_refs指向本次新release，未清空字段映射；旧资产和发布快照hash完全不变。
10. 提供待补配置入口/接口，并确保重启后仍可补填API凭据而不改每个节点；不携带旧连通性/密钥配置标志。

完成条件：故障注入任一步均全回滚，重复主动导入两套独立副本，网络重试只有一套。

## 7. T4：前端整合

- 注册settings-transfer及数据管理分组，保持用户名设置入口和返回工作区行为；概览导出快捷入口只传预选上下文。
- 按原型做导出选择/冻结预览/下载、导入文件/检查/重命名/结果。不额外设计复杂迁移向导或覆盖策略。
- 复用app/http的JSON错误处理与postBlob；分片上传经过同一鉴权/401链，页面不得手写fetch。
- 各阶段区分loading/error/empty；错误带重试与返回，不用空列表冒充成功。
- 点击确认生成requestId，至明确结果前不换；超时提示“结果待确认”，查询回执/同ID重试；“再次导入此文件”才新建ID。
- 原型模拟与实际实现分开：正式版解析上传ZIP并调用真实API，不使用演示清单冒充用户文件；不把原型按钮“模拟写入失败”带进产品。
- 结果跳转传新ID，不能按名字选择；切到新资产前遵循保存离开流程，不覆盖当前未保存表单。
- 预览多行列表局部滚动，名称可键盘编辑，1040左右窄屏可横向滚动表格而非遮住确认区；精确验收按M23。

完成条件：目标账号能从结果打开新本体/项目、编辑保存并继续校验，旧内容保持不动。
