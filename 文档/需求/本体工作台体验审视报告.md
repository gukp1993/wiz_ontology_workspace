# 本体工作台 · 需求与体验审视报告

> 评估范围：本体区主界面（工作概览、对象建模工作区、本体校验与发布、"更多工具"聚合页）
> 评估视角：需求与用户体验（信息架构、功能布局、操作路径、信息优先级、视觉层次、认知负荷）
> 立场：不评估技术实现，只评估"用户能不能更顺畅地完成任务"
> 日期：2026-09-20

---

## 0. 结论速览

本体工作台**安全网已成熟**（离开保护、引用检查、撤销、空态/中性态），基础体验不差，能完成核心任务。真正短板集中在四件事：

1. **入口分散**——属性创建的必经依赖（值类型）藏在二级工具页。
2. **编辑态与浏览态节奏断裂**——点编辑整页变全屏表单，钻入钻出上下文丢失。
3. **建模与校验割裂**——对象建模时看不到自己的问题，到最后校验页才批量爆发。
4. **专业概念暴露过早**——"复制/引用"等低频决策每次都让用户判断。

一句话：**能完成，但绕、且发现错误太晚。** 优化目标不是加功能，而是缩短主路径、提前暴露错误、降低认知负荷。

## 1. 评估对象与用户目标

### 1.1 核心界面

| 界面 | 角色 | 关键结构 |
|---|---|---|
| 工作概览（OntologyHome） | 本体总入口 | 版本/草稿状态、校验问题聚合、空态/中性态 |
| 对象建模工作区（ObjectWorkspace） | 主操作区 | 对象列表 + 详情 + 四页签（属性/链接/动作/规则）+ 本体图谱 |
| 本体校验与发布 | 收口环节 | 批量校验、发布 |
| "更多工具"聚合页（ToolsPage） | 附属能力 | 平铺 10 项（接口定义、本体浏览、画布、实例预览、历史图谱、值类型……） |

### 1.2 三类典型用户与目标

| 角色 | 核心目标 | 关键路径 |
|---|---|---|
| 建模新人（多数业务/建模人员，非开发者） | 从零搭本体 | 概览 → 创建对象 → 加属性 → 加链接 → 关联规则 → 发布 |
| 维护者 | 改属性 / 处理校验问题 | 对象建模改定义 / 概览看校验问题 → 去处理 |
| 浏览者 | 理解已有本体 | 概览 → 图谱/对象列表 → 查看定义 |

> 注意：储能领域的使用者多为业务/建模人员，**易用性门槛比纯开发者场景更高**，专业概念的暴露成本应被重点压低。

## 2. 系统性问题（现象 → 影响 → 优化方向）

### A. 信息架构：入口与心智模型错位

**A1 值类型管理沉到"更多工具"**
- 现象：属性必须引用值类型，但值类型不在本体区主菜单，建属性时要去二级工具页找。
- 影响：属性创建的**必经依赖**藏在深层，主路径被打断。
- 方向：把"值类型管理"提升到本体区主菜单，与对象/共享/规则/动作并列。

**A2 "更多工具"存在双入口与废弃入口**
- 现象：动作定义已并入主菜单，mapping 仍是"旧版映射入口"，同一能力两处可达。
- 影响：用户困惑"该从哪进"，且易点进废弃入口。
- 方向：收敛为每个功能的**唯一主入口**，废弃项明确标注或下线。

**A3 本体/项目两空间是隐性概念**
- 现象：首屏无"什么是本体 / 什么是项目"的引导，两空间靠左侧切换器区分。
- 影响：业务用户易在"我在哪、我在建什么"上迷路。
- 方向：首次进入给一次**非阻塞概念引导**，或在空间切换器旁加一行说明文字。

### B. 核心操作区：编辑态与浏览态节奏断裂

**B1 图谱入口隐蔽**
- 现象："对象列表 / 本体图谱"只是工具栏里一组小 tab，但图谱是全屏画布、列表是双栏编辑，两种范式差异巨大却视觉权重相同。
- 影响：新用户默认进列表，可能不知道有鸟瞰视图，错失建立全局认知的机会。
- 方向：把"本体图谱"作为本体区**主入口之一**（或给更显眼的"可视化查看"入口），让用户建立"列表=编辑、图谱=鸟瞰"的心智。

**B2 全屏表单替换打断双栏浏览**
- 现象：点"编辑属性"后整页变表单，保存再跳回双栏（当前靠 `restoreListScroll` 兜底）。
- 影响：从"左列表右详情"钻入全屏再钻出，**上下文断裂**，用户容易忘记自己刚在看哪条。
- 方向：属性/链接编辑改为**详情区内嵌子面板（就地展开/抽屉）**，仅"新建对象"等需独占焦点的场景用全屏。

**B3 库定义与对象关联跨页跳转**
- 现象：在对象内"添加规则"开弹窗，看规则正文又要跳回规则库。
- 影响：定义与引用分散在两页，来回成本高。
- 方向：对象页签内提供"查看/直达库中定义"的**一键入口**（现有"到业务规则维护"埋在抽屉里，应前置）。

### C. 信息优先级与视觉层次

**C1 详情头主次不清**
- 现象：对象名称 + 业务定义 + [收藏][编辑定义][更多操作] 挤一行，操作与内容平级。
- 影响：用户扫一眼抓不到重点，操作按钮喧宾夺主。
- 方向：明确分层——名称/定义为一级，操作收进**次级操作区或 hover 显示**；业务定义给足展示空间。

**C2 建模与校验割裂（高优先）**
- 现象：对象建模页看不到"当前对象有何问题"，只有最后去校验页才批量发现。
- 影响：**错误发现严重滞后、返工成本高**——这是当前最影响"顺畅完成任务"的短板。
- 方向：在对象详情提供**轻量"当前对象校验状态"**（复用已有校验能力，按对象粒度），让问题在建模当下可见。

**C3 长文本截断降低浏览效率**
- 现象：动作"业务效果"等用省略号截断，需逐行开抽屉。
- 影响：浏览者要在"列表 ↔ 抽屉"间反复跳转才能读懂。
- 方向：表格内提供**展开 / 悬浮增强**，减少"查看"跳转。

### D. 认知负荷：专业概念暴露过早

**D1 共享属性"复制/引用"二选一埋在添加弹窗（高优先）**
- 现象：每次添加共享属性都要判断"复制为私有 / 引用共享"。
- 影响：对低频用户是负担，且选错有后续维护成本。
- 方向：**默认推荐"引用共享"并附一句解释**，把"复制为私有"降级为进阶；在共享库页给决策引导。

**D2 链接/属性的专业语义缺语境**
- 现象：正向/反向名称、数量关系、时间序列等概念偏硬，无业务示例。
- 影响：业务用户填表时不确定"为什么要这样填"。
- 方向：补**业务示例与"为什么这样填"的提示**（现有 help 可强化）。

**D3 全局状态分散**
- 现象：保存成功/失败、草稿改动、校验过期散落在顶栏、详情提示、概览 pill。
- 影响：用户难以一眼判断"本体现在健不健康"。
- 方向：顶栏或概览给一个**"本体健康度"总览**。

### E. 连续性与反馈

**E1 校验页"去处理 →"直接扎进全屏表单**
- 现象：从校验上下文被打到编辑上下文，看不到"哪个对象、哪类问题"。
- 影响：处理问题时丢失来龙去脉。
- 方向：跳转**先定位到对象双栏浏览态并高亮问题行**，而非一竿子进全屏表单；或表单内标注"来自校验：xxx"。

**E2 列表选中与筛选联动有边界 case**
- 现象：`selectedHidden` 提示说明逻辑复杂（当前查看对象被筛选掉时的处理）。
- 影响：用户偶尔困惑"我正在看的东西去哪了"。
- 方向：简化"当前查看对象"与"列表筛选"的语义，使其更直观。

## 3. 优先级建议（影响 × 成本）

| 优先级 | 项 | 预期收益 |
|---|---|---|
| **Now（立即）** | C2 对象级轻量校验状态 | 错误在建模当下可见，直接降返工 |
| **Now（立即）** | B2 属性编辑内嵌化 | 消除钻入钻出断裂，缩短主路径 |
| **Now（立即）** | A1 值类型主菜单化 | 解除主路径上的深层依赖 |
| **Next（随后）** | B1 图谱入口显眼化 | 建立全局心智，降低迷路 |
| **Next（随后）** | D1 共享引用默认推荐 | 降低每次添加的决断负担 |
| **Next（随后）** | C1 详情头分层 | 提升扫描效率 |
| **Next（随后）** | E1 校验跳转改定位 | 处理问题保留上下文 |
| **Later（沉淀）** | A2/A3 入口收敛与概念引导 | 系统性整洁度 |
| **Later（沉淀）** | C3/D2 信息增强 | 降低认知负荷 |
| **Later（沉淀）** | D3 健康度总览 | 全局状态一屏可判 |

## 4. 可量化指标（用于验证优化效果）

1. **主路径步骤/耗时**：从"新建对象"到"首条属性创建"的步骤数与耗时（目标下降）。
2. **错误前置率**：建模期主动发现校验问题的比例（目标提升，而非等到发布前校验页）。
3. **误触/折返率**："更多工具 / 值类型"入口的误触与折返次数（目标下降）。
4. **连续任务完成率**：从创建到发布的端到端完成率与中断率。

---

## 5. 明确不应动的部分（既有优势）

以下能力已成熟，优化时**不可破坏**：
- 自动保存 / 离开保护 / 引用检查 / 撤销等安全网；
- 概览页的空态、中性态（无版本、仅草稿）处理；
- 校验能力本身（仅建议"按对象粒度前置展示"，不改动校验逻辑）。
