## 2. 必须实现的行为

- 输入框底部提供“模型”和“思考强度”两个选择器，支持键盘与窄屏；模型来自当前账号已保存且可发起请求的提供方脱敏列表，展示提供方名与模型 ID，不逐个探测、不回显密钥。初始模型取有效的自动填写用途配置，否则取账号默认；用途模型失效时提示重新选择，不静默回退。用户在面板改选只影响该面板的后续填表/检查/解释请求，不写用途设置或账号默认；同目标收起重开保留，切目标重置。
- 支持强度控制的模型初始为**低**；能力允许时提供关闭/低/高/最高/跟随模型设置。GLM-5.3-Flash 是强制思考，只能低/高/最高/跟随，不能显示关闭；DeepSeek V4.1 Flash 官方 API 模型 ID 为 `deepseek-flash`，可关闭或设低/高/最高。未知能力只显示跟随且说明不支持控制，不能假称低已生效。能力由后端按**端点与具体模型**共同判定，前端消费脱敏能力元数据；不能沿用只按 `bigmodel.cn` 域名判断“可关闭”。先核对智谱与 DeepSeek 官方文档及真实 API 对参数的响应。
- `POST /api/assist-generate` 接受本次模型与强度；后端以登录账号重新加载并授权 provider，明确校验强度，发送正确的提供方参数。旧客户端省略新字段继续按旧用途配置。选了其他有效模型时，旧 `assist-context.modelReady=false` 不得阻断新客户端生成；仍保留上下文令牌的账号、目标、草稿、契约校验及 409。跨账号/删除的 provider 和不支持的强度返回明确错误，不静默回退。响应 `meta` 报实际 provider/model/请求强度和原有模型/总耗时，不泄露密钥、提示词或敏感草稿。
- 提交瞬间固定选择，生成中禁改；停止等待、失败、超时保留输入与选择，补答/重试沿用当前面板选择。一次生成仍只请求一次模型，结果继续走 `autofill/1` 校验与原子草稿回填，不自动保存。现有设置用途配置、账号默认、编排/计算、全部 10 个表单的权限与候选边界保持有效。

## 3. 验证、提交与交接

先做合成契约/权限/能力测试：DeepSeek 与 GLM 的 low 参数确实发送、GLM 关闭被拒、未知模型不误标低、跨账号/已删除 provider 被拒、旧请求兼容、指定其他模型时 context `modelReady` 的兼容、生成中切换/迟到响应、同目标保持与切目标重置。前端测试覆盖菜单、键盘、窄屏、状态与提示词保留。运行后端相关自动填写 HTTP/契约/对象轻量专项测试和 `python3 tests/run.py all`，以及 `cd frontend && npm run build`。若某项环境不可用，登记实际原因和未覆盖，不写已通过。

在隔离分支实例和隔离浏览器实际填写合成样例“我想新建储能簇这个对象”：确认默认低、模型切换、两字段本地草稿回填、未保存、查看修改/撤销、错误及窄屏。真实模型调用前检查出网内容只含合成数据；分别记录实际模型、请求参数、`meta.modelDurationMs`、服务端总耗时和 HTTP/浏览器耗时，至少 5 次相同输入/提示词比较强度，不把模型、提示词、时段同时改变后归因于强度；不承诺固定秒数。

分支服务显式使用登记端口（执行时核对；此前记录 18941）与 `WIZ_WORKBENCH_ROOT=<开发工作树根>`，并确认没有继承指向真实库的 `WIZ_DATABASE_URL`；测试用独立合成空库/数据根和端口。分支后端托管自身已构建 dist；未经核对不得用 Vite 默认代理 18765 验收。不得停止其他服务、打印/提交根密钥、改真实 ontology 数据。Git 提交前检查状态，仅暂存本任务文件，按 `类型(范围): 简述` 写改动与真实验证；不提交 `data/`、`keys/`、`.runtime/`、`dist/`、`node_modules/`。最后用开发树 `.collaboration/context.py record` 交接，报告开发 cwd、base/最终 SHA、URL/端口/数据根、文件 owner、实际参数/能力、测试与浏览器证据、未覆盖项和“未合并”；不手工改自动摘要。若验收不通过，在原树修复并提交新 SHA。
