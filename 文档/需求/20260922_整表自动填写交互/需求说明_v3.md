# 自动填写 v3：需求说明

日期：2026-09-23。状态：需求交付，待开发与独立验收；**未授权集成或合并 main**。本文件是自动填写的最新需求基准：v2 的短句生成、字段策略、草稿与安全规则继续有效；v3 改动是把模型与思考强度选择放进自动填写输入区，默认强度“低”。[局部交互原型](交互原型_v2.html)只演示旧版对象填写；本版输入区外观参考用户所附截图，以本文行为为准。v1 中未与本文冲突的权限、候选、草稿、撤销和保存约束继续有效。

## 1. 目标与范围

用户可一直手填；需要帮助时打开当前表单的“自动填写”，输入一句名称或较长业务说明，系统填写**能合理生成的字段**，而非把完整内容反问给用户。对象输入“储能系统”应一次填入“对象名称”和可编辑的“业务定义”草稿。

本期覆盖现有本体对象、属性、链接、规则、动作及项目实例识别、属性来源、链接映射、动作接口绑定表单；不新增表单、自动创建关联资产、执行 SQL/接口、自动保存或发布。不做提示词配置后台、聊天历史。模型和强度控件集中在共用自动填写输入区，各表单复用，不在每个页面另做一套。

## 2. 填写规则

采用**通用提示词＋表单契约＋当前上下文＋服务端校验**，不为每个页面复制一套提示词。表单契约给每个可填字段声明一种策略：

| 策略 | 行为 | 例子 |
|---|---|---|
| `draft` | 可根据用户主题及已知本体语义生成可编辑草稿；不虚构项目事实 | 对象/属性业务定义、一般说明 |
| `grounded` | 仅依据用户明确输入或可信上下文填写；不明则针对性追问 | 计算口径、接口语义、匹配规则 |
| `candidate` | 只能从当前账号有权访问的候选中选，后端核验归属 | 对象引用、连接、表、字段、编排 |
| `system` | 不发给模型、不允许回填 | 内部 ID、密钥、派生字段 |

“用户原话”用于证明**用户要求填写该字段**，不意味着生成的定义逐字来自用户。服务端只允许 `draft` 字段做这种生成；不能因此放宽 `grounded`/`candidate` 的事实约束。定义写得中性、简短、可修改；设备范围、公式、数据库字段等未确认内容不作为既定事实。只有确实无法安全填写的字段才提问，不能要求用户先把“业务定义”全文写出来。

空字段优先填；已有值仅在用户明确要求修改时覆盖，未提及内容及未知扩展保持原样。类型联动、原子组、引用所属关系在草稿副本上校验后一次写回；清空及会丢弃已有配置的来源切换仍需明确授权。模型输出不是权限或有效性证明，密钥和业务记录不出网。

## 3. 交互

1. 默认是原手工表单；页头次要入口“✦ 自动填写”。打开右侧栏，显示当前表单、一个短提示词输入框和“生成并填入表单”。桌面与表单并排且允许继续查看/编辑表单；窄屏改带遮罩侧栏。
2. 输入框底部、提交按钮旁放紧凑的“模型”和“思考强度”选择器，参考用户所附截图。模型选项显示提供方名称和模型 ID；提交前能看清本次选择，键盘和窄屏均可操作。现有顶部只读模型行可改为本次选择的简短说明，不能显示与输入区相矛盾的状态。没有可选模型时保留输入并引导去「设置 → 模型设置」。
3. 生成中禁重复提交、禁改本次模型和强度，显示实际等待时间。若取消操作仅忽略迟到结果，按钮写“停止等待”；只有真实终止上游请求时才写“取消生成”。手改、切目标或契约变化时，旧响应不得写入。停止等待、报错和超时保留输入与选择；补答、重试沿用当前选择。
4. 成功后直接填当前本地草稿，不保存；无待补项则收起侧栏。字段高亮，状态列出实际字段名，如“已填写对象名称、业务定义，尚未保存”，可查看改动、撤销本轮。手改后不得一键撤销并覆盖手改。
5. 严格字段缺信息时先填独立合法内容，再用中文字段名指出具体缺项和补充问题；不要显示 `comment` 等内部 key。错误、超时、无变更保留提示词和表单，提供重试。检查/解释仍为次要只读帮助。

## 4. 输入区选模型与思考强度

在“设置 → 模型设置”保留已有“自动填写”用途配置，作为输入区的**初始模型**。输入区列出当前账号已保存且配置足以发起请求的模型；列表读取脱敏元数据，不回显密钥，也不因打开菜单逐个请求上游。这里“可选”不保证上游此刻在线，真实调用失败须明确报错。未设用途模型时用账号默认模型；明确指定的模型已删除/不可用时提示用户在输入区重新选择，不静默切换。输入区换模型只作用于该面板会话及之后的主动生成，不修改用途配置、账号默认或其他 LLM 功能；同一表单收起再展开保留，切换表单目标重置到用途配置。

选中支持控制推理强度的模型时，**本次强度默认“低”**；可选“低/高/最高”，支持关闭思考的模型另可选“关闭”，必要时保留“跟随模型设置”以兼容已有配置。模型能力由服务端按提供方接口和具体模型共同判定，前端只展示服务端允许的选项；不支持强度控制的模型显示“跟随模型设置”和“不支持强度控制”，不得假称“低”已生效。GLM-5.3-Flash 强制开启思考，可选低/高/最高，不能关闭；DeepSeek V4.1 Flash 官方 API ID `deepseek-flash` 可关闭思考或选低/高/最高，它默认开启思考，所以选择“低”须显式发送参数。未知模型不猜能力。模型或强度不支持时服务端拒绝，不静默降级。

一次生成只发一次模型请求，除非用户补答或主动重试。提交瞬间固定模型和强度；服务端重新确认选中的提供方属于当前账号，不能相信前端选项。结果元数据分别给出实际模型、实际请求强度、模型耗时与服务端总耗时；界面不承诺一定“秒级返回”。模型连接配置仍只写入 API Key、不回显。自动填写的填表、检查、解释沿用本次面板选择；其他编排/计算请求保持原配置。

## 5. 验收

- 新建对象输入“储能系统”→一次生成名称和业务定义，不追问定义全文；内容可编辑，服务端修订仅在用户点“保存”后改变。
- 属性/项目映射中的连接、表、字段、公式无依据时不编造；可先填独立说明并明确待补项。现有表单的联动、引用、共享影响确认和 CAS 不退化。
- 未提及的已有内容不变；生成中手改/切目标/停止等待后，迟到响应零写入；查看修改、撤销、取消编辑行为正确。
- 输入“我想新建储能簇这个对象”时，输入区初始展示可用的用途模型与“低”（若该模型支持）；一次生成名称和业务定义。切换 DeepSeek `deepseek-flash` 与 GLM-5.3-Flash 时，服务端确实收到对应模型与 `low`；GLM 不出现“关闭”，DeepSeek 可选“关闭”；未知能力显示“跟随模型设置”。
- 当前账号的可选模型可在输入区切换；失效用途模型明确提示、可手动选择其他模型继续；无模型保留输入并引导设置。切换只影响自动填写，不改用途默认、账号默认或其他功能。跨账号/删除的模型 ID、模型不支持的强度被服务端拒绝；旧客户端省略新字段仍按旧用途配置工作。
- 生成中锁定选择；停止等待、超时、重试、补答、同目标收起再展开、切目标的选择保持与重置符合 §3/§4。实际响应的模型/强度元数据与界面一致，不能把“参数已发送”描述为上游保证兑现。
- 用合成数据测试所有既有表单，运行前后端相关测试、前端构建，并在桌面/窄屏浏览器实际操作；记录模型耗时和服务端耗时，但日志不记录原始提示词、凭据或业务数据。未实测的项目标未覆盖。

原型为离线预置模拟，**不是**真实模型效果或设置页实现。正式版以真实表单契约和已授权候选生成，不能移植原型的关键词判断。模型能力以实施时官方文档和实际接口测试为准：智谱 [GLM-5.3-Flash](https://docs.z.ai/guides/vlm/glm-5.3-flash)／[参数说明](https://docs.bigmodel.cn/cn/guide/start/concept-param)，DeepSeek [V4.1 Flash](https://deepseek.com/news/deepseek-v4-1-flash/)／[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。
