# 对象轻量填写：开发计划 v1

日期：2026-09-23。状态：待 harness 实施、待 Codex 独立验收。本计划只优化新建空白对象表单的一次生成链路；现有自动填写 v2 的功能、安全和交互约束继续有效。效果目标是减少模型输入与等待时间，真实提速幅度以实测为准。

## 1. 目标、边界与基线

- 用户在“新建对象类型”的空白表单输入“我想新建储能簇这个对象”，应一次得到对象名称和可编辑的中性业务定义草稿，无需先写完整定义；回填仍只改本地草稿，用户点保存后才写库。
- 采用现有 v2 决定的“通用提示词＋字段策略＋服务端校验”：实现一个按**表单能力**选用的精简模板，首批只让 `object` 进入；不得复制一套长期独立的页面提示词或做关键词固定结果。
- `autofill/1` 的 HTTP 请求/响应、`operations`、`basis`、会话、鉴权、上下文令牌、契约指纹、撤销、停止等待及保存链路均保持兼容。对象编辑已有值、续轮回答和其他表单继续走当前完整链路。本轮不改前端 UI、模型用途配置、数据库结构或真实本体数据。
- 当前观察：主仓库 `/Users/gukepeng/Desktop/ZHDL/code/wiz_ai/wiz_kq_builder_v2` 的 main 为 `131d4a7`；已登记开发 cwd `/Users/gukepeng/Desktop/ZHDL/code/wiz_ai/wiz_kq_builder_v2/worktree/fill_by_llm`，分支 `fill_by_llm` 为 `fd478ad`，`git status` 干净。执行前重核，不能把这些观察当作未来 HEAD。登记端口 18941、`WIZ_WORKBENCH_ROOT` 为工作树根，含真实数据库和根密钥副本，不可自动丢弃。主仓库用于协调和本计划交付，不在 main 直接改业务代码。
- 当前对象契约只有 `label` 与 `comment` 两个 `draft` 字段、无列表、引用和原子组。通用系统提示约 2235 字符；模型调用上限为 4000 tokens。字符数和上限不等于实际请求 tokens 或已生成 tokens。

## 2. 生成路径与冻结接口

协调者开工先核对 `contracts/forms/object.json`、`assist_schema.py`、`assist_service.py`、`assist_ops.py` 和接口文档 04 §6；冻结以下判定，不在并行实施时各自解释：

1. 仅 `mode=fill`、`protocol=2`、首轮无 `sessionId/answers`、`targetKind=object` 且新建目标 `targetId` 为空、规范化草稿 `label/comment` 都为空时，才可走精简路径。再检查契约实际只含两个可写 `draft` 文本字段、没有列表、引用或原子组；任何不满足项走原链路。未来扩展其他表单须另行验证，不能自动放宽。
2. 上下文令牌签名、用户归属、契约 digest、草稿与权威指纹照旧校验；仅**模型出网消息**按能力删去本次不需要的候选、行操作、引用、原子组说明。不得削弱服务端的校验输入或将候选缺省误当作引用合法。
3. 精简模板保留：输入文本只作数据；仅 `label/comment` 两字段；`draft` 可生成中性简短草稿但不能编造项目事实；已有值保护；`set` 带用户原话的逐字引文；返回现有 `operations/questions/unresolved` JSON。模型输出仍由现有 `parse_fill_output`、`assist_ops.validate_operations` 和后续等值/引用核验处理。不改模型协议或让模型直接写库。
4. 不做自动二次模型请求或失败后静默重试；无效输出沿用现有错误口径。精简路径的 `max_tokens` 先按合成输出测试选择一个足够的值（建议从 800 起测），不能仅凭预估压低到导致 `finish_reason=length`。上限变化不作为必然提速证据。
5. 协调者冻结模块对接：`assist_schema.py` 负责一个可测试的“是否适用＋构造消息/建议上限”纯函数；`assist_service.py` 在现有一次 `llm_client.chat` 调用前使用结果。函数签名与 fallback 行为由协调者写进实施记录后再派并行任务。模型出网仅发合成/用户本次允许的内容，不在日志记录原始提示词、业务内容或密钥。

## 4. 效果测量与验收

- **样例**：至少“我想新建储能簇这个对象”“新建储能系统对象”“帮我建一个电池簇对象”三个合成短输入；另测空输入、已有 `label`、已有 `comment`、续轮答案、契约不符、停止等待/切目标的迟到结果。预期短输入一次生成两个字段且无需用户先写定义，定义只陈述中性语义，不编造配置、数量或计算口径。
- **对比**：同账号同提供方、同思考设置，主样例“储能簇”优化前后目标各 5 次，另外两个样例各至少 1 次；少于此数说明原因。若测量工具能同时构造旧版与新版消息，交替采样以减少时段偏差；否则分别测旧服务和新服务，报告其时间偏差。逐次记录模型耗时、服务端总耗时、浏览器/HTTP 墙钟时间、成功/502/截断、输出字段数；汇总主样例中位数与范围。旧服务日志只记完成时间，不能凭日志时间戳声称精确提速。
- **输入体积**：按 UTF-8 字节和字符分别记录模型消息的系统/用户部分大小；精简路径必须确实不包含对象候选与不相关行/引用规则。不要把真实用户数据、密钥或完整出网 payload 写到报告。
- **质量红线**：现有 `basis` 逐字校验、字段白名单、草稿不自动保存、已有值保护、会话/指纹安全、无效输出 fail-closed 不退化。端到端仍是一次模型请求；check/explain、其他表单与编辑对象行为不改变。若速度未显著改善或质量退化，如实交付数据，不宣称“秒级”；由 Codex 验收决定是否继续调整模型/端点。
