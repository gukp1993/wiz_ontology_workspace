## 1. 开工检查

阅读现行 AGENTS.md，检查当前变更与相关文件，避免覆盖同时进行的动作开发。以下是已观察到的目录入口，实施前确认最新实现，不做全仓重构：

| 位置 | 本期职责 |
|---|---|
| frontend/src/app/navigation.ts、App.vue | 本体菜单、页面装配、对象规则页签跳转 |
| frontend/src/ontology/ObjectWorkspace.vue | 对象规则页签、选择规则、移除引用 |

## 2. 实施顺序

### A. 定好最小协议与持久化

固定 `workflow.businessRules` 和 `workflow.businessRuleAssociations`，业务字段严格四个；提供前端纯读取/编辑/引用辅助。旧数据默认空，未知和无关内容无损。复用现有本体保存。

完成后检查：旧本体能读取；新增后 API 保存回读相等；发布快照保留两数组；无项目数据变化。

### B. 规则列表与弹窗

按原型实现三列表格、名称搜索、空态、新建、只读查看和弹窗编辑。四字段必填提示在保存触发；取消/关闭不污染源数据；保存失败保留表单。

完成后检查：长正文换行、搜索、修改名称后列表刷新、打开查看不进入编辑。

### C. 对象规则引用

在现有对象详情增加规则页签。多选关联已有规则，防重复，移除只解除关联。规则列表反向引用从关联数组计算，不额外存引用计数。引用对象弹窗支持跳转到指定对象的规则页签，保留其他对象页签行为。

完成后检查：一条规则被两个对象引用，取消一个后另一对象不受影响；重命名不丢引用。

### D. 校验与变更比较

后端校验四字段、ID、对象和规则引用及关联唯一性，生成清晰定位。补齐发布差异分类；复用现有发布过程，保存修订与历史发布不可变。

仅当触及项目校验规则时才同步金样；本需求原则上不修改项目校验，不跑无关大规模项目网络测试。

### E. 针对性验收

自动化使用临时 WIZ_WORKBENCH_ROOT 和独立端口，绝不写真实 ontology/。按下面验收表覆盖关键行为，再运行前端构建。不要拿 build 成功代替交互验收。

## 3. 验收表

| 编号 | 操作 | 结果 |
|---|---|---|
| A1 | 打开规则库 | 仅名称、引用对象、操作三列，无业务定义摘要/标签/状态 |
| A2 | 搜索、清空、无结果 | 名称过滤正确，列表可恢复 |
| A3 | 新建并保存 | 弹窗恰好四字段；成功后关闭；刷新仍存在 |
| A4 | 查看与编辑 | 查看只读四字段；编辑弹窗；长文本换行保留 |
| A5 | 取消、关闭、Esc | 有修改提示；放弃不改变保存数据 |
| A6 | 缺项或保存失败 | 定位必填；网络失败不假成功，表单输入保留 |
| A7 | 对象添加多条规则 | 搜索不丢勾选，无重复引用，刷新保留 |
| A8 | 同规则关联两个对象 | 列表计数2，引用弹窗列出两对象并正确跳转 |
| A9 | 移除一个对象引用 | 仅减少该关联，不删除规则或其他对象引用 |
| A10 | 修改规则名称 | 所有引用显示新名称，ID不变 |
| A11 | 老数据缺少新字段 | 正常打开，其他定义无损，不自动灌入示例 |
| A12 | 发布与回读 | 新字段随本体发布；历史快照不变，项目引用不自动升级 |
| A13 | 无效引用/重复关联 | 发布校验给出可理解且可定位的错误 |
| A14 | 同时打开两个编辑页面 | 遵循现有revision冲突语义，不新增静默覆盖路径 |
| A15 | 页面巡视 | 无规则依赖、补充配置、预览/检查按钮、原始材料和项目交接页签 |

## 4. 检查命令与交付

- 添加少量针对本体规则存储、引用和发布的回归测试，不复制大套无关用例。
- 执行与修改区相关的现有保存/本体校验测试。
- `cd frontend && npm run build` 必须成功。
- 浏览器在隔离环境检查A1—A10的主要交互并记录截图或操作结果；不需要对每个字段做重复截图。
- 输出简短实施说明：改动文件、协议、验证结果、未完成项和实际耗时。不能将未验证项标为通过。

小范围实现采用上述顺序即可，不强求多agent或大规模并行。稳定协议确定后，前端规则弹窗与后端纯校验可以分工，但不得同时改同一文件。
