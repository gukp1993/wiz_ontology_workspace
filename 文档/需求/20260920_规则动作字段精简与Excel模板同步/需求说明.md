日期：2026-09-20。状态：用户确认字段方向，本文定义后续实施范围；本轮仅交付文档与新版模板，未修改正式代码或线上下载入口。

## 1. 目标和边界

本体规则描述业务如何计算、判断或约束；动作描述操作的业务含义和预期变化。两者均以名称和业务定义为最小完整定义，不要求重复填写同义内容。

- 规则：规则名称、业务定义必填；规则内容选填。取消新建表单中的输出结果。
- 动作：动作名称、业务定义必填；业务效果改称预期效果并选填。
- 适用范围、例外和作用边界写入业务定义，不新增独立字段。
- 不增加类型枚举、输入输出签名、动作参数、提交条件、审批、执行结果或计算引擎。
- 本体仅定义语义；项目SQL、Redis、编排和接口配置不在本次范围。
- 本次明确授权的字段、文案、校验及Excel表头修改是独立小范围需求，不恢复“统一维护体验v2”延期的布局和交互改版。

## 2. 字段定义

| 类型 | 显示名称 | 现有存储字段 | 必填 | 填写含义 |
|---|---|---|---|---|
| 规则 | 规则名称 | name | 是 | 简明识别该业务规则 |
| 规则 | 业务定义 | description | 是 | 规定什么、适用什么情形；必要时说明范围及例外 |
| 规则 | 规则内容 | content | 否 | 具体计算公式、判断逻辑、约束或处理原则 |
| 动作 | 动作名称 | name | 是 | 用动词表达业务操作 |
| 动作 | 业务定义 | description | 是 | 操作目的与含义；必要时说明范围及边界 |
| 动作 | 预期效果 | effect | 否 | 操作成功后期望出现的业务状态变化，不是接口响应结构 |

沿用workflow.businessRules、现有动作集合、稳定ID及关联集合。effect只改显示文案，不另造expectedEffect字段。不得仅因本次文案变化批量提升动作definitionVersion或重写历史数据。content/effect缺失、null、空字符串均按未填处理；非空值必须为文本，不能悄悄把对象/数组转字符串。

必填检查去除首尾空白后判空，不根据长度或是否重复名称进行主观质量拦截。业务定义已表达完整时，选填项留空可正常保存、导入、校验和发布。

### 示例（仅用于提示，不预填用户数据）

| 字段 | 规则示例 | 动作示例 |
|---|---|---|
| 名称 | 储能设备SOC计算规则 | 停止充放电 |
| 业务定义 | 根据所属储能簇的SOC与额定容量计算设备整体SOC；总容量为零时无法计算。 | 请求目标设备结束当前充电或放电，不等同于设备断电。 |
| 选填内容 | 设备SOC＝Σ（簇SOC×簇额定容量）÷Σ（簇额定容量）；参与计算的数据统一比例和容量单位。 | 设备退出充放电运行状态。 |

公式作为文本描述，不由本体或Excel执行。缺失数据处理、截断或平均方式不能由工具擅自补齐。

## 4. 旧数据零丢失

### 4.1 规则旧output字段

取消的是新定义的填写要求和新模板列，**不是删除已有数据**。

- 读取、编辑另一个字段、保存、JSON/schema转换、发布快照、配置迁移均透传保留旧output及未知扩展。
- 有非空output的旧规则在详情/编辑中显示只读“历史补充说明（原输出结果）”。不显示空历史区，不要求用户迁移。
- 不自动拼入业务定义或规则内容，不清空、不批量迁移。用户可复制到规则内容后编辑；本期不另造历史字段清理流程。
- 新建记录不要求生成output，历史存在的空字段允许保留。后端不能仍将output空值视为阻断。
- 旧发布版本保持原样；文案调整本身不应造成业务破坏性变更。实际语义变化继续按现有分类处理，不能放宽依赖失效检查。

### 4.2 动作兼容

现行新格式动作的effect继续原键读写，只改界面名称、必填规则。历史旧格式的参数/权限等只读兼容和显式转换边界不变，不借此次精简静默删除其他旧字段。转换后的新格式也不强制填写effect。

## 5. Excel模板与导入协议

### 5.1 四个业务页

| Sheet | 新表头（按顺序） | 单元格要求 |
|---|---|---|
| 对象 | 对象名称、业务定义 | 沿用当前对象规则 |
| 属性 | 属性名称、业务定义、数据类型、观测值类型、显示格式 | 沿用当前属性规则，默认导入共享属性 |
| 规则 | 规则名称、业务定义、规则内容 | 前两列必填；规则内容可空 |
| 动作 | 动作名称、业务定义、预期效果 | 前两列必填；预期效果可空 |

模板只保留第一行表头和空白填写区，不添加说明行、示例记录、关系列、ID列或新的Sheet。必填说明放在导入页面，表头不要追加星号/“必填”以免改变识别名。冻结首行。容量上限维持现有1000条业务行和文件限制，空白格式行不计数据。

属性类型下拉保持：文本、数值、是／否、时间、数组、结构体、时间序列；观测值类型保持文本、数值、是／否、时间。仅当同一行数据类型为时间序列时，观测值下拉有这些值。H列辅助枚举继续隐藏，非时间序列残留观测值的提示与导入校验保留。Excel无宏，改变类型不会自动清除旧观测值，导入器必须拦截不合法残留，不能假称自动清空。

### 5.2 简单表头样式

四页统一：浅灰底（#F2F4F7）、深色文字（#263238）、11pt加粗、左对齐、26pt首行、浅灰细底线。不使用深色大色块、大字号、合并表头或装饰。保留现有列宽、普通网格和填写区；规则仅三列业务表头，不保留空的深色第四列。

### 5.3 兼容解析规则

按表头名称识别，不能按列号硬编码；规则/动作必须包含名称和业务定义表头。选填列缺失可接受，模板仍提供。

| 输入 | 处理 |
|---|---|
| 规则新三列 | 按新定义导入 |
| 旧规则四列含输出结果 | 正常解析；输出结果写入兼容output，不丢弃；预览提示“旧输出结果将保留为历史补充说明” |
| 动作新预期效果列 | 写effect |
| 动作旧业务效果列 | 作为effect别名，与新列同等支持 |
| 动作同时有新旧列 | 按行处理：一侧空取另一侧；去首尾空白后相同取一份；都非空且不同则报冲突并阻断该批，不擅自选择 |
| 待导入规则/动作缺业务定义 | 定位Sheet、行、列，提示“请填写业务定义”；不以名称自动补齐 |
| 纯空白行 | 忽略 |
| 同名跳过的行 | 沿用既有跳过策略，不引入新的覆盖或批量补定义行为 |
| 非文本、Excel公式、错误值 | 沿用严格解析，旧别名和旧output同样检查；未知非空列不可静默忽略 |

下载入口与新解析器须同一版本交付。**本轮文档目录中的新版模板是后续实施资产；当前正式导入器仍要求旧表头，尚不能承诺新模板现在即可导入。**本轮没有替换frontend/public/templates/ontology-import-v1.xlsx。
