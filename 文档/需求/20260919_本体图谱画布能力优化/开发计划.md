# 本体图谱画布能力优化 · 开发计划 v1

配套：[需求说明](需求说明.md)、[交互原型](交互原型_v1.html)、[执行指令](执行指令.md)。本文件记录计划，不能当作已实施证明。

## 1. 实施策略

先保证图上内容准确，再加操作，最后连接现有定义页面。限于本体图谱及必要导航接点，保持Cytoscape、Vue3和现有视觉体系，不做全站状态库/路由重构。

当前主入口：`frontend/src/ontology/ObjectWorkspace.vue` → `OntologyGraph.vue`。`graphAdapter.ts` 是其他旧画布适配，不可误以为它驱动当前全量图谱；`tools/KnowledgeCanvas.vue`、`tools/InstanceGraph.vue`、`flow/FlowCanvas.vue` 不在本轮范围。

## 2. 建议模块划分

以下为实现建议，执行者可按当前目录微调命名，但保持职责边界，避免几十个微小文件。

| 模块 | 职责 |
|---|---|
| OntologyGraph.vue | 页面装配、筛选/工具/详情、生命周期，调用下面的纯函数与控制器 |
| ontologyGraphModel.ts（新增） | 五类节点/全部实际关系投影、稳定内部ID、异常引用计数、定义导航描述符 |
| ontologyGraphView.ts（新增） | 可见集、搜索、方向BFS、诱导子图、确定性布局等纯函数；必要时布局函数独立一个文件 |
| useOntologyGraph.ts（新增） | Cytoscape初始化/增量同步、指针/快捷键/ResizeObserver、布局历史、视图缓存；不写业务state |
| ObjectWorkspace.vue / App.vue / app/navigation.ts | 仅做打开定义与返回画布的必要桥接；优先复用现有focus/返回逻辑 |
| app/auth.ts | 复用prefGet/prefSet，不复制账号命名空间规则 |

类型建议：`GraphNode { id, domainId, kind, name, aliases, ownerId?, detail }`；`GraphEdge { id, domainId?, kind, source, target, relation, objectPropertyId?, detail }`。不要将graph内部ID写回业务引用。

内部视图状态：全图基础坐标/viewport、filters、selection、inspector、搜索状态；邻域含center/depth/direction/临时坐标和进入前快照。全图与邻域历史分开，最大化只影响容器。

## 3. 分阶段任务

### T1：确认基线和投影（前置）

- 读本轮四文件及AGENTS，读取共享上下文、git status；确认主图实际挂载点与旧分支无混用。
- 构造临时fixture：五类节点、共享/私有属性、平行链接、自关联、同名节点、跨类重复ID、悬空引用、环及孤立节点。
- 提取纯投影，替换按端点/名称去重和禁止自关联的做法。共享引用边保留对象属性ID。
- 对节点/边相关字段做增量同步；端点变更更新move，节点删除清理selection与详情，名称变化不重建；给规则/动作加内部ID前缀。
- 验证G01–G04/G18。避免先做样式再修内容导致返工。

### T2：统一可见状态、搜索与邻域

- 将可见集计算为纯函数，筛选先于方向BFS，诱导边与节点集合分开处理。
- 搜索结果计数/键盘导航/显式显示并定位，不暗改筛选；无命中与无可见节点区分。
- 单选只显示详情；邻域显式进入，1/2跳/全可达与方向切换；环形临时布局、退出恢复。
- 联动清理失效selection/edge/center，显示全部的状态重置行为写一个统一入口。
- 验证G05–G07/G10/G11。

### T3：画布工具与本地布局

- 实现选择/移动模式、Shift组合、Space临时平移、节点多选拖动。
- 自动布局默认确定性类型分列、关联排序；另一种连通分量布局优先复用内置或现有算法。
- 布局历史30步，坐标差异才入栈；撤销不触达App业务历史。临时邻域的布局历史单独处理。
- 缩放/适应/定位选中/重置位置；全局快捷键严格按焦点管理，不以document监听就接管整个应用。
- 缓存有版本、账号/本体隔离，切换flush、非法值过滤、禁用缓存提示。旧匿名缓存不迁移。
- 验证G08–G12/G14/G17/G19。

### T4：面板布局与定义导航

- 按原型整合一层工具栏和筛选/详情，应用现有tokens；保持五类节点色，不为图谱新增另一套页面风格。
- 断点：宽屏双侧栏、中屏筛选折叠、窄屏浮层互斥；容器ResizeObserver调整尺寸并保持模型中心。
- 最大化内容区与恢复，限制键盘作用域；长规则仅在详情内滚动。
- 接通各类“打开定义”，带同本体返回上下文；复用已有表单保存，返回恢复画布，数据改变时增量更新。
- 验证G13/G15/G16。不得把原型的模拟弹窗当正式实现。

### T5：回归与交付

- 纯函数测试：投影身份、重复/自关联/平行边、同名节点、BFS/可见集、边筛选、确定性布局、空图。
- 控制器/组件测试：不emit业务changed，不调用save；拖动撤销；缓存切账号/本体；乱序增量刷新；卸载清理；返回导航。
- 使用现有 `tests/ts_hooks.mjs` 与项目测试约定，新增聚焦文件例如 `tests/ontology_graph.test.mjs`、`tests/ontology_graph_controller.test.mjs`。不为了测试引入大型测试框架。
- 执行 `cd frontend && npm run build`（必需）；新增测试；如果动到导航，执行相关现有导航/懒加载/首页测试。只改本体画布无需跑全部真实HTTP或外部数据库套件；改接口则另行扩大验证并先更新文档。
- 隔离实例：必须同时设置WIZ_WORKBENCH_ROOT、WIZ_DATABASE_URL、WIZ_WORKBENCH_PORT。临时账号+数据，不向真实18765实例写测试数据。
- 浏览器按G01–G20验收。用演示fixture，不依赖用户真实本体ID；清洗本体可以只读比对数量。截图至少包含1440全图/详情、1280搜索、1024关联查看、768工具栏、布局撤销前后。
- 性能样例500节点1200边；记录首次渲染、搜索耗时、交互长任务（可用Performance API），不把开发机实测当所有机器保证。
- 最后追加本文件§6真实实施记录：修改文件、逐项结论、命令与结果、截图路径、剩余问题、commit。保持四文件范围一致。

## 4. 依赖与并行建议

关键依赖：T1图模型接口 → T2状态语义 → T3操作与T4布局/导航 → T5集成。可并行的仅为T1 fixture准备与UI静态布局草拟；T2/T3共享控制器不要分给多个执行者同时修改。若harness使用多代理，按文件所有权拆分且一个负责人集成；不追求并发数量，不要求使用特定模型。

不提前承诺固定耗时。主耗时预计在邻域/全图状态恢复、与现有表单导航往返、输入快捷键和缓存生命周期的验证；不是单纯增加几个按钮。

## 5. 兼容与协议

- 本期没有预期HTTP变更或数据库迁移；接口文档不为“纯前端交互”增加假接口。
- 若实施发现确需扩展导航focus参数，作为前端可选参数，兼容原调用；若实际HTTP契约需改，先列原因、更新接口文档/索引/变更记录，再动代码，不借机扩范围。
- 现有默认图谱包含全部五类；筛选只影响视图。不能恢复旧“只显示对象”的ObjectCanvas代替当前图谱。
- 不改定义顺序、稳定ID、共享语义、动作/规则关联、草稿revision、发布或项目引用。
- 原来的匿名布局仅是偏好，不迁入任何账号；新key首次出现用默认布局。技术说明解释一次，不弹阻断确认。
- 代码回退不会修改真实本体；本轮只有新的本机偏好key，回退后可忽略。

**实施中发现并修复的缺陷（超出原评审清单，均为本轮引入或口径收紧）**

1. 首次进入（无本机缓存）时 `emptyView()` 的默认视口 `zoom=1/pan=(0,0)` 被当作已存视口，图谱落在画布左上角之外：改为「确有坐标记忆才恢复视口，否则适应窗口」。
