# 动作库与对象动作关联需求说明

日期：2026-09-17　版本：V1　状态：供开发实施

## 1. 交付与依据

本目录为本次需求唯一维护位置：

- [交互原型_v2.html](交互原型_v2.html)：新版交互基准。
- [开发计划.md](开发计划.md)：任务顺序、技术边界和验收。
- [执行指令.md](执行指令.md)：交给其他 harness 的独立实施指令。
- 本文：产品行为与范围。原型与本文冲突时以本文明确规则为准，并同步修正原型。

本次只交付原型与文档，未修改运行工作台、真实本体或项目数据。旧原型位于 `文档/备份/prototypes/动作定义与项目绑定交互原型_v1.html`，保留作为历史参考，不再作为开发依据。

## 2. 已确认决定

1. 本体主菜单增加“动作定义”，集中维护动作库。
2. 动作定义不指定对象，不配置输入参数，不配置提交条件。
3. 对象建模增加“动作”页签，从动作库搜索、多选关联；同一动作可被多个对象类型引用。
4. 项目按“项目＋对象类型＋动作”绑定具体实现。同一个动作在不同对象上的实现独立维护。
5. 当前动作指通过业务系统实现写操作或控制操作。自然语言业务效果不是自动执行脚本。
6. 本期支持定义、关联、实现绑定配置；不实现真实接口调用、设备控制、执行表单生成或自然语言自动执行。

此设计借鉴 Palantir Action Type，但“通用动作库＋各实施项目适配”是本项目的产品设计，不宣称为 Palantir 原生固定流程。

## 3. 页面和交互

### 3.1 本体：动作定义

菜单放在对象建模之后。列表显示动作名称、业务定义摘要、业务效果、已关联对象和操作。支持搜索、新建、编辑、删除。

编辑字段仅三项，均必填：

| 字段 | 内容 | 示例 |
| --- | --- | --- |
| 名称 | 简洁描述业务操作 | 停止充放电 |
| 业务定义 | 动作的业务用途 | 请求目标对象停止当前充电或放电 |
| 业务效果 | 自然语言描述期望发生的变化 | 请求停止充放电，目标功率为 0，以设备反馈确认完成 |

不展示作用对象下拉、输入参数、提交条件、权限审批、验收页签、稳定标识编辑或具体接口字段。标识由系统生成并保持稳定。

已关联对象只读反向展示，可点击跳转对象建模的动作页签。动作定义只存一份；编辑后本体草稿中的各处引用同步读取最新定义，不复制成对象私有动作。未关联动作允许保存、保留待用。

保存按钮直接持久化本体草稿；取消不写入；未保存离开提示。预览为只读定义，不显示可执行按钮。

### 3.2 本体：对象建模 → 动作

保留现有属性、链接页签，增加动作页签。

- 已关联列表：动作名称、业务效果、查看定义、移除关联。
- “添加动作”：展开可搜索的多选组件；显示名称和简要定义，已关联项禁用并标明已关联。
- 勾选尚未保存；点击“确认关联”一次保存；取消不变更。
- 查看定义进入动作库对应动作。允许从反向引用回到对象动作页签。
- 移除关联不删除动作定义，不影响其他对象的关联；提交前说明影响。
- 本期不增加“关联到某个属性”、动作输入参数、自动推断关联或画布动作节点。

多对象关联表示一个动作可分别作用于这些类型，不表示批量执行或一次动作同时选择多个类型。

### 3.3 项目：对象映射 → 动作绑定

项目对象映射中增加动作绑定页签，紧邻现有映射页签。可有“动作绑定”快捷入口，但必须进入同一对象映射页签，不建立第二份状态与维护页面。

列表仅以项目固定引用的已发布本体版本中的对象动作关联为有效来源。不得读取本体实时草稿冒充项目引用。原型中的实时联动仅为了演示，页面已标注。

绑定表单：

| 字段 | 规则 |
| --- | --- |
| 对象和动作 | 只读显示，来自当前项目引用版本 |
| 业务效果 | 只读展示本体定义 |
| 实现方式 | 调用项目接口／绑定函数编排 |
| 项目接口路径 | 接口模式必填；本期作为配置说明，不承诺请求方法、认证及实际执行链路已完成 |
| 函数编排 | 编排模式选择已有项目可用编排的稳定引用；不新建另一套编排编辑器 |
| 允许操作的项目角色 | 维护项目权限要求；未接入账号权限系统时只是说明，不宣称已经实施访问控制 |
| 接口／函数参数映射 | 按需填写项目参数来源说明；无参数接口允许留空 |

参数说明可以引用当前操作对象的项目标识、映射字段、固定值、项目配置或未来执行时补充的信息。本期不形成机器可执行的参数签名或自动操作表单。

保存仅写项目草稿，不能修改本体。配置完成显示“已配置 · 未执行验证”，不能显示“可执行”“执行成功”。禁止存放密码或 token，认证后续通过连接安全配置实现。

## 4. 示例

| 动作库定义 | 对象关联 | 项目实现示意 |
| --- | --- | --- |
| 停止充放电 | 储能设备 | `stopCharge(storageId)`，标识来自当前设备项目映射 |
| 停止充放电 | 支持独立控制的储能簇（按业务选择） | 绑定对应控制接口；不能仅因簇属于设备就自动关联 |
| 修改显示名称 | 储能设备、储能簇 | 两个对象分别配置不同接口；新名称由项目操作过程提供 |
| 调整所属储能设备 | 储能簇 | 业务系统修改归属，目标设备信息在项目操作过程中提供 |

不同项目也可将“停止充放电”绑定为 `setStoragePower(storageId, 0)`，前提是该接口在当地业务中确实完成同一效果。接口不支持该动作时保持未绑定，不静默丢弃业务要求。

原型示例只在内存中，刷新复原；不得自动导入真实本体。

## 5. 数据、版本与兼容

- 沿用本体 `workflow.actions` 集中保存动作定义；新增版本标记用于区分本期简化动作与历史动作（推荐 `definitionVersion: 2`）。新格式必需业务字段为 `name/description/effect`。
- 对象动作关联建议作为本体 workflow 内的单一集合 `actionAssociations` 保存：`{objectTypeId, actionId}`。使用真实稳定 ID，组合唯一。由该集合反向推导关联对象，不在两端各存一份。
- 项目绑定建议在项目 `bindings.actionBindings` 保存：`{objectTypeId, actionId, implementation:{...}}` 列表，组合唯一。具体实现字段由开发在第一阶段冻结，前后端一致。
- 本体关联不是业务 Link Type，不生成虚假的“对象—动作”实例关系。
- 发布后快照不可变；项目只在显式升级引用后获得新增、修改或移除的关联。
- 升级时关联失效的旧绑定保留，展示对象名、动作名、原因和修复入口，不默默删除。保留的失效绑定阻止项目发布；用户可在项目草稿中明确移除失效绑定。
- 原型只演示失效提示及配置保留；真实开发需补充失效配置的只读详情和确认移除入口。
- 未使用动作、未绑定动作本身不阻止发布；已填写的绑定结构错误、悬空引用才阻止发布。
- 有对象引用的动作禁止直接删除，先移除关联。已发布版本不受草稿删除影响。
- 删除对象时若有关联，提示并在确认删除对象时只清理该对象草稿关联，保留动作库。不得顺带删除项目绑定。
- 修改共用动作定义需进入现有变更评估；移除对象动作关联、删除已关联能力按破坏性变化处理，业务效果文本变化按待确认处理，不自动声称兼容。
- 历史动作的 `object_type/inputs/criteria/permission/acceptance` 等字段不得批量清空；保持旧格式可读、旧校验路径和其他未修改数据完整。可以内存推导历史对象关联，避免重复。转成新格式必须显式编辑保存并说明被替代的历史字段；首期不做自动数据迁移。

## 6. 验收清单

1. 新动作只填写名称、业务定义、业务效果，不出现对象、输入参数、提交条件字段。
2. 同一动作关联两个对象，修改定义后两个对象草稿展示一致；取消修改不生效。
3. 多选搜索不丢失已勾选项，已关联项不重复写入。
4. 移除一处关联不影响其他对象，删除被引用动作有可读提示。
5. 同一项目中两个对象使用同一动作，分别保存接口配置，互不覆盖。
6. 本体草稿变更不改变项目固定版本；升级后失效绑定保留并可处理。
7. 新格式不被旧的参数、条件、权限、验收必填规则阻止保存或发布；旧动作不丢字段。
8. 本体与项目各自保存、撤销、取消、409 冲突处理符合现有机制。
9. 未绑定显示待绑定；配置完成只显示未执行验证。无真实网络调用或设备控制。
10. 没有修改 SQL 读取执行边界，没有将动作视为属性取值规则，没有写真实 ontology 数据做测试。
