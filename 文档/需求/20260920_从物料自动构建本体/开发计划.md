## 1. 范围与优先级

实现工作台内从代码、DDL、Word/PDF/Excel/MD生成新本体的完整任务链：物料→扫描→多轮范围澄清→确认范围→生成→证据与候选评审→原子创建新本体草稿。

本期必须闭环：真实物料解析、真实LLM对话和生成、输入基线、逐字段证据、弱证据/冲突处理、依赖校验、人工修改保护、合并撤销、再生成对比、任务恢复、新建幂等和账号隔离。不能仅完成外壳或把HTML中的固定样例搬入正式代码。

不做：向已有本体追加/覆盖、自动发布、项目映射、可执行编排/脚本、MCP口径、业务数据库直连、Git平台集成、通用管线编辑器。保留既有其他功能，不恢复统一维护体验v2中的延期项目。

需求§13的未定事项不由执行者自行扩大：

| 未定项 | 可先落地的保守技术处理 | 需要进一步决定的内容 |
|---|---|---|
| 代码/SQL覆盖 | 按需求矩阵实现Java、JS/TS、Python结构解析及明确列出的框架映射，MySQL常见DDL；其他内容降级并告知 | 超出矩阵的框架和方言是否首期增加 |
| OCR | 文本PDF必须真实支持；扫描页检测、失败/缺口确认必须实现；OCR适配接口与可用性提示 | 如需新增远程OCR服务、账户或额外费用，先询问；未配置不能伪称成功 |
| 规模 | 使用可配置且页面可见的保守初始限额，测试后登记，不无上限处理 | 最终大项目容量目标及调整后性能承诺 |

技术选型可按现状落实，但不得将缺失核心解析器、再生成保护或共享转换等必需能力悄悄归为“后续”。对确实无法实现的项目明确报告缺口，不能宣称整体完成。

## 4. 数据与一致性设计

### 4.1 数据记录（最终字段在接口文档冻结）

| 记录 | 最小内容 |
|---|---|
| BuildTask | id、owner、名称、状态、opaque revision、材料修订、范围修订、当前批次、交付目标、时间 |
| Material / Upload | 服务端ID、相对显示路径、类型、大小、内容hash、存储ID、上传状态、解析版本、排除与失败信息 |
| Evidence / Fact | id、材料快照、定位器、原文片段或片段引用、技术事实、解析质量、来源同源组 |
| Scope / Message | 用户消息、助手消息、结构化范围及修订、未决问题、用户确认、模型配置指纹、外发授权范围 |
| Run / Stage | 批次ID、冻结输入基线、阶段checkpoint、lease/fencing token、attempt、取消状态、错误、用量 |
| Candidate | 系统ID、类型、字段、逐字段证据引用、证据状态、人工决定、关联候选ID、结构问题 |
| Review revision | 人工字段编辑、决定理由、合并映射、操作前状态或可逆补丁、基线 |
| Delivery receipt | owner+task唯一约束、requestId+payload digest、结果本体ID、交付基线、创建结果 |

数据库保留结构化任务及元数据；大文件不塞进本体JSON或草稿。建议原始二进制采用受管理的本地blob目录（`DATA_ROOT/data/ontology-build-blobs/`，目录0700、文件0600），SQLite登记归属/哈希/状态。它是任务附件，不是本体权威存储文件回退。blob和任务元数据必须纳入备份/恢复设计：要么备份一起打包，要么明确显示附件缺失并允许恢复材料，不能宣传仅备份数据库即可完整恢复任务。

上传写临时blob→完整校验hash/限额→原子rename→短事务登记可用；中断孤儿由有界清理处理。数据库登记前的文件不可作为可用证据。多账号间不复用可被枚举的全局文件ID；哈希命中不能绕过归属。

### 4.2 修订与失效

区分材料修订、范围修订、生成批次、人工评审修订和运行进度序号，避免每次进度轮询都导致编辑CAS冲突。所有可编辑实体有不透明revision；不可用内容hash代替并发token。

生成基线建议包含：任务ID、材料清单hash与内容修订、范围修订、解析器/提示词/模型配置版本。采用结果时重新核对基线与run token。切换范围、排除材料或新上传使旧结果过期，但保留旧批次只读；LLM晚响应不覆写人工摘要或新结果。

保存前检查产生checkToken，绑定候选选择/字段/关联和结果基线；用户更改后失效。创建请求服务端重新检查，不信任前端token本身代表内容永远合法。

### 4.3 任务执行

本地有界工作池即可；数据库持久记录排队/运行/中断/失败/取消/完成。启动时只恢复状态，不自动外发或重复生成；可将失去lease的运行标中断，用户点击恢复。轮询仅返回轻量进度，证据与候选分页读取，避免2 MB响应或页面一次加载全部。

文件解析、OCR、LLM请求不持全局LOCK或长写事务。每阶段短事务检查owner、取消、输入基线和fencing token后提交。取消在外部请求已发送时不保证立即终止计费，但禁止晚结果写入当前批次；页面如实提示“正在取消/已取消”。有限自动重试需明确错误类型，结构性失败不得无限重试，手动重试复用已匹配的checkpoint。

### 4.4 原子交付和幂等

同一写事务内：确认task owner与未交付→检查幂等记录→校验请求digest与当前评审基线→分配本体和定义ID→重验名称、结构及依赖→创建完整新草稿→记录候选ID映射和任务来源关联→写回执及任务已交付状态→提交。

同一requestId不同payload返回冲突；已成功请求的网络重试返回原结果（先识别成功回执，不能因revision改变误报失败）。不同requestId对已交付任务也不得再创建第二个本体。事务失败全部回滚，无空本体或“任务成功但无草稿”。不能调用会自行提交的create后再补另一个事务；提取可复用的域/存储事务方法并回归原新建路径。

## 5. 上传和外部调用边界

### 5.1 分片上传

保持HTTP JSON总上限2,000,000字节。建议每片原始数据≤512 KiB，base64及JSON仍在现有上限内；前端通过统一http模块上传。该值是技术初始默认，须在能力接口和界面一致展示。

流程：init声明文件名/相对路径/预期大小→chunk含uploadId/index/hash/base64→complete验证连续完整性、总大小、最终hash→登记物料。重复相同chunk幂等，不同内容同index冲突；未授权owner不能读取/补传；expired上传重建，不永久占空间。文件夹由浏览器File输入获取相对路径，不开放服务器任意路径读取API。

建议起始限额：单文件50 MiB、任务总上传200 MiB、ZIP累计展开300 MiB/10,000文件；压缩率、嵌套深度、解析时限另配置。以上为待样本校准的工程默认，实施阶段必须测量并登记，不能视为用户已确认的容量承诺。格式解析器检查内部解包尺寸，DOCX/XLSX也是ZIP，不能只防外层压缩包。限制无界XML实体展开、链接、路径逃逸，不读取外部文档资源。

### 5.2 LLM与检索

先建立本地物料结构索引，按范围召回证据。关键词/别名/显式映射为确定性基础；语义匹配可由现有chat模型分批判断或独立embedding适配器实现。当前模型配置未核实支持embedding，不能自动向chat端点发embedding请求；独立向量服务不是首期依赖。有界检索、去重、上下文长度预算、分批抽象和全局冲突复核必须实现，不可简单截断仓库前N行当作完整分析。

为范围助手、定义抽取和证据复核分别定义版本化system prompt与响应schema。每次模型输出中的evidenceId、对象/属性关联引用，必须对应当前owner当前材料快照里的允许集合；捏造证据或引用时降为待确认/拒收，不能展示虚构文件位置。模型只返回临时候选键，由服务器分配稳定ID。

现有chat trace含源码片段，不直接存储或返回；本模块记录providerId、model、耗时、调用次数、token usage（供应商有返回才记录）、输入输出大小/摘要hash和错误类别。若要改公共llm_client增加安全元信息，保持原编排行为兼容并补回归。不能默认启用代码“求值”工具、执行SQL或调用业务接口。

授权按本任务材料范围/模型供应商记录。供应商改变或增加超出授权范围的材料需要更新授权，不将曾经同意一次视作永久可外发。模型配置变更后不自动替换到其他提供方；明确显示旧批次配置与当前设置差异。

## 6. 解析与生成的具体要求

- 文件先按magic/后缀/编码识别；重复副本和文档复制段落建立同源信息，不堆来源数提升可信度。
- Java/JS/TS/Vue/Python用语法结构与框架规则提取；动态调用无法确定要留证据边界。不能用单个正则完成所有语言，再称结构解析。
- MyBatis XML/SQL、JPA注解、前端请求URL及字段绑定作为明确关联证据。调用关系只对可解析范围承诺；外部依赖未提供须标缺口。
- DOCX保留段落/表格层级；PDF保留页码与版面片段；Excel保留sheet、坐标、公式文本和可用缓存，不执行宏/公式；Markdown保留标题路径及行号。原文取证不将HTML直接渲染执行。
- 选用解析库前核对现有依赖、许可和维护情况；固定依赖版本范围、显式安装，修改setup依赖指纹（如适用），运行请求不得pip/npm install。
- 候选schema包含对象、私有/共享属性、链接、业务规则/动作以及当前协议允许的关联。数组/结构体/时序不得只改类型标签而丢内部结构。规则/动作按最新精简需求处理，不为未填content/effect造值。
- 默认私有属性，共享转换须显示语义/类型差异和对象引用；确认后构造现有共享定义与引用结构，来源不写入description。
- 复核区别“来源中确实存在这句话”与“这句话支持结论”，无法自动证明的内容保守留候选；有依据也不标“业务已验证”。
