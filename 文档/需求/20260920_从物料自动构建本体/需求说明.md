# 从物料自动构建本体 · 需求说明 v1

日期：2026-09-20。状态：**供用户评审；仅交付需求和原型，尚未实施。**

配套：[交互原型_v1.html](交互原型_v1.html)。本轮按用户要求不生成开发计划、执行指令；评审确认后再编制。本文的“应”描述拟议验收目标，不代表当前工作台已有能力。

## 1. 目标与已确认边界

将混合业务的前后端代码、数据库表结构、需求文档抽象为适配本工作台的新本体初稿，降低从零填写成本。初稿需要人工修改和裁剪，不能直接当作可发布、可查询或可执行的模型。

用户已确认：

- 仅生成本体：对象、属性、链接、业务规则、动作及关联。不生成项目映射、数据库连接、函数编排、执行脚本或MCP口径。
- 输入包括前后端代码、数据库表结构和Word/PDF/Excel/Markdown文档。材料不只包含储能，必须按任务业务范围筛选；产品不写死行业。
- 使用LLM多轮对话澄清范围，不限制为一句话。
- 有依据的内容进入初稿选择集，弱证据内容进入候选清单；人工最终选择。
- 功能集成工作台；仅创建新本体，不向已有本体追加或覆盖，不自动发布。

本文新增的流程、状态、文件入口和解析支持矩阵均为本版建议，需用户评审。旧的“本体与项目统一维护体验v2”延期项目不因此恢复。

## 2. 产品原则

1. 事实与推断分开。每个候选字段有来源或明确的人工补充说明，不能用模型自评分代替证据。
2. 先宽范围识别再精筛。排除的是本任务生成范围，不删除材料；单个文件可跨业务，必须支持片段级判断。
3. 不把表、类、接口一一复制成本体对象或动作。技术结构用于理解业务，不固化为通用定义。
4. 不明白就保留疑问；缺失类型、定义、关系端点时不得编造内容满足必填。
5. 保存的新本体结构必须合法；业务正确性仍待人工验证。生成任务的草稿与正式本体草稿是两个生命周期。
6. 范围确认、生成和正式保存是明确动作；对话中的意图不直接写入正式本体。

## 3. 入口、页面与用户流程

入口建议：本体工作区“新建”下提供“空白本体 / 从物料生成”；工作概览可提供同名快捷入口。未选本体也可使用。生成任务为账号级资源，不隶属于当前选中本体。不新增项目菜单，不重做本体管理模块。

| 编号 | 页面 | 用户任务 | 本轮新增内容 |
|---|---|---|---|
| A01 | 生成任务 | 新建、继续任务 | 名称、最近阶段、材料数、更新时间、继续按钮；首次为空态 |
| A02 | 物料 | 添加材料并了解解析覆盖 | 类型/文件清单、扫描报告、失败定位、重试或排除 |
| A03 | 确定范围 | 和LLM多轮讨论 | 左侧对话、右侧可编辑范围摘要、依据和未决问题 |
| A04 | 生成 | 了解真实阶段与阻塞 | 分阶段进度、输入基线、失败重试、取消、保留已完成中间结果 |
| A05 | 评审初稿 | 理解和裁剪候选 | 类型/状态筛选，定义编辑、字段级证据、冲突、纳入/暂缓/排除、合并 |
| A06 | 保存新本体 | 最终核对 | 数量、依赖与结构检查、未纳入内容、名称、保存结果与返回任务 |

正常路径：创建任务→添加材料→扫描→多轮澄清→确认范围→生成→人工评审→保存新本体→进入现有对象建模。

可以返回修改范围/物料。修改后旧结果仅可查看，不可直接保存；重新确认并生成新结果修订。人工修改和排除决策保留，与新候选冲突时显式比较，不自动覆盖。

## 4. 物料接入与解析范围

### 4.1 入口与支持程度（建议矩阵，待评审）

| 输入 | 第一版建议支持 | 边界 |
|---|---|---|
| 代码 | 文件/文件夹或ZIP；优先Java Spring/MyBatis/JPA、Vue/React JS/TS、Python常见结构 | JS/TS、Java、Python结构解析；框架映射必须有专项适配。其他语言以文本线索降级，提示覆盖不足，不称完整理解 |
| 数据库结构 | SQL DDL文件；数据字典Excel/Markdown | 优先MySQL常见DDL。其他方言识别失败可作为文本线索；不连业务数据库，不读取表数据 |
| Word | DOCX段落、标题、表格 | .doc提示转换为.docx；页码不稳定时用标题路径+段落/表格编号定位 |
| PDF | 文本型PDF；扫描页OCR为候选支持范围 | 文本/表格顺序不确定标记低质量；OCR未配置或失败则逐页报告，不假称解析成功 |
| Excel | XLSX多Sheet、表头、单元格、公式及可用缓存值 | 不执行宏/外链；缺少公式缓存不能当计算结果；.xls建议提示转换 |
| Markdown | MD标题、段落、表格和代码块 | 保留章节路径和行号 |

输入只要求至少一份可解析相关材料，不强制代码/DDL/文档齐全。材料缺失降低覆盖度并告知，不自动补造。ZIP不是上传可执行环境；不构建或运行代码，不执行SQL、宏或文档指令。密钥、凭据文件、构建产物、依赖目录默认排除；可查看排除清单。

文件/任务大小、解析时间、ZIP展开文件数与体积必须有上限并提前显示；具体数值待样本试验确定。防目录穿越、符号链接越界和解压炸弹。首版不要求Git托管平台连接器、远程仓库登录或在线数据库目录获取。

### 4.2 扫描反馈

每份材料展示：文件名、类型、解析状态、识别模块、定位方式、纳入片段数/失败片段数。状态至少有待处理、解析中、成功、部分成功、失败、用户排除。失败可重试或排除，不能静默当空文件继续。

没有相关可用证据时阻止生成。部分失败可以继续，但需用户明确确认覆盖缺口，缺口进入生成和保存摘要。上传新材料或改变排除状态使扫描/范围/结果基线失效；相同内容哈希可复用解析，不将重复副本视为独立佐证。

## 5. 多轮范围澄清

### 5.1 对话行为

用户可先表达目标，再上传材料；扫描后基于真实识别结果继续追问。每轮优先一至两个会影响建模边界的问题，给简明建议及理由，允许自由输入、“不确定”和暂缓非关键问题。无固定轮数，不为填满表单反复追问。

例如：检测到设备管理、监测、计划、收益结算→询问纳入模块；发现园区/电表为关联概念→询问是否只保留必要关联，避免扩张到园区全部业务。

LLM失效时保留对话和范围，可重试或手工编辑摘要；不能伪造回答、未经确认自动缩小范围。物料中的提示词与命令是材料内容，不是系统指令。

### 5.2 范围摘要

| 内容 | 必要性 |
|---|---|
| 目标业务与用途 | 用户理解的建模目标；初步名称不要求唯一 |
| 纳入范围 | 业务模块、对象范围及所需深度 |
| 排除范围 | 明确不生成的业务/技术内容 |
| 必要关联 | 公共概念只保留到什么程度 |
| 材料覆盖和冲突 | 缺文档、缺依赖代码、不同版本材料等 |
| 待确认问题 | 区分阻断范围确认与可留到候选评审的问题 |

用户可直接修改摘要，也可继续对话；人工修改不能被后续模型响应悄悄覆盖。存在重大矛盾（同一模块同时纳入和排除且无解释）时不能确认。点击“确认范围并生成”记录材料清单/哈希、范围修订、解析版本和模型配置标识，不记录密钥。

确认后变更范围：保存新的范围草稿，提示旧结果过期；必须再次确认。晚到的扫描/LLM/生成响应不能覆盖新基线。不能仅用聊天最后一句作为生成依据。

## 6. 自动构建逻辑与质量要求

| 阶段 | 方法建议 | 产物与失败处理 |
|---|---|---|
| 解析 | 语法树、框架适配、DDL解析、文档结构/OCR | 带定位的事实记录；降级说明及失败列表 |
| 筛选 | 关键词+语义检索、必要时重排序；按依赖有限扩展 | 相关/关联/排除/待确认片段；记录原因 |
| 对齐 | 显式映射优先，名称/结构/上下文辅助 | 跨前端、后端、表、文档的证据组，不仅按同名合并 |
| 抽象 | LLM依据任务范围和证据生成结构化候选 | 对象/属性/链接/规则/动作及关系；事实/推断/冲突分开 |
| 复核 | 类型/引用等确定性检查+证据语义复核 | 问题位置、原因及可修复建议；模型互相同意不算事实证明 |
| 适配 | 对接当前工作台协议与关联模型 | 合法可预览的候选数据，不直接写真实本体 |

这些是职责说明，未冻结具体算法库、模型、向量库或图数据库选型。第一版无需训练专有模型或建设通用编排引擎。检索分数只用于排序，不展示为准确率；模型自报置信度不决定自动纳入。

过滤不能只按文件名。链接数量关系需要约束/文档/实现依据；外键本身不能证明目标一侧必然拥有记录。复杂计算需保留过滤、单位、缺失值、分支和时间口径，缺代码则标记不完整。不把HTTP方法等同于动作语义，不从常识补充材料未提及的阈值和控制行为。

每阶段保存结果和版本，可取消、失败重试；取消不创建本体。复用中间结果必须匹配输入基线。任务进度用真实阶段和已处理数量，无法估时不展示虚假倒计时；模型调用次数/用量可在任务详情查看。离开页面不中断任务；服务重启不能显示“仍在运行”假状态，应标为中断并允许恢复/重试。

## 7. 本体输出及协议适配

生成数据是本工作台自有格式，不宣称兼容Foundry或任意OWL导入。接口以现有`文档/接口文档/01-通用约定与数据模型.md`及相关分册为准；未来实施须先核实最新协议与字段精简是否落地，不能仅照旧示例写数据。

| 定义 | 生成内容 | 限制 |
|---|---|---|
| 对象 | 名称、业务定义；有依据的别名等现有选填 | 不要求对应实体表；虚拟聚合对象可有依据地生成 |
| 属性 | 名称、业务定义、数据类型；时间序列观测值类型；有依据的显示格式 | 文本/数值/是或否/时间/数组/结构体/时间序列按现有枚举；复杂子结构遵循现行协议。无依据不猜单位和精度 |
| 共享属性 | 语义、类型、口径一致的跨对象定义及引用 | 不套用Excel“默认全共享”；默认对象私有，提出共享建议供确认，不因同名自动合并 |
| 链接 | 名称、业务定义、两端对象、数量关系、现有反向描述 | 两端稳定ID引用；缺数量关系或端点时留候选，不能随意默认多对一 |
| 业务规则 | 名称、业务定义；规则内容选填；对象关联 | 沿用字段精简需求，不要求输出签名，不创建可执行公式 |
| 动作 | 名称、业务定义；预期效果选填；对象关联 | 不新增输入参数、提交条件、API路径、权限或执行实现 |

规则/动作字段依据：[规则与动作字段精简需求](../20260920_规则动作字段精简与Excel模板同步/需求说明.md)。业务关联使用当前协议，不强加未支持的“规则绑定属性”等新关系；来源信息可以记录“此规则与某属性相关”的分析线索。

所有ID由受控生成/保存机制分配，模型不自行发明引用；definitionOrder与各定义集合一致。任务候选ID与正式定义ID有显式映射，转换后引用全量校验。未知解析元数据留在任务侧，不塞进本体业务定义。来源、页码、代码片段、分析结论及人工决定属于任务附件，需能从生成后的本体入口返回任务查看；不改现有配置迁移包自动包含原始代码的行为。

## 8. 候选评审

### 8.1 两条状态轴

- 证据状态：有依据、推断待确认、来源冲突、材料不足。按字段记录，记录级取需要关注的状态；不做伪精确百分比。
- 人工决定：拟纳入、暂缓、已排除。另记录未审阅/已审阅；“拟纳入”不等于人工已验证。

有依据且结构完整的候选默认拟纳入；弱证据/冲突/结构不完整默认暂缓。用户可批量查看有依据项，但保存前必须明确确认选定集合。弱证据转为拟纳入时需补充定义、说明确认依据；来源冲突需明确采用口径或手工改写并记录理由。批量纳入不能绕过冲突或结构问题。

### 8.2 评审页面

左侧候选列表支持类型、决定状态、证据状态、名称搜索；中部编辑定义；右侧/窄屏下方展示按字段分组的证据。证据包含文件、章节/页码/单元格/源码行、原文片段、支持的字段、材料修订及解析质量。

支持保存编辑、取消、纳入/暂缓/排除；显示关联对象和下游依赖。排除对象而仍纳入其属性/链接时，应提示具体依赖并阻止最终保存，不能静默级联删除。保留所有被排除项，支持恢复；候选为空仍可返回范围重新生成。

合并只处理类型兼容的重复定义，用户选择保留项、确认字段差异及关联变化；保留双方证据与原候选到新候选的映射。跨对象属性转共享需另确认语义一致，不等同于名称去重。不能合并不兼容数据类型或关系角色。撤销合并需恢复先前字段与关联；有后续编辑时先提示影响。

### 8.3 再生成

重新生成产生新结果修订，不覆盖旧评审。以候选身份和证据来源辅助对齐，展示新增、变动、消失、人工修改冲突。保留人工否决记录；新证据支持重新提出时标明原因。禁止再次生成自动复活已排除候选。本期可完整重跑，精细增量计算不是必要条件。

## 9. 保存新本体

1. 显示选定对象/属性/链接/规则/动作数量、共享方案、依赖、结构错误及未解决问题。
2. 暂缓/排除项不写入本体，留在任务中；非阻断问题和解析覆盖缺口随摘要展示。某个暂缓项被选定项依赖时仍阻断。
3. 输入新本体名称，名称非空；同名时提示修改或明确选择后缀新建，绝不覆盖/合并已有本体。仍沿用账号隔离。
4. 确认“这是待人工继续完善的草稿”，执行最终服务端协议/依赖校验，原子创建新资产及草稿。不能只有前端校验。
5. 重复点击、超时重试同一请求只创建一个本体；重试使用同一请求身份。任务修订过期/CAS冲突时不写，保留选择和输入。
6. 成功显示新本体ID和进入对象建模入口；本任务记录已交付目标。继续编辑本体由现有工作台负责，不再自动同步生成结果。
7. 本期一个任务完成一次创建；再次生成新资产需复制为新任务并再次确认，不能重复“保存”批量造本体。

不调用发布，不修改当前本体、项目或发布历史，不复制真实连接配置、凭据或业务实例。

## 10. 任务与数据边界

任务属于当前账号，列表/文件/证据/结果同样隔离；跨账号不可通过ID访问。记录任务名、目标、物料清单和内容哈希、阶段、范围修订、生成批次、候选、人工决策、错误与交付目标。长任务可断点恢复；自动保存必须有明确状态和冲突反馈。

生成数据/元数据走现有存储与接口规范，不手工写ontology旧目录，不绕过API直接写SQLite。大文件实体存储方式留到开发计划确定；需与任务记录、清理生命周期一致。任务及文件删除必须独立确认；已创建本体不随任务删除，删除后原始证据不可用须明确提示。第一版可不提供任务批量清理，但不能无上限静默保留上传失败临时文件。

复用工作台模型设置。上传材料本身不触发外发；开始扫描/对话/生成前标明是否调用远程模型以及将发送的材料范围。模型密钥不进入任务、响应或日志。远程模型不可用时保留结果，不自动切到其他供应商。技术文件/文档均按不可信内容处理，禁止执行其中命令或按其指令改变任务范围。

## 11. 储能贯穿示例（演示数据）

| 证据/问题 | 预期结果 |
|---|---|
| 实体、DDL、页面共同说明capacity为额定容量 | 生成数值属性并保留三处证据；没有单位证据不补单位 |
| Redis实时SOC与采样流程 | 相同基本业务含义，分别生成数值与时间序列候选；不创建连接或编排 |
| storage_id且实现/文档说明所属设备 | 生成簇到设备链接；数量关系按依据确认 |
| 系统无表但文档与汇总代码定义设备集合 | 可以生成系统对象及组成链接 |
| 设备SOC：文档加权、代码简单平均 | 规则默认暂缓，列双方原文，不替用户选口径 |
| setPower(0)与停止按钮 | 动作可被提出，但无业务效果依据时保留待确认，不推断断电 |
| 物料包含光伏、收益结算、权限模块 | 按确认范围排除；园区按必要关联保留；公共工具不生成对象 |
| Word损坏或PDF部分OCR失败 | 明确覆盖缺口；重试/排除/确认缺口后继续，不宣称全量解析 |

## 14. 原型与参考

原型只在内存运行，演示完整主流程、模拟多轮对话、扫描失败/重试、范围确认、分阶段生成、证据/冲突评审、依赖保护及新建草稿。可选择文件仅显示文件元信息，不解析内容；预置示例物料及证据均为虚构。对话采用显式建议选项与本地示例回复，自由输入只记为待核对说明，不具备真实LLM理解。模型、进度、保存与新本体页面均模拟；刷新复位，不调用任何接口，不产生正式本体。
