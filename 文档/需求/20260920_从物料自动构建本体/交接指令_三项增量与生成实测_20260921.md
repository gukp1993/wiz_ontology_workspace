## 2. 任务二：chuangzhiyuan2.zip 生成实测（API 全链路，真实模型）

素材：`/Users/gukepeng/Desktop/ZHDL/code/chuangzhiyuan2.zip`（**177MB / 13724 条目 / 解压 248.9MB / 8190 个 .java / 724 个 .xml / 含大量 `._*` 垃圾与 `.dll/.so` 二进制**）。限额已放宽可直接整包上传（capabilities 实测 fileBytes=268435456）。

用 Python 标准库脚本执行（`urllib` + `http.cookiejar`；**必须用 `urllib.request.build_opener(urllib.request.ProxyHandler({}))` 绕过本机 7890 代理**）。范围：储能相关（用户指定）。

链路（按序，全部走 http://127.0.0.1:18881）：
1. `POST /api/auth-login` `{username:admin,password:admin}`（cookiejar 保持会话）；
2. `GET /api/llm-providers` → 取 MiniMax-M3 的 id；`POST /api/llm-provider-default` 切默认（GLM 今日 429）；
3. `POST /api/build-task-create` `{name:"创智源储能生成实测"}` → taskId；
4. `GET /api/build-capabilities` 取 chunkBytes（524288）；整包分片上传：每片 sha256 + base64 → `POST /api/build-upload-chunk`（约 360 片，串行）；`POST /api/build-upload-complete` `{finalHash}`（服务端自动安全展开 1.3 万+ 物料）；
5. `POST /api/build-scan` → 轮询 `GET /api/build-run?taskId=…` 至终态（1.3 万文件解析可能 10–40 分钟，轮询间隔 5s、耐心等）；
6. `GET /api/build-messages` 取 revision → `POST /api/build-scope-save`：
   `goal="储能相关业务本体初稿"`、`include="储能设备、储能监测、储能运行"`、`exclude="权限、日志、导出"`、`coverage="聚焦储能相关模块"`（纳入/排除词不得互为子串，否则 422 阻断）；
7. `POST /api/build-scope-confirm` `{taskId, revision, providerId:"llm-8a581a91f9"}`（MiniMax id 以第 2 步实查为准）→ 轮询生成 run 至终态（真实模型多批调用，可能 10–20 分钟）；
8. `GET /api/build-candidates?taskId=…` 统计（按类型/证据状态/决定），抽样 5–10 个候选名记录；
9. `POST /api/build-deliver-precheck` → `POST /api/build-deliver` `{taskId,name:"创智源储能本体",checkToken,requestId:"trial-chuangzhiyuan-1"}`（requestId 固定，超时可原样重试，服务端幂等）→ 记录 ontologyId。

**失败纪律**：任何一步失败如实报告接口原文（尤其 run.error），不得伪造成功、不得降级当成功；模型 429/超时按 retryable 重试一次。全程不改任何后端/前端文件、不重启 18881（生成在后台线程跑，重启会杀掉它）。
