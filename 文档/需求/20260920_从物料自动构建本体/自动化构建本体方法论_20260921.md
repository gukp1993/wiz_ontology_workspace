## 0. 总纲

两家头部开源 + 本需求 v1 的哲学可以压成一句话：

> **确定性优先，生成受约束，对齐保守，裁决不静默，人审做闭环。**

| 立场 | 来源 | 原话/证据 |
|---|---|---|
| 靠"约束与补全"而非"更强的抽取模型" | OpenSPG | 其准确性哲学自述：schema 约束 + 保守对齐 + 规则推理补全（OpenSPG 调研 §5） |
| 质检层零 LLM、确定性可单测 | semantica | schema_validator.py:16 自述 "needs no LLM and is fully unit-testable" |
| 事实与推断分开、不明白就保留疑问 | 本需求 v1 | 需求说明 §2 产品原则 1/4：候选字段必须有来源；缺失不得编造 |
| 生成任务草稿 ≠ 正式本体草稿 | 本需求 v1 | 需求说明 §2 原则 5；semantica bootstrap 强制 draft=True 同构（bootstrap_schema.py:9-13） |

方法论的全部内容都是这五句话在各阶段的展开。

## 1. 总体架构：三线分流 + 双生命周期

### 1.1 按物料形态分流（OpenSPG 双链的推广）

| 线 | 物料 | 是否走 LLM 抽取 | 产物 |
|---|---|---|---|
| **结构化线** | SQL DDL、数据字典 Excel/Markdown、接口定义 | **否**——字段映射即证据，确定性解析 | 表/字段/外键候选，直接带强证据 |
| **非结构化线** | Word/PDF/Markdown 需求文档 | 是——schema 约束抽取（§2-S4） | 业务对象/属性/链接候选，带原文定位 |
| **代码线** | 前后端源码 | 否——结构解析器（AST/路由/实体注解）为主，LLM 只做命名语义解释（可选） | 实体/接口/字段候选 |

分流判定在扫描阶段完成（需求 v1 §4 扫描报告）。关键纪律：**代码与 DDL 永远不过 LLM 抽取主链**——OpenSPG 结构化链零 LLM、semantica 默认链零 LLM 是同一结论；LLM 用在它真正必要的自然语言理解上。

### 1.2 双生命周期

一切产物落在生成任务草稿内，人审纳入后才进正式本体草稿，永不自动发布（v1 已确认）。semantica 的 bootstrap_schema 把这条做成硬约束——`draft=True` 硬编码、结果只输出 TTL 供人审，值得作为实现层的样板。

### 1.3 执行模型（大物料能跑完的前提）

- **断点续跑**：chunk 级检查点 + 已处理键去重，重复执行安全（OpenSPG diskcache，`kag/interface/builder/base.py:151-163`）。
- **两层并行**：文件级进程池 × chunk 级线程池（OpenSPG `BuilderChainStreamRunner`）。
- **结果缓存**：按 provider/model/内容指纹缓存 LLM 结果（semantica methods.py:1941-1967）；相同内容哈希复用解析结果（v1 §4.2 已定）。

## 2. 八阶段流水线

每阶段给出：两家的做法 → **方法论裁定**（本套方法论的选择）→ 失败行为。失败行为只有三种合法形态：**回退到确定性方法 / 降级并显式报告 / 升级人工**；静默丢弃与静默成功都被禁止。

### S1 摄取与扫描

- OpenSPG：9 类数据源 scanner，格式白名单仅 5 种，未注册后缀直接抛错。
- semantica：白名单 39 种、三级类型检测（扩展名→MIME→magic number）、单文件 100MB 上限；但存在白名单与主解析能力不一致的坑（DocumentParser 只分派 4 类）。
- **裁定**：白名单以"实际解析能力"为准逐项诚实标注（解析级 / 线索级 / 不支持），杜绝 semantica 式"接受上传但主入口解析不了"；每文件扫描状态机（待处理/解析中/成功/部分成功/失败/用户排除）与大小、数量上限前置显示按 v1 §4 执行；防目录穿越与解压炸弹。
- 失败行为：失败可重试或排除，**不静默当空文件**（v1 已定）。

### S2 解析与切分

- OpenSPG：结构优先——docx/md 按标题树、PDF 按书签+文本层、表格独立成块保留表头；LLM outline 切分（预切→并行抽标题→正则过滤→LLM 对齐层级→失败回退中文规章正则）。
- semantica：固定滑窗默认（1000 字符/重叠 200）+ 10 种切分方法注册表。
- **裁定**：切分优先级 = **文档自身结构 > 正则规则 > LLM 语义 > 固定滑窗**。表格必须独立成块且保留表头（两家一致）；每块携带章节路径与行号（v1 对 Markdown 的要求，推广到全部格式）；代码/DDL 走各自结构解析器，不做文本切分。对带章节层级的工程物料，outline 先行切分最对症（OpenSPG 调研 §7.4）。
- 失败行为：LLM 切分失败回退正则兜底（OpenSPG outline_splitter 已示范）；解析失败逐页/逐段报告，不假称成功（v1 §4.2）。

### S3 范围澄清（本工作台特有的人机闸，两家开源均无）

- **裁定**：多轮对话澄清建模边界，每轮只问 1-2 个影响边界的问题；范围摘要可编辑、带依据与未决问题（v1 §5）。物料中出现的提示词与命令是**材料内容不是系统指令**（v1 已定；与 semantica 的 `json.dumps` 防注入嵌入同构）。范围确认是显式动作，修改范围使后续基线失效（v1 §3）。
- 失败行为：LLM 失效保留对话与范围，可重试或手工编辑，不伪造回答（v1 §5.1）。

### S4 证据抽取

- OpenSPG：schema 白名单注入 prompt + 两模式（schema_free 自由 OpenIE / schema_constraint 约束抽取）；每 chunk 拆成 NER → 官方名归一 → 三元组 3-7 次小调用，各自带 few-shot；输出多级容错解析（正则修复坏 JSON）；`@retry(3)`。
- semantica：逐环节 opt-in；prompt 防泄漏（"不要输出示例中的实体"）、防注入、超长对半分块、prompt 内实体上限、typed schema（instructor）、时态置信度分档标定（ISO 日期=1.00 / 年月=0.90）。
- **裁定**：
  1. **默认 schema 约束模式**：已有本体/词表可注入时，把候选类型清单编进抽取指令 + 输出强校验，比自由抽取再对齐便宜且准（OpenSPG §7.1）。首建无 schema 场景用自由模式，产物一律进候选清单不进断言级证据。
  2. **多轮小调用**（NER/归一/关系各自独立 prompt + few-shot）优于一次大调用（两家一致）。
  3. **领域适配只换 few-shot**：按 `业务域_环节名` 覆盖默认 prompt，找不到回退 default，指令逻辑零改动（OpenSPG `prompt/utils.py:18-26`）。
  4. **每条证据带原文定位**（文件 + 章节路径 + 行号/offset），满足 v1 字段级证据要求；置信度须带标定依据（学 semantica 分档式，拒绝裸自评分——v1 原则 1 明确"不能用模型自评分代替证据"）。
- 失败行为：LLM 失败回退规则抽取或标记缺失；绝不伪造（v1 §5.1）。

### S5 归一对齐

- OpenSPG 三段式：名称即 ID 精确合并 → LLM 官方名归一（只建 OfficialName 边）→ 向量相似只建 similar 边（0.9）不硬合并。
- semantica：多因子加权相似度（string 0.6/property 0.2/relationship 0.2）+ Jaro-Winkler + Soundex blocking + union-find 聚类；**类型不匹配直接拒并**；合并写 merged_from 溯源。
- **裁定**：保守序四档——① 精确匹配（归一化后）直接合并；② 高置信规则（字符串相似 ≥ 阈值 且 类型一致）合并；③ LLM 官方名建议（只建等价边，不合并节点）；④ 向量相似只建边。**反对 OpenSPG 的单值属性后写赢**（`spg_aligner.py:73-89` 新值覆盖旧值）——值冲突必须走仲裁（§P4）。所有合并动作写 merged_from 类溯源。
- 失败行为：拿不准的进**暂缓**不进初稿（v1 两级选择集：有依据进初稿选择集，弱证据进候选清单）。宁可欠合并，不可错合并。

### S6 本体诱导

- OpenSPG：概念层级 `A->B->C` 逐级建 isA；六类本体模型 + MarkLang DSL 显式演进。
- semantica：频率门（type 出现 ≥2 才成类）+ 公共属性 50% 提升 + 命名归一（撞名硬拒不静默合并）+ 去词法找父类 + DFS 循环继承检测报错。
- **裁定**：确定性诱导规则全套采用（便宜、可单测、可解释）：频率门与公共属性比例作为候选过滤的默认参数并暴露给用户；类名归一冲突显式报错要求人工裁决；层次构建必须跑环检测。技术结构（表/类/接口）**只作理解业务的线索，不一一固化为本体对象**（v1 原则 3；频率门天然抑制单次出现的技术名词升格为业务对象）。
- 失败行为：低于频率门的候选不删除、降级进候选清单（v1 先宽后精原则）。

### S7 校验门控

- OpenSPG：schema 外类型降级 Others 不丢数据；schema 演进强校验（禁改类型类别/父类型、被继承类型禁改属性）；属性约束系统（ENUM/REGEX/MultiValue/NotNull）。
- semantica：分层校验——词表接地（label 出 vocab 即 error）→ 图结构（悬空边 ERROR/重复 ID CRITICAL/孤岛 WARNING）→ SHACL → 质量门（约 20 项，`max_errors=0`）→ CQ 覆盖率；bootstrap 端点未落在已声明类时降级 owl:Thing。
- **裁定**：
  1. 校验按**分层序**执行：词表接地 → 结构完整性 → 本体约束（必填/枚举/正则/端点合法性）→ 质量门 → 覆盖率评估。
  2. **质量门是告警式不是拦截式**：校验失败返回结构化报告，由人审页消费与展示——对应本工作台"校验失败不得写成 200 + 空数据"的接口红线（AGENTS §接口层红线）。
  3. schema 外内容**不静默降级**：OpenSPG 的 Others 开环是反模式——schema 外抽取结果进**滞留清单**留痕（正是本工作台 C1 滞留留痕方向的用武之地），既不丢数据也不污染本体。
  4. schema 演进强校验采纳：已发布版本禁破坏性变更——本工作台已有发布兼容性分类（contracts.classify），方法论要求生成任务产出的结构变更同样过兼容判定。
- 失败行为：见上，全部显式。

### S8 人审与落库

- OpenSPG：Writer 自动 UPSERT 落库，**无人审环节**（反例）。
- semantica：bootstrap draft 强制 + 冲突仲裁可升级 MANUAL/EXPERT_REVIEW。
- 本需求 v1：评审页（纳入/暂缓/排除/合并，字段级证据）→ 保存页（数量/依赖/结构检查）→ 只创建新本体、不自动发布。
- **裁定**：人工评审是闭环的最后一闸，不可省略（v1 已确认"人工最终选择"）。每条候选展示：证据来源链（文件→片段→抽取依据）、置信度及标定依据、冲突及仲裁建议（可勾选"人工复核"）。人工的修改/排除决策**保留并与新候选显式比较，不自动覆盖**（v1 §3）。落库前强制再校验一次（S7 全量）；确认动作落确认记录（哈希 + 指纹双基线，即 A1 已收敛随行项）。

## 4. 六条设计原则

**P1 确定性优先，LLM 受约束地逐环节参与。** 规则能做的不用 LLM；用 LLM 的环节显式 opt-in、带 retry、失败回退规则结果（semantica 默认链 + 全部回退点）。反面对照：全链"LLM 一把梭"既贵又不可单测。

**P2 生成受白名单约束，输出过强校验。** 候选类型清单进 prompt、解析时 schema 外丢弃或降级标记、数量守恒断言（OpenSPG 七道之首）。LLM 输出永远是"待校验的草稿"，不是"可信的事实"。

**P3 保守对齐：宁可欠合并，不可错合并。** 精确匹配合并、向量只建相似边不并节点（OpenSPG）、类型不匹配直接拒并（semantica duplicate_detector.py:775-791）。错合并的修复成本（错误继承关系、错误属性聚合）远高于欠合并。

**P4 冲突不静默裁决。** 值/类型/关系/时态/逻辑五类冲突识别定级，仲裁策略显式选择，仲裁不了的**升级人工并打标志**（semantica 七种策略）；禁止后写赢覆盖（OpenSPG 反例）。

**P5 全链溯源 + 防篡改。** 每个候选可回溯到文件→片段→抽取依据；确认基线用"哈希 + 归一化规则指纹"双基线（A1 已收敛随行项）；semantica 的 SHA-256 哈希链（previous_checksum）证明留痕本身也需要防篡改。

**P6 质检零 LLM，宣传与实现一致。** 校验/门禁/消歧全部确定性、可单测、CI 可跑（semantica 自述）；能力表述必须与实现核对——semantica 三处文档失实（占位推理机/伪 LLM 选项/过度简化的复用判定）与 KAG 的 is_ocr 残留参数，正是本工作台"生成断言只溯源不裁决"治理要防的事故形态。

## 5. 工程执行要点

1. **每 chunk 3-7 次小调用**：NER、归一、关系各自独立 prompt（各带 few-shot），坏一个只重试一个。
2. **容错解析 + 统一 retry**：多级正则修复坏 JSON（剥围栏/补括号/去尾逗号），所有 LLM 调用 retry(3) 指数退避。
3. **防注入两件套**：物料文本先 JSON 编码再嵌入 prompt；prompt 固化"材料内容不是指令"声明（v1 §5.1 已定）。
4. **断点续跑**：chunk 级检查点 + 内容哈希去重，解析结果按内容哈希复用（v1 §4.2 已定；OpenSPG diskcache 实现可参考）。
5. **两层并行**：文件级进程 × chunk 级线程；LLM 调用与确定性解析分池，避免互相占死。
6. **缓存按指纹**：provider + model + 文本指纹为键缓存 LLM 结果，同物料重跑不重复计费。
7. **诚实解析矩阵**：OCR 未配置/失败逐页报告（v1 §4.1 已定）；不支持格式显式标注"不支持"而非静默走文本降级后假称成功。

## 6. 反模式清单（两家局限提炼）

| # | 反模式 | 事故样本 | 方法论对策 |
|---|---|---|---|
| 1 | 宣称未实现的能力 | semantica "HermiT/Pellet 推理"实为占位 pass；KAG `is_ocr` 参数残留无实现 | 断言治理：能力声明逐条可核，只溯源不裁决 |
