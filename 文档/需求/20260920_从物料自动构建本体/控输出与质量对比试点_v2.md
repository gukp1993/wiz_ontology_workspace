## 3. 模型输出减负，但不丢语义

### 3.1 compact-v1中间协议

保持可读命名，先不采用难调试的位置数组。顶层为codecVersion、candidates、coverage。candidate必含 key/type/name/evidenceStatus/evidence；其余字段按类型和证据出现：definition、ownerKey、fields、conflicts。不输出无用空数组、空字符串和重复默认值。

```json
{
  "codecVersion": "compact-v1",
  "candidates": [
    {"key":"battery","type":"object","name":"电池","evidenceStatus":"supported","evidence":{"name":["f0"]}},
    {"key":"battery_rated_power","type":"property","name":"额定功率","ownerKey":"battery","fields":{"dataType":"number"},"evidenceStatus":"supported","evidence":{"name":["f1"],"ownerKey":["f1"],"dataType":["f1"]}}
  ],
  "coverage": [{"unit":"u0","status":"processed"}]
}
```

f0/f1是本次调用限定的短别名，映射表由程序保存到原factId和定位。模型不能自行发明源ID；别名不跨批通用。示例只是形状，真实输出必须有对应材料证据。

程序负责生成数据库id、稳定命名空间、时间、批次/来源记录、UI结构和技术性空容器。不用模型生成同一结构的重复解释，也不要求最后输出全量本体。当前SYSTEM_EXTRACT已主要输出候选，实际可节约项须以编码长度和模型usage验证，不能把未由模型生成的字段计为“节省”。

严禁程序补造supported、关系基数、单位、owner、端点、业务定义。缺业务信息标未知/待确认。definition有区分意义时必须保留，不能为了省token强删。证据要保留字段级引用；不能把一条候选有一个引用当所有字段均获支持。conflict必须保留冲突两侧及来源。

### 3.2 去重和合并

第一轮仅确定性去重完全相同的结构事实，保留所有来源映射。不同单位、枚举、约束、名称或类型不折叠；不能只看布尔/短标量删除。业务结构与JSON包装元数据区分必须有路径规则及金样；没有规则则保留。

跨批对象按来源命名空间、结构身份和显式标识判断；禁止仅同名自动合并。属性身份含所属对象。跨批引用用已有稳定ID或本批局部key，不给模型全部历史候选。遇歧义，把候选对及必要原文交给小范围复核；最多8个额外复核调用/试验臂，超出标待确认。复核usage单列且计入总量，不隐藏。

## 4. 小批执行与恢复的试验参数

- 不根据文件字节预测总输出。一个单元是一个对象/表/章节/结构对象的定义片段及其证据；大单元按属性组或关系组继续拆，不按整文件分一个巨批。
- 首批最多4个语义单元；参考v1工程估算，以字段/关系数量而非单纯事实条数计算，系数须写入plan。试点只允许减小批次，不做自动扩批，减少变量。
- 可见正文目标约3000 token只是软目标；请求输出cap默认沿用当前32000并受实际模型能力约束，推理token可能占用其中部分。不能设cap=3000后声称仍能产出3000正文。绑定实际provider/model、contextLimit、输出cap及推理配置；缺能力资料先配置核实值，不猜1M。
- 输入预算估算必须覆盖system/schema/来源表/邻域等完整请求，满足I+输出cap+2048≤contextLimit；输出估算≤0.5×cap。有兼容tokenizer用真实计数，否则标UTF-8启发式，不声称精确。
- length/incomplete、输入超限、响应体超限均不可标成功；父批响应不作为完整候选。持久化拆分计划后再执行子批，primary目标守恒，重复context不计覆盖。
- finish=stop仍须严格JSON/字段/引用校验；若coverage缺目标或明确remaining，只能对缺项继续处理，不能接受为全批成功。模型自报processed不是语义完整证明，必须用金样评价漏项。
- 每次物理请求独立Attempt。格式修复最多1次，网络/429重试最多2次；错误类型区分，鉴权/模型配置错不拆批。拆分深度≤8；单个不可拆单元仍超限就blocked，不无限“继续”。
- 每个试验臂每个样本总Attempt≤64（包括重试与复核）、并发=1、墙钟≤30分钟、已知输出累计≥100000 token后停止派发；最多存在1个在途调用，报告最终实际可能越过软累计阈值。供应商不返usage时只靠调用/时间上限，不伪称账单上限。
- 独立实验结果存到明确指定的临时目录（不得默认真实ROOT），用SQLite事务保存计划、attempt、结果和来源映射；可用Python标准库sqlite3，不做业务DB迁移。每叶成功即提交，恢复仅调用未成功叶。
- 请求指纹包括材料hash/事实快照/建模范围/模型配置/prompt/codec/批内容。A/B各自命名空间；冷跑不共享缓存，恢复测试复用自己缓存；崩溃后的已发送未返回请求记unknown，不能保证供应商只收费一次。
- 最终JSON由程序序列化，图再大也不发起一次全量重写调用。有限局部复核不得演变成全量reduce。已有在线500候选限制在报告列明；独立试验结果不能绕过门禁写进正式草稿。

## 5. 试验矩阵：先看因果，再接页面

所有试验臂使用相同已解析事实快照、范围、模型版本、温度/推理配置和请求cap；记录实际HEAD与未提交差异，在线在途代码必须由owner交接后冻结基线。

| 臂 | 协议 | 分批 | 目的 |
|---|---|---|---|
| A | 当前候选协议 | 当前已交接实现（记录实际拆批/重试） | 真实对照，不伪造旧缺陷基线 |
| B | compact-v1 | 与A相同初始批与策略 | 观察协议减负效果 |
| C | 当前候选协议 | 本文语义小批＋恢复 | 观察调度效果 |
| D | compact-v1 | 本文语义小批＋恢复 | 观察组合效果 |

所有臂都需统一外层attempt计数与预算，A中内部重试也必须记账。首次只跑A/D各一次做冒烟，正确性通过再跑A/B/C/D；最终每臂至少3次独立冷跑，交错顺序，报告中位数和范围。耗费超过预设预算就停并报告未完成矩阵，不据一次偶然快慢下结论。

样本分三层：

1. 原8KB物料：执行者定位实际文件并记录hash；未找到就报告缺失，不伪造原样本。先人工建立类型、属性归属、关系端点、关键约束与证据金样。
2. 合成重复实例JSON：规模可放大至100MB，保持类型结构固定；另含稀有字段、不同单位、异常枚举，保证去重不能丢少数结构。先验证解析是否完整；如果当前解析只给数组摘要，标“解析边界”，不能拿低token宣称100MB完整建模。
3. 大Schema样本：增加独立对象类型/属性/关系，包含同名异对象、跨块关系、冲突与晚出现类型；验证真正的定义规模增长时可以拆分，不把大量内容简单去重掉。

先用假模型注入截断、非法引用、半批失败、usage缺失、取消与崩溃，不花真实模型费用验证调度；再对上述小样本真实调用。真实样本仅使用用户已授权给当前模型处理的材料；新样本先用合成数据，不扩大外传范围。

## 6. 指标与通过条件（试点门槛，不是效果承诺）

| 维度 | 报告口径/门槛 |
|---|---|
| 调度完整性 | 所有目标都有成功处理记录或明确阻塞；最终成功时未处理=0；注入截断不得误成功 |
| 证据与身份 | 已接受结果非法引用=0、悬空owner/端点=0；同名异主体金样不误合并 |
| 语义质量 | 小型确定性金样的关键类型、属性归属、关系端点、冲突保留100%；真实样本人工评审召回/精确率分别报告，D不得比A下降超过2个百分点 |
| Token | prompt/completion/reasoning分别报；reasoning若已包含于completion不重复相加；usage缺失写unknown；父截断/重试/复核全计入 |
| 可见输出 | 用同一tokenizer统计正文；没有时只报字符/字节，不与供应商completion直接相减冒充推理量 |
| H1收益 | B相对A可见正文token中位数降低≥20%，且质量通过，才确认协议减负值得接入；不足就保留原协议 |
| H2收益 | 注入故障用例完整通过，成功叶重试调用数=0；真实完成率/截断次数/最大单次输出如实报告，不要求首次绝不截断 |
| 成本/时延 | D总token若较A增加>10%，需说明稳定性收益与额外成本，由用户选择；速度单列，不用增加并发伪装节省token |

恢复暖跑与冷跑分表。测试结果不得把输入规模缩小、材料过滤、未完成或解析丢失当作节省。A/D都只是在相同事实快照上的比较；另外报告原文件→事实的解析覆盖，避免两个臂同样漏材料却得出质量合格结论。

- 回退用git revert，再验证；代码回退不还原数据。集成成功后按授权停止本人任务服务/worker、释放端口、清理已合并分支及工作树和登记可丢弃产物；真实数据副本、未提交内容或归属不明项保留并报告，删除需用户明确处置确认。不得强制清理绕过保护。
- 每阶段read共享上下文，交付前record、render，禁止手改session_context.md。只提交自己的文件与本轮记录；最终列分支/SHA/URL/ROOT、测试及限制、独立验收状态、main是否合并、清理/保留情况与主服务是否更新。
