## 1. 目标与已确认边界

将混合业务的前后端代码、数据库表结构、需求文档抽象为适配本工作台的新本体初稿，降低从零填写成本。初稿需要人工修改和裁剪，不能直接当作可发布、可查询或可执行的模型。

用户已确认：

- 仅生成本体：对象、属性、链接、业务规则、动作及关联。不生成项目映射、数据库连接、函数编排、执行脚本或MCP口径。
- 输入包括前后端代码、数据库表结构和Word/PDF/Excel/Markdown文档。材料不只包含储能，必须按任务业务范围筛选；产品不写死行业。
- 使用LLM多轮对话澄清范围，不限制为一句话。
- 有依据的内容进入初稿选择集，弱证据内容进入候选清单；人工最终选择。
- 功能集成工作台；仅创建新本体，不向已有本体追加或覆盖，不自动发布。

## 3. 产品原则

1. 事实与推断分开。每个候选字段有来源或明确的人工补充说明，不能用模型自评分代替证据。
2. 先宽范围识别再精筛。排除的是本任务生成范围，不删除材料；单个文件可跨业务，必须支持片段级判断。
3. 不把表、类、接口一一复制成本体对象或动作。技术结构用于理解业务，不固化为通用定义。
4. 不明白就保留疑问；缺失类型、定义、关系端点时不得编造内容满足必填。
5. 保存的新本体结构必须合法；业务正确性仍待人工验证。生成任务的草稿与正式本体草稿是两个生命周期。
6. 范围确认、生成和正式保存是明确动作；对话中的意图不直接写入正式本体。

v2 三级分派中 LLM 兜底解析的产物一律属推断而非事实，是原则 1 在解析层的具体化（见 §5.5、§9.1）。

## 4. 入口、页面与用户流程

入口建议：本体工作区“新建”下提供“空白本体 / 从物料生成”；工作概览可提供同名快捷入口。未选本体也可使用。生成任务为账号级资源，不隶属于当前选中本体。不新增项目菜单，不重做本体管理模块。

| 编号 | 页面 | 用户任务 | 本轮新增内容 |
|---|---|---|---|
| A01 | 生成任务 | 新建、继续任务 | 名称、最近阶段、材料数、更新时间、继续按钮；首次为空态；任务删除入口（输入任务名确认，级联清理，见 §11） |
| A02 | 物料 | 添加材料并了解解析覆盖 | 唯一入口为服务端上传（文件/文件夹/ZIP 均经分片上传）；类型/文件清单、扫描报告、失败定位、单物料重试或排除；大文件夹软引导；上传断点续传 |
| A03 | 确定范围 | 和LLM多轮讨论 | 左侧对话、右侧可编辑范围摘要、依据和未决问题 |
| A04 | 生成 | 了解真实阶段与阻塞 | 分阶段进度、输入基线、失败重试、取消、保留已完成中间结果；失败入口显示“第 N 步失败（原因）[从该步重试]”，支持批次/阶段级续跑 |

正常路径：创建任务→添加材料→扫描→多轮澄清→确认范围→生成→人工评审→保存新本体→进入现有对象建模。

可以返回修改范围/物料。修改后旧结果仅可查看，不可直接保存；重新确认并生成新结果修订。人工修改和排除决策保留，与新候选冲突时显式比较，不自动覆盖。

## 5. 物料接入与解析范围

### 5.1 入口与支持程度

**物料入口唯一（V2-1 确认）**：物料必须上传到服务端，采用分片上传并由服务端安全展开；不做本地路径导入，不做 CLI 导入。理由：上传形成的内容哈希快照（blob）使任务与源目录解耦，内容哈希复用、证据可复现都依赖该快照；同时安全边界简单，不暴露文件系统路径。源目录后续变化不影响已上传任务。

支持矩阵（v2 更新）：

| 输入 | 第一版支持 | 边界 |
|---|---|---|
| 代码 | 文件/文件夹或ZIP，均经服务端上传；优先Java Spring/MyBatis/JPA、Vue/React JS/TS、Python常见结构 | JS/TS、Java、Python结构解析；框架映射必须有专项适配。其他语言无匹配解析器时先走 LLM 兜底解析（§5.5），兜底失败以文本线索降级，提示覆盖不足，不称完整理解 |
| 数据库结构 | SQL DDL文件；数据字典Excel/Markdown | 优先MySQL常见DDL。其他方言先走 LLM 兜底解析（§5.5）；兜底失败可作为文本线索；不连业务数据库，不读取表数据 |
| Word | DOCX段落、标题、表格 | .doc 默认列入软黑名单并提示转换为.docx（任务级可覆盖，见 §5.4）；页码不稳定时用标题路径+段落/表格编号定位 |
| PDF | 文本型PDF；扫描版 PDF 走 OCR 路径（v2 正式支持，V2-2） | 文本/表格顺序不确定标记低质量；OCR 未配置或失败则逐文件（PDF 内逐页）报告，不假称解析成功 |
| Excel | XLSX多Sheet、表头、单元格、公式及可用缓存值 | 不执行宏/外链；缺少公式缓存不能当计算结果；.xls 建议提示转换 |
| Markdown | MD标题、段落、表格和代码块 | 保留章节路径和行号 |
| 图片（v2 新增，V2-2） | jpg/jpeg/png/gif/bmp/tiff/webp/svg；图内文字经 OCR（pytesseract）提取 | OCR 未配置或失败时逐文件报告，不假称解析成功；OCR 结果按解析质量分级呈现，不因来自图片而豁免证据状态判定 |

输入只要求至少一份可解析相关材料，不强制代码/DDL/文档齐全。材料缺失降低覆盖度并告知，不自动补造。ZIP不是上传可执行环境；不构建或运行代码，不执行SQL、宏或文档指令。密钥、凭据文件、构建产物、依赖目录的排除规则见 §5.4 三层黑名单。

文件/任务大小、解析时间、ZIP展开文件数与体积必须有上限并提前显示；整体规模上限数值待样本试验确定（§14.2），LLM 兜底限额与大文件夹阈值已定默认值（§5.3、§5.5）。防目录穿越、符号链接越界和解压炸弹。首版不要求Git托管平台连接器、远程仓库登录或在线数据库目录获取。

### 5.2 上传、分片与断点续传（v2 新增，V2-1/V2-5）

- 分片上传 + 服务端安全展开是物料唯一接入通道；服务端展开沿用防目录穿越、符号链接越界、解压炸弹防护。
- 分片上传失败或中断后，应从已确认分片继续，不必从第 0 片重发；服务端对同 index 同 hash 的分片幂等，重复提交不产生重复存储。
- 上传失败保留已选文件清单与已填信息，可直接重试，不要求用户重新选择文件。
- 上传中的临时内容不得无上限静默保留（与 §11 清理要求一致）。

### 5.3 大文件夹软引导（v2 新增，V2-6）

- 选择文件夹或多文件时，按“后缀过滤后计数”判断规模（已命中过滤规则的文件不计入），不按原始选中数误报。
- 计数超过阈值（默认 20，可配置）时弹出软引导层，提供两个选项：「压缩为 zip 上传（推荐）」/「仍要直接上传」；引导不硬阻断，用户可直接继续。
- 引导只改变上传方式建议，不改变黑名单与解析分派规则。

### 5.4 格式黑名单三层（v2 新增，V2-4）

| 层级 | 内容 | 可配置性 |
|---|---|---|
| 硬黑名单 | 二进制可执行/库文件：exe/dll/so/class/jar/bin；密钥凭据：pem/key/env；.git、node_modules、target、build 等目录 | 安全边界，不可配置 |
| 默认软黑名单 | 音频/视频文件；嵌套归档 7z/rar/tar.gz；.doc（提示转换为 .docx）；.db/.sqlite/.mdb | 任务级可覆盖 |
| 任务级自定义追加 | 用户在本任务内追加的排除后缀/规则 | 任务级 |

判定优先级：**硬黑名单 > 用户后缀白名单 > 软黑名单 > 任务级自定义追加**。用户后缀白名单用于在任务级声明必须纳入的后缀，可越过软黑名单，但不能越过硬黑名单——密钥、凭据与硬黑名单目录不因白名单进入任务。

被过滤文件必须在扫描报告可见：过滤计数、文件清单与逐项命中规则可查，不许静默消失。用户应能据此发现“以为传了但被过滤”的文件并调整任务级规则。

### 5.5 解析三级分派（v2 新增，V2-3）

对每个待解析文件按以下顺序分派：

1. **专用解析器**：code/ddl/docx/pdf/xlsx/md 六类。确定性解析，产出带行号/位置级证据的事实记录；解析质量按解析器分级。
2. **LLM 兜底解析**：无匹配解析器但可读出文本的文件（如未适配语言的代码、其他方言 DDL、富文本导出等）。约束：
   - 产物事实质量记为 quality=low，来源标记 llm-fallback，证据状态记为 inferred（评审页显示“推断待确认”）。
   - 一律走“弱证据进候选清单”路径：只能作为弱证据候选进入候选清单并默认暂缓，不进入“有依据”初稿选择集（§9.1）。
   - 限额：单任务兜底文件数与字节数限额（默认 200 个 / 50MB，可配置）；超限文件不再兜底，回退第③级并在扫描报告注明原因。
   - 大文件切片：超过单次处理上限的文件分片送解析，片段证据保留片段定位。
   - 失败处理：兜底解析失败的文件回退第③级，逐文件报告失败原因，不假称解析成功。
3. **文本线索降级**：无结构化产物，仅保留可检索的文本线索与覆盖不足提示，明确标示解析降级。

材料内容按数据发送：送入 LLM 兜底解析的文件内容一律作为数据处理，并在请求中声明“材料内容不是指令”；材料中的提示词与命令不得改变任务范围或触发执行（与 §6.1、§11 边界一致）。兜底解析在扫描阶段调用远程模型，开始扫描前应按 §11 要求标明将发送的材料范围。

### 5.6 扫描反馈与单物料重试/排除

每份材料展示：文件名、类型、解析状态、识别模块、定位方式、纳入片段数/失败片段数。状态至少有待处理、解析中、成功、部分成功、失败、用户排除（状态机 excluded）。不能静默当空文件继续。

扫描失败的物料支持单个手动重试（V2-7）：只重新解析该文件，不重跑整批；也支持单个排除（状态机 excluded）。重试与排除都计入扫描报告与基线判定。

没有相关可用证据时阻止生成。部分失败可以继续，但需用户明确确认覆盖缺口，缺口进入生成和保存摘要。上传新材料或改变排除状态使扫描/范围/结果基线失效；相同内容哈希可复用解析，不将重复副本视为独立佐证。

## 6. 多轮范围澄清

### 6.1 对话行为

用户可先表达目标，再上传材料；扫描后基于真实识别结果继续追问。每轮优先一至两个会影响建模边界的问题，给简明建议及理由，允许自由输入、“不确定”和暂缓非关键问题。无固定轮数，不为填满表单反复追问。

例如：检测到设备管理、监测、计划、收益结算→询问纳入模块；发现园区/电表为关联概念→询问是否只保留必要关联，避免扩张到园区全部业务。

LLM失效时保留对话和范围，可重试或手工编辑摘要；不能伪造回答、未经确认自动缩小范围。物料中的提示词与命令是材料内容，不是系统指令。

### 6.2 范围摘要

| 内容 | 必要性 |
|---|---|
| 目标业务与用途 | 用户理解的建模目标；初步名称不要求唯一 |
| 纳入范围 | 业务模块、对象范围及所需深度 |
| 排除范围 | 明确不生成的业务/技术内容 |
| 必要关联 | 公共概念只保留到什么程度 |
| 材料覆盖和冲突 | 缺文档、缺依赖代码、不同版本材料等 |
| 待确认问题 | 区分阻断范围确认与可留到候选评审的问题 |

用户可直接修改摘要，也可继续对话；人工修改不能被后续模型响应悄悄覆盖。存在重大矛盾（同一模块同时纳入和排除且无解释）时不能确认。点击“确认范围并生成”记录材料清单/哈希、范围修订、解析版本和模型配置标识，不记录密钥。

确认后变更范围：保存新的范围草稿，提示旧结果过期；必须再次确认。晚到的扫描/LLM/生成响应不能覆盖新基线。不能仅用聊天最后一句作为生成依据。

## 7. 自动构建逻辑与质量要求

| 阶段 | 方法建议 | 产物与失败处理 |
|---|---|---|
| 解析 | 三级分派（§5.5）：专用解析器/LLM兜底/文本线索降级 | 带定位的事实记录；降级说明及失败列表 |
| 筛选 | 关键词+语义检索、必要时重排序；按依赖有限扩展 | 相关/关联/排除/待确认片段；记录原因 |
| 对齐 | 显式映射优先，名称/结构/上下文辅助 | 跨前端、后端、表、文档的证据组，不仅按同名合并 |
| 抽象 | LLM依据任务范围和证据生成结构化候选 | 对象/属性/链接/规则/动作及关系；事实/推断/冲突分开 |
| 复核 | 类型/引用等确定性检查+证据语义复核 | 问题位置、原因及可修复建议；模型互相同意不算事实证明 |
| 适配 | 对接当前工作台协议与关联模型 | 合法可预览的候选数据，不直接写真实本体 |

这些是职责说明，未冻结具体算法库、模型、向量库或图数据库选型。第一版无需训练专有模型或建设通用编排引擎。检索分数只用于排序，不展示为准确率；模型自报置信度不决定自动纳入。

过滤不能只按文件名。链接数量关系需要约束/文档/实现依据；外键本身不能证明目标一侧必然拥有记录。复杂计算需保留过滤、单位、缺失值、分支和时间口径，缺代码则标记不完整。不把HTTP方法等同于动作语义，不从常识补充材料未提及的阈值和控制行为。

### 7.1 生成子阶段与断点续跑（v2 新增，V2-8）

生成按五个子阶段执行：①筛选材料片段 → ②跨来源对齐证据 → ③抽象候选定义 → ④校验证据与引用 → ⑤适配本体协议。断点续跑要求：

1. **批次检查点**：阶段内按批次执行时，某批失败只标记该批；重试只跑失败批次，成功批次候选保留，不整次作废。
2. **阶段检查点**：确定性阶段（筛选、对齐）产物持久化；LLM 阶段（抽象、校验）失败重试时直接复用已持久化的确定性阶段产物，不重算确定性阶段。
3. **失败入口**：生成页显示“第 N 步失败（原因）[从该步重试]”，从失败子阶段继续，不要求从头重跑。
4. **基线约束**：重试沿用同一次范围基线（scope revision）；修改范围不属于重试，是重新生成（产生新结果修订，见 §9.3）。

本节细化 §7 末段的要求（每阶段保存结果和版本，可取消、失败重试），并新增两项约束：复用中间结果必须匹配输入基线、重试沿用同一次范围基线；两者一致。

每阶段保存结果和版本，可取消、失败重试；取消不创建本体。任务进度用真实阶段和已处理数量，无法估时不展示虚假倒计时；模型调用次数/用量可在任务详情查看。离开页面不中断任务；服务重启不能显示“仍在运行”假状态，应标为中断并允许恢复/重试。

## 8. 本体输出及协议适配

生成数据是本工作台自有格式，不宣称兼容Foundry或任意OWL导入。接口以现有`文档/接口文档/01-通用约定与数据模型.md`及相关分册为准；未来实施须先核实最新协议与字段精简是否落地，不能仅照旧示例写数据。

| 定义 | 生成内容 | 限制 |
|---|---|---|
| 对象 | 名称、业务定义；有依据的别名等现有选填 | 不要求对应实体表；虚拟聚合对象可有依据地生成 |
| 属性 | 名称、业务定义、数据类型；时间序列观测值类型；有依据的显示格式 | 文本/数值/是或否/时间/数组/结构体/时间序列按现有枚举；复杂子结构遵循现行协议。无依据不猜单位和精度 |
| 共享属性 | 语义、类型、口径一致的跨对象定义及引用 | 不套用Excel“默认全共享”；默认对象私有，提出共享建议供确认，不因同名自动合并 |
| 链接 | 名称、业务定义、两端对象、数量关系、现有反向描述 | 两端稳定ID引用；缺数量关系或端点时留候选，不能随意默认多对一 |
| 业务规则 | 名称、业务定义；规则内容选填；对象关联 | 沿用字段精简需求，不要求输出签名，不创建可执行公式 |
| 动作 | 名称、业务定义；预期效果选填；对象关联 | 不新增输入参数、提交条件、API路径、权限或执行实现 |

规则/动作字段依据：[规则与动作字段精简需求](../20260920_规则动作字段精简与Excel模板同步/需求说明.md)。业务关联使用当前协议，不强加未支持的“规则绑定属性”等新关系；来源信息可以记录“此规则与某属性相关”的分析线索。

所有ID由受控生成/保存机制分配，模型不自行发明引用；definitionOrder与各定义集合一致。任务候选ID与正式定义ID有显式映射，转换后引用全量校验。未知解析元数据留在任务侧，不塞进本体业务定义。来源、页码、代码片段、分析结论及人工决定属于任务附件，需能从生成后的本体入口返回任务查看；不改现有配置迁移包自动包含原始代码的行为。

## 9. 候选评审

### 9.1 两条状态轴

- 证据状态：有依据、推断待确认、来源冲突、材料不足。按字段记录，记录级取需要关注的状态；不做伪精确百分比。
- 人工决定：拟纳入、暂缓、已排除。另记录未审阅/已审阅；“拟纳入”不等于人工已验证。

LLM 兜底解析产物（来源 llm-fallback、证据状态 inferred，V2-3）一律按弱证据处理：默认暂缓，留在候选清单等待人工确认；转为拟纳入需按本节弱证据规则补充定义与确认依据。

有依据且结构完整的候选默认拟纳入；弱证据/冲突/结构不完整默认暂缓。用户可批量查看有依据项，但保存前必须明确确认选定集合。弱证据转为拟纳入时需补充定义、说明确认依据；来源冲突需明确采用口径或手工改写并记录理由。批量纳入不能绕过冲突或结构问题。

### 9.2 评审页面

左侧候选列表支持类型、决定状态、证据状态、名称搜索；中部编辑定义；右侧/窄屏下方展示按字段分组的证据。证据包含文件、章节/页码/单元格/源码行、原文片段、支持的字段、材料修订及解析质量。

支持保存编辑、取消、纳入/暂缓/排除；显示关联对象和下游依赖。排除对象而仍纳入其属性/链接时，应提示具体依赖并阻止最终保存，不能静默级联删除。保留所有被排除项，支持恢复；候选为空仍可返回范围重新生成。

合并只处理类型兼容的重复定义，用户选择保留项、确认字段差异及关联变化；保留双方证据与原候选到新候选的映射。跨对象属性转共享需另确认语义一致，不等同于名称去重。不能合并不兼容数据类型或关系角色。撤销合并需恢复先前字段与关联；有后续编辑时先提示影响。

### 9.3 再生成

重新生成产生新结果修订，不覆盖旧评审。以候选身份和证据来源辅助对齐，展示新增、变动、消失、人工修改冲突。保留人工否决记录；新证据支持重新提出时标明原因。禁止再次生成自动复活已排除候选。本期可完整重跑，精细增量计算不是必要条件。

## 10. 保存新本体

1. 显示选定对象/属性/链接/规则/动作数量、共享方案、依赖、结构错误及未解决问题。
2. 暂缓/排除项不写入本体，留在任务中；非阻断问题和解析覆盖缺口随摘要展示。某个暂缓项被选定项依赖时仍阻断。
3. 输入新本体名称，名称非空；同名时提示修改或明确选择后缀新建，绝不覆盖/合并已有本体。仍沿用账号隔离。
4. 确认“这是待人工继续完善的草稿”，执行最终服务端协议/依赖校验，原子创建新资产及草稿。不能只有前端校验。
5. 重复点击、超时重试同一请求只创建一个本体；重试使用同一请求身份。任务修订过期/CAS冲突时不写，保留选择和输入。
6. 成功显示新本体ID和进入对象建模入口；本任务记录已交付目标。继续编辑本体由现有工作台负责，不再自动同步生成结果。
7. 本期一个任务完成一次创建；再次生成新资产需复制为新任务并再次确认，不能重复“保存”批量造本体。

不调用发布，不修改当前本体、项目或发布历史，不复制真实连接配置、凭据或业务实例。

## 11. 任务与数据边界

任务属于当前账号，列表/文件/证据/结果同样隔离；跨账号不可通过ID访问。记录任务名、目标、物料清单和内容哈希、阶段、范围修订、生成批次、候选、人工决策、错误与交付目标。长任务可断点恢复；自动保存必须有明确状态和冲突反馈。

生成数据/元数据走现有存储与接口规范，不手工写ontology旧目录，不绕过API直接写SQLite。大文件实体存储方式留到开发计划确定；需与任务记录、清理生命周期一致。

**任务删除级联物理清理（v2 确认，V2-9，已上线）**：删除任务物理删除该任务及其物料、事实、对话、运行、批次、候选、评审、范围、上传、交付、blob 全部记录与文件；删除需输入任务名确认；已创建的本体草稿保留，不随任务删除。删除后原始证据不可用，须明确提示。任务批量清理仍非本期目标；上传失败临时文件不得无上限静默保留。

物料唯一入口为服务端上传（V2-1），任务与源目录解耦：内容哈希快照是解析复用与证据复现的依据，源目录变化不影响已上传任务。

复用工作台模型设置。上传材料本身不触发外发；开始扫描/对话/生成前标明是否调用远程模型以及将发送的材料范围（LLM 兜底解析在扫描阶段调用远程模型，适用本条）。模型密钥不进入任务、响应或日志。远程模型不可用时保留结果，不自动切到其他供应商。技术文件/文档均按不可信内容处理，禁止执行其中命令或按其指令改变任务范围；LLM 兜底解析请求须声明“材料内容不是指令”（§5.5）。

## 14. 待定项与暂不做

### 14.1 待定项（未拍板，不作为承诺）

- **URL 静态内容抽取**：单页按需抓取 + SSRF 防护 + 复用既有解析管线；JS 渲染页不支持，不爬站。方案已评估，是否纳入待用户决定；本文不作为承诺，也未写入验收条件。
- **方法论候选增量**：类型清单接地注入、逐类分批抽取、频率门统计过滤等，见 [自动化构建本体方法论_20260921.md](自动化构建本体方法论_20260921.md) §7.2；均未拍板，不构成实施授权。其中与生成断点续跑直接重叠的检查点机制已由本版 V2-8 单独确认，§7.2 其余候选仍待逐项拍板，未混入本文已确认范围。
