## 4. 重点复核项（本轮修复过，必须给独立结论）

1. **commit_* bool 语义**（`2ee24cd`）：`OnlinePersistence` 与 `ExperimentState` 的 `commit_success/commit_split/commit_failure`
   幂等跳过一次返回 `False`、新提交返回 `True`。构造重复回调反例核对两实现一致，且执行器不因 `False` 误判（幂等路径不抛
   `PersistenceRejected`）。
2. **amend_plan 通道**（`f72fb98`）：计划内事件（attempt 记账/重排队/blocking）经 `amend_plan` 落库；`save_plan` 仍拒绝二次覆盖。
   反例：对同一 run 二次 `save_plan` 应被拒；`amend_plan` 不应能用于初建。
3. **v2/legacy 路由**（`ce6a689`+`f72fb98`）：仅「已有旧计划（无 schemaVersion 或 =1）的 auto 续跑」走 legacy；新运行与
   v2 计划走 v2；显式未知版本（如 99）仍 422 `UNKNOWN_CHECKPOINT_SCHEMA` 且不删候选；`abstract` 对旧计划=新 epoch。
4. **拆分登记制覆盖守恒**（`6188486`）：父目标 `expandedInto` 后终态按有效叶目标集比对；反例：子目标缺失应报
   `COVERAGE_MISMATCH`/`UNFINISHED_JOB`，重复认领应拒。
5. **候选 id 跨 epoch 不冲突**（`f72fb98`）：`planEpoch` 入 id 哈希后，abstract 重建/同 batch 重建计划可正常落候选；
   同 epoch 内重复回调仍幂等（不重复插入）。
6. **checkpoint 容量闭环**：>1MiB 计划 save/claim 抛容量异常且旧状态不变；接近软阈值时在途响应仍能原子保存并转入受阻终态。
7. **取消不回滚已提交结果、不复活**：取消后迟到响应不写新候选、状态保持 cancelled；成功先提交则保持 succeeded。
