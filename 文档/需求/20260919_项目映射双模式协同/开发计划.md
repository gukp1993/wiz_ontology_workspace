# 开发计划 · 项目映射说明与配置 v2

当前阶段：原型交互评审，未授权改正式工作台。

基准：[交互原型_v2.html](交互原型_v2.html)、[需求说明.md](需求说明.md)。指令：[执行指令.md](执行指令.md)。v1 仅历史。

## 1. 调整理由

v1 把配置机制当成页面主要内容，模式标识、双卡片编号、流程条和理解示例分散注意力。v2 围绕对象、属性、链接、动作展开，直接维护项目说明，已有配置按需展开。新增链接、动作的说明覆盖，不表示新增动作执行授权。

## 2. 代码入口（实施前重核对）

- frontend/src/project/ObjectSources.vue：实例识别、身份与来源。
- frontend/src/project/PropertySources.vue：属性配置清单、字段/Redis/编排。
- frontend/src/project/LinkMappings.vue：两端来源表/字段和关联逻辑。
- frontend/src/project/ActionBindings.vue、actionHttpModel.ts：现有 HTTP 动作映射（仅配置、不发送请求）；保留参数、凭据及历史只读分支。
- frontend/src/project/ProjectBinding.vue：对象映射页签与数据下发（以现状确认）。
- bindingModel.ts、project/api.ts、app/http.ts、formGuard/saveCoordinator：协议适配、统一请求和保存。
- workbench/project_validation.py 及相关分模块、action_http.py：项目校验。
- workbench/storage/：SQLite 权威存储。无 YAML 在线回退。

## 3. 实施顺序（待授权）

### A. 交互确认与协议

先确认 v2，停止沿用 v1 模式切换/标签方案。定义四类项目说明、连接范围和上下文引用协议；链接按同一关系映射保存，动作按项目+对象+动作定位，不改本体定义。先更新接口文档再实现前后端。

仍需冻结的后台内容：纯说明对象身份解析、发布校验与执行就绪判定、说明与具体配置的依赖/冲突、旧客户端不支持语义时的处理。不要通过强制自动转编排规避这些问题。

### B. 配置保存与页面

后端读写/快照/兼容完成后，接入四类说明。前端抽取最小共享说明编辑区，配置表单继续复用；实现清单、折叠和保存守卫。一次提交两部分内容，不生成独立普通模式副本；列表派生摘要不产生额外状态字段。

未知结构原样保留；链接反向共用记录；动作旧映射保留。仅文本调整不应影响现有字段或接口参数。

### C. 理解与只读取值

获得相应实施授权后，为对象/属性/链接增加理解与授权只读执行边界、实际工具调用、类型和身份校验、失败追溯。说明不能只是无效备注，也不能被执行器忽略。动作本期仍只保存配置，真实动作执行不随此阶段启用。

### D. 验证与交付

复用相关对象映射、属性来源、链接及动作绑定测试，新增有价值的说明读写兼容、反向共享、保存守卫测试。前端 build；隔离实例下验收 V01–V11，分别说明哪些为配置验收、哪些是实际执行验收。避免无关全站重构。

## 4. 协作与数据保护

协议先冻结再按 ObjectSources、PropertySources、LinkMappings、ActionBindings 分工；共享适配层与样式由单人集成。不依赖特定 harness、模型或并发数量。不覆盖他人修改。

测试独立 WIZ_WORKBENCH_ROOT、端口和 WIZ_DATABASE_URL；不写真实业务数据，不调用设备接口，不把凭据带入说明、日志和快照。
