# 项目映射：说明与配置 · v2

日期：2026-09-19；当前阶段：交互评审，未授权实施正式功能。

当前视觉及交互基准：[交互原型_v2.html](交互原型_v2.html)。配套：[开发计划.md](开发计划.md)、[执行指令.md](执行指令.md)。v1 文件仅用于历史对照；不得继续按其模式标签、编号分区及流程条开发。

## 1. 本次修正

用户要求的是：每个对象、属性、链接和动作都能填写描述，同时继续使用已有配置能力。UI 不需要解释“普通模式”“严格模式”“组合使用”，也不需要把“自然语言”作为一种特殊功能突出。

产品呈现改为：**写说明，需要时再补充具体配置。**

这不是增加一个无效备注栏：项目说明应作为未来理解和取值/行为实现的依据之一，与已配置的字段、关联或接口一起保留。产品中不再标识填写采用了哪种机制。严格定义的结构化能力仍保留，位置更收敛。

说明属于当前项目对本体元素的实现描述，不覆盖本体的业务定义。编辑页通过「查看本体定义」按需查看只读内容，避免两种描述混淆。

## 2. 范围与页面结构

对象映射保留左侧对象选择，右侧四个页签：

| 页签 | 说明描述什么 | 需要时补充的配置 |
|---|---|---|
| 对象 | 实例来自哪里、唯一身份、哪些记录有效、多表如何补充 | 数据来源：连接、表、实例主键、原有登记身份及补充来源 |
| 属性 | 从哪里取值、怎样计算、异常如何处理 | 取值配置：字段、Redis、函数编排等原有能力 |
| 链接 | 两端对象在当前项目如何关联 | 关联条件：两端已登记来源表及字段、现有成员关系等 |
| 动作 | 本项目怎样完成动作、接口含义和结果确认方式 | 接口配置：已有请求方式、地址、参数和凭据引用 |

项目页签名称采用对象/属性/链接/动作；既有路由和链接定位保持兼容。不改变主导航或添加新的规则工作区。

## 3. 列表

- 对象页签直接展示来源说明，下方数据来源摘要折叠，提供一个「编辑」入口。
- 属性、链接、动作采用同一三列表格：**名称、项目说明、操作**。
- 名称下方显示现有类型或关系方向，不增加配置模式列、模式标签或 AI 状态。
- 项目说明最多显示两行。若已有字段/关联/接口配置，可在下方以灰字显示其真实摘要，便于定位已有配置。未填说明显示「暂无说明」，不把缺少说明当作无配置。
- 搜索名称与说明；名称点击和「编辑」进入同一表单。原型样例量较少，不展示分页；正式版保留现有大量列表能力。
- 来源始终是项目固定引用本体版本；失效/未知配置仍需原样保留并提示，不能因原型省略而隐藏或删除。

## 4. 统一编辑页

从上到下只有五部分：

1. 返回入口、当前元素名称及必要的类型/对象信息。
2. 「查看本体定义」只读折叠内容。
3. **说明**：默认展开，可收起；一个多行文本框，按元素类型给一句填写提示。没有编号、模式选择器和规则命名要求。
4. **具体配置**：对象叫「数据来源」、属性叫「取值配置」、链接叫「关联条件」、动作叫「接口配置」。默认折叠，标题旁显示当前摘要或「需要时补充」。展开后复用原有表单。
5. 底部「保存」「取消」。不提供测试/执行动作按钮，不展示理解演示或配置流程图。

说明提示按对象、属性、链接、动作分别使用业务语境；不要求用户填写技术上的函数签名或重复属性数据类型。

### 说明中的辅助信息

- 对象、属性、链接可从已有项目连接中选择说明涉及的连接，支持多个。已配置连接与额外选择的范围在正式版以稳定 ID 处理。
- 属性、链接、动作可辅助插入「当前实例 ID」；时序属性可插入「本次查询时间范围」。界面不强迫用户学习模板变量语法。
- 动作认证继续在原接口配置中处理，不把密钥输入到说明。
- 插入按钮是辅助，可以完全用文字描述；正式版存储引用的方式需协议阶段确定，不能只依赖容易重名/改名的显示名称。

### 折叠与保存

- 折叠只改变展示，不表示禁用配置，不清空文字，不触发保存或撤销记录。
- 同一次编辑重绘保留折叠状态，重新进入说明默认展开，具体配置默认折叠。
- 说明可空，已有配置也可独立使用；无需强迫用户为简单字段重复写一段说明。
- 两部分一次保存同一项目草稿；取消恢复原值，未保存离开有提示，失败保留输入，409 使用既有保存协调器。
- 移除具体配置需确认；说明保留，依赖失效需提示。清空全部映射仍按原来的显式清除流程，不因空表单自动清掉旧配置。
- 仅保存说明不等于配置可执行或发布通过。真实解释、校验与执行另行建设。

## 5. 四类示例

### 对象：储能簇

> 储能簇来自 m_storage_cluster_phase，每条记录表示一个储能簇。id 是唯一编号，name 是显示名称。仅使用 del_flag 为 0 的记录。

下方数据来源保留业务库、表和主键；对象身份必须唯一稳定，多表补充不能重复产生实例。

### 属性：额定功率／采样 SOC

> 额定功率读取当前储能簇记录的 rated_power 字段。

> 使用当前实例 ID 查询 s_attr_scada，取得 scada_table 与 scada_id；查询对应配置表，取得 sample_table_name 与 sample_field_name；按本次时间范围读取采样表的 record_time 和采样字段，返回时间和值组成的序列。

单字段可仅配置字段，不填说明。复杂规则可先写说明，不必先建规则或搭节点。数据类型继承本体，采样输出必须包含时间与观测值。

### 链接：所属设备

> 储能簇的 storage_id 对应储能设备的 id，通过这个关联找到所属设备。

同一链接在两端共用说明及配置，反向入口不复制第二条定义。反向编辑时提示两端都会更新。关系字段选择只能使用两端对象已配置来源，不能随意填未知表。

### 动作：停止充放电

> 调用设备功率设置接口，storageId 使用当前储能设备实例 ID，power 固定为 0。接口受理仅表示请求提交，停止完成以设备反馈为准。

作用于储能簇时，如果项目只有设备级接口，不能简单拿所属设备 ID 代替：这可能停止同设备下其他簇。原型中的簇级动作只保留说明，等待匹配接口；设备级动作展示模拟接口。原型绝不发送请求。

## 6. 解释与执行边界

这些是后台实现要求，不以“模式”标签堆在填写页面：

- 明确配置是确定依据，说明补充业务条件与步骤；两者冲突不能静默选一方或覆盖。
- 说明由大模型理解时必须通过授权工具真实读数/计算，不能用模型生成值替代实际数据。
- 保留连接权限、稳定身份、输出类型、时间范围、超时/数据量/步骤限制，不能绕过现有 dbdrivers 固定探测边界。
- 只读映射的解释不授权动作写入。动作页本期与现有 ActionBindings 一样只配置、不执行；未来执行应单独设计参数解析、权限、确认和结果反馈。
- 纯说明和说明补充配置均需明确保存、发布和执行就绪的协议；不能为了“简单填写”把未验证说明当成已通过校验。
- 旧客户端或执行器若不支持说明语义，应明确提示不支持，不得忽略说明只跑旧字段映射。
- 用记录集合做中间输出再加工成属性值属于后续协议设计，不能擅自放宽现有输出类型校验。

## 7. 非目标

不改本体字段、共享语义、现有链接定义及动作参数模型；不新增设备控制能力；不改工作台存储；不提供自然语言自动生成 SQL/编排的强制流程；不增加模式徽标、AI 检查示例、流程条、多个重复保存入口。

## 8. 原型边界与验收

当前原型有储能簇、储能设备两组示例，可切换四页签、搜索列表、编辑说明、展开配置、选择连接、保存取消，包含同一链接的反向共享。

示例参数绑定为只读简化展示，正式版必须接回完整的已有表单；未展示的旧能力不得删掉。数据仅保存在内存，刷新恢复，无数据库/模型/设备调用。

| 编号 | 验收 |
|---|---|
| V01 | 用户流程中无普通/严格/组合使用/自然语言模式标签，无模式选择器 |
| V02 | 四类元素均可填写说明；说明在前，可折叠，具体配置在后默认折叠 |
| V03 | 清单统一名称、项目说明、编辑入口；字段/接口等已有摘要仍可识别 |
| V04 | 不强制同时填写说明和配置；本体定义只读不被覆盖 |
| V05 | 说明和配置一起保存；取消恢复，未保存离开有提醒 |
| V06 | 折叠不丢文本、不写数据；编辑中重绘保留状态 |
| V07 | 链接两端指向同一配置，反向编辑提示影响，不反转物理关联条件 |
| V08 | 动作只保存映射；不执行、不自行将簇级操作扩大为设备级操作 |
| V09 | 搜索、连接选择、表字段联动、类型匹配和既有兼容能力保留 |
| V10 | 1440/1024/768px 可用，局部表格滚动，键盘和弹窗可操作 |
| V11 | 正式实施后另验保存/发布/解释执行；原型不能替代实际功能证据 |
