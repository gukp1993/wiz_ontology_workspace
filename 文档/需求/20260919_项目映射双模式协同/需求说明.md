# 项目映射：结构化配置与自然语言协同 · v1

日期：2026-09-19。状态：交互评审稿；业务功能未实施。

配套：[交互原型_v1.html](交互原型_v1.html)、[开发计划.md](开发计划.md)、[执行指令.md](执行指令.md)。

## 1. 已确认方向

- 项目映射支持普通模式（自然语言描述）和严格模式（结构化配置），严格模式仍为主力。
- 两者可以一起使用，包括同一个对象来源、同一个属性取值中组合使用，不设计互斥模式开关。
- 自然语言原文可由大模型在查询时理解，不强制先转成 SQL 或函数编排。
- 本体定义仍是抽象层；项目中的物理表、字段、连接和取值步骤不回写本体。
- 用户本轮授权产出原型，未授权实施正式功能或操作真实项目数据。

## 2. 页面设计

保留「项目 → 对象映射 → 选择对象 → 实例识别／属性取值」路径，不新增普通模式工作区。

### 实例识别

编辑同一份对象来源配置，两个区域按以下顺序排列：

1. **自然语言来源说明／普通模式**：默认展开，点击标题栏可折叠。可直接描述实例从哪里来、唯一身份、记录过滤、多表关系。连接可从项目已配置连接多选，不让用户填写密码。
2. **结构化配置／严格模式**：位于自然语言说明下方，复用现有实例身份配置、数据库表/视图与主键、项目登记、补充来源等能力。已配置内容默认展开；未配置显示「添加结构化配置」。

例：储能簇来自 m_storage_cluster_phase，每条有效记录表示一个实例，id 唯一标识，name 是显示名称，只取 del_flag=0 的记录。其他表补充属性，不重复创建实例。

纯自然语言对象来源可以保存草稿，但实际实例枚举与身份识别必须能产生稳定、唯一的实例标识；未明确身份或多表拼接产生重复时，不得猜测、用显示名当主键或直接标为可执行。自然语言说明不是绕过原身份约束的后门。

### 属性取值

清单列：属性名称与数据类型、配置方式、取值依据、配置按钮。

「配置方式」只根据内容派生：仅结构化／仅自然语言／组合使用／未配置。它不是可编辑开关，也不是验证或执行成功状态。

单页编辑，默认同时看到两个区域：

1. **自然语言取值说明**：置于结构化配置之前，默认展开、允许折叠。一个多行输入框；简单规则一句即可，复杂规则允许分步。无需另建命名规则或逐步声明输入输出。
2. **结构化配置**：继续使用数据库字段、Redis、函数编排等已有入口。新增设计不删除旧来源或强制迁移。

顶端只读展示当前对象、属性业务定义、预期输出类型。底部统一「保存配置」「取消」；两个区域一次保存同一项目草稿，不额外增加保存草稿步骤。

### 展开与折叠

对象来源和属性编辑页一致：自然语言在前，结构化配置在后。说明标题栏显示「收起／展开」，支持键盘。折叠只隐藏内容，不停用、不清空、不保存、不改变取值方式或执行优先级；未保存文本也必须保留。同一次编辑内，选择连接、调整结构化字段后的重绘应保留折叠状态；重新打开配置默认展开。对象来源只读摘要也按相同顺序展示。

## 3. 字段与来源

| 内容 | 用户如何填写 | 来自哪里 |
|---|---|---|
| 对象、属性、预期输出类型 | 无需重复填写，只读 | 项目固定引用的本体发布版本 |
| 结构化配置 | 沿用现有表单；可不填 | 当前项目绑定 |
| 自然语言说明 | 一个文本框；可不填 | 当前项目绑定，原文保留 |
| 说明可使用的数据连接 | 从当前项目连接中多选 | 稳定连接 ID；名称仅展示 |
| 当前实例 ID | 执行时提供，可辅助插入引用 | 已解析的对象实例身份 |
| 本次查询时间范围 | 查询时提供，可辅助插入引用 | 查询上下文，包含明确时间/时区 |
| 结构化配置结果 | 已有结构化配置时可引用 | 当前配置的实际执行结果 |

连接默认可沿用本项结构化配置直接使用的连接。额外连接必须显式关联；引用编排时不能因其内部访问过某连接就给自然语言自动扩大权限。内部表名、字段名可能由前序查询动态解析，运行时仍需校验连接范围和返回标识是否合法。

上下文辅助按钮不要求用户手写内部 ID。正式实现应保留稳定引用信息；文本中的显示名称不能成为唯一绑定依据。原型仅插入可阅读文字，不实现协议。

两区域可单填，也可组合；保存未完成说明只表示保存草稿，不能宣称已验证、可执行或发布通过。现有「清除来源」语义保留；正式版删除全部配置必须显式清除，避免空表单误覆盖。

## 4. 组合语义

- 结构化配置明确的连接、字段、身份或编排为确定依据，自然语言补充未表达的取值/过滤/处理规则。
- 属性常见流程：解析当前实例 → 执行结构化取值 → 将其结果与自然语言说明交给解释执行层 → 校验最终属性类型。
- 对象来源常见流程：结构化枚举候选实例 → 按说明明确的条件过滤或补充 → 验证身份唯一稳定。不得因补充表一对多而重复生成同一实例。
- 纯自然语言可以描述多步读取和计算，由执行层组织调用；未提供连接、关联条件、时间范围等必要信息时必须返回缺失项。
- 结构化配置失败，不得悄悄按自然语言另找来源兜底。文本与结构化来源矛盾时报告冲突，不擅自覆盖、合并或选优先级后静默执行。
- 文本改变时，先前理解/验证结果失效。模型检查只能称为「识别到的问题／未发现明显问题」，不能保证全部语义冲突都被检测。
- 所有连接、对象、属性、编排引用继续使用稳定 ID，项目仍引用发布本体版本。

**类型边界**：本期原型中的结构化输出与目标属性类型一致；自然语言可以检查和处理该值，但最终仍须匹配本体类型。将「记录集合」作为中间输入并输出数值的通用处理链，会涉及结构化输出与最终输出的分离，不得借本次原型偷偷放松现有编排类型校验；需单独补充协议后实施。

## 5. 原型示例

| 示例 | 结构化配置 | 自然语言内容 | 预期结果 |
|---|---|---|---|
| 储能簇来源 | 业务库、m_storage_cluster_phase、id | 仅 del_flag=0 有效，其他表补充信息不新增实例 | 稳定实例集合 |
| 额定功率 | 当前记录 rated_power 字段 | 空 | 数值 |
| 实时 SOC | Redis GET m_storage_cluster_phase-{id}-soc | 缺失或超范围报告异常，不截断，不用采样替代 | 数值或明确的异常状态 |
| 采样 SOC | 默认空 | 查询 s_attr_scada → 动态 scada_table → 动态采样表/字段，按时间范围返回 | 时间序列（时间+数值） |

原型提供「添加结构化配置」，采样 SOC 演示补充序列输出编排，两块内容共存且不自动删除原文。重复描述已有查询步骤不应导致重复查询；正式解释层应识别可复用结果或提示用户调整，原型不模拟语义判断。

## 6. 保存与检查

- 编辑局部草稿，取消恢复原配置；离开未保存表单提示继续编辑或放弃。
- 移除结构化部分需明确确认，仅改局部草稿；自然语言不删除。说明仍引用其结果时给出依赖失效提示；保存不静默修正文案。
- 两块一起通过现有保存接口和 revision/CAS 保存；失败保留输入，409 沿用既有协调器。
- 「查看理解示例」仅原型演示入口，固定展示组合、冲突、缺少条件；不能把它当正式模型检查接口。
- 正式版建议「检查说明」提供理解摘要/缺失项/冲突定位；属于解释能力，需要独立定义接口和模型失败状态，不允许硬编码“校验通过”。
- 发布与执行须区分：说明草稿可保存；普通/组合配置的发布校验规则与执行就绪判定必须在实施前冻结，旧客户端/执行器遇到不支持的配置需明确拒绝，不能仅执行结构化部分。

## 7. 执行边界

本原型不查询业务库、不调用模型、不运行 SQL 或函数。不改 dbdrivers 的固定探测限制。

后续真实执行使用单独的只读取值执行边界：模型负责解释与工具编排，工具实际查数/计算；模型不得编造缺失数据。解释层必须受连接授权、只读查询、超时/行数/步数限制及数据类型检查约束，记录实际访问来源、各步骤结果/失败原因及使用的配置版本。对象映射取值不授权业务写入或设备动作。

这些属于正式执行的必要设计边界，并非原型已实现的能力。不要将新功能压缩为一个不参与取值的备注字段，也不要未经用户授权就开放任意 SQL/Python 执行。

## 8. 原型范围与验收

原型只有储能簇及三个属性的演示数据；其他导航为背景上下文。连接、表、字段和编排均为模拟目录。无网络、无 localStorage、无数据库写入；本页保存仅内存，刷新恢复。

| 编号 | 验收项 |
|---|---|
| P01 | 对象来源和属性取值均可同时填写两块内容，没有互斥模式开关 |
| P02 | 三个属性可分别演示仅结构化、仅自然语言、组合使用 |
| P03 | 自然语言输入即时更新配置方式标识，不自行生成或覆盖结构化配置 |
| P04 | 可选多个示例连接、插入上下文、展示当前数据类型 |
| P05 | 保存后清单更新，取消恢复，未保存离开有提醒 |
| P06 | 移除结构化部分前确认，原文保留，取消移除不改变配置 |
| P07 | 表切换清空相关字段；时序示例编排声明序列输出 |
| P08 | 预设组合/冲突/缺失反馈清晰，全部标明模拟，不能表示真实检查通过 |

| P11 | 自然语言说明位于结构化配置之前；默认展开、可折叠，折叠不丢文本、不触发保存，编辑期间重绘保留折叠状态 |
| P10 | 不修改产品源码与真实数据；正式接口、保存、执行及兼容验证另行实施 |
