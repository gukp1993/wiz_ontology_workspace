## 2. 阶段安排

### P0 源码清点与能力冻结

1. 读双方 AGENTS、当前共享上下文、本文及需求；检查双方 git status，不覆盖未提交修改。
2. 清点 EditorView 所有 import、子组件、CSS、图标、资源、预览页和相关导出实现。检查源项目其他位置 AGENTS。
3. 建立逐入口能力表，覆盖所有按钮、快捷键、上下文操作；按需求确定对接方式。无法迁入的核心功能不得直接删掉，记录具体阻塞。
4. 记录源文件 hash；在隔离环境体验原编辑器的关键操作，形成实际行为基线。无可运行数据则使用临时合成数据，不改旧项目真实库。

完成标准：清单可评审、数据写入边界清楚；不先开始重画UI。

### P1 整体复制与宿主接入

复制主编辑页、依赖弹窗、shared/布局、预览相关代码。建议目录 legacyGraph，保留源文件名称便于比较。只改模块路径、样式作用域、宿主尺寸和必要资源路径，先接入内存测试数据，证明旧交互在目标构建环境可运行。

避免搬旧 router/main/App/login；提供宿主导航适配，当前 hash 路由仍唯一。旧 useGraph 中的数据访问与定时保存必须在任何真实运行前替换或切断，不允许一边临时接旧后端一边迁移。旧全局 CSS 只复制编辑器依赖规则并限定容器，验证不污染当前表单。

完成标准：原交互代码已实际运行，有复制来源 diff，非从零实现；没有旧 API 出站路径。

### P2 数据与领域编辑适配

入口定位：当前 ontology/OntologyGraph.vue、ObjectWorkspace.vue、ontologyGraphModel.ts、graphAdapter.ts、modelFormat.ts、PropertyManager.vue、SharedLibrary.vue、BusinessRuleLibrary.vue、ActionLibrary.vue；实际复用按现状核对，不要求全部修改。

- 建立 read projection 与 domain command 两方向适配；完整未知字段保留，稳定ID不重生成。
- 新建/编辑五类节点；共享属性引用、私有归属、对象链接、规则/动作引用。
- 连线模式和批量目标保留旧交互，结果使用当前协议；一次命令原子应用，先全量校验。
- 删除影响提示与保护；撤销/重做作用于真实领域模型；外部内容改变后清理旧撤销基线。
- 接入当前 before-change/changed/commit-now、saveCoordinator；不得启动旧3秒自动保存和旧 saveVersion。

完成标准：隔离 API 回读、刷新和列表与图谱互验一致。需要接口变化先更新 文档/接口文档/ 对应分册、README变更记录、05清单及路由白名单。

### P3 视图、预览与导入导出接入

- 当前账号+本体+版本偏好接入旧布局/视口；临时邻域独立存储，处理重挂载恢复。
- 单图/多图预览复制后接当前资产与版本查询；命名空间防碰撞，只读。
- 坐标导入导出走视图数据；旧业务导入导出入口接当前服务，明确格式与字段损失。
- 复用离线导出涉及的最小旧服务/打包逻辑时，经当前鉴权接口输出，绝不迁入旧账号/数据库/进程管理。导出文本必须安全转义，资源离线可用，不能把 API Key/连接凭据加入包。
- 图谱管理、版本查看、保存发布映射当前流程；旧外围 MCP/问数控件从嵌入页剔除并列清单。

完成标准：无假按钮；权限/只读边界、实际文件再导入与断网查看通过。

### P4 集成、替换与清理

将对象建模画布入口切换到迁入编辑器。移除已无调用的当前重复交互控制器；保留有用投影、字段适配和测试。现有二跳、最大化、定义返回定位等能力不可因迁入丢失，优先在旧实现上做小范围补接。

修复当前已知 C01–C05 场景，不能只修改旧测试使其跳过。修复旧代码确有缺陷时记录原因及改动位置。避免与需求无关的全站UI/存储重构。

### P5 验证与交付

1. 单元/组件测试：投影与领域命令、边真实端点、共享引用与删除、撤销/重做、临时布局恢复、坐标解析、只读多图命名空间。
2. 隔离 HTTP 回读：真实保存链路、失败/409、发布不可变、账号隔离；接口有变化跑相关后端测试。
3. 真实浏览器验证所有交互，尤其键盘冒泡、指针、输入框、拖动、工具栏按钮；headless Cy 不能替代。
4. `cd frontend && npm run build`；运行相关现有回归。当前基线可执行 `node --import ./tests/ts_hooks.mjs tests/ontology_graph.test.mjs`、`node --import ./tests/ts_hooks.mjs tests/ontology_graph_controller.test.mjs`。重构后必要时更换测试入口并记录真实命令，保留业务场景。
5. 按 R01–R18 逐项登记证据；截图与性能记录放本目录，未测明确标注。
6. 检查运行请求不含旧应用 API；检查真实 ontology/数据/密钥均未改变；清理隔离环境。
7. 通过共享上下文脚本记录实施事实；git只提交自己修改，给出提交SHA、改动清单、验证及剩余风险。

## 3. 依赖和工作分配

P0→P1→P2 为主链；P2定义适配边界后，视图/预览、导入导出、测试可由可用人员独立推进。主编辑文件与保存适配由单一负责人维护，禁止多人同时重写 EditorView。并行不是验收条件，不要求特定模型或并发数量。

## 4. 风险与处理

- 旧编辑器大组件耦合高：先整体迁入，再仅隔离数据接口；不要借机大拆重构。
- 旧任意图结构与当前受约束本体不同：限制的是非法业务关系，不是删除编辑能力；用现有字段和明确提示解决。
- 撤销覆盖外部变更：按内容基线重置历史，不能用整图快照覆盖未知字段与新草稿。
- 旧导出不支持新字段：不能默默丢失；完整迁移仍走当前格式。
- 复制代码还包含旧账号/网络依赖：移植阶段扫描调用并拦截测试，未接通功能不能假成功。
