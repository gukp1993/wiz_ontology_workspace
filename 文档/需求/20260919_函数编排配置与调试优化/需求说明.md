# 函数编排配置与调试优化 · 需求说明 v1.1

日期：2026-09-19。状态：需求与原型交付，正式功能尚未按本需求实施。

配套文件：[交互原型_v1.html](交互原型_v1.html)、[开发计划.md](开发计划.md)、[执行指令.md](执行指令.md)。v1.1 表示本文已包含最新的中间片段测试需求，原型继续使用同一个 v1 文件。

## 1. 目标与已确认方向

解决三个实际问题：节点配置分散；画布、详情、测试结果挤在同一页；无法独立测试中间连续节点。

用户明确要求：

1. 沿用当前工作台的浅色风格，不换设计体系。
2. 测试结果不能被挤在画布下方，必须有足够的查看空间。
3. 对 A → B → C → D → E，能够只测试 B → C → D：手工提供原本来自 A 的数据，不执行 A；范围内自动传递数据；不执行 E。
4. 每个被测节点的输入、输出及错误可分别查看；返回设计时保留工作状态。

本期围绕这些目标改造既有编排功能，不新建一套执行平台。

## 2. 范围和原型边界

| 项目 | 本期处理 |
|---|---|
| 编排列表、设计页、连续节点配置 | 按最新原型优化，保留既有能力 |
| 独立测试视图 | 必须实现，包含全部、单节点、所选片段 |
| 中间片段隔离测试 | 必须实现；前后端均支持，不是只加入口 |
| 输入来源选择、兼容性与节点结果 | 优化交互，沿用稳定 ID 引用 |
| 属性映射与编排间返回 | 保留当前属性表单并定位所选编排，不另造属性取值执行器 |
| 当前五种节点 | 保留 SQL、Redis、HTTP、计算、Python；不能为模仿原型删除现有配置项 |
| Python 沙箱 | 不在本期；目前仍是 LLM 推演，必须清楚标识 |
| Redis 给原记录追加字段、列表加权表达式 | 原型说明用途的拟议能力，本期不实现；不能硬编码 SOC 算法冒充通用能力 |
| 时间序列属性接入、编排版本固定、运行历史 | 后续需求，本期不扩展 |
| 新节点类型、条件循环、任务调度、真正暂停/取消后台任务 | 不在本期 |
| 顶层菜单和资产归属重组 | 不在本期。编排继续独立存储，连接/凭据来自项目 |

原型以 SOC 为例，包含 A 整理编号、B 查询簇、C 读取 SOC、D 加权计算、E 整理输出。原型的 TRIM、SUM(rows.soc * rows.capacity)、列表字段追加不是现有公式语言的正式承诺。正式验收用现有计算节点支持的表达式构造等价五节点链，详见 §12；不得自行扩充表达式语法来满足原型示例。

原型只模拟固定样例，不发起网络、不保存真实数据。正式版必须使用已有真实接口、参数与节点执行器，不能复制模拟检查、固定 52% 结果、假连接或原型临时数据。

## 3. 页面结构

### 3.1 编排列表

- 复用当前表格风格。名称和简短说明放在同一列；其他列为处理节点数、配置状态、更新时间、操作。
- 搜索名称及说明；编辑为主要操作，复制和删除进入“更多”。不得删除已有复制/软删除能力。
- 原型的“使用位置”用于说明属性入口。不要求本期新增全局反向引用索引；有可靠数据才显示，无数据不编造“未使用”。
- 新建继续使用现有名称/说明表单，创建后进入设计。列表加载失败、空列表、无搜索结果分别展示。

### 3.2 设计视图

结构：顶部编排信息与运行项目 → 画布工具栏 → 可收起的节点列表 / 画布 / 按需打开的节点配置。

- 顶部：返回列表、名称、保存状态、显式运行项目、检查配置、测试片段、测试编排。
- 说明可以折叠；项目上下文不能藏在说明里。复用当前项目选择链路，顶栏与侧栏项目一致；切换前完成既有保存/离开处理，不静默重绑连接。
- 画布保留拖动、缩放、全图、整理、节点选择及已有连接交互。选节点才打开详情；关闭详情恢复空间，不自动重排画布。
- 节点展示名称、节点类型、输入/输出摘要和当前有效状态。颜色主要表示选中、问题和测试状态，不为每种节点另造一套强色卡。
- 节点列表支持搜索和定位，默认按可用宽度收起。输入/输出边界与处理节点应区分，处理节点数不包含两个边界。
- 设计页可保留紧凑问题入口与定位列表；不在其底部继续展开大型测试输入或输出区域。
- 测试范围不是编辑选中状态。查看节点、选择测试范围、修改输入来源互不冒充。

### 3.3 连续节点配置

右侧顺序为：名称与说明（可折叠）、输入、实现、输出、高级设置（默认折叠）。不再要求在四个页签之间来回切换。

- 每个输入先显示紧凑摘要：显示名、类型、取值来源；技术名和嵌套字段按需展开。
- 实现保留现有真实编辑器和配置项；SQL/Python 等长内容可放大编辑。取消放大编辑不应用缓冲内容。
- 输出显示名称、类型和结构；复杂类型可展开。多输入、多输出、对象字段和嵌套列表不能退化成原型的单输入单输出。
- 模型、连接、凭据下拉分别处理加载中、失败、未配置、已加载，不能都显示空选项。
- Python 始终标明“LLM 推演”，不能显示成代码已在沙箱执行。
- 表单保存/自动保存、撤销重做保持既有逻辑，不增加“另存草稿”步骤。

## 4. 输入来源配置

统一来源选择器，按“编排入口参数”“节点输出”“固定值”分组；对象输出可以继续展开选择字段路径。用户不必先切换到另一种来源类型才能选择字段。

- 文案展示名称，实际存储用既有节点、参数、输出、字段的稳定 ID。
- 新增参数并选择来源时，可带出来源类型；已有参数换来源时先检查兼容性，不静默覆盖其类型、实现代码或下游声明。
- 不相容选项禁用并解释；成环、自引用、已删除输出不能作为有效选择。
- 可用来源按依赖图计算，不按 nodes 数组顺序或节点画布左右位置过滤。
- 画布连线仍是输入绑定的派生视图。沿用连接操作作为快捷方式，不能生成与参数绑定脱节的第二份连线事实。
- 清除绑定需明确显示未绑定，不自动取第一个选项。
- 当前共享来源/固定值能力保持兼容。固定 0、false、空文本与“未填写”区分。

## 5. 独立测试视图与布局验收

测试视图替换主工作区中的画布和节点详情，沿用同一应用导航。不是新浏览器窗口，也不是压在页面底部的结果弹层。

布局：

- 顶部：返回编排、编排名称、测试调试标识、当前项目。
- 左侧：测试范围、片段起止或节点选择、外部输入、执行按钮。
- 右侧：本次范围与状态、节点结果切换、输出/本节点输入/执行记录。

尺寸原则：

- 1440×900、1280×800、1024×768 下，测试标题与右侧输出区首屏可见，无需先向下滚动整页寻找结果。
- 主工作区高度由视口减导航/页头计算，容器设置 min-height:0；左右分别滚动，正文不能撑高整个页面。
- 左侧建议 280–340px；1024px 可缩至约 245px。右侧占剩余宽度；长文本/表格仅在自身容器滚动。
- 768px 宽度可自动收起应用侧栏并保持可用的左右区域；更窄设备允许在“输入/结果”之间切换，不要求本期重建手机版工作台。
- 结果顶部摘要和节点切换应保持容易访问；长日志不能挤走范围/运行状态。
- 示例数据的单值和短表格不需要垂直滚动才能看到；大型结果局部滚动属于正常行为。

返回设计时保留选中节点、画布视口、表单、测试范围、测试输入和最近结果。切换模式本身不能触发保存。换编排/账号后必须隔离或清理测试状态，不能把另一个编排的结果带入。

## 6. 三种测试范围

| 范围 | 要求 |
|---|---|
| 整条编排 | 执行当前编排，填写入口参数；继续保留既有 revision、全量校验与并发约束 |
| 单节点 | 只执行当前节点；来自上游的输入手工提供 |
| 所选片段 | 仅执行明确选中的处理节点；范围外输入手工提供，内部绑定照常传递 |

### 6.1 选择连续片段

- 在设计页点击“测试片段”进入测试视图；测试范围可切换全部/单节点/连续片段。
- 对简单链提供起点、终点下拉。以真实依赖路径生成范围，不使用数组下标 slice 或画布位置作为执行语义。
- 展示实际节点序列、数量以及范围外不执行的节点。
- 同一个节点作为起止等价单节点范围；逆序、无路径、已删除节点提示具体错误。
- 起止之间有多条路径时，不猜选哪条：提示“存在多条路径，请明确选择节点”，复用已有多选能力显示最终集合。节点集应连通且无环；不新增分支设计器。
- 不自动加入范围外上游。旧“补选所需上游”不得再成为新片段测试的必经条件。
- 存在范围外侧路输入时，按目标节点与目标输入分别列出，不能只为第一个节点生成一个输入框。

### 6.2 核心示例

依赖 A → B → C → D → E，用户选择 B、C、D：

1. 展示 B 的输入原来源是 A，用户提供替代值；这是本次测试数据，不修改 B 的持久化绑定。
2. B 执行，返回值通过原声明自动送入 C。
3. C 执行，返回值自动送入 D。
4. 展示 B/C/D 各自结果；A/E 显示“本次范围外，不执行”。
5. A 的 SQL/连接/代码未完善、E 的输出配置未完善，不应仅因此阻止这段测试。被测节点自身结构、实现、连接和类型仍必须有效。
6. 若 D 另有来自范围外 X 的输入，应同时要求提供该输入，不执行 X。
7. 片段未连接全局“编排输出”也可测试；结果取被测节点输出，不伪装为整条编排的最终返回值。

范围外数据完全由用户输入提供；本期不自动抓上次上游结果、不混用跨项目缓存。

## 7. 输入边界与类型规则

以每个“目标节点 ID + 输入参数 ID”作为覆盖值的稳定身份。显示名/技术名只用于呈现或与既有协议转换。

| 输入来源 | 片段测试行为 |
|---|---|
| 范围内节点输出/字段 | 自动取真实上游结果，不允许测试值覆盖 |
| 范围外节点输出/字段 | 提供最终传给目标输入的值；不要求填写整个范围外输出对象 |
| 编排入口参数 | 测试页提供入口值，可为多个目标输入复用，并按各目标类型验证 |
| 固定值 | 沿用当前定义，显示只读摘要，本次不单独覆盖 |
| 未绑定来源 | 可为已声明的输入提供本次测试值；标明测试不会修复正式绑定 |
| 不存在的输入/非法来源结构 | 拒绝，不忽略、不绑定同名参数替代 |

文本、数值、布尔、日期时间、对象、列表沿用既有类型体系。前后端都做测试输入验证，后端最终决定：缺字段与显式空值区分；0/false 有效；数值不可为 NaN/Infinity；对象/列表不仅验证 JSON 可解析，还要按声明验证结构及字段类型。日期时间沿现有约定。现有协议没有可空语义时，不自行把缺少必填数值转换为 null。

同名输入属于不同节点时不得冲突。内部输出类型或字段路径错误必须失败，不能退回人工输入来掩盖。

## 8. 执行、错误和结果

- 按所选子图依赖顺序执行，客户端提交顺序不决定执行顺序。
- 请求发出前检查范围与输入完整性。新隔离测试应预检全部边界输入，缺值/类型错误在任一节点真实执行前阻断。
- 某节点失败，其所选下游传递性标为 skipped；不要执行后再报“上游没输出”。范围外节点不是 skipped，不伪造执行结果。
- 保留此前成功节点的结果；失败节点展示错误、可用的已解析输入与日志，未执行节点不能显示旧输出。
- 右侧按被测节点切换，展示该节点本次实际解析的输入、输出、状态、耗时、行数及日志。不能仅展示用户提交的整体 JSON 冒充所有节点输入。
- 标量直接展示；记录列表优先表格；对象/嵌套值提供 JSON；长文本和日志可复制。表格先显示前 100 行并说明预览限制，不截断传给下游的实际数据。
- 现有接口为一次性响应。完成前如不能获取逐节点进度，只显示“执行中/等待响应”，不得用动画或定时器伪造成功进度；本期不新增流式接口。
- 保留当前 SQL/Redis/HTTP 的真实执行提示与写操作确认，按本次所选范围生成；范围外写节点不应被执行或要求确认。
- 测试不修改编排草稿、项目绑定或发布版本，但真实 SQL/HTTP 等节点仍可能产生业务副作用，界面不能称其为纯模拟。

### 8.1 结果有效性和会话状态

测试结果关联提交时的编排 ID、配置签名、项目 ID、范围、输入值以及请求代次。

- 改实现/绑定/输出声明、切项目后，原结果标记为旧配置/旧项目结果。
- 只改测试输入/范围后显示“上次测试结果，尚未按当前输入/范围运行”；结果仍明确标注原范围，不能换标题冒充新结果。
- 只缩放画布/选择节点/切换结果页签不让结果过期。
- 同次测试未结束不能重复发起。返回设计不是取消后台执行；再次进入展示真实运行状态。
- 换编排或退出登录后，晚到响应不得污染当前页面。不能仅凭组件仍存在就写入结果。
- 缓存使用页面内存，按编排/项目/范围/参数签名隔离；不持久化到 localStorage、共享上下文或编排资产。

## 9. 目标接口变更（实施前必须登记）

本节是待实施目标，不代表当前接口已支持。执行者先同步 `文档/接口文档/04-编排与LLM接口.md`、`01` 涉及的数据结构、`05` 速查表及 README 变更记录，再改代码。继续复用 POST `/api/flow-run`，不另造通用执行 API。

### 9.1 向后兼容的隔离测试请求

```json
{
  "state": "此处为完整 FlowState 对象，示意省略",
  "projectId": "当前可访问项目的 ID",
  "testMode": "isolated",
  "targets": ["node-b", "node-c", "node-d"],
  "inputOverrides": {
    "node-b": {"input-b-x": 10}
  }
}
```

- `testMode` 新增可选字段，仅接受 `isolated`；必须带非空、无重复、存在的处理节点 `targets`。
- `inputOverrides` 新增可选对象：节点稳定 ID → 输入稳定 ID → 类型正确的值，只允许覆盖本次范围的外部/未绑定输入。
- `inputs` 继续承接编排入口值；同一输入同时通过入口值和 inputOverrides 赋值时拒绝歧义，不能靠未说明的优先级处理。
- 固定来源、内部依赖不得通过 overrides 覆盖；未知/范围外节点、未知参数、多余覆盖项应报错。
- `testMode=isolated` 不通过旧的 `nodeId.技术名` 覆盖路径绕过内部依赖。新前端统一使用稳定 ID；旧调用保留旧协议处理分支。
- 省略 `testMode`：既有全图、单节点、上游闭合范围测试保持兼容。不是把所有旧 targets 调用静默改义。
- targets 省略继续是全图运行；`[]` 绝不能解释为全图。省略 targets 却携带 isolated/overrides 为非法请求。
- 全图运行的 revision/409/per-flow 互斥保留；局部测试沿用不落盘的配置快照，不借测试保存资产。

### 9.2 响应的兼容补充

继续返回既有 status/nodeResults/startedAt/durationMs；nodeResults 只包含真实所选范围，顺序为实际执行顺序。现有 outputs/outputNames 等字段不改名。

新增可选字段：

- `nodeResults[].inputs`：该节点实际解析的输入值，以输入技术名为键，便于展示；命名与类型从提交快照读取。
- `nodeResults[].inputsTruncated`：是否为有界预览。输入预览每节点最多 100 条列表记录、序列化总量建议 64 KiB；超过时截短并标记，不改变节点真正收到的数据。
- 输入解析前失败/未执行：不伪造 inputs；前端显示“未获得本次输入”。执行器已收到输入后失败：可展示已解析输入。

预览生成集中封装，任何不可序列化/超限处理都不能把执行成功改成接口 500。不得返回注入的连接密码、认证头、API Key 或模型密钥；继续沿用已有凭据隔离/日志脱敏边界。

状态码约定：请求结构/模式/节点集非法 400；类型不符/边界缺值/选中节点配置错误 422（含定位信息）；资源不存在或无权访问按现有 404/401；全图冲突 409。节点已经开始执行后的业务失败仍按现有 200 + status:error + nodeResults 返回。不能把预检错误包装成成功。

## 10. 校验的分层范围

1. 请求结构与归属校验始终执行，不能通过测试跨账号获取项目、编排、凭据或数据。
2. 被测集合自身必须无环且连通；不存在/重复 ID、输入结构不合法直接拒绝。
3. 检查被测节点自身实现、连接、输出声明和内部绑定的存在性/类型。
4. 对被手工替代的边界输入，只检查目标输入声明与提供值，不要求外部节点实际可运行。
5. 不把范围外节点的实现/连接错误、未绑定全局输出，当成片段运行阻断项。整图校验仍完整保留。
6. 不靠搜索/过滤错误文案跳过校验。按结构化 code、节点 ID、参数 ID、依赖归属明确分类。

## 11. 属性绑定、保存与兼容

- 从属性取值进入时打开已选编排，返回恢复对象、属性和未提交表单；测试输入绝不写入属性的 inputs 配置。
- 保留 flow/output/inputs 的稳定 ID 协议，当前标量属性兼容限制不因本次布局变更放松。
- 旧 SQL、Redis、HTTP、计算、Python 编排必须原样读写；未知扩展字段不丢失；不迁移真实资产。
- 本体、项目、编排保存线独立；保留自动保存、undo/redo、CAS 与 409 处理。已有 flow saver 优先复用。
- 浏览/切换测试/看结果不触发保存；修改正式节点配置仍走现有 before-change/changed 链。

## 12. 确定性验收样例

不依赖业务数据库或模型服务，用现有 calc-expression-1 公式构造五个数值节点：

| 节点 | 输入 | 公式 | 原关系 |
|---|---|---|---|
| A | 编排入口 x | `{x}` | 编排入口 → A |
| B | x | `{x} + 2` | A → B |
| C | x | `{x} * 3` | B → C |
| D | x | `{x} / 2` | C → D |
| E | x | `{x} * 100` | D → E |

选 B–D，手工提供 B.x=10：B=12、C=36、D=18；A/E 执行计数严格为 0，不能出现 E=1800 的本次结果。切回全图，入口 10 得到 E=1800。此例测试真正的片段执行，不依赖 SOC 拟议表达式。
