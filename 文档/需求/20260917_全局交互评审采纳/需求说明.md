## 2. G1：等待必须有结束状态与恢复入口

### 2.1 必要读取

- 本体初始化成功、失败、等待中应有明确状态；必要读取失败不能渲染成“没有本体”，不能引导用户误建重复本体。
- 本体加载不等待无关项目读取，保留上一批的懒加载、请求去重与旧响应隔离。
- 初始化及项目必要读取超过3秒时显示“仍在加载，请稍候”，不要直接推断服务离线。
- 本期采用默认15秒读取超时，集中配置，可在测试中注入更短时间；作用于必要本体／项目列表、状态及引用版本读取。不得机械套用到SQL执行、连接测试或其他长任务。
- 超时从发起读取计算到响应体解析完成。结束等待并显示“读取本体数据超时”或“读取项目数据超时”，提供“重试”；项目区同时保留“返回本体”。
- 优先使用AbortController并兼容调用方已有取消信号；超时、用户切换导致的取消、网络失败应区分。取消过期请求不弹失败提示，晚到结果不得覆盖当前上下文。
- 重试只重新读取所需数据，不刷新整个浏览器、不丢弃已编辑表单；连续点击不得重复并发请求。初始化重试不得重复注册事件监听器或重复初始化保存器。

### 2.2 不把读取重试套在写操作上

- 不给所有POST统一加15秒自动中断／重试。连接测试、只读校验虽然可用POST，也应按操作含义处理。
- 保存、发布仍在等待时显示“正在保存／发布，请勿重复操作”；超过15秒可补充“响应较慢，正在等待结果”，不提前认定失败。
- 若写请求网络中断且无法确认服务端是否完成，提示“未收到保存／发布结果，暂不能确认是否成功”，保留输入；不显示“已保存”或“未写入”这类无依据结论，不自动重发。
- 使用现有修订／版本查询能力协助核对结果。读取服务器状态不能直接覆盖本地未保存内容；发布先查看是否已有目标版本，不诱导用户重复发布。
- 保留现有保存器、revision、409与用户主动重试机制；不得另建自动重试保存队列、幂等协议或放宽冲突校验。

## 3. G2：错误说明与处理动作

### 3.1 呈现内容

统一最小结构：操作标题、可理解的原因／当前状态、真正可用的下一步；技术详情默认折叠。根据上下文复用小组件或展示辅助函数，不要求改遍全站。

| 场景 | 推荐内容与动作 |
| --- | --- |
| 本体读取超时 | “读取本体数据超时”；检查本地服务后“重试读取” |
| 项目读取失败 | “项目数据加载失败，本体建模可继续使用”；“重试”“返回本体” |
| Origin明确被拒绝 | “当前页面地址未通过服务校验，本次请求已被拒绝”；给出正确访问地址和说明，修正后再操作 |
| 表单校验不通过 | 具体字段及原因，保留输入；不得显示为网络错误 |
| 配置校验请求失败 | “未能完成校验”；不把网络错误计入业务问题数、不保留‘本次校验通过’假象；允许重新校验 |
| 保存冲突409 | 说明服务端内容已更新；保留现有冲突处置入口及确认，不能普通重试静默覆盖 |
| 写操作结果未知 | 明确未收到结果，先核对服务器修订／已发布版本，再使用现有处置流程 |

- 保存失败、发布失败、冲突应在对应页面或状态区持续可见，处理成功或用户明确关闭后再消失。关闭提示不改变错误事实或把保存器改为成功。
- 同一次错误只显示一个完整错误面板，避免全局红条和局部红字重复。顶栏可保留简短状态，但不能隐藏当前表单错误。
- 成功等短反馈可用短提示；不能将关键失败统一换成自动消失Toast。
- 不添加无目标的“联系管理员／查看文档”按钮。技术详情仅包含必要的操作、状态码、脱敏端点、原因；不得泄露凭据、请求正文或真实数据库记录。

### 3.2 Origin问题排查

执行者须用允许的本机访问地址复现，并核对页面Origin、请求目标及开发代理。保留服务器Origin白名单和现有安全边界，不允许使用通配Origin、关闭校验或伪造Origin绕过。

正式访问提示默认使用当前服务配置的本机地址，不能把测试端口写死为18765，也不能使用未校验的任意请求参数生成跳转地址。打开正确地址不能自动丢弃未保存表单；最好提供独立标签页链接与保留输入说明。

如果标准本机地址可正常访问，报告错误来自评审环境，则明确记录这一结论并改进提示，不虚构服务端Bug。若确认是项目开发代理配置不一致，可最小修复该配置，不扩展远程部署支持。

## 4. G3：保存状态准确表达

不新增业务状态字段，使用现有表单guard与Saver状态派生显示；文案应与真实状态同步。

| 实际状态 | 展示要求 |
| --- | --- |
| 没有表单，草稿已保存 | “已保存” |
| 打开表单但内容未改 | 可显示“编辑表单”，不能标成有未保存修改；已保存只指现有草稿 |
| 表单有未提交修改 | 显示“表单有未保存修改”；不再单独并列一个无范围的绿色“已保存” |
| 表单有修改且工作区草稿有其他保存结果 | 如需同时显示，应写“工作区草稿已保存；表单修改尚未提交” |
| 保存中／失败／冲突 | 保留相应状态、输入与现有处理入口，不能被表单提示遮蔽 |
| 保存成功／取消／把输入还原 | 按实际dirty与Saver状态恢复展示，不滞留未保存提示 |

适用于通过现有form-guard接入的对象、链接、属性、动作、规则、连接等表单；不另建字段级差异系统。仅打开表单不应触发“丢弃修改”确认；真正dirty时保留现有离开保护。可使用静态琥珀色辅助区分，不能只靠颜色。

不加脉冲动效、可点击状态摘要、修改字段数量或全局未保存清单。

## 5. G4：常用操作直达，低频操作收纳

| 页面 | 行内保留 | 更多操作 |
| --- | --- | --- |
| 共享属性库 | 维护定义、查看引用 | 引用到对象、复制为私有、删除定义 |
| 数据连接 | 配置、测试 | 删除及本行已有的其他低频操作（不新增能力） |

- 现有频繁使用的表结构查看／刷新入口不因收纳而失踪；保留其原位置即可，不扩展重排全页。
- 更多菜单中删除放底部，用分隔与危险样式区分；支持键盘操作、Escape关闭、焦点回到触发按钮和窄屏点击。
- 确认内容必须反映现有代码：共享属性若转为私有则说清转换及不再同步；存在不允许删除的引用应阻止。连接被引用时继续阻止，允许删除时说清连接配置／目录等真实影响；不能暗示删除外部数据库业务记录。
- 沿用现有稳定ID、引用检测与撤销机制，不改变级联清理策略，不为美化提示新增删除能力。

- 项目引用本体名称与版本保留可见，允许独立换行或缩短其他文案；不隐藏到只靠hover的提示。
