# 登录与账号体系 · 需求说明

日期：2026-09-18　　状态：用户已确认（4 项业务问题当场拍板），实施中
配套：[开发计划](开发计划.md) · [接口文档 06-认证与账户](../../接口文档/06-认证与账户接口.md)

> 说明：本次为公司内部直接驱动的小型改造，用户要求「帮我做」，实施与验收同轮推进，
> 因此不另出交互原型 HTML 与独立执行指令（避免与开发计划重复）；界面基准沿用工作台既有视觉。

## 1. 需求（用户原话）

> 「帮我做登录页，所有数据都要和账号绑定，现在的数据绑定到 admin 用户。」

## 2. 已确认的业务决定（2026-09-18 用户逐项拍板）

| # | 问题 | 决定 |
| --- | --- | --- |
| 1 | 数据可见性 | **完全隔离**：每个账号一套独立数据（本体、项目、编排、连接密钥、模型配置），互相看不见；admin 只是持有现有数据的账号 |
| 2 | 账号来源 | **登录页开放注册**：任何人可在登录页自助注册；新账号自带空白数据空间 |
| 3 | 配置级数据（连接密码 / API 凭据 / 模型 Key） | **按账号隔离**；现有配置全部归 admin |
| 4 | admin 初始凭据 | 用户名 `admin`，初始密码 `admin`（用户明确指定；已如实提示为弱密码，登录后可改） |

## 3. 功能范围

1. **登录页**：未登录时整个工作台不可用（不显示侧栏与业务数据），只显示登录/注册表单。
2. **开放注册**：同一页面切换注册；注册成功即登录并进入空白数据空间。
3. **数据按账号绑定**：登录后所有既有接口只操作「当前账号的数据」；跨账号数据一律按不存在处理（404），任何响应不泄露他账号数据的存在与内容。
4. **存量数据迁移**：现有 SQLite 库中全部资产（本体/项目/编排）、模型配置、设置、凭据 → 归属 admin；迁移幂等、可重复执行、迁移前先备份。
5. **会话与退出**：登录态通过 Cookie 会话保持（30 天）；左下用户区显示真实用户名；「退出登录」从禁用变为可用，退出后回到登录页。
6. **本地偏好按账号隔离**：浏览器 localStorage 里的偏好（收藏、上次打开的项目/编排、界面状态）按账号加前缀，避免换账号串数据。

## 4. 非目标（本期不做）

- 不做密码找回、邮箱/手机号、二次验证、账号禁用/删除（后续如需再加）。
- 不做管理员后台（用户管理页）；注册开放，账号平等。
- 不改服务监听范围：仍只绑定 `127.0.0.1`，不对外网暴露；因此不做 HTTPS（后续如需局域网部署另行立项）。
- 不改任何既有业务接口的请求/响应结构（除新增 401 语义与 4 个认证接口）。

## 5. 数据与安全约束

- 密码只存 **scrypt 哈希**（stdlib `hashlib`，随机盐），永不存明文、永不回传、不进日志。
- 会话令牌随机 32 字节，库里只存 SHA-256 摘要；Cookie `HttpOnly + SameSite=Strict`，杜绝前端脚本读取与跨站携带。
- 保留既有安全边界：POST 白名单、Origin 校验、2MB 上限、写锁；新增 401 统一错误码 `UNAUTHENTICATED`。
- 迁移真实库前**先做在线备份**（`transfer backup`），迁移在服务停止状态下执行；不手改业务数据。

## 6. 验收标准

| 编号 | 标准 |
| --- | --- |
| A01 | 未登录访问任意业务接口返回 401（`UNAUTHENTICATED`）；页面只显示登录页 |
| A02 | 注册 → 自动登录 → 空白空间（无本体）；创建本体、保存、发布全链路可用 |
| A03 | 账号 A 与 B 数据完全隔离：A 的本体/项目/编排/连接/模型 B 完全看不见；用 A 的 id 直连 B 的接口返回 404 |
| A04 | admin 登录后能看到迁移前的全部数据（本体清单、项目、编排、模型配置、连接凭据齐全），行为与迁移前一致 |
| A05 | 退出登录后回到登录页；刷新保持登录（Cookie 会话）；再次访问业务接口 401 |
| A06 | 密码错误、用户名重复、非法用户名的错误提示准确；密码/令牌不出现在任何响应、日志与快照 |
| A07 | 存量数据迁移脚本幂等：重复执行不产生重复归属、不改变既有内容（备份 → 迁移 → 校验内容哈希一致） |
| A08 | 既有回归：前端构建通过、后端测试通过（含本次新增 auth/隔离用例）；服务器仍仅监听 127.0.0.1 |

## 7. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 唯一约束从 (kind, external_id) 变为 (kind, owner, external_id)，需重建 wb_assets 表 | 迁移脚本在事务内执行；真实库先备份；先用真实库副本演练后再上真实库 |
| 各业务模块遗漏归属过滤 → 数据串号 | 归属过滤收口在存储层（assets/configuration），域层统一 `require_user_id()`；新增隔离用例覆盖 4 类数据 |
| 现有测试大量直连域函数 | 逐一改为显式传入归属（测试用 `u-test`）；HTTP 测试先注册登录再调用 |
