## 2. 关键设计决策

1. **归属过滤收口在存储层**，业务层不各自拼 SQL：`assets.py` 的读写函数新增必填 `owner_user_id`；`configuration.py` 的用户级设置走新表 `wb_user_settings`（复合主键，不动旧 `wb_settings` 的全局语义）。
2. **身份来自会话 Cookie**，`auth.bind_request(user)` 把当前用户放进请求上下文（`contextvars`）；域函数用 `require_user_id()` 取值，未登录即抛 `AuthRequired` → HTTP 401。CLI/迁移不设上下文，直接走 engine 层。
3. **唯一约束按账号**：(kind, owner_user_id, external_id)；同名检查同样按账号。默认本体 id `storage` 因此每账号各有一份。
4. **凭据归属传导**：连接/API 凭据的 `owner_key` 仍是项目资产 uid（项目已按账号归属，凭据自然隔离）；LLM 凭据的 `owner_key` 从固定 `'global'` 改为**用户 id**。
5. **回退友好**：迁移只新增列/表与换唯一约束，不删除任何历史内容；`assign-owner` 只填空值列，可重复执行。

### 5.2 实施中发现并修复的缺陷

1. **`/api/auth-state` 不解会话**：它被列为免登录接口后跳过了解会话，导致刷新页面永远报 `user:null`、被弹回登录页（浏览器实测发现；已改为"免登录接口也解会话，只是允许 None"，并补回归断言）。
2. **退出登录不切界面**：`logout()` 只清了前端状态，未通知引导层；已让退出走与 401 相同的回调路径。
3. **`assign-owner` 直接改 owner_key 会让 LLM 密钥无法解密**：AES-GCM 的 AAD 绑定 `owner_key`；已改为"按旧 AAD 解密 → 按新 AAD 加密"重加密，解密失败的条目保留原行并在输出中明示（不静默丢弃）。
4. **`start.sh` 健康检查用业务接口**：账号体系后 `/api/ontologies` 返回 401，导致服务起来又被判"未就绪"杀掉；已改用免登录端点。

### 5.5 遗留与说明

- **口令方案为 PBKDF2-HMAC-SHA256（600000 轮）而非 scrypt**：本机 Python 3.9 不提供 `hashlib.scrypt`（实测 AttributeError），改用标准库同级的 PBKDF2；接口文档 06 §4 已同步为 PBKDF2 描述。
- **admin/admin 为弱口令**：按用户指定设置；本地单用户工具、仅监听回环，已如实提示可随时改密（改密入口本期未做界面，可用 `transfer create-user --reset-password` 重置）。
- **本期未做**：忘记密码自助找回、账号禁用/删除、管理员用户管理页。
- **浏览器实测的一个环境事实**：Cookie 按主机名共享、不按端口隔离——同一浏览器在 `127.0.0.1` 上访问多个实例会共用 `wiz_session`；本地开发多实例请用不同主机名（如 `localhost` 与 `127.0.0.1`）区分。
