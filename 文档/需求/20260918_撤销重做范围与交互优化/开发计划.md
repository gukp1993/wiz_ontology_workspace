## 1. 顺序及代码入口

| 阶段 | 入口 | 工作 | 验收 |
|---|---|---|---|
| 0 基线 | App.vue、workspace.ts、shortcuts.ts、formGuard.ts | 记录各事件/表单/图操作/快捷键现状，确认最新分支及未提交改动 | 不误伤其他harness工作 |
| 1 范围 | app/navigation.ts或独立小型策略、App.vue | 编辑页白名单、scopeKey、生命周期；非编辑页按钮与键盘同时禁用；移除项目压栈 | U01、U07、U08 |
| 2 历史事务 | app/workspace.ts、form-save及编辑事件链 | 操作名称、target、候选事务、无变化丢弃、60步响应式、失败取消 | U03、U06、U12 |
| 3 业务操作接入 | ontology/ObjectWorkspace、PropertyManager、SharedLibrary、BusinessRuleLibrary、ActionLibrary、ObjectCanvas；flow/FlowEditor、FlowCanvas、NodeConfig、BoundaryConfig | 添加动作元信息、表单保存只记一次、绑定与删除原子、连续文本/拖动合并 | U04、U05、U13 |
| 4 保存与交互 | App.vue、shortcuts.ts、formGuard.ts；按需少量适配Saver | canUndo/canRedo、表单/弹窗/运行阻断、事务锁、失败与重试、检查过期 | U02、U09–U11 |

一个集成人负责App/workspace接口后再接具体编辑器，避免同文件多人改。单个harness顺序执行即可，不要求新开多个agent。

## 2. 推荐技术实现

1. 小型编辑策略由明确view白名单判定，不能 `space==='ontology'` 全放行。兼容未来全局settings路由：非白名单默认无业务历史。
2. createUndoArea演进为带操作元信息的轻量历史管理器；继续快照方案，栈只存内存。推荐begin/commit/cancel事务语义，实际命名自由。currentRef+scopeKey确保资产一致；每个操作用唯一token防失败错误取消别人的记录。
3. 表单submitForm先保留历史候选与原redo，成功才提交历史；失败回滚working同时取消候选。撤销入口与正常表单都不得重复push。只给操作描述可选参数并逐页补足，不改后端schema。
4. 即时字段按focus→blur事务聚合，structural操作前结算；保留自动保存频率，不用900ms节流代替历史分组。代码编辑器输入使用自己的undo，不手动接管文本历史。
5. 撤销/重做调用同一入口：flush基线→验证scope未变→应用历史→串行commitNow→状态反馈。事务期间业务编辑锁定；结果属于提交时scope，旧响应不能影响切换后的资产。
6. 当恢复后保存失败时，保持本地恢复结果和一次历史指针变动，交给现有错误/冲突UI重试；重载清空历史。不要写第二套自动重试，不用undo()作为“撤销失败回滚”。
7. 工作副本恢复需保护非业务字段：不以快照旧revision替换Saver.revision；运行结果与检查状态失效；尽量保留有效视口。未知业务字段完整保留，勿手工挑少数字段造成丢失。
8. 页级编辑范围变化时清空，两区来源返回机制仍保留选中与视口；不要把“保存编辑现场”理解为必须跨页保留undo栈。和全局设置方案一致：数据不丢，历史重置有说明。

不新增全局状态框架、路由框架、事件总线、操作日志数据库。不重写saveCoordinator；确需改该敏感文件先补针对用例，依照AGENTS运行其既有回归。

## 3. 测试

- 历史单元：具名before/after、空操作、60上限、redo分支、scope reset、事务取消、重复begin保护、原子删除绑定、连续输入聚合。
- 快捷键/策略：白名单与否、输入控件及composedPath、contenteditable/editor根、IME、defaultPrevented、任意模态/局部表单、执行中、栈空；按钮与键盘一致。
- formSave：成功只入一次；mutate异常、明确保存失败、unknownOutcome各自遵循现有状态；失败不损伤redo；不允许错误重试自动提交已取消表单。
- Saver适配：flush失败不pop；撤销保存失败后retry不再移动；409显式处理；切换资产或重载后的旧回包隔离。使用可控延迟的请求替身。
- 保留并运行 `tests/save_queue.test.mjs`、`tests/mapping_forms.test.mjs`、`tests/object_workspace.test.mjs` 中与实际改动相关的既有用例；按当前项目命令运行，不未经检查安装新测试框架。
- `cd frontend && npm run build`。
- 使用临时WIZ_WORKBENCH_ROOT+独立端口、合成模型/编排。真实浏览器手测Ctrl/Cmd+Z文本行为、失焦后一次结构撤销、弹窗阻断、属性删除恢复、跨页重置、失败重试；覆盖按钮与键盘两条入口。
- 不使用真实ontology写入，不调用真实SQL/Redis/HTTP/LLM，不改vault。测试只需模拟保存与执行状态，不必真的运行设备动作。
