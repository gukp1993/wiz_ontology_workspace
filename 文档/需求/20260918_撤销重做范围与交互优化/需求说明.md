# 撤销／重做范围与交互优化需求

版本 v1 · 2026-09-18 · 状态：方案交付，未修改正式工作台。

配套：[交互原型](交互原型_v1.html) · [开发计划](开发计划.md) · [执行指令](执行指令.md)。

## 1. 目标与确认范围

按照用户接受的方向：**保留本体建模与函数编排的编辑撤销；普通配置表单使用保存／取消；文本撤销归输入控件；发布、执行和密钥操作不由编辑撤销处理。**

用户应能预判“撤销什么、影响哪个内容、是否已经保存”，不会在模型设置页按 Ctrl+Z 改掉本体，也不会误以为撤销节点配置可以撤回已执行的 HTTP 请求。

本期只改前端编辑历史、入口、快捷键与现有保存机制的衔接。保持自动保存、revision/409、离开保护与后端不可变发布线。不新增历史版本管理、审计平台、协同编辑、数据库回滚或执行补偿。

## 2. 当前实现及问题

核对入口：`frontend/src/App.vue`、`app/workspace.ts`、`app/shortcuts.ts`、`app/formGuard.ts`、`app/saveCoordinator.ts`。

- 当前本体、项目、编排分别有完整状态快照栈，默认最多60步；before-change压栈，没有操作名称。
- undo/redo替换区域 working，再commitNow立即形成草稿修订；不是只取消屏幕上未保存文字。
- 顶栏和快捷键按区域选择撤销栈，页面范围约束不够，用户可能在非编辑页撤回其他页面的变化。
- 普通输入框、textarea、select、contenteditable已有让出Ctrl/Cmd+Z的逻辑，必须保留，不重做浏览器文本历史。
- form-save在mutate前压历史；失败会回滚working并clearFailed，但该流程没有对应的历史事务取消，可能残留无效步骤。
- 编排名、节点名等部分字段每次input都会before-change，形成逐字符快照。保存队列的900ms合并不是撤销步合并，两者不能混同。

以上是源代码审阅结果，不代表本轮已做正式浏览器复现；实施前核对最新代码，复用其他harness已完成的修复。

## 3. 哪些地方保留

| 页面/场景 | 页面撤销按钮 | Ctrl/Cmd+Z | 操作说明 |
|---|---|---|---|
| 对象建模 objects：对象、属性、链接、对象与规则/动作关联、内嵌画布 | 保留 | 非输入且无表单/弹窗占用时有效 | 以当前本体、当前编辑页为范围 |
| 共享属性 library、业务规则 rules、动作定义 actions | 保留 | 同上 | 支持该页已应用的定义编辑，不能跨页撤回其他工作 |
| 函数编排编辑 f-editor | 保留 | 同上 | 当前编排节点/绑定/输入输出/实现配置/位置 |
| 项目映射 binding、取值规则 implements、连接 connections、项目信息/版本引用 | 不展示 | 不执行业务撤销 | 显式表单保存/取消；保存后再编辑改正 |
| 全局设置及模型配置 | 不展示 | 不执行业务撤销 | 使用其独立表单；不能触发背后工作区历史 |
| 工作概览、项目概览、函数编排列表、校验发布、数据浏览/预览 | 不展示 | 不执行业务撤销 | 列表删除整个资产不进入本轮编辑历史 |
| 历史辅助页（契约、接口、值类型等非本期编辑白名单） | 不展示 | 不执行业务撤销 | 本期不扩展这些页面；已有保存/取消与离开保护不变 |
| 任意普通输入框、代码编辑器、contenteditable | 不使用业务快捷键 | 当前控件自身撤销 | 即使文本栈为空，也不能继续冒泡去撤销本体 |
| 发布、模型连通测试、运行编排、业务接口调用、凭据变更 | 无编辑撤销 | 不可由此回滚 | 对外执行、已发布版本与密钥均在范围之外 |

移除项目撤销入口不等于把整套项目编辑改成逐字段自动保存。现有表单继续按保存/取消提交；已有明确点击即生效的列表操作维持其原有确认逻辑，只修正文案中不再成立的“可撤销”承诺。

未成功提交的本地表单，取消只丢弃该表单输入。已经保存的配置，取消不会恢复保存前的数据；用户需再次编辑保存。

## 4. 作用范围与历史生命周期

### 4.1 范围

一期采用保守、易解释的编辑会话：

- 本体：`ontologyId + 当前编辑页key`；如对象建模页是一个范围，共享属性页是另一个范围。
- 编排：`flowId + f-editor`。
- 页面内切换对象/节点、详情页签、列表/画布不切换范围；对象建模画布允许撤回同一本体内多个对象的操作，但按钮明确标出目标名称。
- 历史只在内存中，最多60个完整操作，不写本体/项目数据文件，不恢复浏览器上次会话。

### 4.2 何时清空

离开当前编辑页、切换本体/编排、刷新、重新加载服务端状态后，清空undo和redo；返回该页以当前已保存内容建立新起点。包括进入全局设置后再返回。**这只清空编辑历史，不丢弃已保存内容或原页面选中位置。** UI帮助明确“撤销仅限当前页面本次编辑，离开页面后重置”。不每次导航都弹确认，现有未提交/保存失败保护照常。

进入只读子面板、同页弹窗不清历史。导航被离开保护取消时也不能清。应在实际成功离开时结束会话，不在点击菜单第一时间清空。

成功发布、导入/批量替换、恢复快照或其他未被本历史系统记录的变更，如改变当前资产，建立新历史基线；取消/失败没有改变working时保留历史。普通自动保存成功不清历史，否则无法撤回误操作。

redo在一次新的真实修改完成后清空；只打开/取消表单、校验失败、没有变化的保存、浏览/选择、缩放平移都不清redo。

## 5. 一次操作对应一步

| 操作 | 历史记录示例 | 粒度 |
|---|---|---|
| 新建/删除对象 | 新建对象「储能簇」；删除对象「储能设备」 | 一次确认操作一步，包含该操作的关联清理 |
| 保存属性表单 | 修改属性「储能簇 · SOC」 | 一次成功应用的表单保存一步，不按字段分拆 |
| 新建/移除链接或引用 | 删除链接「储能簇 → 所属设备」 | 相关引用变化原子恢复，沿用现有删除保护 |
| 新建/删除编排节点 | 删除节点「查询簇 SOC」 | 节点与它被清理的绑定一起恢复 |
| 建立绑定 | 修改绑定「计算 SOC · 额定容量输入」 | 确认一次一步；取消不入历史 |
| 节点拖动、批量移动、自动整理 | 移动节点「查询额定容量」；整理画布 | 拖动开始前到结束后为一步，取消拖动不入历史 |
| 直接编辑节点名/代码等即时字段 | 修改节点「计算 SOC」的实现 | 同一字段一次聚焦编辑为一步，离开字段/结构操作/切页前结束 |
| 展开编辑窗口、重建代码骨架 | 修改节点实现；重建节点代码骨架 | 按现有应用方式确认一次一步，覆盖前仍确认 |

连续输入合并必须基于同一实体ID、同一字段、同一次编辑会话，不能把不同字段混合，也不能用Saver的自动保存时间充当操作边界。中文输入法composition不拆步骤。

本地表单保存失败：working保持或恢复到提交前，表单输入保留；历史也回到提交前，既不增加空步骤，也不清掉redo。`mutate`异常同理。优先采用候选事务，确定成功后登记；不能仅先push再失败时随便pop（可能移除并发的其他操作）。

即时文本先让输入控件处理自己的撤销，失焦时再结算合并历史；若最终内容与进入字段时相同，不入业务历史。不能因监听到了Ctrl+Z就手工替换textarea内容。

## 6. 按钮与快捷键

### 6.1 按钮

只在白名单编辑页显示撤销/重做工具组，放在该编辑区现有工具栏或顶栏同一处，不重复提供两组。

- 按钮文字“撤销”“重做”；hover/focus及邻近简短提示显示具体动作：“撤销：删除属性「储能簇 · SOC」”。需要时省略长名称但完整可查看。
- 辅助技术名称包含动作，例如 aria-label=`撤销：删除节点「计算 SOC」`。
- 栈空禁用，原因“当前页面没有可撤销的操作”。
- 有表单或模态编辑窗口打开时禁用业务撤销，提示“请先保存或取消当前表单”；固定的编排内联详情不算独立局部表单。即使本地表单尚未变脏，也不能在背后替换working。
- 运行编排、提交保存/撤销事务或冲突未解决时禁用，原因明确。输入控件自己的文本撤销不因页面按钮禁用而被全局拦截。
- 正常撤销不二次确认；删除/覆盖时原有确认仍保留。

### 6.2 快捷键优先级

1. 已被子组件处理（defaultPrevented）或正在输入法组合：应用层不接管。
2. INPUT/TEXTAREA/SELECT/contenteditable及代码编辑器根：Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z由控件处理，业务层不preventDefault、不落到业务历史。支持事件composedPath和编辑器注册/标记，不只检查最外层tagName。
3. 有模态/局部表单编辑：不触发背后编辑历史；Esc/菜单快捷键沿用该控件行为。
4. 当前可用白名单编辑页：Ctrl/Cmd+Z撤销，Ctrl/Cmd+Shift+Z重做。快捷键和按钮必须调用同一个canUndo/canRedo和动作处理函数。
5. 非编辑页、栈空、不可操作状态：不调用任何业务undo/redo；不改变隐藏工作区。没有相应动作时不无条件preventDefault。

本期不新增快捷键偏好页，不改Ctrl+S、复制粘贴、Esc、图快捷键或编辑器自己的历史系统。

## 7. 保存、失败与并发

### 7.1 自动保存与撤销并不冲突

已经自动保存的编辑仍可撤销。撤销后的内容作为**新的草稿修订**保存，不回写或删除历史发布版本。恢复目标的稳定ID不变，不重新创建业务ID。

一次撤销/重做的步骤：

1. 确定当前历史范围及状态可用，结束尚未结算的即时字段事务。
2. 若此前有待保存内容，先走现有Saver.flush，期间防重复提交；基线保存失败/冲突则停止，历史位置不移动。
3. 在当前会话内应用目标快照，移动历史指针一次，清除/标记相关检查与结果为过期。
4. commitNow串行保存恢复后的工作副本；成功后显示“已撤销……，已保存”。

处理期间阻止新的业务结构修改和再次撤销/重做，不把它排成多个不可见操作。不得直接发fetch绕过队列。

### 7.2 恢复后的保存失败

目标快照已应用时发生保存错误：保留屏幕上的恢复内容与已移动一次的历史位置，显示“已在当前页面撤销，保存失败／结果未确认”，提供现有重试或重载处理。不能把未收到响应说成服务端一定没改，也不能自动逆向恢复再发一次请求。

失败期间禁止继续业务历史操作；点击重试只重提当前恢复内容，不再次撤销、不再次移动历史。保存确认成功后解除锁定。放弃本地并重载服务端状态则清空历史。409使用现有显式冲突处理，不自动换revision覆盖别人修改。

这与“普通表单提交失败”不同：表单按既有契约恢复working并保留局部草稿；不要为了统一两者而改变全站表单失败行为。结果不确定时始终沿用Saver的unknownOutcome提示，下一次提交必须继续走现有并发校验。

### 7.3 快照内容

历史记录业务编辑状态和需要撤销的节点位置，保留未知扩展字段；不把revision、运行结果、检查结论、保存状态、连接密码或模型密钥放入恢复负载。视口zoom/pan、当前选中、搜索词不作为撤销动作；恢复业务快照时尽量保留当前有效视口，若选中目标已被删则解除选中并给出可读提示。

修改当前编排配置后，测试/运行结果是旧快照结果，不能恢复成当前成功。运行期间不允许结构撤销；运行完成后的配置撤销不会撤销外部副作用，结果仍按原执行快照显示。

## 8. 实现边界

推荐继续用轻量快照，增加操作元信息与事务边界，不要求重写为命令总线/事件溯源或新增依赖。建议历史元信息：

```ts
// 只在前端内存；正式接口按现有实现调整
{
  scopeKey: 'ontology:<id>:objects',
  actionLabel: '删除属性「储能簇 · SOC」',
  target: { kind: 'property', id: '<stable-id>', ownerId: '<stable-id>' },
  before: /* 可编辑业务状态 */,
  after: /* 可编辑业务状态 */,
  mergeKey: /* 可选，同字段同次编辑 */
}
```

默认limit仍60，依赖状态需响应式更新，不能使用普通数组counts而漏刷新按钮。前后快照无变化则不记录。

项目历史不再被任何业务入口调用。可移除projectUndoArea，或暂保留无入口实现以降低改动，但禁止继续无意义压入项目快照。不要删before-change事件后误伤保存、校验或其他用途；按调用链分辨。

原子表单保存需允许传入可选操作描述/事务上下文，确保成功时只产生一条历史，不和组件before-change重复记录。定义新增/删除/字段修改、图拖动与form-save至少各覆盖一条完整路径。

## 9. 验收标准

| 编号 | 场景与通过条件 |
|---|---|
| U01 | 指定编辑页有且只有一组历史按钮；其他页不展示；在模型设置/项目映射按快捷键不改本体/编排 |
| U02 | 在输入框/代码编辑器内撤销只影响文本；文本历史为空也不撤销节点；IME与子组件已处理事件不被劫持 |
| U03 | 删除SOC属性→已自动保存→撤销恢复同ID并另存草稿→重做删除；标签和数量准确 |
| U04 | 删除编排节点及其绑定作为一步恢复；不会产生残缺绑定；类型/引用校验仍有效 |
| U05 | 连续改一个字段为一步；换字段分开；拖动一步、整理一步；缩放/选择/打开取消无记录 |
| U06 | 表单保存成功一步；校验失败、请求失败、mutate异常、无变化保存不留空历史且不清redo |
| U07 | 项目映射/连接/模型表单保存取消原行为不变；取消不撤回已经保存的数据 |
| U08 | 同页切选中/页签保留历史；成功离页/切资产/刷新/重载清空；导航取消保留；普通保存不清空 |
| U09 | 撤销前flush失败不移动历史；应用恢复后保存失败显示本地已改未保存，重试仅提交一次恢复结果 |
| U10 | 409/未知结果不冒充成功，不绕过并发；重载建立新基线，无重复撤销/旧响应跨资产污染 |
| U11 | 发布、运行、密钥不进入编辑历史；设置/其他弹窗打开时不得撤销后台；运行中禁结构撤销 |
| U12 | redo只有真实新编辑才清；最多60操作；按钮状态可响应更新，快捷键与按钮规则一致 |
| U13 | 历史不携带secret/旧revision/检查与执行状态；未知业务扩展不丢；节点布局可恢复视口不乱跳 |
| U14 | 构建+定向测试+隔离浏览器操作验证；真实ontology/vault无改动，无外部业务执行 |

## 10. 原型说明

原型模拟对象/编排编辑、具名撤销、表单保存/取消、非编辑页面隐藏操作、页面切换重置历史，以及撤销保存失败和重试。模拟状态不写工作台，不调用服务。浏览器文本原生撤销需真实浏览器手测；DOM脚本验证不能替代它。

原型为简化交互样例；正式实现保留当前全部字段、协议、自动保存与校验。开发计划列出的错误/并发场景必须用隔离环境验证，不能把原型里的模拟成功搬入产品。
