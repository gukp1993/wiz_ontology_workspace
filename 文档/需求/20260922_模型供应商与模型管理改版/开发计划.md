## 2. 目标设计

### 2.1 三层配置模型（镜像 ZCode，落到本工作台）

```
第 1 层  内置目录（仓库数据文件，只读，catalogRevision）
         workbench/llm_catalog.json：
         { "schemaVersion": 1, "revision": 1,
           "templates": [ { "templateId": "bigmodel-standard", "name": "智谱 BigModel（OpenAI 兼容）",
               "apiType": "openai-chat-completions", "baseUrl": "https://open.bigmodel.cn/api/paas/v4",
               "apiKeyManagementUrl": "https://bigmodel.cn/usercenter/apikeys",
               "models": [ { "modelId": "glm-4.7", "displayName": "GLM-4.7", "enabledByDefault": true,
                   "contextWindow": 128000, "maxOutputTokens": 16384,
                   "reasoningLevels": ["disabled","low","medium","high"] }, … ] } ], …
           "customTemplates": [ {"templateId":"openai-compatible","name":"OpenAI 兼容自定义","apiType":"openai-chat-completions","baseUrl":"","models":[]},
                                {"templateId":"anthropic-compatible","name":"Anthropic 兼容自定义","apiType":"anthropic-messages","baseUrl":"","models":[]} ] }
第 2 层  用户供应商（SQLite wb_llm_providers，按账号）
         templateId（可空=纯自定义）+ 覆盖：name/apiType/baseUrl/headers/enabled/超时/温度/密钥
第 3 层  用户模型规则（SQLite wb_llm_models，按账号）
         mode='catalog'：增量覆盖目录模型（enabled/上下文/最大输出/思考档位/显示名）
         mode='manual' ：全量手动模型（目录不存在时）
默认项   wb_user_settings 键 models.default = {"providerId","modelId","reasoningLevel"?}
```

继承语义与 ZCode 一致：目录模式下**行不存在 = 目录默认**；行存在 = 该行字段覆盖目录，未覆盖字段仍继承目录。目录升级（改 JSON、升 revision）不回写用户行。

### 2.2 表结构（Alembic 迁移草案）

```sql
-- 新表 1：供应商（替代 wb_model_configs）
wb_llm_providers(
  owner_user_id TEXT NOT NULL, provider_id TEXT NOT NULL,        -- 主键 (owner_user_id, provider_id)
  name TEXT NOT NULL,                 -- 显示名 ≤60
  template_id TEXT,                   -- 内置模板 id，可空
  api_type TEXT NOT NULL,             -- 'openai-chat-completions' | 'anthropic-messages'
  base_url TEXT NOT NULL,             -- API 根（不含 /chat/completions、/messages）
  headers_json TEXT,                  -- 附加请求头 JSON 对象（键值均字符串，禁 Authorization）
  enabled INTEGER NOT NULL DEFAULT 1,
  timeout_seconds INTEGER NOT NULL DEFAULT 60,   -- 1..300
  temperature REAL NOT NULL DEFAULT 0,           -- 0..2
  key_management_url TEXT,            -- 可选
  secret_id TEXT,                     -- wb_credentials(namespace='model') 引用
  model_order_json TEXT,              -- 可选显示顺序（modelId 数组）
  metadata_revision INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL )
-- 新表 2：模型规则
wb_llm_models(
  owner_user_id TEXT NOT NULL, provider_id TEXT NOT NULL, model_id TEXT NOT NULL,  -- 主键三元组
  mode TEXT NOT NULL,                 -- 'catalog' | 'manual'
  enabled INTEGER NOT NULL DEFAULT 1,
  display_name TEXT,                  -- 覆盖/手动显示名
  overrides_json TEXT,                -- catalog 模式：{"contextWindow":…,"maxOutputTokens":…,"reasoningLevels":[…]} 部分覆盖
  manual_json TEXT,                   -- manual 模式：全量 {"contextWindow","maxOutputTokens","reasoningLevels"}（必填）
  metadata_revision INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL )
```

密钥沿用 `wb_credentials`（namespace=`model`，AAD=`model|<user>|<provider_id>`）。**迁移保持 provider_id 原值（llm-xxx）不变，密钥零重加密**。默认项写入 `wb_user_settings`（键 `models.default`，替代旧键 `models.default_provider_id`）；`model-default` 写护栏沿用。

### 2.3 有效配置合并器（域层核心，唯一实现点）

新模块 `workbench/llm_config.py`（或并入 llm_providers.py，实施时定）：

```
effective_providers(user) =
  对每个启用/禁用供应商：
    模板 = 目录 templates[template_id]（无则空模板）
    effective_models = 目录模板.models（各自 enabledByDefault/元数据）
                       ∪ 用户行(manual)
                       按 (provider_id, model_id) 合并：用户行字段覆盖目录字段
    顺序 = model_order_json 中列出的在前，其余按目录序/创建序
resolve_call(user, provider_id?, model_id?, reasoning_level?) =
  provider_id 空 → 默认项；model_id 空 → 该供应商默认模型（默认项指向的模型，否则首个启用模型）
  返回 {api_type, base_url, headers, api_key, model, max_tokens, reasoning注入参数, timeout, temperature}
```

`llm_providers.list_metadata()` 改为基于合并器输出（保持消费方接口形状尽量稳定，新增字段向后兼容），`resolve()` 返回值升级为含 model 维度。

### 2.4 请求参数注入（替代 ZCode 的 map 表达式）

不引入表达式引擎，按 `api_type` 内置固定映射（唯一允许的实现方式）：

| 内部选项 | openai-chat-completions | anthropic-messages |
| --- | --- | --- |
| `maxOutputTokens` | `"max_tokens": <n>`（默认取目录值，替代硬编码 4000） | `"max_tokens": <n>` |
| `reasoningLevel` | `low/medium/high` → `"reasoning_effort": <level>`；`disabled` → 不注入 | `low/medium/high` → `"thinking": {"type":"enabled","budget_tokens": <档位表>}`（档位=目录 `thinkingBudget` 或 max 的 25%/50%/80% 取整到千）；`disabled` → 不注入 |
| `temperature` | 沿用现有（MiniMax 特判保留） | 同现有语义 |

各协议请求体由 `llm_client.py` 内两个独立构建函数实现（`_build_openai_chat` / `_build_anthropic_messages`），共享响应解析与 JSON 提取逻辑。思考档位值域固定 `disabled/low/medium/high`（目录可少给，不给则该模型无档位选项）。

### 2.5 默认项与删除兜底规则

- `set_default(providerId, modelId, reasoningLevel?)`：幂等；目标必须存在且启用，否则 404/400。
- 删除供应商：同时删其模型行与密钥；若是默认项指向的供应商 → 兜底 = 其余供应商中首个启用模型（按列表序），并在响应中返回新默认（前端提示）。`models.default` 指向已禁用模型时：选择列表顶部提示「默认模型已禁用，将回退 …」，resolve 时跳过禁用项取首个启用。
- 禁用供应商 ≠ 删除：配置保留；消费方校验按「已禁用」报错（新增错误信息区分于 NOT_FOUND）。

### 2.6 API 契约（最终以接口文档 04 冻结稿为准）

| 端点 | 方法 | 请求 | 响应 | 说明 |
| --- | --- | --- | --- | --- |
| `/api/llm-catalog` | GET | — | `{schemaVersion, revision, templates:[…], customTemplates:[…]}` | 内置目录只读 |
| `/api/llm-providers` | GET | — | `{items:[{id,name,templateId,apiType,baseUrl,enabled,keyConfigured,keyManagementUrl,timeout,temperature,models:[{id,displayName,enabled,mode,contextWindow,maxOutputTokens,reasoningLevels,overridden:[…]}]}], defaultSelection:{providerId,modelId,reasoningLevel}\|null}` | 合并器输出；无密钥 |
| `/api/llm-provider-save` | POST | `{providerId?, templateId?, name, apiType, baseUrl, headers?, apiKey?(留空沿用), enabled?, timeout?, temperature?, keyManagementUrl?}` | `{saved:true, provider:{id,…}}` | 持 LOCK；校验同现规则 + apiType 枚举 + headers 禁 Authorization 键 |
| `/api/llm-provider-delete` | POST | `{providerId}` | `{cleared:true, newDefault?}` | 幂等；返回兜底默认 |
| `/api/llm-provider-default` | POST | `{providerId, modelId, reasoningLevel?}` | `{ok:true, defaultSelection}` | 目标须启用 |
| `/api/llm-model-save` | POST | `{providerId, modelId, mode:'catalog'\|'manual', enabled?, displayName?, overrides?:{contextWindow?,maxOutputTokens?,reasoningLevels?}, manual?:{全量}}` | `{saved:true, model:{…effective}}` | catalog+manual 同键 400；模型 id 格式校验 |
| `/api/llm-model-delete` | POST | `{providerId, modelId}` | `{cleared:true}` | catalog 行删除=回到目录默认；manual 行删除=移除 |
| `/api/llm-provider-test` | POST | `{providerId, modelId?}` 或临时 `{name,apiType,baseUrl,apiKey?,timeout?}` | `{ok,message,latencyMs}` | 真实探测不持锁，沿用 ping+max_tokens=1；anthropic 协议探测用 max_tokens=1 的 messages 请求 |
| `/api/llm-models-fetch` | POST（P1，可选） | `{providerId}` 或临时配置 | `{models:[id…]}` | GET `{baseUrl}/models`，不持锁 |

旧响应字段 `isDefault`（配置级）被 `defaultSelection` 取代，属**破坏性变更**，在 `README.md` 变更记录登记。`GET /api/llm-providers` 消费方仅设置页/节点面板/构建页/flows 检查，前后端同批发布。

### 2.7 迁移（wb_model_configs → 新表）

Alembic 迁移内程序化搬移（非 SQL 直拷后不管）：

1. 每行 `wb_model_configs` → `wb_llm_providers` 一行：`provider_id/name/timeout/temperature/secret_id` 原样；`base_url` = 原 endpoint 去掉尾部 `/chat/completions`（不匹配则整段保留并在响应/日志警告）；`api_type='openai-chat-completions'`；`template_id=NULL`；`enabled=1`。
2. `model` 列 → `wb_llm_models` 一行（mode='catalog'，enabled=1，overrides 空——目录没有该模型时降级为 manual_json 全量：contextWindow 缺省 128000、maxOutputTokens 4000、reasoningLevels `[]`，显示名=model id）。
3. `wb_user_settings` 键 `models.default_provider_id` → `models.default={providerId, modelId=迁移模型}`，删旧键。
4. 旧表 `wb_model_configs` 在迁移中 DROP（备份先行：迁移前 `transfer backup` 快照；回滚 = down migration 重建旧表并把模型行搬回）。
5. 迁移演练进 `tests/test_storage_transfer.py` 或新增 `tests/test_llm_migration.py`：建旧表造数据→upgrade→断言新表/密钥可解密/默认项等价→downgrade 往返。
