## 阶段 1 · 协议与配置校验 v2（两端镜像）

**新增模块 `workbench/flow_sql.py`（纯函数，无 IO）**

- MyBatis 动态 SQL 子集解析：标签树（`<if>/<choose>/<when>/<otherwise>/<where>/<set>/<trim>/<foreach>`）+ `test` 表达式子集（null/字符串/数字/布尔字面量比较、and/or/not、括号）；
- 参数引用扫描：`#{name}`、`:name`、`${name}`、`<foreach collection>`，去重保序；
- 渲染器：给定参数字典 → 最终 SQL + 预编译参数列表（`where/set/trim` 负责修剪多余 AND/逗号）；`foreach` 展开为 `(?,?,…)` 占位。

**修改 `workbench/flows.py`（check_flow v2 规则，全部 additive）**

- SQL：动态标签闭合与 `test` 可解析；`#{}`/`:param` 引用与输入声明双向核对（沿用一期 SQL_PARAM_SCAN 逻辑并合并）；`${}` 报 warning；`foreach collection` 必须是声明的 list 输入；多输出 warning（仅第一个参与执行）；
- Redis：`command` 在白名单表内（新常量 `REDIS_COMMANDS`：命令 → 参数形态 → 返回类型映射）；`args` 引用的参数已声明；仅 keyTemplate 的旧草稿按一期规则推断；管理命令报 error；
- Python：`ast.parse` 校验代码可解析且定义了 `main`（标准库 ast，允许）；形参与输入声明不匹配报 warning；
- `node.execution`：`timeoutMs` 1~300000、`maxRows` 1~10000、`allowWrite` 仅 sql 节点。

**修改 `frontend/src/flow/flowModel.ts`（与 flows.py 镜像，两端必须同步）**

- 类型常量（REDIS_COMMANDS 摘要、EXEC 限制）、来源解析沿用、检查文案一致。

**测试**：新增 `tests/test_flow_sql_dialect.py`（解析/渲染/foreach/test 表达式/错误用例）；扩展 `tests/test_flows.py`（v2 检查规则、旧草稿兼容）。运行方式：`python3 tests/xxx.py` 直跑，`WIZ_WORKBENCH_ROOT` 临时根。

## 阶段 2 · 执行引擎

**新增模块 `workbench/flow_executor.py`（唯一执行入口，纯后端）**

- 拓扑排序（复用 flows.check_flow 的依赖收集思路）→ 逐节点执行 → 结构化 nodeResults；
- Python 执行器：tempdir 写用户代码 + 包装器（stdin 传 JSON 入参、结果文件回传返回值、stdout/stderr 分离收集）；`sys.executable` 子进程；`timeoutMs` 超时 kill；rlimit CPU/内存尽力设置（平台差异容忍）；返回 dict 校验（缺声明输出→失败，多余键→warning 丢弃）；
- SQL 执行器：自建 PyMySQL 连接（凭据读 `secrets.py` vault）；默认 `SET SESSION TRANSACTION READ ONLY`，`allowWrite` 关闭；驱动 connect_timeout/read_timeout + 渲染后语句执行；`maxRows` 截断；SELECT→按第一输出声明映射（list<object>/object/标量，列名=字段技术名），DML→影响行数；decimal/datetime/date → number/ISO text；
- Redis 执行器：自建 redis 连接（同 vault）；单键/行模式；按 REDIS_COMMANDS 表的返回映射（integer→number、bulk→text、nil→null、array→list、HGETALL→object）；
- 可选依赖缺失（PyMySQL/redis 未安装）→ 返回可读错误提示，不做静默假成功；
- 进程内按 flowId 互斥（`threading` 标记，**绝不持 `workbench.locking.LOCK`**）；重复运行请求返回明确失败。

**路由**：`workbench/flow_routes.py` 新增 `post_flow_run(payload)`（先 `flows.check_flow`，errors>0 拒绝；再执行）；`server.py` 的 `POST_ROUTES` 增加 `'/api/flow-run'`（Origin/2MB 白名单沿用，不放松）。

**测试**：新增 `tests/test_flow_executor.py`——mock 驱动（注入假 pymysql/redis 模块对象，断言只读会话语句、参数列表、行数截断、映射结果）+ Python 执行器真实子进程用例（小代码、超时代码）+ 失败传播（下游 skipped）。不连任何真实数据库/Redis。

## 阶段 3 · 前端（画布运行交互）

- `frontend/src/flow/api.ts`：`runFlow(payload)`（经 `app/http`）；
- `App.vue`：`flowRun` 结果 ref（与 flowCheck 同级），透传给 FlowEditor；运行不属于保存线，不进 saveCoordinator；
- `FlowEditor.vue`：工具栏「运行全部 / 运行选中 / 清除状态」；入口参数试运行表单弹层（按类型生成控件，object/list 用 JSON 域）；错误时复用检查面板定位；快照标注文案；
- `FlowCanvas.vue`：节点状态徽标（idle/running/success+ms/failed/skipped）、失败红框、边行数徽标（数据从 runResults 传入，连线仍由绑定派生）；
- `NodeConfig.vue`：execution 字段（超时/行数上限/允许写，仅对应节点类型显示）、SQL 模板语法帮助文案、Redis 命令下拉（表驱动）与参数输入；
- `vue-tsc` 严格模式注意 `$event.target` 转型；`npm run typecheck` + `npm run build` 通过。

## 阶段 4 · 验收与交付

3. 浏览器验收：按 `需求说明.md` §11 清单逐项实测（真实连接冒烟只允许用户自备测试库、只读语句）；
4. git 提交（按 AGENTS.md 粒度：阶段 1 协议+校验、阶段 2 执行引擎、阶段 3 前端可分 commit；测试随阶段走；实施结果追加到本文件后再提交 docs）。

## 依赖与顺序

阶段 1 → 阶段 2 → 阶段 3 串行；阶段 2 的 `/api/flow-run` 响应结构可先与前端约定（见需求说明 §5），状态展示（阶段 3 画布徽标）可在引擎联调前用假数据并行开发。

## 范围边界（务必遵守）

- 不动 `dbdrivers.py` 的固定只读探测边界；执行连接由 `flow_executor.py` 自建；
- 不持 `LOCK` 执行；不放松 `server.py` 安全边界（白名单/Origin/2MB）；
- 编排仍无发布线；运行结果不落盘、不写修订流；
- 本体区/项目区零改动；`saveCoordinator`/409/撤销机制不受影响；
- 测试与开发一律 `WIZ_WORKBENCH_ROOT` 临时根；真实 `ontology/` 零写入。
