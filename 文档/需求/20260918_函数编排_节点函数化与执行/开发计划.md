## 阶段 1 · 协议与配置校验 v2（两端镜像）

**新增模块 `workbench/flow_sql.py`（纯函数）**：MyBatis 动态 SQL 子集（`<if>/<choose>/<when>/<otherwise>/<where>/<set>/<trim>/<foreach>` + test 表达式子集）解析、参数引用扫描（`#{}`/`:name`/`${}`/foreach collection）、渲染（最终 SQL + 预编译参数列表）。

**新增模块 `workbench/flow_http.py`（纯校验，执行在 executor）**：URL 模板占位解析（参考 `action_http.placeholders`）、method/bodyMode/headers/responsePath 校验、模板渲染（URL 编码与 JSON 值替换）。

**修改 `workbench/flows.py`（check_flow v2，全部 additive）**

- `NODE_KINDS` 扩为 `('python','sql','redis','http','calc')`；
- SQL：标签闭合/test 可解析/参数双向核对/`${}` warning/foreach collection/多输出 warning；
- Redis：`REDIS_COMMANDS` 白名单表（命令→参数形态→返回映射）、args 校验、管理命令 error、旧 keyTemplate 推断兼容；
- Python：`ast.parse` 语法与 main 存在（不执行）；`providerId` 有效性（提供 LLM 元数据列表时校验）；
- HTTP：URL http(s)/占位参数已声明/method/GET+body warning/credentialId 存在性（列表不可读降提示）；
- 计算：`mode='formula'`（默认）逐条公式过 `calc_functions` 静态检查（输入存在、类型 number/string/boolean）；`mode='llm'` 校验 instruction 非空与 provider；
- `node.execution`：timeoutMs 范围（LLM 节点默认 60s 上限 300s，其余默认 30s）、sql maxRows/allowWrite。

**修改 `frontend/src/flow/flowModel.ts`**：与上述逐条镜像（KIND 标签、五类节点配色常量、检查文案一致）。

**测试**：`tests/test_flow_sql_dialect.py` 新增；`tests/test_flows.py` 扩展（五类节点检查规则 + 旧草稿兼容）。

## 阶段 2 · LLM 配置模块

**新增 `workbench/llm_providers.py`**（对齐 `api_credentials.py` 边界）：

- 存储 `<DATA_ROOT>/ontology/vault/llm-providers/<id>.json`：0600/0700、tempfile+os.replace 原子替换、路径逃逸防护；
- 结构 `{id,name,endpoint,model,timeout,temperature,isDefault,api_key}`；`list_metadata()` 只回 id/name/model/isDefault/keyConfigured，**密钥只写不读回**；`read()` 仅供服务端执行器调用；
- 至多一个 `isDefault`；删除默认后自动指派剩余第一个（无则空）。

**新增 `workbench/llm_client.py`（代执行公共层）**：OpenAI 兼容 chat/completions 调用（urllib，参考 `formatting.py`）；temperature=0 纪律、max_tokens/响应大小上限、finish_reason=length 截断判错、HTTP 错误转中文可读错误；`evaluate_json(prompt_messages, provider, timeout)` → 解析 JSON（剥离代码围栏）失败带反馈重试 1 次；返回 (result, trace) 供日志留痕。

**路由**（`server.py` 白名单 + Origin；探测不持 LOCK）：`GET /api/llm-providers`、`POST /api/llm-provider-save`、`POST /api/llm-provider-delete`、`POST /api/llm-provider-test`（极小探测请求）。

**前端**：`frontend/src/tools/LlmProviders.vue`（列表/新增/编辑/删除/设默认/测试连通；密钥输入框留空=沿用已存）+ `navigation.ts` 挂辅助工具菜单。

**测试**：`tests/test_llm_providers.py`（临时根：CRUD/元数据无密钥/默认唯一性/路径逃逸拒绝 + mock urllib 的 llm_client 解析与重试）。

## 阶段 3 · 执行引擎

**新增 `workbench/flow_executor.py`**（唯一执行入口）：

- 入口 `run(state, targets, inputs, conn_context, llm_context)`：targets 校验连续链（节点来源⊆被测集）、收集外部输入（fixed 带值；缺失→明确报错）、拓扑序执行、失败传播 skipped、组装 nodeResults；
- **python 执行器**：组装提示词 → `llm_client.evaluate_json` → 按输出契约承接（缺→失败、多→warning 丢弃）；trace 写 logs（provider/model/耗时/请求与响应摘要截断）；
- **calc 执行器**：formula 模式逐输出调 `calc_functions` 求值（纯函数）；llm 模式走 `llm_client`；
- **sql 执行器**：`flow_sql.render` → 自建 PyMySQL 连接（凭据 vault）；默认只读会话、allowWrite 关闭；驱动+语句双超时；maxRows 截断；SELECT 按第一输出声明映射 / DML→影响行数；decimal/datetime→number/ISO text；
- **redis 执行器**：REDIS_COMMANDS 表驱动、单键/行模式、返回类型映射；
- **http 执行器**：`flow_http.render` → urllib 出站；超时/2MB 响应上限/2xx 校验/JSON 解析/responsePath 提取；可选 api_credentials 注入认证 header；
- 可选依赖（PyMySQL/redis）缺失→可读错误；进程内按 flowId 互斥（**绝不持 `workbench.locking.LOCK`**）。

**路由**：`flow_routes.py` 新增 `post_flow_run`（全图形态先 check_flow，errors>0 拒绝；targets 形态校验被测节点）；`server.py` 的 `POST_ROUTES` 增加 `'/api/flow-run'`。

**测试**：`tests/test_flow_executor.py`——mock 驱动（假 pymysql/redis 模块）+ mock LLM（monkeypatch `llm_client.evaluate_json`）+ mock urllib（http 节点）；覆盖：链校验与外部输入缺失、拓扑序与失败传播、五类节点各 2+ 用例（成功/失败）、LLM 非法 JSON 重试、只读会话语句断言、行数截断。不连任何真实服务。

## 阶段 4 · 前端（画布运行/测试交互 + LLM 配置入口）

- `flow/api.ts`：`runFlow(payload)`（经 `app/http`）；
- `App.vue`：`flowRun` 结果 state（不进 saveCoordinator）；
- `FlowEditor.vue`：工具栏「运行全部/测试选中/链选择开关/清除」；入口参数表单弹层；**测试表单弹层（外部输入按类型生成控件，fixed 锁定）**；链校验错误提示；

## 范围边界（务必遵守）

- 编排仍无发布线；运行/测试结果不落盘、不写修订流；
- **本机不执行任何用户代码**（Python 仅 ast 解析；公式走 calc_functions 白名单引擎；无沙箱需求）；
- 不动 `dbdrivers.py` 固定只读探测边界；执行连接由 `flow_executor.py` 自建；
- 不放松 `server.py` 安全边界；执行/探测接口不持 `LOCK`；
- 不改 `formatting.py`/`api_credentials.py` 既有行为（新功能独立模块）；
- 本体区/项目区零改动；`saveCoordinator`/409/撤销机制不受影响；
- 测试一律 `WIZ_WORKBENCH_ROOT` 临时根 + mock；真实 `ontology/` 与真实外呼零触碰。
