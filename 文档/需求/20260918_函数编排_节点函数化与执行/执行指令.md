## 1. 背景一句话

一期函数编排（已上线）只存配置不执行；本任务把每个节点变成可执行的"函数"（输入参数→输出），SQL 节点采用 MyBatis 风格动态 SQL，Redis 节点执行白名单命令，Python 节点子进程执行代码（**本版明确不做安全沙箱**），全部运行操作在画布完成。

## 2. 实施任务与顺序（按开发计划阶段执行，不得跳跃合并）

### 阶段 1 协议与校验 v2
1. 新建 `workbench/flow_sql.py`：MyBatis 动态 SQL 子集（`<if>/<choose>/<when>/<otherwise>/<where>/<set>/<trim>/<foreach>` + test 表达式子集）的解析、参数引用扫描（`#{}`/`:name`/`${}`/foreach collection）、渲染（最终 SQL + 预编译参数列表）。纯函数、无 IO。
2. `workbench/flows.py`：check_flow 增加 v2 规则（SQL 标签闭合/test 可解析/参数双向核对/`${}` warning/foreach collection 校验/多输出 warning；Redis 命令白名单表 `REDIS_COMMANDS` 与 args 校验，管理命令 error；Python `ast.parse` 校验 main 存在；`node.execution` 字段范围）。全部 additive，不破坏一期规则与文案结构。
3. `frontend/src/flow/flowModel.ts` 与步骤 2 逐条镜像（两端必须同步，字段与文案一致）。
4. 测试：新增 `tests/test_flow_sql_dialect.py`；扩展 `tests/test_flows.py`（v2 规则 + 旧草稿兼容）。

### 阶段 2 执行引擎
5. 新建 `workbench/flow_executor.py`：拓扑序执行；Python 子进程执行器（tempdir + 包装器 + stdin JSON 传参 + 结果文件回传 + stdout/stderr 分离 + `timeoutMs` 超时 kill + rlimit 尽力而为 + 返回 dict 契约校验）；SQL 执行器（自建 PyMySQL 连接、凭据读 `workbench/secrets.py` vault、默认 `SET SESSION TRANSACTION READ ONLY`、`allowWrite` 关闭、语句/驱动双超时、`maxRows` 截断、SELECT 按第一输出声明映射 / DML→影响行数、decimal/datetime→number/ISO text）；Redis 执行器（白名单命令表驱动、单键/行模式、返回类型映射）。可选依赖缺失给可读错误，绝不静默假成功。进程内按 flowId 互斥，**绝不持 `workbench.locking.LOCK`**。
6. `workbench/flow_routes.py` 增加 `post_flow_run`（先 `flows.check_flow`，errors>0 拒绝运行）；`server.py` 的 `POST_ROUTES` 增加 `'/api/flow-run'`。请求/响应结构以 `需求说明.md` §5 为准，无状态、不落盘。
7. 测试：新增 `tests/test_flow_executor.py`（mock 驱动注入 + 真实子进程 Python 用例 + 失败传播 skipped 断言）。**绝不连接真实数据库/Redis**。

## 3. 范围边界（违反任何一条即停）

- 编排仍**无发布线**：只改草稿行为与校验；运行结果不持久化、不写修订流。
- 不动 `workbench/dbdrivers.py` 的固定只读探测边界（SELECT 1 / PING / information_schema 之外它不做任何事）；执行连接由 `flow_executor.py` 自建。
- 不放松 `server.py` 安全边界（POST 白名单、Origin 校验、2MB 上限）；执行接口不持 `LOCK`。
- 本体区/项目区零改动；`app/http`、`saveCoordinator`、409/撤销机制不受影响；`flows.py`/`flowModel.ts` 之外的镜像协议（`model_format` 等）不涉及。
- 定时调度、重试、并行网关、错误分支、嵌套编排、动作绑定自动触发：全部非目标，不做。
- 原型中的模拟数据/模拟失败开关不得出现在正式实现。

## 4. 真实数据保护（最高优先级）

- `ontology/` 下一切是用户真实资产：**零写入、零删除、零移动**。测试一律 `WIZ_WORKBENCH_ROOT=<临时目录>` 挂独立数据根（参考 `tests/test_flows.py` 头部做法）。

## 5. 兼容与保存规则

- 旧一期草稿必须无损打开：无 `execution` 字段按默认值；SQL `:name` 继续有效；Redis 仅 keyTemplate 的旧草稿按一期 `{{行字段}}/`${参数}`规则推断。未知字段零丢失原则延续，`schemaVersion` 保持 1。
- 保存/检查行为不变：检查失败仍可保存草稿；只有**运行**被 `errors>0` 阻止。
- 新增字段全部 additive；`flows.py` 与 `flowModel.ts` 每处改动两端同步。
