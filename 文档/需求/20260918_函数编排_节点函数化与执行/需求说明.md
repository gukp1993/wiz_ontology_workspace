## 1 背景与目标

一期函数编排已落地：草稿修订存储、cytoscape 画布（连线由输入绑定派生）、三类节点（Python/SQL/Redis）、纯配置校验（**绝不执行**）。

本需求（二期）把每个节点升级为可执行的"函数"：**接受输入参数、返回输出**，编排整体也是一个函数（入口参数 → 编排输出）；配置、连线、**运行、查看结果**全部在画布完成。借鉴对象：Windmill（步骤绑定与结果查看）、Kestra（运行前 gate 与类型化参数表单）、n8n（边行数徽标与单节点运行）、DolphinScheduler（节点超时参数）、DifySandbox（仅作为后续安全执行演进参考，本版不采用）。

## 2 已确认需求（用户 2026-09-18 原话归纳）

1. 每个节点都是一个"函数"：接受输入参数，返回输出。
2. SQL 节点：**类似于 MyBatis 的 XML**——支持参数占位与动态 SQL 片段，执行结果映射到节点声明的输出。
3. Redis 节点：就是**调用 Redis 命令**。
4. Python 节点：就是**执行 Python 代码**（**这版暂时不用沙箱**）。
5. **所有都在画布上操作**。

## 3 节点即函数（统一抽象）

- **函数签名 = 节点已有的输入/输出声明**（一期结构不变）：输入 `{id, name(技术名), label, type, source}`，输出 `{id, name, label, type}`。
- **调用约定**：运行时按「输入技术名 → 值」传参；输出按声明的稳定 ID 供下游绑定引用。延续一期原则：改显示名不影响任何引用。
- **编排本身也是函数**：入口参数即函数入参（运行前经自动表单填写），编排输出即返回值。项目动作绑定 `implementation.kind='flow'` 已引用编排稳定 ID，执行引擎落地后即可衔接"动作触发编排"（**本期仅画布手动运行，衔接列为后续，不在本版范围**）。
- 画布节点卡片显示：名称、类型、**签名摘要**（如 `rows:列表 · total:数值`）、运行状态徽标。

## 4 三类节点执行语义

### 4.1 Python 节点

- **契约**：代码须定义 `def main(...)`，形参与输入技术名一一对应；返回 `dict`（键对应输出技术名）或 `None`。
- **执行方式**：独立子进程（`sys.executable`）。包装器把输入 JSON 从 stdin 传入、调用 `main`、把返回值与日志写入结果文件；主进程捕获 stdout/stderr 作为节点日志。超时（`execution.timeoutMs`，默认 30000，上限 300000）杀进程并判失败。
- **资源限制**：尽力而为的 CPU/内存 rlimit（平台差异注明）；**仅作稳定性控制，不是安全边界**。
- **依赖声明**：本版承诺仅标准库可用；第三方 import 不保证（报错如实回显）。
- **输出校验**：声明输出缺失 → 节点失败；返回多余键 → warning 且丢弃（输出声明即契约）。

### 4.2 SQL 节点（MyBatis 风格）

- **模板语法**（v2，完全向后兼容一期 `:name`）：
  - `#{name}`：预编译参数占位（与 `:name` 等价，两种都继续支持）；
  - `${expr}`：原文拼接——配置检查报 **warning**（注入风险提示），运行照常执行（本地可信工具前提）；
  - 动态标签子集：`<if test="…">`、`<choose>/<when>/<otherwise>`、`<where>`、`<set>`、`<trim>`、`<foreach collection item index open close separator>`；
  - `test` 表达式子集：参数与 `null`/字符串/数字/布尔字面量的比较、`and/or/not`、括号。不追求完整 OGNL，只支持可枚举子集，解析失败在配置检查报错。
  - `<foreach>` 的 `collection` 必须是本节点声明的 list 类型输入（或其对象字段路径）。
- **连接**：引用项目「数据连接」菜单的 MySQL 连接；凭据仅服务端从 vault 读取，不回传、不进日志。
- **执行安全（默认值）**：
  - 只读会话：`SET SESSION TRANSACTION READ ONLY`；节点显式勾选「允许写」后关闭只读并允许 DML；
  - 语句级超时 + 驱动超时双保险；
  - 行数上限 `execution.maxRows`（默认 1000，上限 10000），超出截断并标记 warning。
- **结果映射**：SELECT → 按节点**第一个输出声明**承接：`list<object>` 收全部行、`object` 收首行、标量类型取首行首列；列名（或别名）= 对象字段技术名自动映射，缺失列该字段为 null。DML → 输出声明为 number 时填影响行数。多输出节点仅第一个参与执行（配置检查 warning 提示）。

### 4.3 Redis 节点（命令调用）

- **v2 显式三要素**：`command`（白名单命令表）+ key 模板（沿用一期 `{{行字段}}`/`${参数}` 语法与互斥规则）+ `args`（参数模板，可绑定输入参数）。一期仅 `keyTemplate` 的旧草稿兼容读取（按模板形态推断 GET 与单键/行模式）。
- **模式**：单键模式（执行一次命令）；行模式（输入为列表时逐行执行，输出列表与输入顺序一一对应，沿用一期语义）。
- **命令白名单**（内置表，后续可配置化；表驱动：命令 → 参数个数/形态 → 返回类型映射）：
  - 读：GET MGET EXISTS TTL TYPE STRLEN HGET HGETALL HMGET HKEYS HVALS HLEN LRANGE LLEN SISMEMBER SMEMBERS SCARD ZSCORE ZRANGE ZCARD
  - 写：SET SETEX SETNX DEL INCR DECR HSET HMSET LPUSH RPUSH SADD ZADD EXPIRE
  - 禁止：FLUSHALL FLUSHDB KEYS CONFIG SHUTDOWN DEBUG 等管理/危险命令（配置检查报 error）
- **返回映射**：integer → number；simple/bulk string → text；nil → null；array → list；HGETALL → object（动态键原样承接，与输出声明字段不一致仅 warning 不报错）。
- **连接**：引用项目 Redis 数据连接，凭据仅服务端 vault。

## 5 执行模型与 API

- **拓扑序执行**：按 DAG 拓扑序串行执行（并发执行列为非目标）；配置检查已拦截循环依赖。
- **运行前 gate**（借鉴 Kestra）：配置检查 `errors > 0` 拒绝运行（warnings 放行，检查失败仍可保存草稿——延续一期）。
- **失败传播**：某节点失败 → 其全部下游标记「跳过」，运行继续返回完整报告。
- **无状态同步执行**：不建运行历史、不写修订流；每次运行自包含：

```
POST /api/flow-run
{ flowId, state, revision, inputs: {技术名: 值},
  only?: nodeId, mock?: {inputId: 值}, upstream?: {nodeId: 输出值} }
→ { status: success|error,
    nodeResults: [{ nodeId, status: success|failed|skipped,
                    durationMs, output, rowCount, error, logs }],
    startedAt, durationMs }
```

  - 全图运行：`inputs` 必填（入口参数按声明校验）；
  - 单节点试运行：`only` + `mock`（未 mock 且无 upstream 缓存的入参 → 明确报缺失）；
  - 运行结果仅随响应返回，画布在前端持有展示。
- **并发与锁**：执行是长网络操作，**绝不持全局 `LOCK`**；进程内按 flowId 互斥（同编排重复运行请求直接拒绝并提示）。
- **安全边界沿用**：POST 白名单 + Origin 校验 + 2MB 上限在 `server.py` 统一完成，不放松。
- **凭据**：服务端从 `secrets.py` vault 读取，永不回传、不进项目数据、不进日志。

## 6 画布操作（全部在画布完成）

- **工具栏**：▶ 运行全部 / 运行选中节点 / 清除运行状态；运行中显示进度文案。
- **节点状态徽标**：待运行 / 运行中 / 成功（耗时 ms）/ 失败（错误摘要，节点红框）/ 跳过；点击节点右侧面板出现「查看输出」入口。
- **输出检查器**：弹层展示节点输出 JSON（树形 + 复制）与 stdout/stderr 日志（借鉴 Windmill 步骤结果面板）。
- **边行数徽标**（借鉴 n8n）：运行后连线显示传递的行数/条数。
- **试运行表单**：入口参数按类型自动生成控件（text/number/boolean/datetime 用对应控件；object/list 用 JSON 编辑域，带格式校验）——借鉴 Kestra 自动表单。
- **快照语义**：运行使用提交时的 state 快照；运行中可继续编辑，但结果标注「基于运行时快照」，编辑不改变进行中的运行。
- 「模拟失败」仅存在于交互原型，用于演示失败/跳过状态，正式实现无此开关。

## 8 范围与非目标

**范围**：上述节点执行语义、执行引擎与 `/api/flow-run`、画布运行交互、配置检查 v2 增强、兼容旧草稿。

**非目标（本版不做）**：

- 安全沙箱（明确声明；Python 子进程仅稳定性隔离）
- 定时/事件触发调度、失败自动重试
- 并行网关/分支并发执行（拓扑串行即可）
- 错误分支路由、条件分支节点
- 嵌套子编排（编排作为节点）
- 运行历史持久化与执行列表页
- 编排发布线（仍只有草稿；动作绑定触发编排列为后续衔接）
- 权限体系

## 9 数据/版本/兼容约束

- **存储不变**：仍走 `ontology/drafts/flows/<id>/revisions/` 修订流 + `current.json` 原子指针；运行结果不落盘。
- **协议 additive**：新增字段全部可选（`node.execution`、`implementation.command/args`），未知字段零丢失原则延续；`schemaVersion` 保持 1；`flows.py` 与 `flowModel.ts` 必须两端同步改。
- **旧草稿兼容**：无 `execution` 字段按默认值；SQL `:name` 模板继续有效；Redis 仅 keyTemplate 的旧草稿按一期规则推断模式。
- **边界不动**：`dbdrivers.py` 仍只做固定只读探测（SELECT 1 / PING / information_schema），**不改不放松**；执行用连接由新模块 `flow_executor.py` 自建（PyMySQL/redis 为可选依赖，未安装时返回可读提示，不做静默假成功）；执行接口不持 `LOCK`。
- **前端约定**：请求一律经 `app/http`；画布连线仍由绑定派生，运行不产生持久连线；保存线（flowSaver/409/撤销）不受影响。

## 10 安全边界声明（重要）

1. 本版 Python 节点在子进程执行用户代码，**不是安全沙箱**：适用于本地单机、可信用户场景；不做网络、文件系统、import 封锁。安全隔离列为后续演进（届时参考 DifySandbox 独立进程 + seccomp 方案）。
2. SQL 默认只读会话 + 超时 + 行数上限；写操作须节点显式勾选「允许写」。`${}` 原文拼接保留但检查报 warning。
3. Redis 命令白名单，管理/危险命令在配置检查即报 error。
4. 一切执行仅由用户在画布显式点击触发；保存、检查配置**永不**触发执行。

## 11 验收标准

1. **回归**：一期草稿（含 `:name` SQL、仅 keyTemplate 的 Redis）打开/编辑/保存/检查全部不回归；`tests/test_flows.py` 全绿。
2. **Python**：两入一出的节点画布运行成功，输出检查器看到返回 dict；`timeoutMs` 超时用例判失败且日志可见。
3. **SQL**：`#{}`/动态标签/`foreach` 渲染断言（`tests/test_flow_sql_dialect.py`）；只读会话下执行 DML 报错；勾选允许写后可执行；`maxRows` 截断生效。
4. **Redis**：白名单命令按映射产出正确类型；行模式逐行输出列表；禁用命令配置检查报 error。
5. **运行链路**：入口参数表单 → 拓扑执行 → 节点徽标/耗时/边行数/输出查看器全链路可用；上游失败下游跳过；`errors>0` 时拒绝运行并给出定位。
6. **工程**：`cd frontend && npm run build` 通过；新测试全部 `python3 tests/xxx.py` 直跑通过；浏览器按本清单实测。
7. **数据保护**：测试一律 `WIZ_WORKBENCH_ROOT` 临时根 + mock 驱动，真实 `ontology/` 与真实数据库零写入；如需真实连接冒烟，只允许指向用户自备的测试库且仅只读语句。
