## v2 变更记录（相对 v1）

1. **新增 HTTP 接口节点**（调用 HTTP 接口）。
2. **新增计算节点**（数学计算）：公式模式复用既有 `calc-expression-1` 确定性求值；另设 LLM 模式。

## 1 背景与目标

一期函数编排已落地：草稿修订存储、cytoscape 画布（连线由输入绑定派生）、三类节点（Python/SQL/Redis）、纯配置校验（绝不执行）。本需求（二期）把每个节点升级为可执行的"函数"：**接受输入参数、返回输出**，编排整体也是一个函数（入口参数 → 编排输出）；配置、连线、**测试、运行、查看结果**全部在画布完成。

借鉴对象：Windmill（步骤绑定与结果查看）、Kestra（运行前 gate 与类型化参数表单）、n8n（边行数徽标与单节点运行）、DolphinScheduler（节点超时参数）、DifySandbox（仅作为远期安全执行参考，本版不采用）。

## 2 已确认需求

**v1 已确认（2026-09-18）**：

1. 每个节点都是一个"函数"：接受输入参数，返回输出。
2. SQL 节点：**类似于 MyBatis 的 XML**——参数占位与动态 SQL 片段，结果映射到声明输出。
3. Redis 节点：调用 Redis 命令。
4. 所有操作都在画布上完成。

**v2 新增（2026-09-18 第二轮确认）**：

5. 新增 **HTTP 接口节点**：调用 HTTP 接口。
6. 新增 **计算节点**：执行数学计算。
7. **每个节点再加测试**：指定输入、返回输出（单节点测试）；并支持**选定多个连续节点**做链式测试。
8. **Python 代码不在沙箱执行，交给 LLM 执行**（需新增 LLM 配置功能）；**计算节点也交给 LLM**（见 §4.5：设计上保留确定性公式模式为默认，LLM 模式并列提供——理由见该节）。

## 3 节点即函数（统一抽象）

- **函数签名 = 节点已有的输入/输出声明**（一期结构不变）。
- **调用约定**：运行/测试按「输入技术名 → 值」传参；输出按稳定 ID 供下游引用；改显示名不影响引用。
- **节点类型扩为 5 种**：`sql / calc / python / redis / http`（NODE_KINDS 与前端 NODE_KIND_LABELS、画布配色同步扩展）。
- **编排本身也是函数**：入口参数即入参；项目动作绑定 `kind='flow'` 未来可触发运行（本期仅画布手动，衔接列为后续）。
- **测试即单函数调用**：给定全部输入 → 立即得到输出（§7）；链测试 = 复合函数调用。

## 4 五类节点执行语义

### 4.1 Python 节点（LLM 代执行，本机不运行代码）

- **契约不变**：代码须定义 `def main(...)`，形参对应输入技术名；返回 `dict`（键对应输出技术名）或 `None`。
- **执行方式（v2 变更）**：代码**不在本机执行**。执行器组装提示词（system：确定性 Python 求值器，只返回 JSON；user：代码 + 输入值 JSON），调用配置的 LLM 提供方（默认提供方或节点指定 `implementation.providerId`），解析响应 JSON 按输出契约承接：缺声明输出 → 节点失败；多余键 → warning 且丢弃。
- **求值纪律**（沿用 `formatting.py` 先例）：`temperature=0`、`max_tokens` 上限、响应大小限制、`finish_reason=length` 判截断报错、非法 JSON 自动带反馈重试 1 次、仍失败则节点失败并回显响应摘要。
- **静态检查保留**：配置检查仍用 `ast.parse` 校验语法与 main 存在（只解析不执行）；LLM 提供方未配置/所选 provider 不存在 → 配置检查 error。
- **留痕**：nodeResult.logs 记录 provider/model/耗时/请求与响应摘要（截断），**LLM 求值具非确定性，每次运行必须可核查**。
- `execution.timeoutMs` 同样约束 LLM 调用（默认 60s，上限 300s）。

### 4.2 SQL 节点（MyBatis 风格，真实执行）

- 模板语法（向后兼容一期 `:name`）：`#{name}` 预编译参数；`${expr}` 原文拼接（检查报 warning）；动态标签子集 `<if test>/<choose>/<when>/<otherwise>/<where>/<set>/<trim>/<foreach>`；test 表达式子集（null/字面量比较、and/or/not、括号）；`foreach collection` 须为声明的 list 输入。
- 连接引用项目 MySQL 数据连接，凭据仅服务端 vault 读取。
- 执行安全默认：只读会话（`SET SESSION TRANSACTION READ ONLY`）；语句级超时；`maxRows` 默认 1000 上限 10000；DML 须节点显式勾选「允许写」。
- 结果映射：SELECT → 按第一输出声明承接（list<object> 全部行 / object 首行 / 标量取首行首列，列名=字段技术名）；DML → 影响行数；多输出仅第一个参与执行（检查 warning）。

### 4.3 Redis 节点（命令调用，真实执行）

- v2 显式三要素：`command`（白名单表）+ key 模板（一期 `{{行字段}}`/`${参数}` 语法沿用）+ `args`（绑定输入或字面量）；仅 keyTemplate 的旧草稿按一期规则推断。
- 单键模式/行模式（列表输入逐行执行，输出按序对应）。
- 白名单：读 GET MGET EXISTS TTL TYPE STRLEN HGET HGETALL HMGET HKEYS HVALS HLEN LRANGE LLEN SISMEMBER SMEMBERS SCARD ZSCORE ZRANGE ZCARD；写 SET SETEX SETNX DEL INCR DECR HSET HMSET LPUSH RPUSH SADD ZADD EXPIRE；管理/危险命令（FLUSHALL FLUSHDB KEYS CONFIG SHUTDOWN DEBUG 等）配置检查报 error。
- 返回映射：integer→number；simple/bulk→text；nil→null；array→list；HGETALL→object（动态键原样承接，与声明不符仅 warning）。

### 4.4 HTTP 节点（调用 HTTP 接口，真实执行）

- **implementation**：`{language:'http', method:'GET'|'POST'|'PUT'|'DELETE', url:'URL 模板', headers:{静态 KV}, bodyMode:'none'|'json', body:'JSON 模板', credentialId?:'', responsePath?:'', timeoutMs}`。
- **参数占位**：URL 与 body 模板中 `{技术名}` 引用输入参数（URL 占位做 URL 编码；body 中做 JSON 值替换）——占位解析可参考 `action_http.py` 的 placeholders/path_params 先例；占位参数必须已声明，未声明的占位在配置检查报 error。
- **认证**：可选引用**项目 API 凭据**（`api_credentials.py` 目录，与动作接口映射同库；注入方式 Bearer header 或自定义 header 名）。凭据只写不读回、只进服务端出站请求。
- **执行**：服务端 urllib 出站（标准库，无新依赖）；仅 http(s)；超时 `timeoutMs`（默认 15s）；响应体大小上限（2MB）；状态码非 2xx → 节点失败（回显状态码与响应前 N 字符）；响应须为 JSON（非 JSON → 失败）。
- **结果映射**：`responsePath`（点路径，留空=根）提取子树 → 按输出声明承接（object/list/标量）；提取路径不存在 → 失败并回显实际结构摘要。
- **配置检查**：URL 必须 http(s) 开头；method 合法；GET 带 body 报 warning；headers 名合法；`credentialId` 存在性（提供项目凭据列表时校验，列表不可读降为提示）。

### 4.5 计算节点（数学计算，双模式）

- **公式模式（默认，确定性）**：复用工作台既有 `calc_functions.py`（`calc-expression-1`：数值/文本/布尔字面量、`{参数}` 引用、四则与比较、IF/MIN/MAX/ABS/ROUND/ERROR 白名单函数；后端解析 + 静态类型检查 + 确定性求值，禁 eval 无 IO）。每个输出声明对应一条公式 `{输出技术名: 表达式}`；输入参数按技术名引用；object/list 输入不可进公式（检查报错）。**为何默认不用 LLM**：数学计算要求确定性，工作台已有专用安全引擎且能在保存前做静态类型检查；LLM 算术具非确定性。此为对"计算节点也交给 LLM"的修订建议，LLM 模式完整保留（见下），最终默认值列为待确认（§14）。
- **LLM 模式**：`{mode:'llm', instruction:'自然语言计算规则', providerId?}`——输入 JSON + 规则交 LLM 计算，响应 JSON 按输出声明承接；纪律与留痕同 §4.1。适合公式语言表达不了的逻辑。
- 两模式共用 `execution.timeoutMs`；配置检查：公式逐条过 `calc_functions` 静态检查（引用的输入须存在且类型合规）；LLM 模式校验 instruction 非空与 provider 有效性。

## 5 LLM 配置功能（新增）

- **定位**：工作台级配置（flows 不属于任何项目，故不挂项目下），供 Python / 计算（LLM 模式）节点代执行使用。显示格式化功能沿用其既有 `format-llm.json` 配置，**互不影响**。
- **多提供方**：`{id, name, endpoint(chat/completions 完整 URL), model, timeout, temperature(默认 0), isDefault, key(只写)}`；其一为默认；节点可 `providerId` 指定，留空用默认。
- **存储**：`<DATA_ROOT>/ontology/vault/llm-providers/<id>.json`——**完全对齐 `api_credentials.py` 边界**：文件 0600/目录 0700、原子替换、路径逃逸防护、密钥只写不读回（HTTP 层只回传元数据与"密钥已配置/未配置"状态，响应/日志/快照永不出现密钥）。
- **API**（POST 白名单 + Origin，探测类不持 LOCK）：`GET /api/llm-providers`（元数据）、`POST /api/llm-provider-save`、`POST /api/llm-provider-delete`、`POST /api/llm-provider-test`（发送极小探测请求验证地址/密钥/模型，返回可读结果）。
- **入口**：辅助工具页新增「LLM 配置」；编排编辑器内 Python/计算节点面板与错误提示提供跳转；LLM 未配置时相关节点在配置检查中给出明确指引。

## 6 执行模型与 API（统一）

```
POST /api/flow-run
{ flowId?, state, revision?, inputs?: {技术名: 值}, targets?: [nodeId…] }
→ { status: success|error,
    nodeResults: [{ nodeId, status: success|failed|skipped,
                    durationMs, output, rowCount, error, logs }],
    startedAt, durationMs }
```

- **三种形态**：targets 省略 = 全图运行（需 flowId+revision 并发校验+入口参数）；targets 单个 = **单节点测试**；targets 多个 = **链测试**。测试形态不落盘、不要求 revision。
- **targets 校验**：被测集合须构成"连续链"——存在拓扑序使每个被测节点的节点来源都落在被测集合内；不满足 → 400 并指出缺失的上游节点。链的外部输入（来源不在集合内，含入口来源与未绑定）必须由 `inputs` 提供（键：`节点Id.输入技术名` 或统一技术名，实现取一，文档记录）；fixed 来源自动带值。
- **全图运行 gate**：配置检查 errors>0 拒绝（测试形态放宽为仅要求 targets 内节点自身可执行——同一 errors 校验，定位到被测节点）。
- **失败传播**：链内/全图某节点失败 → 其下游标记 skipped。
- **无状态**：不建运行历史、不写修订流；结果仅随响应返回。
- **并发**：绝不持全局 `LOCK`；进程内按 flowId（全图）互斥；测试形态可并行。
- **安全边界沿用**：server.py 白名单/Origin/2MB；LLM/HTTP/DB 凭据均只走服务端。

## 7 节点测试（每个节点都有）

- **单节点测试**：节点配置面板「测试本节点」→ 弹窗按输入声明生成表单（类型感知控件；fixed 来源自动带值并锁定；未绑定输入必填）→ 执行 → 输出检查器展示输出 JSON + 日志。
- **链测试**：画布链选择模式逐个点选（或框选）多个节点 → 工具栏「测试选中」→ 校验连续链 → 弹窗展示执行顺序与全部外部输入表单 → 按拓扑序执行 → 逐节点徽标 + 输出检查器。
- **画布多选**：cytoscape shift/框选 + 链选择模式按钮；选中集高亮（虚线描边）。
- 测试结果与全图运行共用同一套画布状态徽标/边行数/输出检查器展示。

## 8 画布操作（全部在画布完成）

工具栏：▶ 运行全部（入口参数表单）/ 测试选中（单节点或链）/ ⛓链选择开关 / 清除状态；节点状态徽标（待运行/运行中/成功+耗时/失败/跳过，失败红框）；边行数徽标；输出检查器（输出 JSON + 日志双页签，LLM 节点留痕）；快照语义（运行用提交快照，编辑互不影响）。原型中所有模拟数据与开关仅用于演示。

## 10 范围与非目标

**范围**：五类节点执行语义、LLM 配置功能、统一执行 API、节点/链测试、画布运行交互、配置检查 v2、旧草稿兼容。

## 11 数据/版本/兼容约束

- 存储不变：`ontology/drafts/flows/` 修订流；测试/运行结果不落盘；LLM 提供方写 `ontology/vault/llm-providers/`（vault 受保护目录，不入库）。
- 协议 additive：新节点 kind、`implementation.method/url/headers/bodyMode/body/credentialId/responsePath`、`implementation.mode/formulas/llmInstruction/providerId` 全部可选；`schemaVersion` 保持 1；`flows.py` 与 `flowModel.ts` 两端同步改。
- 旧草稿兼容：v1 三类节点原语义不变（Python 节点无 providerId = 默认提供方；一期"代码仅保存"的草稿在 LLM 未配置时检查报 error 并指引配置——这是唯一行为变化，须在检查文案中讲清）。
- 边界不动：`dbdrivers.py` 固定只读探测不变；执行连接由 `flow_executor.py` 自建；执行接口不持 LOCK；`formatting.py`/`api_credentials.py` 既有调用方不受影响（新增模块，不改其行为）。

## 12 安全边界声明（重要）

1. **本机不执行任何用户代码**：Python 代码只做 ast 静态解析；计算公式走受限表达式引擎；因此无需沙箱。用户的"交给 LLM 执行"即此含义：LLM 代为求值。
2. **LLM 求值非确定性**：同一输入可能得到不同输出；必须在节点日志中保留 provider/model/请求与响应摘要供核查；适用于业务可容忍非确定性的场景，重要数值建议用计算节点公式模式。
3. **真实外呼**：SQL/Redis/HTTP 节点真实执行出站调用——SQL 默认只读会话+写勾选；Redis 白名单；HTTP 仅 http(s)、超时、响应大小上限；提示注入风险（`${}`、外部响应内容）在检查与文档中声明。本地单机工具不做内网地址限制（SSRF 面），列为待确认项。
4. 密钥（DB/Redis/LLM/API 凭据）只写不读回，不出服务端、不进日志与快照。
5. 一切执行/测试仅由用户显式点击触发；保存与检查永不触发执行。

## 13 验收标准

1. **回归**：一期草稿（含 `:name` SQL、仅 keyTemplate 的 Redis）打开/保存/检查不回归；`tests/test_flows.py` 全绿。
2. **LLM 配置**：新增/编辑/删除/设默认/测试连通全流程可用；密钥保存后接口不回传；未配置时 Python/LLM 计算节点检查报 error 且文案指引配置入口。
3. **Python 节点**：LLM 代执行返回 dict 承接正确；非法 JSON 重试后仍失败→节点失败且回显响应摘要；截断（finish_reason=length）报错；日志含 provider/model/耗时。
4. **计算节点**：公式模式静态类型检查（错公式保存前报错）+ 确定性求值正确；LLM 模式按 instruction 求值；模式切换不丢输出声明。

7. **测试链路**：单节点测试（指定输入→输出）全类型可用；链测试校验连续性（选断链给明确报错）、外部输入表单完整、按拓扑序执行、失败传播 skipped。
