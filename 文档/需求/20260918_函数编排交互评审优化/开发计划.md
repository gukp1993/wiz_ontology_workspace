## 1. 基线与实施边界

开工先读根 AGENTS.md，核对当前 git 状态和最新五类节点实现。不要回滚用户正在编辑的 ontology 草稿；不要以旧需求“尚未实现”字样删除当前执行能力。

已有执行/存储/绑定协议不重写。本期仅允许对检查返回增加诊断定位信息；普通 UI 状态（当前页签、面板开闭、检查请求代际）不写入业务定义。

## 3. 代码组织建议

先复用现有组件。只有当职责确实独立时拆 `FlowIssuesPanel.vue`、`FlowResultPanel.vue`、`FlowRunDialog.vue`，不要机械给每块按钮新建文件。父页集中维护选择、模式和快照，子组件只发结构化事件。

建议维护四种独立状态：

- `selectedId`：当前查看的节点/边界。
- `interactionMode`：inspect / bind / testSelection，唯一互斥来源。
- `testNodeIds`：执行范围，与选中详情无关。
- `checkSnapshot`、`runSnapshot`：包含 flowId、配置签名、上下文及请求代际；禁止只用一个成功布尔量。

配置签名排除布局/缩放/运行徽标；包含实际配置与影响连接解析的上下文。展示文字改变时诊断名称至少更新或待重检。签名不包含密码、不记录凭据原文。前端保存回包和主动检查都必须校验提交快照，不只防主动检查旧响应。

画布状态更新优先更新节点 data/classes；拓扑变化才增删元素，保留已有坐标/视口。定位处理边界节点与处理节点，不能只有处理节点有效。

## 4. 诊断最小协议

后端在原检查结果上增 `diagnostics[]`，元素为需求说明第6节结构。现有 `errors/warnings/items/status` 兼容保留；不得为定位改变校验顺序或业务判断。既有异常兜底保留。

优先覆盖：输入缺绑定/失效引用/类型、实现缺连接或提供方、SQL/Python/公式缺正文、输出缺绑定/声明。无精确 field 的问题退到 section/节点。前端使用稳定 ID 注册聚焦目标，不用行号、不用数组下标定位可重排参数，不解析报错文案。

在本文件追加最终字段表和覆盖清单。如果当前实现已有等价字段，复用并说明，不再建立同义字段。

## 5. 验证计划

不要把一轮 UI 优化扩成全仓执行引擎审计；但下面直接相关的行为必须有证据。

1. Python 检查回归：运行现有 `tests/test_flows.py`，补诊断结构/顺序兼容用例；执行入口未改时不重写执行测试。若触及运行参数/范围，运行 `tests/test_flow_executor.py` 相关用例并确认使用替身。
2. 前端状态测试：检查旧响应、保存检查旧响应、布局不失效、模式互斥、选择与测试范围独立、不同编排的结果隔离。按现有 Node TS 钩子组织，不为演示 HTML 写大量镜像单测。
3. 前端 `cd frontend && npm run build`（包含 vue-tsc）。不要只报 build 通过就称交互通过。
4. 临时 `WIZ_WORKBENCH_ROOT` + 独立端口启动。用合成编排与模拟连接/执行响应验证；不得测试真实 SQL/HTTP/Redis，也不得让 LLM 请求产生实际费用。
5. 在 1440×900、1366×768、1280×800、1024×768 验收；记录默认/选中/问题展开/测试弹窗各关键状态。检查超长节点名、无节点、大于20节点、多个错误、加载失败。
6. 手工走通：检查→定位输入→修改→待重检→重检；绑定取消和成功；单节点测试；补选上游；更改配置后查看历史快照结果；重建骨架取消/确认/撤销；Esc/Tab 焦点。
7. 结束只提交功能源码、定向测试和本需求文档；不包含 ontology、vault、dist、临时截图包或node_modules。

若某项测试工具缺失，记录具体未验证项，不为获得截图安装无关运行服务。安全地补齐必要验证后再宣称完成。

## 6. 建议提交切分

- `fix(flow): expand canvas and preserve viewport during editing`
- `feat(flow): locate configuration issues and track report freshness`
- `refactor(flow): simplify node configuration and test interactions`

可按实际变更合并，但每次提交必须可描述、可回退。不要把用户已有未提交改动混入。
