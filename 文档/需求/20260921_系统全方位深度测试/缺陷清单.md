# 复验整改记录（第二轮 · F01–F05）

依据 [S1S3独立复验记录_20260921.md](S1S3独立复验记录_20260921.md)：独立复验判定「不通过」，理由是本测试交付的**判定器仍可被错误响应骗过**，以及机器覆盖核对存在漏检。下列整改均只改 `tests/deep_*` 与文档，**未改业务代码**；测试结论（A01/R02/D-Q02-01 等）不变。

## F01（高）· 拒绝分支未校验「版本零新增」

**问题**：`classify_guard_attempt` 只在 2xx 分支看版本变化，返回 422 命中诊断即判 product_pass；把 `version_after` 置为 `None`（读不到版本）同样通过。这正好漏掉「返回错误码但版本已被写入」这一重要反例。

**整改**：
- 拒绝分支同样受版本门约束：要求零新增时必须能证明版本未增加——**版本不可读 → test_error（证据不足）**，**拒绝却已新增版本 → new_defect_reproduced（拦截未生效，独立缺陷）**。
- `_versions_of` / `_releases_of` 改为经 `_count_versions` 计数：**500、非 200、响应结构不符一律返回 `None`，不再默认为 0**（把不可读当 0 条正是漏检来源）。

**反例锁定**（`tests/deep_verdicts_test.py`）：拒绝且版本 1→2 → 缺陷；拒绝且 after/before 不可读 → test_error；拒绝且 3→3 → product_pass（对照）。

## F02（高）· R02 场景绕过状态码校验，500 也能通过

**问题**：`scenario_r02` 的 project-validate 分支只检查 errors 文字，未判 HTTP 成功与响应结构；注入 500 + 诊断文案时 `R02-5` 得 product_pass。负对照记录了 `validateBlocked` 却未用于结论，validate 段失败仍宣布整条负对照通过。

**整改**：
- 新增 `classify_validate_observation`：校验接口观察**必须先过传输 / 状态码（200）/ 响应结构（`errors` 必须是数组）**，再看正式诊断；500 或结构不符一律 test_error，不得按文案记通过。
- 负对照改为**两段都须满足期望**（validate 拦到「编排不存在」诊断 + publish 422 且版本零新增）才记 product_pass；两段不一致记 test_error 并要求人工确认。

**反例锁定**：validate 500 带诊断文案 → test_error；errors 非数组 / 响应非对象 / 网络失败 → test_error；有错误但诊断无关 → test_error；200 且有目标诊断 → product_pass。

## F03（中）· 从整个响应搜索任意词，无法证明诊断针对目标

**问题**：`_diag_hit` 把整份响应序列化后做子串匹配，回显载荷里的 `flow`、`类型` 等词就能让无关错误（如「名称重复」）被判成「针对目标」而记通过。

**整改**：
- 诊断文本只从**约定诊断字段**（errors/diagnostics/error/report/check/items/issues 等）递归提取，显式排除回显载荷（state/data/payload/revision/requestId/name）；无诊断字段时回退为整份响应（截断）并如实记入证据。
- 新增 `diagnostic_term_groups`：**组内 OR、组间 AND**；A01/R02 改用「字段/对象定位 + 具体错误原因」两组，仅命中「类型/输出」这类泛词不再算数。
- 修复过程中发现并修掉自身一个真实缺陷：原提取逻辑**漏收集诊断键下的字符串列表**（真实 `.errors = ["文案"]` 形态），已用真实 HTTP 复跑暴露并修复，并补两条锁定用例。

**反例锁定**：泛词只出现在回显 state/payload → test_error；诊断字段确实含该词 → product_pass；分组只命中原因组 → test_error；两组都命中 → product_pass；`errors` 字符串列表与嵌套 `report.errors/items` 均被收集。

## F04（中）· 拆分替代只要求命中任意一个子用例

**问题**：`validate_superseded_coverage` 用集合交集判断，旧编号拆成 O4-07a/O4-07b 时**只覆盖其中一个也通过**（构造「只有 a」的批次实测 uncovered=[]）。

**整改**：区分两种语义——

- `CASE_ID_ALTERNATIVES`（任选其一）：命中任意等价编号即可。

## 交付前对抗性自验（第三轮加固）

在把整改稿交独立复验**之前**，实施方另做了一轮**对抗性自验**：主动尝试"骗过判定器"，即构造无关错误、
基础设施故障、形态畸变与配置类型错误的输入，看能否被记成 `product_pass`。共发现并修复 7 类残余通道——
**这些是测试工具的缺陷，不是产品缺陷**；修复后真实 HTTP 分类完全不变。

| 编号 | 攻击方式（真实可发生） | 修复 |
|---|---|---|
| H1 | 无关错误借**泛词**在同一条消息内凑齐"定位+原因"两组：如真实文案「动作绑定 …：实现方式未选择（项目接口或函数编排）」「属性来源 …：读取失败（StorageUnavailable），暂不能校验该绑定」同时含"编排/绑定/未选择" | 诊断分组改为**锚定具体身份**（被引用属性/对象/编排 id、被追加记录 id），不再用泛词；并保留"同一条消息内 AND"约束 |
| H2 | 两条**不同**消息各贡献一半拼出假命中（早期实现把全部诊断拼成一整串再找词） | `diag_messages` 按**条目**成条：`errors[].name+message` 同条目可合并，`errors:["甲","乙"]` 各自独立；`_diag_hit` 要求存在**单条**消息覆盖全部组 |
| H3 | 状态清单 `items[].name/id/kind` 被当诊断文案（真实接口为**每个**条目回显这些字段），使定位组无条件命中 | 信封收缩：`items[]` 只下钻其 `issues/problems/errors` 等错误字段，回显字段不收集；忽略键改为**大小写不敏感**（`Kind/DATA/Payload` 等变体一并挡住） |
| H4 | 非 JSON 响应（网关 HTML 错误页）被整体当诊断文本 | 取消整体兜底：取不到约定诊断文案即 `test_error` |
| H5 | 配置类类型畸变静默放行：`status='422'`、`diagnostic_terms='未绑定'`（退化为逐字符）、`['']`、`require_no_version_increase=0`、`precondition_ok='false'`、`known_defect='false'`、`block_status='422'` | 全部加类型自检：非 int 状态码、非列表诊断词、空串诊断词、非布尔开关/前置/标记 → 一律 `test_error`；版本回退（2→1）判证据自相矛盾 |
| H6 | 接受态（2xx）同时传 `require_no_version_increase` 时，可能因"版本未增加"被改判通过 | 接受分支不再借用版本门判通过，直接按"未被拦截"记缺陷复现 |
| H7 | 证据索引兜底：未知 `verdict` 默认算 `product_pass`；工具错误豁免按 case 名字含 `crash` | `verdict` 不在枚举内即报错退出；豁免只依据记录自身声明（kind/title/evidence 含"中断/异常/Traceback"），与名字无关（业务场景名含 crash 不得豁免，名字平常但有堆栈应豁免） |
