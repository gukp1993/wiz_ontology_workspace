## 3. 尚需修订的具体问题

### F01 · 高：422分支完全忽略版本零新增约束

位置：`tests/deep_verdicts.py:170–184`；调用方 `deep_reverify_scenarios.py` 的A01与R02发布判定。

独立输入：

```python
classify_guard_attempt(True,
    {'status':422, 'json':{'errors':['输出未绑定']}},
    {'block_status':422, 'diagnostic_terms':['输出'],
     'require_no_version_increase':True,
     'version_before':1, 'version_after':2})
# 实际：product_pass
```

把after改None也product_pass。代码只在2xx分支看版本变化，422命中诊断立即返回通过，正好漏掉“返回错误但已写入版本”的重要反例。

要求：拒绝分支同样要求版本查询成功、前后状态可比较且无新增；无法读版本归test_error/证据不足，拒绝却新增版本归独立缺陷，不能通过。`_versions_of/_releases_of`不得把500/空响应默认为0当正常计数。补反例并验证调用方。

### F02 · 高：R02场景绕过状态码校验，500也能通过

位置：`tests/deep_reverify_scenarios.py:276–287`、`320–337`。

用内存API替身使创建/保存/flow-check四前置成功，然后令 `/api/project-validate` 返回：

```json
{"status":500,"json":{"errors":["activePower 编排输出未绑定"]}}
```

实际 `scenario_r02(...)["cases"]["R02-5"] == "product_pass"`。该分支仅检查errors文字，没有判断HTTP成功与响应结构；无文字的500还可能被误报成已知缺陷复现。

同一反例中负对照 `validateBlocked=false`，publish给422“编排不存在”后 `R02-7`仍product_pass，说明记录了ghost_validate却没有把它用于结论。

要求：project-validate必须先通过传输/状态码/响应结构检查，再按正式诊断判断；负对照的validate及publish两段都应满足期望，否则不能宣称整条负对照通过。本轮另验证project-save=500会正确blocked且publish未调用，该前置修正可以保留。

### F03 · 中：从整个响应搜索任意词，无法证明诊断针对目标

位置：`tests/deep_verdicts.py:103–112`；scenario中的宽泛词列表。

独立输入422响应：

```json
{"error":"名称重复","state":{"kind":"flow"}}
```

diagnostic_terms包含flow时，实际product_pass。flow仅在回显state里，真正错误是名称重复。A01同样使用“文本/类型”等泛词，也可能误收其他字段类型错误。

要求：只检查约定的errors/diagnostics/error等诊断字段，并把对象/属性/字段定位与具体错误原因结合；没有稳定code时保守匹配已知诊断，不搜索整份响应或仅命中一个“类型/输出/flow”词就认定正确阻断。

### F04 · 中：拆分替代只要求命中任意一个子用例

位置：`tests/deep_results_index.py:300`。

独立构造传入 `validate_superseded_coverage`：旧批次只有O4-07；有效批次只有O4-07a；别名仍是 `{O4-07a,O4-07b}`。实际返回uncovered=[]。当前实现用集合交集判断，因此漏掉O4-07b也被认定完整覆盖。

要求：明确一拆多的必需集合与“任选其一”的替代区别；本例必须两个子用例都在有效批次。补“只a”“只b”“a+b”的反例。当前实际日志同时具有a/b，本条不是指当前已经丢失数据，而是机器保证可被错误配置绕过。错行号检查实测有效，无需重写。

### F05 · 低：历史计划的旧统计缺少就地失效标记

位置：`测试计划.md:50–76`。旧记录保留合理，但应在该历史段标题/开头明确旧数字不可用于现状，并链接最新索引与继续验证结论。当前还会直接读到“73通过”“~75断言I1–I9全符合契约”，不满足复验指令M09的防混淆要求。
