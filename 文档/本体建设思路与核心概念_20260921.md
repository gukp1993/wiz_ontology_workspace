# 本体建设思路与核心概念

日期：2026-09-21。

本文整理当前项目已经确定的概念和设计方向，用于理解本体建设，不是新增开发需求，也不代表全部配套功能已经完成验收。

## 一、核心思路与产品边界

先定义业务世界中有哪些事物、具有什么特征、彼此如何关联、遵循什么规则、支持什么操作，再由具体项目配置这些定义如何落地。

本体是一套可复用的业务定义。例如“储能本体”定义储能系统、储能设备、储能簇，以及它们的容量、SOC、组成关系和停止充放电操作。

同一个储能本体可以用于多个项目。不同项目的数据库表、Redis Key、计算方式和业务接口可以不同，但应尽量保持业务概念一致。

| 层级 | 主要回答 | 储能示例 |
|---|---|---|
| 本体建设 | 是什么、意味着什么、有什么关系 | SOC 表示剩余电量百分比 |
| 项目映射 | 在这个项目中如何识别、获取或操作 | SOC 从 Redis 读取，或者通过函数编排计算 |
| 下游问数系统 | 如何根据问题使用这些配置 | 找到设备 A，获取并解释它的 SOC |

工作台主要维护前两层。后续通过 MCP 向问数系统提供定义和取值规则，是已经明确的方向；MCP 不提供数据库或 Redis 连接信息，相关资源由问数系统管理。具体返回规范与计算口径生成仍待确定，不能视为已经交付。

## 二、本体的五类核心概念

| 概念 | 定义 | 主要描述内容 | 储能示例 |
|---|---|---|---|
| 对象类型 | 一类具有业务意义的事物 | 名称、业务定义，以及关联的属性、链接、规则、动作 | 储能簇、储能设备、充放电计划 |
| 属性 | 描述对象某一方面的特征 | 名称、业务定义、数据类型、必要的类型补充、可选显示格式 | 额定容量、显示名称、SOC |
| 链接 | 两类对象之间的业务关系 | 两端对象、关系名称、阅读方向、数量关系 | 储能设备包含储能簇 |
| 业务规则 | 业务中的计算口径、判断依据或约束 | 规则名称、业务定义；规则内容选填 | 储能设备 SOC 计算规则 |
| 动作 | 对对象发起的业务操作 | 动作名称、业务定义；预期效果选填 | 停止充放电、修改所属设备 |

业务规则和动作可以独立维护，再关联到多个对象。关联表示适用关系，不代表已经配置执行实现。

## 三、对象类型与对象实例

- **对象类型**：储能簇，定义这一类事物的共同特征。
- **对象实例**：储能簇 A、储能簇 B，是项目中的具体事物。

本体建设主要定义类型。实例从哪里来、用什么识别，属于项目映射。

对象不要求必须对应一张数据库表。储能系统即使是多个设备组成的业务集合，只要具有独立的业务身份、属性和关系，就可以定义为对象类型。

需要区分两种情况：

| 情况 | 建模理解 |
|---|---|
| 园区储能系统 | 有业务身份的对象，可具备容量、SOC、成员关系等 |
| 一次查询筛选出的所有高 SOC 设备 | 通常是查询结果集合，不一定需要新建对象类型 |

是否建对象，取决于业务含义，而不是数据库有没有对应表。

## 四、属性：业务含义与取值实现分离

属性顶层不划分“静态属性”和“动态属性”。它们统一描述业务特征，通过数据类型表达值的结构，通过项目映射确定来源。

| 属性示例 | 本体数据类型 | 项目中的可能实现 |
|---|---|---|
| 显示名称 | 文本 | 数据库字段 |
| 额定容量 | 数值 | 数据库字段或汇总计算 |
| 当前 SOC | 数值 | Redis、接口或计算函数 |
| SOC 采样序列 | 时间序列，观测值为数值 | 多步查询定位历史表和采样字段 |

当前类型包括：文本、数值、是／否、时间、数组、结构体、时间序列。只有时间序列需要指定观测值类型；观测值类型包括文本、数值、是／否、时间。

当前 SOC 和 SOC 采样序列都应首先说明“剩余电量百分比”，再分别补充“最新值”和“随时间记录的采样值”。二者业务基础相同，但表达的数据不同。

可选展示配置统一收敛到“显示格式”。显示格式不等于数据单位转换：V 与 kV、0～1 与 0～100 的差异，仍需在项目取值和计算中明确处理。

## 五、共享属性与私有属性

共享属性是一种定义复用机制，不是另一种业务属性。

| 方式 | 含义 | 修改影响 |
|---|---|---|
| 对象私有属性 | 定义由一个对象维护 | 主要影响该对象 |
| 共享属性 | 多个对象引用同一份属性定义 | 需要检查所有引用对象 |
| 复制已有属性 | 借用填写内容，生成独立定义 | 之后互不联动 |

例如储能设备和储能簇都可以引用“额定容量”。判断是否共享，依据是业务含义、数据类型和口径是否一致，不能只看名称相同。

共享定义不意味着共享数据来源：设备容量可能来自汇总，簇容量可能直接读取字段。不同项目的物理单位或表示方式不同，应在映射中明确转换后保持语义一致。

## 六、链接：描述业务关系

例如：

```text
储能设备 — 包含 → 储能簇
储能簇 — 所属于 → 储能设备
```

这是同一业务关系的两个阅读方向。本体定义关系含义和数量约束；项目映射确定通过哪些字段或实现找到对应实例。

| 关系 | 含义 | 注意事项 |
|---|---|---|
| 是一种 | 分类关系 | 不等于组成关系 |
| 组成／包含 | 整体与部分的关系 | 储能簇可以是储能设备的组成部分 |
| 所属／管理 | 业务归属关系 | 应根据实际业务定义范围和数量约束 |

“储能簇是储能设备的组成部分”，不等于“储能簇是一种储能设备”。上表用于澄清语义，不表示当前已经实现独立的类型继承机制。

链接基数需要业务依据。看到一台设备包含两个储能簇，不能据此认定一个储能簇在所有场景中都只能属于一台设备。

## 七、业务规则、动作、函数与编排

| 概念 | 负责什么 | 不代表什么 |
|---|---|---|
| 业务规则 | 说明业务怎么算、怎么判断 | 写入公式文本就自动执行 |
| 动作 | 说明要执行什么业务操作及预期变化 | 已绑定接口、已具备执行能力 |
| 计算函数 | 实现一次具体计算 | 新增一种本体概念 |
| 函数编排 | 组织查询、计算等处理步骤 | 本体本身的业务定义 |

### 7.1 设备 SOC 计算示例

- **属性**：设备 SOC。
- **业务规则**：按所属储能簇容量加权计算 SOC。
- **项目实现**：查询储能簇 → 获取各簇 SOC 和容量 → 计算并汇总。
- **实现载体**：计算函数或函数编排。

业务公式可描述为：

```text
设备 SOC = Σ（簇 SOC × 簇额定容量）÷ Σ（簇额定容量）
```

参与计算的比例和容量单位必须一致。缺失数据、零容量等处理口径不能由模型擅自补齐。公式作为本体规则文本，不由本体定义自身执行。

### 7.2 停止充放电示例

| 层级 | 内容 |
|---|---|
| 动作名称 | 停止充放电 |
| 业务定义 | 请求目标设备结束当前充电或放电，不等同于设备断电 |
| 预期效果 | 设备退出充放电运行状态 |
| 项目 A 实现示例 | 调用 stopCharge(storageId) |
| 项目 B 实现示例 | 调用 setStoragePower(storageId, 0)，前提是该接口确实符合动作语义 |

本期动作没有要求定义输入参数、提交条件、审批等结构。不同接口如何适配由项目层处理；不能为了迁就某个接口而随意改变通用动作的业务含义。

### 7.3 查询计划与生成计划

“充放电计划”可以是对象类型；查询已有计划是读取对象实例。“生成明天的充放电计划”表达的是业务操作，具体算法或编排属于项目实现。是否保存、下发、执行，需要分别明确业务边界，不能从“生成”自动推导出全部后续操作。该示例用于解释概念，不表示这些链路已经完成实现。

## 八、组织、交付与版本演进

建设过程是：

```text
建立业务定义
  → 关联对象、属性、链接、规则和动作
  → 校验
  → 发布固定版本
  → 项目引用
  → 评估变更后升级
```

应遵循以下原则：

1. **稳定标识负责关联，名称用于理解和展示。** 避免改名导致引用断裂。
2. **草稿与发布版本分开。** 编辑草稿不应修改已有发布版本。
3. **项目固定引用版本。** 本体发布新版不自动改变所有项目。
4. **共享定义变更需要看影响范围。** 不能只检查当前编辑对象。
5. **列表、详情、图谱操作同一份模型。** 图谱是理解和操作模型的视图。
6. **不同建设入口遵守同一套定义与校验。** Excel、配置迁移、AI 辅助填写不能各自形成不同的数据规则。
7. **AI 提供候选与依据。** 生成结果不能直接视为已确认、已发布的业务事实。

历史恢复、影响分析等具体能力的完成情况需以对应版本验收为准，本文不作为功能验收结论。

## 九、希望交付的结果

本体建设最终交付一份能被人理解、被项目实现、被下游系统使用，并且能够持续演进的业务模型。

对业务专家而言，它回答“我们的业务有哪些概念、关系和规则”；对项目实施人员而言，它明确“需要实现哪些业务能力”；对下游问数系统而言，它提供理解问题和寻找项目取值规则的语义基础。
