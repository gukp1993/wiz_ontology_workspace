# 通用属性来源配置 — 数据契约与实施设计（内部）

日期：2026-09-14。本文档是本轮开发的**唯一接口契约**，所有并行开发以此为准；与需求文档冲突时以需求文档为准，编码细节以本文档为准。实现完成后由实施说明文档取代。

## 0. 总原则

- 兼容优先：旧编码（字符串直取、field/related/redis/computed）语义与存储不变；只读加载不迁移真实数据。
- 新结构用明确 `kind` 分支识别；未知 kind 一律报"属性来源方式无效"，绝不默认解释为 computed。
- 只允许"确实等价于旧身份表直接字段"的配置压缩为字符串（见 §2.4）。
- 本轮无业务执行：所有新配置只做结构校验；界面必须体现"配置校验通过 ≠ 已执行验证"。
- 前后端协议镜像：`modelFormat.ts` ↔ `model_format.py`、`bindingModel.ts` ↔ `projects.py` 的编码必须一致。

## 1. 本体侧：结果形态 valueShape

### 1.1 编码

- schema 形态（API 边界）：`properties`/`sharedProperties` 记录新增可选字段 `valueShape`，取值 `'scalar' | 'timeSeries'`。
- JSON-LD 形态（编辑器）：`mg:valueShape`，**普通字符串字面量**（同 `mg:valueSuffix` 模式，进 FIELDS 映射，不进 JSON_FIELDS）。
- **规范化约定：单值不落盘**。`valueShape==='scalar'` 时删除字段；只有 `timeSeries` 才写 `mg:valueShape:'timeSeries'`。旧文件因此零改动（满足 A1）。
- FIELDS 映射（两端镜像新增）：`valueShape ↔ mg:valueShape`（`workbench/model_format.py` FIELDS、`frontend/src/modelFormat.ts` fields）。
- validate（两端镜像）：`valueShape` 若存在必须是 `'scalar'|'timeSeries'`；为 `'timeSeries'` 时 `dataType.type` 不得是 `array|struct`（报错）。

### 1.2 共享属性继承

- `workbench/properties.py` 的 `FIELDS`（effective() 拷贝清单）新增 `'mg:valueShape'`。
- `frontend/src/propertyModel.ts` 的 `metadataKeys` 新增 `'mg:valueShape'`（attach/detach/asShared 自动覆盖）。
- 后端属性校验：`mg:valueShape` 值合法性同 §1.1；共享定义与引用方不需一致（引用继承共享定义）。

### 1.3 契约与变更分类（contracts.py）

- `STRUCTURAL_FIELDS` 新增 `'valueShape'`：scalar↔timeSeries 互改 = breaking。
- classify 比较前对两侧 valueShape 做规范化：`缺失/''/'scalar' → 'scalar'`，避免旧版本误报。

### 1.4 本体 UI（PropertyManager.vue）

- 详情页"数据类型"下新增"结果形态"：AppSelect 单值（默认）/时间序列；`dataType` 为 array/struct 时隐藏并提示不支持。
- 选择单值时删除字段（不写 'scalar'）；选择时间序列写入 `'timeSeries'`；切换数据类型为 array/struct 时重置为单值（沿用 baseChanged 清理模式）。
- timeSeries 的帮助文案：「数据类型表示每个观测值的类型；时间由序列结构自带，无需另建时间属性」。
- 已有属性不自动转换（无任何按名称猜测的逻辑）。

### 1.5 属性形态解析（项目侧要用）

- 目标属性有效形态 = `effectiveProperty(node).['mg:valueShape'] === 'timeSeries' ? 'timeSeries' : 'scalar'`（后端用 `workbench.properties.effective`）。
- 记为工具函数：后端 `projects._value_shape(node, graph)`；前端 bindingModel.ts `valueShapeOf(p, graph)`。

## 2. 项目侧：属性来源新结构（bindings.object_bindings[].properties[api]）

### 2.1 既有编码（全部不变）

| 编码 | 含义 |
|---|---|
| `"rated_power"`（字符串） | 实例来源（身份表）直接字段 |
| `{kind:'field', source, field, selection?, timeField?, tieBreaker?, missing?}` | 已登记 db 补充来源 |
| `{kind:'related', ...}` | 旧格式，只读兼容（内存适配为 field） |
| `{kind:'redis', source, command:'GET'|'HGET', key, params, hashField, conversion, missing}` | 已登记 Redis 补充来源 |
| `{kind:'computed', implementation, output}` | 项目函数输出 |

### 2.2 新增：数据库直选表 `{kind:'database'}`

```json
{
  "kind": "database",
  "connection": "<项目连接稳定ID，engine=mysql>",
  "table": "telemetry_sample",
  "lookup": {
    "match": [
      {"field": "object_id",  "operator": "eq", "value": {"kind": "identityKey"}},
      {"field": "asset_code", "operator": "eq", "value": {"kind": "identityField", "field": "asset_code"}},
      {"field": "device_code","operator": "eq", "value": {"kind": "property", "property": "deviceCode"}},
      {"field": "object_type","operator": "eq", "value": {"kind": "constant", "value": "storage_cluster"}},
      {"field": "site_code",  "operator": "eq", "value": {"kind": "parameter", "parameter": "siteCode"}}
    ],
    "timeRange": {
      "field": "sampled_at",
      "start": {"kind": "context", "name": "startTime"},
      "end":   {"kind": "context", "name": "endTime"},
      "bounds": "[start,end)"
    }
  },
  "result": {
    "valueField": "value",
    "timestampField": "sampled_at",
    "timestampEncoding": "datetime",
    "timezone": "Asia/Shanghai",
    "order": "ascending",
    "duplicateTimestamp": "error",
    "secondarySort": {"field": "id", "order": "descending"},
    "selection": "",
    "missing": "null"
  }
}
```

字段规则：

- `connection`：必填，必须是本项目 connections 中 engine=mysql 的连接 id。与已登记来源（field）**互斥**：database 不引用 sources[]，field 不含 connection。
- `table`：必填，来自该连接的服务端目录（table 或 view）。
- `lookup.match[]`：首期仅 `operator:'eq'`。`value` 判别联合：
  - `{kind:'identityKey'}` 当前实例主键
  - `{kind:'identityField', field}` 当前实例身份表字段（身份表 = 绑定的 connection+table）
  - `{kind:'property', property}` 当前对象已映射的**单值**属性（apiName）
  - `{kind:'constant', value}` 常量（字符串存储，按目录字段类型解释）
  - `{kind:'parameter', parameter}` 项目参数名（state.parameters 键）
- `lookup.timeRange`：可选；仅当目标属性形态为 timeSeries。`start/end` 本轮只接受 `{kind:'context',name:'startTime'|'endTime'}`；`bounds` 只接受 `'[start,end)'`。字段含义：调用时由执行上下文提供具体时间，配置只保存参数角色。
- `result`：
  - `valueField` 必填。
  - timeSeries 目标：`timestampField`、`timestampEncoding`（`'datetime'|'epochSeconds'|'epochMillis'`）必填；`timestampEncoding==='datetime'` 时 `timezone` 必填（IANA 名称，前端默认取 `parameters.timezone`）；`order` 默认 `'ascending'`（可 `'descending'`）；`duplicateTimestamp` 默认 `'error'`（可 `'secondarySort'`，此时 `secondarySort:{field,order}` 必填）。
  - scalar 目标：`timestampField/timestampEncoding/timezone/order/duplicateTimestamp/secondarySort` **必须缺省**（有即报错「单值属性不能映射时间序列结果」）；可选 `selection: ''|'latest'|'sum'|'average'`（默认 ''=预期零或一条，多行报错；`latest` 需 `timestampField+timestampEncoding(+timezone 规则)`，`sum/average` 要求值字段为数值）；可选 `missing:'null'|'error'`（默认 null）。
  - timeSeries 目标禁用 `selection/missing`（多行即数据本体，无记录=空列表，值为空保留 null——这些默认行为只做页面说明，不落盘）。

### 2.3 扩展：Redis 直连（复用 kind:'redis'）

- `source` 与 `connection` **互斥**：`{kind:'redis', source:'src-x', ...}` = 旧登记来源；`{kind:'redis', connection:'conn-x', ...}` = 直连（connection 必须是 engine=redis 的项目连接）；两者都空或都非空 = 无效。
- `params` 取值联合新增：`{from:'identityField', field:'<身份表字段>'}`，与 database 匹配的 identityField 同一表示。既有 `{from:'primary'}`、`{from:'property',property}` 不变。
- **Redis 直连/登记来源都只能绑定 scalar 目标**：目标形态为 timeSeries 时报错（普通 GET/HGET 数值不能当时间序列）。

### 2.4 压缩规则（commitProperty，防数据丢失的关键）

`kind:'database'` 草稿在**同时满足**以下条件时编码为字符串 `result.valueField`（等价于旧 identity 直取）：

1. `connection === b.connection` 且 `table === b.table`（就是身份表本行）；
2. `lookup.match` 为空且无 `timeRange`；
3. 目标属性形态为 scalar；
4. `result` 仅含 `valueField`（无 selection/missing/timestamp/secondary）。

其余一律保存完整 dict。反向：字符串输入 `propertyView` 解码为 field 视图（现状不变）。field/redis/computed 的既有压缩行为不变。

### 2.5 函数输出形态声明（outputDeclarations）

- `implementations[].outputDeclarations[]` 条目从 `{outputId, note}` 扩展为 `{outputId, note, valueShape?:'scalar'|'timeSeries'}`；缺省 = scalar。不写 'scalar' 落盘。
- computed 属性校验：声明的 valueShape 必须等于目标属性形态（不等 = block「函数输出结果形态与属性要求不匹配」）。这保证 A10（标量输出绑序列属性 → 校验不通过）。
- 契约（workflow.functions）与实现规则本体不动；不新增函数执行器。

### 2.6 状态机（列表展示，前端推导 + 后端 report 兜底）

每个属性状态取优先级最高者：

1. `配置有误`：前端本地结构校验有 blocking，或 projectReport 中该属性 item.status==='invalid'
2. `元数据待核对`：配置引用的连接无目录缓存、或表/字段不在目录中（后端对应 warning）
3. `配置校验通过 · 未执行验证`：已配置且无上述问题
4. `未配置`：无任何来源

后端 `validate_project` 的 items（kind='propertySource', id='{ot}.{prop}'）已有 status/issues，前端直接消费；本地推导用于未触发全局校验时的即时反馈。

## 3. 后端校验规则（projects.validate_project 增量）

对 `kind:'database'`（全部为 blocking，除注明 warning）：

1. connection 必须存在于项目连接且 engine==='mysql'；table 必填（空=pending 未配置完）。
2. 目录不可用时：warning「表结构目录未读取/已过期，元数据待核对」（不 block，保留配置）。目录可用时：table 不在目录 → warning；match.field / result.valueField / timestampField / secondarySort.field / timeRange.field 不在表字段 → warning（指明具体字段）。
3. match 结构：operator 必须是 'eq'；value.kind 白名单五种；identityKey 要求绑定已配置 primary_key；identityField.field 必填（目录可用时须在身份表字段中）；property.property 必须是本对象已配置属性、不得等于本属性、且**被引用属性的有效形态必须是 scalar**；parameter.parameter 必须存在于 state.parameters（值为标量）；constant.value 必填，目录字段类型可用时：数值型字段（double/decimal/integer）要求可解析数值（integer 要求整数），否则 block「常量类型与字段不兼容」。
4. **至少一条 match 绑定当前实例**（identityKey 或 identityField），除非 `connection===b.connection && table===b.table`（身份表本行自动定位）；否则 block。
5. 循环依赖：本对象内 database 属性经 {kind:'property'} 形成依赖图，DFS 检测环（含自引用）；环 = block。
6. timeRange：目标为 scalar 时出现 → block；目标为 timeSeries 时 field 必填；start/end/bounds 不符合 §2.2 约定 → block。
7. result：按 §2.2 scalar/timeSeries 分支校验；timezone 用 `zoneinfo.ZoneInfo` 验证（不可识别 → block）；epoch* 编码在目录可用时要求字段类型为数值类型，datetime 编码要求字段类型为 date/dateTime 类（不匹配 → block；目录不可用 → 跳过）。
8. **目标形态为 timeSeries 的属性只允许 `kind:'database'` 或 `kind:'computed'`（且声明形态匹配）**；string/field/related/redis → block「时间序列属性需要数据库直选表的时间序列映射，或声明序列输出的函数结果」。

对 redis（增量）：

9. source/connection 互斥校验；直连时 connection 存在且 engine==='redis'。
10. params 支持 `from:'identityField'`：field 必填（目录可用时须在身份表字段中）。
11. 目标属性形态为 timeSeries → block。

对 computed（增量）：

12. 按 §2.5 校验输出声明形态与目标属性形态一致。

连接删除保护：

13. 前端 ConnectionManager 的引用收集（referencesOf）加入：database.connection、redis 直连 connection。后端 validate 的「引用的数据连接不存在」覆盖新结构（兜底）。

升级预检：

14. valueShape 变化经 classify（STRUCTURAL_FIELDS）自动产生 breaking reasons；upgrade_check 的属性模糊匹配已覆盖，无需新逻辑；补测试证明 A12。

## 4. 前端视图模型（bindingModel.ts 增量，后端 projects.py 保持镜像）

```ts
export type MatchValueView={kind:'identityKey'}|{kind:'identityField';field:string}
  |{kind:'property';property:string}|{kind:'constant';value:string}|{kind:'parameter';parameter:string}
export interface MatchConditionView{field:string;operator:'eq';value:MatchValueView}
export interface TimeRangeView{field:string;start:{kind:'context';name:'startTime'};end:{kind:'context';name:'endTime'};bounds:'[start,end)'}
export interface ResultView{valueField:string;timestampField:string;timestampEncoding:''|'datetime'|'epochSeconds'|'epochMillis';timezone:string;order:'ascending'|'descending';duplicateTimestamp:'error'|'secondarySort';secondarySortField:string;secondarySortOrder:'ascending'|'descending';selection:''|'latest'|'sum'|'average';missing:'null'|'error'}
export interface DatabaseView{kind:'database';connection:string;table:string;lookup:{match:MatchConditionView[];timeRange:TimeRangeView|null};result:ResultView}
export type RedisParamView={from:'primary'}|{from:'property';property:string}|{from:'identityField';field:string}
// RedisView 增加 connection:string（''=登记来源模式）；PropertyView 联合增加 DatabaseView
```

- `propertyView(b,api)`：解码 `{kind:'database'}` 为 DatabaseView；redis 解码时 `connection` 与 `source` 互斥还原；其余不变。未知 kind 返回 `{kind:'unknown'}`（**不得**当 computed）。
- `commitProperty(b,api,view)`：按 §2.4 压缩规则；DatabaseView 完整落盘（省略默认值：order='ascending'、duplicateTimestamp='error'、missing='null' 不落盘）；redis 写 connection 或 source（互斥）。
- 新增助手：`valueShapeOf(p,graph)`；`mysqlConnectionsOf(projectState)`/`redisConnectionsOf(projectState)`；`identityTableOf(b)`；`databaseSummary(view,labels)` 生成配置摘要文本；`propertyLocalIssues(b,api,view,shape)` 本地结构校验（blocking 规则的轻量前端镜像：必填项、实例绑定存在性、series 必填项、redis 占位符绑定）。
- 现有导出（sourcesOf/dbSourcesOf/redisSourcesOf/sourceById/commitSources/dropSource/relationView/commitRelation/catalog 系列/keyTokens/refreshCatalogOf）签名不变。

## 5. 属性来源表单（PropertySources.vue 重构）

- props 增加 `report?:any`（projectReport，用于状态列）；ProjectBinding.vue 透传（必要时 App.vue 补一句）。
- 列表列：属性（名称+类型）/ 结果形态徽标（单值|时间序列）/ 当前来源摘要 / 状态（§2.6 四态）/ 操作。
- 编辑器按需求 §4 顺序：
  1. **属性要求**（只读）：名称、定义、数据类型、结果形态、单位（来自 refState 的 effectiveProperty）。
  2. **数据来源**（单选）：数据库取值 / Redis 查询 / 函数结果；timeSeries 目标时 Redis 选项禁用并说明。
  3. **记录定位或输入绑定**：
     - 数据库三种模式（互斥 radio 或来源下拉分组）：`使用实例来源`（预填 connection+table=身份表；保持旧编码路径）/ `使用已登记补充来源`（现有 field 路径不变）/ `直接搜索项目连接下的表`（先选 mysql 连接 → 表 AppSelect searchable → database 新结构）。条件编辑器：每行「来源字段 AppSelect + 操作符(固定=等于) + 比较值来源 AppSelect（当前实例主键/身份表字段/已映射单值属性/常量/项目参数）+ 按类型的第二输入（字段选择或文本框）」；可增删行；重复字段/空条件就地提示；timeSeries 时显示时间范围卡（startTime/endTime 上下文，只读约定展示）。
     - Redis：连接下拉（项目 redis 连接，直连）或「已登记 Redis 来源」分组；GET/HGET、Key 模板、参数绑定下拉新增「身份表字段」选项；结果转换/缺失策略；本地 Key 预览保留。
     - 函数：实现+输出下拉；输出旁显示声明形态徽标，与目标不符就地提示（仍可保存草稿但后端会拒？——不：就地显示错误并禁止保存，与现状 editError 一致）。
  4. **结果映射**：值字段必选；timeSeries 显示时间字段/编码/时区（默认 parameters.timezone）/排序/重复时刻处理（secondarySort）；scalar 显示多行处理（默认零或一条，latest/sum/average）与缺失策略。换连接/换表时清除草稿中不再有效的字段、条件、排序并提示重选。
  5. **配置摘要**（databaseSummary 等生成的可读文本）+ 高级处理默认折叠（无记录=null、空序列=[]、空值保留 null、无效时标报错——只读展示）。
  6. 保存/取消：沿用 draft 机制，取消不动 b；保存前本地校验。
- 目录异步保护：refresh 捕获当前 connectionId，await 后连接已变则放弃本次结果（不写入草稿）；目录刷新失败保留旧配置并显示原因（沿用 refreshCatalogOf）。
- AppSelect 表/字段全部 searchable；不提供手输表名/SQL 输入。
