## 一、启动方式

```bash
python3 -m workbench.server     # http://127.0.0.1:8765
```

前端如需开发模式：`cd frontend && npm run dev`（代理 /api 到 8765）。生产模式由后端直接托管 `frontend/dist`。

## 二、两区结构（方案第 3 节）

左侧导航分为三组：

| 分组 | 页面 | 说明 |
| --- | --- | --- |
| 本体建模 | 建设流程 / 对象类型 / 链接类型 / 属性管理 / 计算定义 / 校验与版本 | 业务专家维护通用定义；原"校验与验收"+"本体与版本管理"合并为"校验与版本" |
| 项目绑定 | 项目选择与管理 / 对象与链接绑定 / 项目校验 | 实施人员维护数据映射与计算实现 |
| 辅助 | 本体画布 / 对象与链接编辑 / 本体浏览 / 对象数据浏览 / 实例与计算预览 / 历史图谱导览 | 保留原有功能 |

顶部工具栏随区域切换：本体区是"保存草稿/校验模型/发布版本"，项目区是"保存项目草稿/校验项目配置/发布项目版本"。两区各自独立保存、独立撤销。

## 三、计算契约（方案 4.3）

计算定义页分两组：

- **通用契约**（guide_version 3）：结构化签名——输入参数与输出均为"类型引用 + 显示名称 + 说明"列表。类型引用可选对象类型、属性（含共享属性）或基础类型；选择后名称自动带出，技术标识系统生成。支持"无输入"声明；输出至少一项且均为必需。通用业务约定与适用对象（可选多选、按输入建议）折叠维护。
- **历史定义**：旧函数原文只读展示，标记"待核对"，一键"转为通用契约"生成草稿并保留原文（不删除、不自动拆分）。

## 四、项目绑定区（方案 5）

**项目选择与管理**：项目列表（按当前本体过滤）、新建项目（选固定引用的本体发布版本）、版本升级（预检 → 影响表 → 切换草稿引用）、数据连接（只读，首期文件维护）、项目参数（键值编辑）、迁移待核对项（旧属性 valueSource）。

**对象与链接绑定**：左对象列表，右侧四区——

1. 对象数据映射：连接 / 表 / 主键 / 标题属性
2. 链接映射：关联字段
3. 属性来源：每属性选择"数据字段"或"计算结果"（实现 + 输出）
4. 计算实现：适用契约（只读签名）+ 跳转实现入口

页内"全部计算实现"标签维护所有契约的实现：数据连接、自然语言规则、环境（预留）、**结构化输入绑定**（对象 / 数据字段 / 常量 / 其他计算输出，含循环依赖检测）与**输出声明**（覆盖契约全部必需输出）。

**项目校验**：配置校验（结构层）+ 各配置项状态（未配置 / 配置有误 / 校验通过）+ 项目版本发布。执行验证需要执行器，首期未包含——发布的是配置快照，不等于上线或可运行。

## 五、版本机制（方案 7、8）

- 本体发布：先调用 `/api/publish-check` 得到分类建议（兼容候选 / 破坏性 / 待人工确认 / 初始），对话框中人工确认后发布。检测到引用失效的结构变化时禁止标记为兼容。破坏性 → 大版本号递增，兼容 → 小版本号递增。
- 版本落盘：`ontology/releases/models/<id>/<version>/`（含 manifest.yaml 记录变更类型、说明、父版本）+ index.json 原子更新。旧 ZIP 快照仍可恢复为草稿。
- 项目固定引用发布版本，升级必须预检（比较实际起终点版本），影响映射到对象映射 / 属性来源 / 链接映射 / 计算实现。
- 草稿存储：`ontology/drafts/models|projects/<id>/revisions/<序号>-<哈希>/` 多文件修订 + current.json 指针原子替换；修订号乐观并发（409 拒绝旧页面覆盖）。`models/`、`projects/` 基础目录仅为初始化输入，不再回写。storage 的 1.0.0 版本由基础文件一次性登记，供旧项目引用。

## 六、后端新增模块

| 模块 | 职责 |
| --- | --- |
| workbench/contracts.py | 契约签名校验、变更分类（结构差异 → 兼容/破坏性/待确认）、valueSource 迁移待办 |
| workbench/versions.py | 本体版本注册表（发布、读取、列表、基础版本登记） |
| workbench/projects.py | 项目存储（草稿修订/发布）、配置校验、升级预检 |
| workbench/workspaces.py | 扩展为多文件本体草稿存储；旧单文件草稿仅作初始化 |

新增 API：`/api/versions`、`/api/version-state`、`/api/publish-check`、`/api/projects`(GET/POST)、`/api/project-state`、`/api/project-save|validate|publish|upgrade-check`、`/api/project-releases`。旧预览/浏览端点接受可选 `projectState` 合并，内置演示引擎只消费直接字段映射（计算结果来源不参与演示物化）。

## 七、兼容与迁移

- 首次加载 storage 从旧 `ontology/drafts/draft.json` 初始化（剔除 bindings/parameters），首次保存写入新位置；旧文件不动。
- chuangzhi 项目从 `ontology/projects/chuangzhi/` 基础文件初始化（model_version 映射为引用版本），首次保存产生项目草稿。
- 旧 ZIP 快照恢复只恢复本体部分；项目数据由项目区独立维护。
- 属性"值的来源"编辑已从属性管理移除（保留只读引导跳转）；旧 valueSource 数据在项目首页显示为迁移待核对项。

## 八、验收对照（方案第 10 节）

联调已验证：新建空白本体不预置项目内容；本体无项目时可独立校验发布；发布分类（兼容 1.1.0 / 破坏性覆盖被 422 拦截）；升级预检影响映射；项目实现结构化绑定与输出声明校验；未配置执行器时明确显示"未执行验证"；旧实例预览（SOC 70%）与对象数据浏览在新结构下正常。
