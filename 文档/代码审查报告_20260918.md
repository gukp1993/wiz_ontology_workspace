## 2. 架构优点（明确保留，不要重构掉）

1. **存储层的"绝不隐式"原则**：初始化/迁移/备份必须走显式 CLI（`storage/transfer`），服务启动与请求路径绝不隐式 DDL/导入/文件回退。这是最容易在迭代中被破坏的约束，建议写进自动化守护测试。
2. **revision 是不透明 token（`r-<uuid>`）且与内容 hash 分离**，CAS 失败返回 409 + `currentRevision`，前端保存队列据此换基线重试——并发模型正确。
3. **写锁边界纪律**：`/api/connection-*`、`/api/flow-run`、`/api/llm-provider-test`、`/api/catalog-refresh` 明确不持全局锁；`/api/project-property-preview` 只在核对 revision 时短锁，联网期间释放。这个纪律在代码注释里被反复强调，很有效。
4. **三类凭据隔离**：连接密码（`secrets`）、项目 API 凭据（`api_credentials`）、LLM 密钥（`llm_providers`）各命名空间独立，全部只写不读回。
5. **前后端协议层镜像 + 金样测试**：`model_format.py` ↔ `modelFormat.ts`，项目校验金样（`test_validation_split.py`）逐字节等价回放，改规则必须同步金样——这套机制是防回归的核心资产。
6. **前端请求出口唯一**（`app/http.ts`）：全仓 `grep fetch(` 在 `src/` 下**零违规**，页面没有自写请求与错误解析。

## 3. 问题清单

### P0 · 必须修复

#### P0-1 `/api/restore` 调用了不存在的函数（真实缺陷，恢复功能不可用）

- 位置：`workbench/model_routes.py:542`
  ```python
  backup_data = json.dumps(encode_state(_server_current(identifier)), ...)
  ```
- 事实：全仓检索 `_server_current` **只有这一处引用，无任何定义**；同模块实际提供的读取函数是 `current()`（第 56 行）。
- 后果：`POST /api/restore` 在写恢复前备份时必抛 `NameError`，经 `do_POST` 兜底 → 400，**历史快照恢复功能整体不可用**。
- 原因推断：模块重构（文件版草稿 → DB Repository）时函数名改了但调用点漏改；该路径**没有任何自动化用例覆盖**，所以没被发现。
- 修复：改为 `current(identifier)`；并补一条恢复用例（建临时本体 → 发布 → 导出/记录快照 → restore → 断言状态与 revision）。

#### P0-2 未知异常统一吞成 400，且把内部异常文本回传客户端

- 位置：`workbench/server.py:177`
  ```python
  except Exception as exc:
      return self.respond({'error': str(exc)}, 400)
  ```
- 后果：① 服务端 5xx 全部变成 400，客户端（含 `saveCoordinator`）会误判为"请求有问题"而非"服务端故障"，重试语义错误；② `str(exc)` 可能包含表结构、文件路径、SQL 片段等内部信息，本地工具虽不对外，但日志/截图外泄仍有风险；③ 排障时服务端没有任何堆栈记录。
- 修复：拆成两条分支——业务异常（已有类型）→ 400；其余 → **500 + 服务端 `traceback` 日志 + 泛化消息**（如"服务处理失败，请查看服务端日志"）。

#### P0-3 `GET /api/projects` 的语义由「URL 是否带 query 串」隐式决定

- 位置：`workbench/server.py:126` + `project_routes.get_projects(query, url_query_present)`
- 现状：不带任何 query → 返回全部项目；带任意 query（哪怕 `?ontology=` 之外）→ 按 `ontology` 过滤。
- 后果：调用方无法从接口签名理解行为；前端 `listProjects(ontologyId?)` 一旦传空字符串就会产生歧义。
- 修复：改成显式参数（如 `?all=1` 返回全部，`?ontology=` 过滤），旧行为保留一版后切换。

### P1 · 本轮迭代应处理

#### P1-1 接口层无错误码，响应形态不统一

- 错误只有 `{"error": "中文消息"}`；客户端只能靠字符串匹配（如 `isOriginRejected` 用 `/来源/` 正则）判断类型，脆弱。
- `/api/releases` **返回裸数组**，其余列表接口返回 `{items}`。
- 业务失败：校验类 200 + 报告、发布/运行阻断 422、连接探测 200 + `ok:false`——三类混用。
- 建议：按 `文档/接口文档/README.md` §2.4 引入 `code` 字段（保留 `error` 兼容），统一 `{items}` 与「纯查询 200 / 写阻断 422 / 外部探测 200+ok」规则。

#### P1-2 GET 路由的工作区副作用外溢到无关接口

- 位置：`workbench/server.py:121`，所有 `/api/*` GET 先执行 `workspaces.describe(query.get('ontology', ['storage'])[0])`。
- 后果：`/api/flows`、`/api/llm-providers`、`/api/storage-status` 与本体工作区无业务关系，却被这行代码绑定；传入非法 `ontology` 时它们也会 404/400。
- 建议：工作区定位下沉到本体/项目路由内部，按区分派。

#### P1-3 路由表可读性：`lambda` 包装 + 路径字符串分支 + `None` 占位

- 6 个端点用 `lambda payload: handler(payload, '/api/xxx')` 注册，处理函数内部再 `if path == ...` 分支；`/api/export` 在 `POST_ROUTES` 中值为 `None`，靠 `do_POST` 内特判。
- 后果：白名单表不再是"自解释的接口清单"（值 `None` 却表示已注册）；漏改分支不会有静态错误。
- 建议：改用具名函数或 `functools.partial`；导出接口注册真实 handler，由 `respond` 按 `(bytes, content_type)` 分派。

#### P1-4 无可观测性：无访问日志、无 requestId、无健康检查

- 现状：排障只能靠客户端表现；`storage-status` 部分承担但前端未接入。
- 建议：加 `X-Request-Id`（中间件生成并回写响应头）、结构化访问日志（`method/path/status/latencyMs/requestId/revision`）、`GET /api/health` 与 `GET /api/ready`。

#### P1-5 接口契约测试缺失

- `tests/` 有 51 个文件（含前端 `.test.mjs`、金样、存储契约 45 项），但**没有针对 HTTP 接口的请求/响应 schema 契约测试**——正因如此 P0-1 才长期潜伏。
- 建议：加 `tests/test_api_contract.py`，对全部 52 个接口做「必填字段存在 + 类型正确 + 错误码符合」的快照断言；CI 必跑。

#### P1-6 REST 语义偏离

删除/更新/动作全部用 POST（`flow-delete`、`llm-provider-delete`、`save`、`publish`、`flow-run`），无 `PUT`/`DELETE`、无版本前缀、无 `Location`、并发令牌在请求体而非 `If-Match`。
详见 `文档/接口文档/05-接口清单与规范差距.md` §2（G3–G7、G10）。

## 8. 批次 B / C 完成（2026-09-18）

### 批次 B（R3 / R4 / R5）

1. **R3 异常分类**（`server.py`）：废除「未知异常 → 400 + str(exc)」兜底。现在 ValueError（业务输入校验约定）与 KeyError/TypeError（请求形态，消息泛化、细节进日志）→ 400；其余（含 OSError）→ **500 INTERNAL_ERROR**，客户端只收通用消息 + requestId，完整堆栈写服务端日志（与默认访问日志同源）。错误信封实装稳定 `code` 字段（分派层全覆盖 + 业务层内联 409 补 `REVISION_CONFLICT` / `FLOW_RUNNING`）；全部响应新增 `X-Request-Id` 头。
2. **R4 工作区依赖解除**（`server.py::do_GET`）：先判路由存在（未知端点稳定 404），删除全部 GET 共用的 `workspaces.describe` 前置；本体/项目接口在自身边界校验，flows / llm-providers / storage-status 与本体无关。
3. **R5 筛选语义**（`project_routes.get_projects`）：仅 `ontology` 参数控制范围；空值 400、合法格式不存在 404、其他参数不隐式改变范围；前端 `listProjects` 无筛选不带参数（已核实零兼容影响），签名去掉 `url_query_present`。
