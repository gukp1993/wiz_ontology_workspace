# 08 · 从物料自动构建本体接口（v1 冻结，2026-09-20；2026-09-21 收敛修订）

需求：[需求说明](../需求/20260920_从物料自动构建本体/需求说明.md) · [交互原型](../需求/20260920_从物料自动构建本体/交互原型_v1.html) · [开发计划](../需求/20260920_从物料自动构建本体/开发计划.md)。

本分册是「从物料生成新本体」任务族的唯一契约。所有端点走统一鉴权门（06 分册），
未登录 401；数据按 `owner_user_id` 完全隔离，跨账号一律按 404/空处理。
所有写操作按 §0 的口径携带当前 `revision`（任务级 token、候选级 token 或整数清单/范围修订），
冲突 409 + `currentRevision`。
新增路由全部登记 `workbench/server.py` 的 `GET_ROUTES`/`POST_ROUTES` 白名单。

通用错误码沿用既有约定：400 `INVALID_ARGUMENT`、401 `UNAUTHENTICATED`、
404 `NOT_FOUND`、409 `REVISION_CONFLICT`/`DUPLICATE_NAME`/`ALREADY_DELIVERED`/`UPLOAD_CONFLICT`/`UPLOAD_EXPIRED`、
413 `PAYLOAD_TOO_LARGE`、
422 `INVALID_STATE`（带 `issues` 数组）/`HASH_MISMATCH`/`ZIP_INVALID`/`LIMIT_EXCEEDED`、
503 `STORAGE_UNAVAILABLE`。
域层异常可携带 `code`/`status`/`issues`（`workbench/server.py` 的 `ValueError` 分支按此映射：
有 `issues` → 422 + `code` + `issues`；只有 `status` → 该状态码 + `code`；都没有 → 400 `INVALID_ARGUMENT`），
禁止把上述细分码压成 400 `INVALID_ARGUMENT`。禁止 200 + 空数据伪装失败。
请求体沿用 2 MB 全局上限；文件内容只经分片上传进入，
不存在“按服务端任意路径读取”的接口。

## 0. 写操作 revision 口径（2026-09-21 冻结）

`revision` 在不同端点是**不同种类的值**，混用是历史 P0（D05）。收口口径：
**必填的端点缺失或空串一律 400 `INVALID_ARGUMENT`（不做“空值跳过比对”）；
值不匹配一律 409 `REVISION_CONFLICT` 并回传服务端当前值 `currentRevision`（字符串）。**

| 端点 | `revision` 传什么 | 缺失/空串 | 不匹配 |
|---|---|---|---|
| `build-task-rename` | 任务 token（`task.revision`，r-uuid 字符串） | 400 | 409 + `currentRevision`=任务 token |
| `build-material-exclude` | **`String(materialRevision)`**（整数清单修订的字符串形态，不是任务 token） | 400（数字形态也 400：必须是字符串） | 409 + `currentRevision`=当前字符串修订 |
| `build-candidate-update` / `build-candidate-decide` | **该候选**的 token（`candidate.revision`，r-uuid） | 400 | 409 + `currentRevision`=该候选 token |
| `build-candidates-merge`（`confirmed=true`） | **保留项（`primaryId`）候选**的 token | 400 | 409 + `currentRevision`=保留项 token |
| `build-candidates-merge`（`confirmed=false` 预览） | **不携带**（只读，不做 CAS） | — | — |
| `build-review-undo` | **保留项候选**的 token | 400 | 409 + `currentRevision`=保留项 token |
| `build-diff-resolve` | **该候选**的 token | 400 | 409 + `currentRevision`=该候选 token |
| `build-scope-save` / `build-scope-confirm` | 整数 `scopeRevision` | 省略按 `0` 处理：范围已有修订时必 409（等价必填） | 409 + `currentRevision`=当前整数的字符串 |
| `build-message` | 整数 `scopeRevision`，**可选**：省略或 `0` = 跳过比对（消息只追加） | 跳过比对 | 409 |
| `build-regenerate` | 整数 `scopeRevision`，**可选**：省略即跳过范围比对（前端默认省略） | 跳过比对 | 409 |
| `build-deliver` | 不用 revision：`checkToken`（§8，**必填**）+ `requestId` 幂等 | 400 | 409/422 见 §8 |
| 其余写端点（`build-scan`/`build-material-retry`/`build-run-*`/`build-task-create`/`build-task-delete`/`build-upload-*`/`build-deliver-precheck`） | 不携带 `revision`（幂等或由服务端推进基线） | — | — |

## 1. 数据模型（响应字段与 `workbench/storage/ontology_build.py` 的视图函数逐字一致）

### 1.1 BuildTask
`id` · `name` · `status`(draft/materials/scope/generating/review/delivered) ·
`stageLabel`(给页面显示的中文当前阶段) · `revision`(r-uuid 字符串，任务级 token) ·
`materialRevision`(整数，材料清单变更即 +1) · `scopeRevision`(整数) · `currentBatch`(batch id 或 '') ·
`deliveryOntologyId` · `createdAt`/`updatedAt`。
**列表/详情响应不含材料数量**：材料数量由 `GET /api/build-materials` 的 `items` 长度给出
（前端 A01 逐行读取详情属已知绕行，见开发计划）。
材料/范围变化会推进 `materialRevision`/`scopeRevision` 并使旧批次结果标记 `stale`（旧结果只读）。

### 1.2 Material
`id` · `taskId` · `relPath`（浏览器相对路径，展示用；服务端校验无 `..`、绝对路径、
符号链接语义）· `kind`(code/ddl/docx/pdf/xlsx/md/zip/other，识别后填入) · `size` · `contentHash`(sha256) ·
`parseState`(pending/running/success/partial/failed/excluded) ·
`coverage`(解析覆盖摘要：modules[]、notes[]、failedSegments[]、factCount) · `sourceGroup`(同源组=内容哈希前缀，
重复副本不算独立佐证) · `excluded`(bool) · `error` · `revision`。
`uploadState`(open/complete/aborted) 只存在于上传会话（`wb_build_uploads`），**不在 Material 响应里**。

### 1.3 Fact（解析事实，任务侧数据，不进本体协议）
`id` · `taskId` · `materialId` · `locator` · `snippet`（原文片段，≤500 字）· `kind` · `data`(结构化) · `quality`(high/medium/low)。
`locator` 按材料类型：`{kind:'code',file,line,symbol}` · `{kind:'ddl',file,line,table,column}` ·
`{kind:'docx',file,section,block}` · `{kind:'pdf',file,page}` · `{kind:'xlsx',file,sheet,cell}` ·
`{kind:'md',file,section,line}`。定位器必须来自真实解析，模型不得发明。

### 1.4 Scope / Message
Message：`id` · `seq`(任务内单调递增，增量轮询游标) · `role`(user/assistant) · `content` ·
`patch`(助手给出的范围补丁，可空) · `error`(助手侧失败的可读文案，成功为空) ·
`scopeRevision`(该消息产生时的范围修订) · `createdAt`。
Scope：`taskId` · `goal` · `include` · `exclude` · `relations`（必要关联与深度）·
`coverage`（材料覆盖与冲突说明）· `openQuestions[]`（`{text, blocking}`）· `confirmed`(bool) ·
`revision`(整数) · `confirmedAt` · `providerFingerprint`(providerId/name/model，不含密钥)。

### 1.5 Run / Batch
Run：`id` · `taskId` · `kind`(scan/dialog/generate) · `state`(queued/running/succeeded/failed/cancelled/interrupted) ·
`stage`(scan: parse/index → generate: retrieve/align/abstract/verify/adapt) · `stageLabel` ·
`progress`(`{done,total}`) · `baseline`(`{materialRevision,materialHashes,scopeRevision,providerFingerprint,promptVersion,parserVersion}`) ·
`attempt` · `error`(可读文案) · `retryable`(bool) · `usage`(`{calls,promptBytes,completionBytes,durationMs}`) ·
`batchId` · `cancelRequested`(bool) · `createdAt`/`updatedAt`。
Batch：`id` · `taskId` · `runId` · `baseline` · `stale`(bool) · `createdAt`。

### 1.6 Candidate（候选定义）
`id`（服务端生成的稳定 ID）· `taskId` · `batchId` · `type`(object/property/link/rule/action) ·
`key`(模型临时键，仅批内) · `name` · `definition` · `alignedKey`（跨批次对齐键，属性含 dataType 与规范化宿主名）·
`fields`(按类型：property→`dataType`(枚举 `text/number/boolean/dateTime/array/struct/timeSeries`；
`timeSeries` 必须带 `valueType`，枚举 **`string/double/decimal/integer/boolean/date/dateTime`**，
与 `workbench/model_format.py` 的 `SERIES_VALUE_TYPES` 单一来源一致；旧值 `text`/`number` 一律判
`OBSERVATION_VALUE_TYPE_INVALID`，见 §8) · link→`sourceRef`/`targetRef`(候选 key 或
已合并候选 ID)/`cardinality`(`{source:'one'|'many',target:'one'|'many'}`，无依据不下默认) ·
rule→`content`(选填) · action→`effect`(选填)) · `ownerKey`(property/rule/action 的所属对象 key) ·
`evidence`(`{字段名: [factId,...], '_record': [factId]}`，可空字段不硬造) ·
`evidenceStatus`(supported/inferred/conflict/insufficient) · `conflicts[]`(`{field,sides:[{factId,value}],note}`) ·
`decision`(include/defer/exclude) · `reviewed`(bool) · `reason` · `issues[]`(`{code,message,field}`) ·
`origin`(`{batch,key,mergedFrom:[candidateId,...],mergedInto:candidateId|null,revived?:true}`) ·
`revision`(r-uuid，候选级 CAS token)。
默认决定：有依据且结构完整 → include；弱证据/冲突/结构不完整 → defer。
命名与字段一律不猜单位、不造参数、不默认数量关系。

### 1.7 ReviewOp（可撤销操作）
`id` · `taskId` · `kind`(merge/edit) · `payload`（撤销所需前后状态） · `reverted`(bool) · `createdAt`。
只在 `build-candidates-merge` 响应里回 `opId`，无独立查询端点。

### 1.8 Delivery
响应视图：`id` · `taskId` · `requestId` · `ontologyId` · `createdAt`（`payloadDigest` 只落库，不回传）。
同任务只允许一次成功交付；同 `requestId` + 同请求内容指纹的网络重试返回原结果
（`replayed:true`）；同 `requestId` 不同 payload → 409（§8）。

## 2. 能力与限额

### 2.1 能力查询
`GET /api/build-capabilities` → 200
```json
{"limits": {"chunkBytes": 524288, "fileBytes": 52428800, "taskBytes": 209715200,
            "zipExpandedBytes": 314572800, "zipMaxEntries": 10000, "parseTimeoutSeconds": 120},
 "ocr": {"available": false, "reason": "未配置 OCR 服务；扫描页将逐页报告失败"},
 "provider": {"id": "…", "name": "…", "model": "…"} | null,
 "parserVersion": "v1", "promptVersion": "v1",
 "candidateTypes": ["object","property","link","rule","action"],
 "propertyDataTypes": ["text","number","boolean","dateTime","array","struct","timeSeries"],
 "valueTypes": ["string","double","decimal","integer","boolean","date","dateTime"]}
```
限额为工程保守默认（合成样本校准后登记），页面必须原样展示，不得承诺更大容量。

**`provider` 为 null 时的口径（D17）**：

| 端点 | provider 缺失的行为 |
|---|---|
| `build-scope-confirm` / `build-regenerate` / `build-run-resume`(dialog/generate) | **422 `INVALID_STATE`**（`status=422`，无 `issues`），页面引导去「更多工具 → LLM 配置」 |
| `build-message` | 例外：用户消息**已经落库**，返回 **200 + `assistantPending:false` + `assistantError`**（丢输入比错一个状态码更糟；见 §6） |
| `build-capabilities` | 200 且 `provider:null`（只报告能力，不报错） |

## 3. 任务

- `GET /api/build-tasks?limit=20&offset=0` → `{"items":[Task],"total":n}`
- `POST /api/build-task-create` `{"name":"…"}` → `{"task":Task}`（名称可空：自动“未命名任务-日期”；>160 字 → 400）
- `GET /api/build-task?taskId=…` → `{"task":Task,"materials":[Material],"scope":Scope,
  "run":Run|null,"batch":Batch|null,"delivery":Delivery|null,"stale":bool,
  "capabilities":{"limits":{…},"ocrAvailable":false}}`
- `POST /api/build-task-rename` `{"taskId","name","revision"}` → `{"task":Task}`
  （`revision`=任务 token；409 带 `currentRevision`；空名 400）
- `POST /api/build-task-delete` `{"taskId","confirmName"}` → `{"ok":true,"note":"…"}`
  （`confirmName` 与任务名不一致 → **400 `INVALID_ARGUMENT`**（路由自身确认校验）；
  已交付任务删除后原始证据不可用，`note` 说明保留的本体草稿；本体草稿不随任务删除）
- 任务不存在/跨账号 → 404 `NOT_FOUND`

## 4. 分片上传与物料

- `POST /api/build-upload-init` `{"taskId","relPath","size"}` → `{"uploadId","chunkBytes","maxChunks","received":0}`
  - 校验：单文件 ≤ fileBytes；任务累计（已登记+上传中）≤ taskBytes（超限 → 422 `LIMIT_EXCEEDED`）；
    `relPath` 安全（拒绝绝对路径、`..`、空名、>512 字符、控制字符 → 400）；`size` ≤0 或非整数 → 400。
  - 任务不存在/跨账号 → **404 `NOT_FOUND`**。
- `POST /api/build-upload-chunk` `{"uploadId","index","hash","dataBase64"}` → `{"received":n,"nextIndex":n}`
  - `dataBase64` 是**唯一不受通用 512 字符参数上限约束的字段**（D01）：路由层放行到请求体上限（2 MB），
    真正的分片上限按 `chunkBytes` 推导的标准 base64 长度判定
    （`4*ceil(chunkBytes/3)` = 699052 字符；`protocol.CHUNK_BASE64_CHARS`），
    超过即 **422 `LIMIT_EXCEEDED`**（不是 400「参数过长」）。
  - 同 index 同 hash 幂等返回既有结果；同 index 不同 hash → **409 `UPLOAD_CONFLICT`**；
    空分片/序号越界/跳号/非法 base64 → **400 `INVALID_ARGUMENT`**；分片解码后 > chunkBytes → 422 `LIMIT_EXCEEDED`；
    hash 为分片 sha256，校验失败 **422 `HASH_MISMATCH`**。
  - 过期上传（30 分钟无写入、显式 abort 后临时文件已清理）不可续传，必须 init 重建 → **409 `UPLOAD_EXPIRED`**；
    上传不存在/已结束（含 complete 成功后重复调用）/跨账号 → **404 `NOT_FOUND`**；临时文件有界清理。
- `POST /api/build-upload-complete` `{"uploadId","finalHash"}` → `{"materials":[Material]}`
  （ZIP 展开为多份材料时另带 `"excludedPaths":[…]`；单文件 `materials` 长度为 1）
  - 校验累计分片齐全（未齐 → 400）、实际大小与声明一致（不一致 → 整包回收 + 422 `HASH_MISMATCH`）、
    最终 hash（与请求 `finalHash` 不符 → **422 `HASH_MISMATCH`**，会话保留，带正确摘要重发即可登记）；
    ZIP 按 §4.1 展开为多份材料（虚拟 relPath = 容器路径 + 包内路径）。
    失败：422 `HASH_MISMATCH` / `ZIP_INVALID` / `LIMIT_EXCEEDED`，临时内容不登记为可用材料。
  - 成功后 `materialRevision` +1 并使旧批次失效（由路由在同一事务内推进）。
- `POST /api/build-upload-abort` `{"uploadId"}` → `{"ok":true}`（重复调用幂等；不存在/跨账号 → 404 `NOT_FOUND`）
- `GET /api/build-materials?taskId=…` → `{"items":[Material],"revision":materialRevision}`（`revision` 是**整数**）
- `POST /api/build-material-exclude` `{"taskId","materialId","excluded","revision"}` → `{"material":Material,"task":Task}`
  - `revision` 必填，取值为 **`String(materialRevision)`**（§0）：缺失/空串/数字形态 → 400；
    与当前清单修订不一致 → 409 + `currentRevision`（字符串）。
  - 排除/恢复会推进 `materialRevision`，使扫描/范围/结果基线失效（页面提示旧结果过期）。
  - 材料不存在或不属于该任务 → 404。
- `POST /api/build-material-retry` `{"taskId","materialId"}` → `{"runId"}`（等价于对该材料重新扫描）
- `POST /api/build-scan` `{"taskId"}` → `{"runId"}`
  - 后台解析全部未排除材料；单材料失败不阻塞其余；
    **无可用材料 → 422 `INVALID_STATE` + `issues:[{code:'NO_MATERIAL',field:'materials',…}]`**（不是 400）。
  - 已成功且内容哈希未变的材料复用解析结果（不重复解析）。

### 4.1 ZIP 展开的安全口径
逐条校验后才解压：绝对路径/盘符、`..` 段、符号链接与特殊文件 → **422 `ZIP_INVALID`**（整包拒绝，
已解压内容全部回收，绝不登记半份材料）；条目数 > `zipMaxEntries`、展开声明总量 > `zipExpandedBytes`、
单条目压缩比异常（典型炸弹特征）→ 拒绝；展开期按**实际写出字节**计入预算，不只信目录声明值（D12）；
`node_modules`/`.git`/`__pycache__` 等排除目录内的条目进 `excludedPaths` 上报，不静默丢弃。

## 5. 运行

- `GET /api/build-run?taskId=…&runId=…`（runId 省略取最近一次）→ `{"run":Run,"taskStatus":…}`
  - 轮询轻量：不返回 facts/candidates 详情。`state=interrupted` 表示服务重启丢失执行（不得显示“仍在运行”）。
  - 无可用运行记录 → 404 `NOT_FOUND`。
- `POST /api/build-run-cancel` `{"taskId","runId"}` → `{"run":Run}`（取消不保证立即终止已发出的模型请求，
  但晚结果禁止写入当前批次；页面如实显示“正在取消/已取消”）
- `POST /api/build-run-resume` `{"taskId","runId"}` → `{"runId"}`（仅 failed/cancelled/interrupted；
  复用已匹配 checkpoint；服务重启只标记中断，不自动重发）
  - 状态不满足（例如对 `succeeded` 运行重试）→ **400 `INVALID_ARGUMENT`**（路由自身前置状态检查，
    属本分册里唯一保留 400 的状态类拒绝；无 provider 可恢复时按 §2.1 返回 422 `INVALID_STATE`）
  - run 不属于该 taskId / 跨账号 → 404

## 6. 范围对话

- `GET /api/build-messages?taskId=…&after=0` → `{"messages":[Message],"scope":Scope,"revision":scopeRevision,"stale":bool}`
- `POST /api/build-message` `{"taskId","content","revision"}` → `{"messageId","assistantPending":true}`
  - `content` ≤8000 字符（超限 400）；`revision` 可选整数：省略或 0 跳过范围比对，
    非 0 且与当前 `scopeRevision` 不符 → 409 + `currentRevision`。
  - 用户消息立即落库；助手回复异步生成（dialog run），轮询 `build-messages` 增量获取。
  - **provider 缺失时（§2.1 例外）**：用户消息与已有摘要保留，
    返回 200 + `{"assistantPending":false,"assistantError":"尚未配置可用的 LLM 提供方…"}`，
    助手的 `error` 同步落进消息流；绝不伪造助手回答。
  - 模型不可用/超时/非法输出：同样保留用户消息与已有摘要，消息流出现 `assistantError`，可重试。
  - 助手 patch 只是建议：不得覆盖人工已保存的范围字段（服务端按 scope.revision 比对，
    人工基线更新后 patch 降级为提示）。
- `POST /api/build-scope-save` `{"taskId","scope":{goal,include,exclude,relations,coverage,openQuestions},"revision"}` →
  `{"scope":Scope}`（`revision` 为整数 `scopeRevision`，**必须携带**：省略按 0 处理，范围已有修订时 409；
  成功即推进 revision 并返回新 `Scope`；`openQuestions` 只取前 50 条、每条文本截 500 字）
- `POST /api/build-scope-confirm` `{"taskId","revision","providerId"}` → `{"runId","batchId"}`
  - `revision` 为整数 `scopeRevision`（必须等于当前值，否则 409 + `currentRevision`）；
    `providerId` 选填，省略则用默认提供方；无可用提供方 → 422 `INVALID_STATE`（§2.1）。
  - 阻断口径（D17）：
    - 纳入/排除同词且未逐对给出覆盖说明、或存在 `blocking` 未决问题 →
      **422 `INVALID_STATE` + `issues`**（`SCOPE_CONFLICT` / `SCOPE_OPEN_QUESTION`，带 `field`）；
    - 目标或纳入范围为空、无成功解析材料 → **400 `INVALID_ARGUMENT`**（域层 `TaskError`，
      未携带 `code`/`status`，见 §11 已知残留）；
    - 材料清单整体为空 → 400（同上）。
  - 确认时冻结输入基线（材料清单/hash、范围修订、解析器/提示词版本、provider 指纹，不含密钥），
    启动 generate run 并创建新 batch。再次确认=新批次；旧批次保留只读。

## 7. 候选评审

- `GET /api/build-candidates?taskId=…&batch=…&type=&decision=&evidenceStatus=&query=&offset=0&limit=100`
  → `{"items":[Candidate],"total":n,"counts":{"byType":{…},"byDecision":{…},"byStatus":{…}},"batch":Batch|null,"stale":bool}`
  - `batch` 省略时取 `task.currentBatch`，再退到最近批次。
  - **列表 `items`/`total` 与 `counts` 一律剔除 `origin.mergedInto` 非空的候选**（D03）：
    被合并项只在候选详情/审计里可见，不参与评审计数。
- `GET /api/build-candidate?candidateId=…` → `{"candidate":Candidate,"evidence":[{"field":…,"items":[{factId,locator,snippet,quality,materialRelPath}]}]}`
  （证据位置已删除的不展示，绝不虚构）
- `POST /api/build-candidate-update` `{"candidateId","fields":{name,definition,ownerKey,dataType,valueType,content,effect,cardinality},"revision"}`
  → `{"candidate":Candidate}`（`revision`=该候选 token，§0；`fields` 只允许列举字段，未知键/坏 `dataType`/
  坏 `cardinality` → 400；写回前重算结构 `issues`；成功推进候选 token）
- `POST /api/build-candidate-decide` `{"candidateId","decision","reason","revision"}` → `{"candidate":Candidate}`
  - 弱证据/冲突/材料不足转 include **必须**带非空 `reason` → 否则 **422 `INVALID_STATE` +
    `issues[0].code='REASON_REQUIRED'`**（D17，不是 400）；`reviewed` 置 true；未知 decision → 400。
- `POST /api/build-candidates-merge` `{"taskId","primaryId","mergeIds":[…],"confirmed":false,"revision"}`
  - `confirmed=false`（预览，只读，**不带 revision**）→
    `{"fields":[{"name","primaryValue","mergeValues":[…],"diff":bool}],"evidenceCount":n,"warnings":[…]}`
    （响应是**扁平对象**，不包 `preview` 层）
  - `confirmed=true`（执行，候选级 CAS）→ `{"candidate":Candidate,"opId":"…"}`
  - 语义阻断一律 **422 `INVALID_STATE` + `issues[0].code`**（D17）：
    `MERGE_TYPE_MISMATCH`（跨类型）、`MERGE_DATA_TYPE_MISMATCH`（property `dataType` 不一致）、
    `MERGE_CARDINALITY_MISMATCH`（link 基数角色不一致）、`ALREADY_MERGED`（保留项或成员已被合并）、
    `MERGE_TARGET_INVALID`（保留项同时出现在 `mergeIds`）；
    `mergeIds` 为空/非法形态、成员不存在 → 400/404。
  - 执行后：保留项取证据并集并记录 `origin.mergedFrom`；被合并候选 `origin.mergedInto` 指向保留项，
    从列表/计数/预检选定集合一并消失（§0、§8）；证据与来源全部保留。
- `POST /api/build-review-undo` `{"taskId","opId","revision"}` → `{"ok":true,"candidate":Candidate}`
  - `revision`=**保留项候选** token（§0）。撤销恢复保留项的先前字段/证据/决定，并清空成员 `mergedInto`。
  - 若保留项在合并之后又有新的编辑（`updatedAt` 晚于操作创建时间）→ **409 `REVISION_CONFLICT`**
    并说明影响，不静默丢弃后写入；操作不存在/不属于该任务 → 404；
    非 merge 操作、已撤销、撤销信息不完整 → 400。
- `POST /api/build-regenerate` `{"taskId","revision"?}` → `{"runId","batchId"}`
  - `revision` **可选整数** `scopeRevision`：省略（前端默认）即跳过范围比对，按当前范围重跑；
    传值必须是整数（传 r-uuid token → 400）、且必须等于当前 `scopeRevision`（否则 409 + `currentRevision`）。
  - 以当前材料/范围基线重跑（完整重跑，不做精细增量）；旧批次保留。
  - 人工决定与编辑保留，新批次按 `alignedKey`（候选 key + 证据来源，属性含 dataType 与宿主）对齐产出 `diff`；
    **旧批次 `decision=exclude` 的候选在新批次绝不自动复活**：生成写事务内强制 `defer`
    并在 `origin.revived=true` 标记（D04），差异报告用 `excludedProtected` 桶如实汇报。
  - 无可用材料 / 无 provider → 400 / 422（同 §4、§2.1）。
- `GET /api/build-diff?taskId=…&batch=…` → `{"against":batchId|null,"newBatch":batchId,
  "buckets":{"added":[…ids],"changed":[{"id","fieldsChanged":[…],"manualConflict":bool}],"removed":[…ids],
  "kept":[…ids],"excludedProtected":[…ids]},"items":[Candidate]}`
  （`against`=除目标批次外最近的一个批次；本端点**只读**，不写保护标记）
- `POST /api/build-diff-resolve` `{"taskId","candidateId","choice":"keepManual"|"acceptNew","revision"}` → `{"candidate":Candidate}`
  - `revision`=**该候选** token（§0）。`acceptNew` 只清 `origin.manualConflict`；
    `keepManual` 以 `alignedKey` 找对照批次的同键候选，**只覆盖旧批次确实填过的字段**（不张冠李戴、不清空新值）。
  - `choice` 非法、无对照批次、对照批次无同键候选 → 400；候选不存在 → 404。

## 8. 交付（原子创建新本体）

### 8.1 预检
`POST /api/build-deliver-precheck` `{"taskId"}` →
`{"ok":bool,"counts":{object:n,…},"issues":[{"code","message","candidateId"?}],"excluded":n,"deferred":n,
 "coverage":{"materials":n,"failedSegments":n,"notes":[…]},"checkToken":"…","batchId":"…",
 "notIncluded":[{id,name,type,decision}],"selectedIds":[candidateId,…]}`
- 只读端点，**总是针对最近批次**（不接受 `batch` 参数）；`selectedIds`/`counts`/`notIncluded`
  一律剔除 `origin.mergedInto` 非空的候选（D03）。
- 服务端确定性校验（与交付完全同口径，D09）：名称/定义非空、属性数据类型枚举、
  timeSeries 观测值类型、链接两端可解析、属性/规则/动作所属对象存在且未被排除、结构自洽。
- **阻断 `issues` 码集合（唯一口径）**：
  `NAME_REQUIRED`、`DEFINITION_REQUIRED`、`DATA_TYPE_INVALID`、`CARDINALITY_INVALID`、
  `OBSERVATION_VALUE_TYPE_MISSING`、`OBSERVATION_VALUE_TYPE_INVALID`、`PROPERTY_OWNER_UNRESOLVED`、
  `LINK_ENDPOINT_UNRESOLVED`、`DEPENDENCY_NOT_INCLUDED`、`STRUCTURE_INVALID`。
- 检查本身无法进行时（域层 `DeliveryBlocked`）返回 **422 `INVALID_STATE` + `issues`**，
  码为 `ALREADY_DELIVERED`（已交付）、`NO_BATCH`（尚未生成）、`STALE_RESULT`（材料/范围已变化，结果过期）。
- 其余情形恒 200：`ok=false` + 可定位 `issues`（`candidateId`）。
- `checkToken` 绑定「最近批次 + 当前选定集合 + `scopeRevision` + `materialRevision`」；
  用户后续修改选择、范围或材料即失效（交付时服务端重算比对 → 422 `CHECK_TOKEN_STALE`）。

### 8.2 交付
`POST /api/build-deliver` `{"taskId","name","checkToken","requestId"}` →
`{"ontologyId","taskId","deliveredAt","revision","warnings":[…],"replayed":bool}`
- **`checkToken` 必填**（D10）：缺失或空串 → **400 `INVALID_ARGUMENT`**，绝不进入交付事务。
  `name`（≤160）、`requestId`（≤80）同样必填（缺失/空/超长 → 400）。
- 令牌内容失效 → **422 `INVALID_STATE` + `issues[0].code='CHECK_TOKEN_STALE'`**。
- 同事务：确认 owner 与未交付 → 幂等回执检查 → 确定性阻断复核（与 §8.1 完全同口径）→
  域内重验基线与结构（**stale 批次在域层再拦一次**，不依赖路由 token）→ 名称查重 →
  分配本体与定义 ID（含 definitionOrder）→ 写完整新草稿 → 记录候选 ID 映射与任务来源 → 写回执与任务已交付。
  失败全部回滚（不得先建空本体）。
- 状态码口径（D10/D17，逐条对应实现）：

  | 情形 | 状态 | code | issues |
  |---|---|---|---|
  | 缺 `checkToken`/`name`/`requestId`、名称或 requestId 超长 | 400 | `INVALID_ARGUMENT` | — |
  | 同 `requestId` 且请求内容指纹一致（网络重试） | 200 | — | —（`replayed:true`，同一 `ontologyId`） |
  | 同 `requestId` 不同 payload（改名或选定集合变化） | 409 | `REVISION_CONFLICT` | — |
  | 任务已交付且 `requestId` 不同 | 409 | `ALREADY_DELIVERED` | **无**（刻意不带清单，状态码语义优先） |
  | 名称与当前账号已有本体重复 | 409 | `DUPLICATE_NAME` | — |
  | 结构性/依赖阻断、stale 批次、无批次、checkToken 失效 | 422 | `INVALID_STATE` | 有（§8.1 码集合 + `CHECK_TOKEN_STALE`/`STALE_RESULT`/`NO_BATCH`） |
  | 任务不存在/跨账号 | 404 | `NOT_FOUND` | — |

  超时/并发重试不得产生第二个本体（回执唯一性与 `requestId` 幂等 + 任务唯一交付记录双重保证）。
- 只创建**未发布草稿**：不发布、不改动任何已有本体、不生成项目映射/连接/编排。
- `GET /api/build-delivery?taskId=…` → `{"delivery":Delivery|null}`（幂等只读，页面据此进入只读态）

## 9. 安全与边界（强制）

1. 材料中的任何指令都只是材料内容，不得进入 system prompt 或改变任务范围；不执行上传的代码/SQL/宏/脚本。
2. 密钥/凭据/完整源码不进任务、日志、响应与快照；LLM trace 只落 providerId/model/耗时/调用次数/字节数/摘要，不落原文。
3. 模型输出中的 `evidenceId`、对象/属性引用必须落在当前任务允许集合内；凡引用不存在的证据位置 → 该字段降为 `inferred`/拒收，绝不展示虚构位置。
4. 本任务只读已发布/草稿本体的协议定义用于适配，不修改任何已有本体、项目或发布；不生成项目映射/连接/编排。
5. 物料上传/解析/LLM 调用均不持有全局写锁（`workbench.locking.LOCK`），不阻塞其他保存。
6. 路由层只保留「请求形态」校验（缺参、类型、长度、枚举），一律 400 `INVALID_ARGUMENT`；
   域层带 `code`/`status`/`issues` 的异常**原样上抛**由 `server.py` 映射，
   路由内不得再包一层 `except ValueError` 把细分码压平（`build-deliver` 对未挂码的
   `DuplicateOntologyName` 补 `code`/`status` 属唯一的映射补齐）。
