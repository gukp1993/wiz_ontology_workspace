# 08 · 从物料自动构建本体接口（v1 冻结，2026-09-20）

需求：[需求说明](../需求/20260920_从物料自动构建本体/需求说明.md) · [交互原型](../需求/20260920_从物料自动构建本体/交互原型_v1.html) · [开发计划](../需求/20260920_从物料自动构建本体/开发计划.md)。

本分册是「从物料生成新本体」任务族的唯一契约。所有端点走统一鉴权门（06 分册），
未登录 401；数据按 `owner_user_id` 完全隔离，跨账号一律按 404/空处理。
所有写操作携带当前 `revision`（任务级或候选级不透明 token），冲突 409 + `currentRevision`。
新增路由全部登记 `workbench/server.py` 的 `GET_ROUTES`/`POST_ROUTES` 白名单。

通用错误码沿用既有约定：400 `INVALID_ARGUMENT`、401 `UNAUTHENTICATED`、
404 `NOT_FOUND`、409 `REVISION_CONFLICT`/`DUPLICATE_NAME`、413 `PAYLOAD_TOO_LARGE`、
422 `INVALID_STATE`/`DEPENDENCY_BLOCKED`（带 `issues` 数组）、503 `STORAGE_UNAVAILABLE`。
禁止 200 + 空数据伪装失败。请求体沿用 2 MB 全局上限；文件内容只经分片上传进入，
不存在“按服务端任意路径读取”的接口。

## 1. 数据模型

### 1.1 BuildTask
`id`(bk-uuid) · `name` · `status`(draft/materials/scope/generating/review/delivered) ·
`stageLabel`(给页面显示的中文当前阶段) · `revision`(r-uuid) · `materials`(数量) ·
`materialRevision`(整数，材料清单变更即 +1) · `scopeRevision`(整数) · `currentBatch`(batch id 或 '') ·
`deliveryOntologyId` · `createdAt`/`updatedAt`。
材料/范围变化会推进 `materialRevision`/`scopeRevision` 并使旧批次结果标记 `stale`（旧结果只读）。

### 1.2 Material
`id`(bm-uuid) · `taskId` · `relPath`（浏览器相对路径，展示用；服务端校验无 `..`、绝对路径、
符号链接语义）· `kind`(code/ddl/docx/pdf/xlsx/md/zip/other，识别后填入) · `size` · `contentHash`(sha256) ·
`uploadState`(open/complete/aborted) · `parseState`(pending/running/success/partial/failed/excluded) ·
`coverage`(解析覆盖摘要：modules[]、notes[]、failedSegments[]、factCount) · `sourceGroup`(同源组=内容哈希前缀，
重复副本不算独立佐证) · `excluded`(bool) · `error` · `revision`。

### 1.3 Fact（解析事实，任务侧数据，不进本体协议）
`id`(bf-uuid) · `taskId` · `materialId` · `locator` · `snippet`（原文片段，≤500 字）· `kind` · `data`(结构化) · `quality`(high/medium/low)。
`locator` 按材料类型：`{kind:'code',file,line,symbol}` · `{kind:'ddl',file,line,table,column}` ·
`{kind:'docx',file,section,block}` · `{kind:'pdf',file,page}` · `{kind:'xlsx',file,sheet,cell}` ·
`{kind:'md',file,section,line}`。定位器必须来自真实解析，模型不得发明。

### 1.4 Scope / Message
Message：`id` · `taskId` · `role`(user/assistant) · `content` · `patch`(助手给出的范围补丁，可空) ·
`createdAt`。Scope：`goal` · `include` · `exclude` · `relations`（必要关联与深度）·
`coverage`（材料覆盖与冲突说明）· `openQuestions[]`（`{text, blocking}`）· `confirmed`(bool) ·
`revision`(整数) · `confirmedAt` · `providerFingerprint`(providerId/model，不含密钥)。

### 1.5 Run / Batch
Run：`id`(br-uuid) · `taskId` · `kind`(scan/dialog/generate) · `state`(queued/running/succeeded/failed/cancelled/interrupted) ·
`stage`(scan: retrieve/align → generate: retrieve/align/abstract/verify/adapt) · `stageLabel` ·
`progress`(`{done,total}`) · `baseline`(`{materialRevision,materialHashes,scopeRevision,providerFingerprint,promptVersion,parserVersion}`) ·
`attempt` · `error`(可读文案 + `retryable`) · `usage`(`{calls,promptBytes,completionBytes,durationMs}`) ·
`batchId` · `createdAt`/`updatedAt`。Batch：`id`(bb-uuid) · `taskId` · `runId` · `baseline` · `stale`(bool) · `createdAt`。

### 1.6 Candidate（候选定义）
`id`(bc-uuid，服务端稳定 ID) · `taskId` · `batchId` · `type`(object/property/link/rule/action) ·
`key`(模型临时键，仅批内) · `name` · `definition` · `fields`(按类型：property→`dataType`(现有协议枚举：
text/number/boolean/dateTime/array/struct/timeSeries，timeSeries 带 `valueType`) · link→`sourceRef`/`targetRef`(候选 key 或
已合并候选 ID)/`cardinality`(`{source:'one'|'many',target:'one'|'many'}`，无依据不下默认) ·
rule→`content`(选填) · action→`effect`(选填)) · `ownerKey`(property 的所属对象 key) ·
`evidence`(`{字段名: [factId,...], '_record': [factId]}`，可空字段不硬造) ·
`evidenceStatus`(supported/inferred/conflict/insufficient) · `conflicts[]`(`{field,sides:[{factId,value}],note}`) ·
`decision`(include/defer/exclude) · `reviewed`(bool) · `reason` · `issues[]`(`{code,message,field}`) ·
`origin`(`{batch,key,mergedFrom:[candidateId,...],mergedInto:candidateId|null}`) · `revision`(r-uuid)。
默认决定：有依据且结构完整 → include；弱证据/冲突/结构不完整 → defer。
命名与字段一律不猜单位、不造参数、不默认数量关系。

### 1.7 ReviewOp（可撤销操作）
`id`(bo-uuid) · `taskId` · `kind`(merge/edit) · `payload`（撤销所需前后状态） · `reverted`(bool) · `createdAt`。

### 1.8 Delivery
`id` · `taskId`(唯一) · `requestId` · `payloadDigest` · `ontologyId` · `createdAt`。
同任务只允许一次成功交付；同 `requestId` 网络重试返回原结果；同 `requestId` 不同 payload → 409。

## 2. 能力与限额

### 2.1 能力查询
`GET /api/build-capabilities` → 200
```json
{"limits": {"chunkBytes": 524288, "fileBytes": 52428800, "taskBytes": 209715200,
            "zipExpandedBytes": 314572800, "zipMaxEntries": 10000, "parseTimeoutSeconds": 120},
 "ocr": {"available": false, "reason": "未配置 OCR 服务；扫描页将逐页报告失败"},
 "provider": {"id": "llm-…", "name": "…", "model": "…"} | null,
 "parserVersion": "v1", "promptVersion": "v1"}
```
限额为工程保守默认（合成样本校准后登记），页面必须原样展示，不得承诺更大容量。
`provider` 为 null 时范围对话/生成不可启动（返回 422 `INVALID_STATE`，页面引导去 LLM 配置）。

## 3. 任务

- `GET /api/build-tasks?limit=20&offset=0` → `{"items":[Task],"total":n}`
- `POST /api/build-task-create` `{"name":"…"}` → `{"task":Task}`（名称非空；空名自动“未命名任务-日期”）
- `GET /api/build-task?taskId=…` → `{"task":Task,"materials":[…],"scope":Scope,"run":Run|null,"delivery":Delivery|null,"capabilities":{…}}`
- `POST /api/build-task-rename` `{"taskId","name","revision"}` → `{"task":Task}`（409 冲突带 `currentRevision`）
- `POST /api/build-task-delete` `{"taskId","confirmName"}` → `{"ok":true}`（confirmName 必须等于任务名；已交付任务删除后原始证据不可用，响应 `{"ok":true,"note":"…"}`；本体草稿不随任务删除）

## 4. 分片上传与物料

- `POST /api/build-upload-init` `{"taskId","relPath","size"}` → `{"uploadId","chunkBytes","maxChunks","received":0}`
  - 校验：单文件 ≤ fileBytes；任务累计（已登记+上传中）≤ taskBytes；`relPath` 安全（拒绝绝对路径、
    `..`、空名、>512 字符、控制字符）。
- `POST /api/build-upload-chunk` `{"uploadId","index","hash","dataBase64"}` → `{"received":n,"nextIndex":n}`
  - 同 index 同 hash 幂等返回既有结果；同 index 不同 hash → 409 `UPLOAD_CONFLICT`；
    index 越界/跳号 → 400。分片解码后 ≤ chunkBytes；hash 为分片 sha256，校验失败 422 `HASH_MISMATCH`。
  - 过期上传（30 分钟无写入或显式 abort）不可续传，必须 init 重建；临时文件有界清理。
- `POST /api/build-upload-complete` `{"uploadId","finalHash"}` → `{"material":Material}`
  - 校验累计大小与最终 hash；ZIP 按 §4.1 展开为多份材料（虚拟 relPath 带 `zip内路径`）。
    失败：422 `HASH_MISMATCH` / `ZIP_INVALID` / `LIMIT_EXCEEDED`，临时内容不登记为可用材料。
- `POST /api/build-upload-abort` `{"uploadId"}` → `{"ok":true}`
- `GET /api/build-materials?taskId=…` → `{"items":[Material],"revision":materialRevision}`
- `POST /api/build-material-exclude` `{"taskId","materialId","excluded","revision"}` → `{"material":Material,"task":Task}`
  - 排除/恢复会推进 `materialRevision`，使扫描/范围/结果基线失效（页面提示旧结果过期）。
- `POST /api/build-material-retry` `{"taskId","materialId"}` → `{"runId"}`
- `POST /api/build-scan` `{"taskId"}` → `{"runId"}`
  - 后台解析全部未排除材料；单材料失败不阻塞其余；无可用材料 → 422 `INVALID_STATE`。
  - 已成功且内容哈希未变的材料复用解析结果（不重复解析）。

## 5. 运行

- `GET /api/build-run?taskId=…&runId=…`（runId 省略取最近一次）→ `{"run":Run,"taskStatus":…}`
  - 轮询轻量：不返回 facts/candidates 详情。`state=interrupted` 表示服务重启丢失执行（不得显示“仍在运行”）。
- `POST /api/build-run-cancel` `{"taskId","runId"}` → `{"run":Run}`（取消不保证立即终止已发出的模型请求，
  但晚结果禁止写入当前批次；页面如实显示“正在取消/已取消”）
- `POST /api/build-run-resume` `{"taskId","runId"}` → `{"runId"}`（仅 failed/cancelled/interrupted；
  复用已匹配 checkpoint；服务重启只标记中断，不自动重发）

## 6. 范围对话

- `GET /api/build-messages?taskId=…&after=0` → `{"messages":[Message],"scope":Scope,"revision":scopeRevision,"stale":bool}`
- `POST /api/build-message` `{"taskId","content","revision"}` → `{"messageId","assistantPending":true}`
  - 用户消息立即落库；助手回复异步生成（dialog run），轮询 `build-messages` 增量获取。
  - 外发前（首个 dialog/generate run）必须已通过 `providerId` 选择；材料发送范围=已纳入材料摘要与选中片段。
  - 模型不可用/超时/非法输出：保留用户消息与已有摘要，消息流出现 `assistantError`，可重试；绝不伪造助手回答。
  - 助手 patch 只是建议：不得覆盖人工已保存的范围字段（服务端按 scope.revision 比对，人工基线更新后 patch 降级为提示）。
- `POST /api/build-scope-save` `{"taskId","scope":{goal,include,exclude,relations,coverage,openQuestions},"revision"}` →
  `{"scope":Scope}`（409 冲突带 `currentRevision`；人工修改推进 revision）
- `POST /api/build-scope-confirm` `{"taskId","revision","providerId"}` → `{"runId","batchId"}`
  - 前置：范围非空且无阻断问题（同一模块同时纳入与排除而未填 `coverage` 说明 → 422 `INVALID_STATE`，带 `issues`）；
    至少一份成功解析材料；provider 存在。
  - 确认时冻结输入基线（材料清单/hash、范围修订、解析器/提示词版本、provider 指纹，不含密钥），
    启动 generate run 并创建新 batch。再次确认=新批次；旧批次保留只读。

## 7. 候选评审

- `GET /api/build-candidates?taskId=…&batch=…&type=&decision=&evidenceStatus=&query=&offset=0&limit=100`
  → `{"items":[Candidate],"total":n,"counts":{"byType":{…},"byDecision":{…},"byStatus":{…}},"batch":{…},"stale":bool}`
- `GET /api/build-candidate?candidateId=…` → `{"candidate":Candidate,"evidence":[{"field":…,"items":[{factId,locator,snippet,quality,materialRelPath}]}]}`
- `POST /api/build-candidate-update` `{"candidateId","fields":{name,definition,dataType?,content?,effect?,cardinality?},"revision"}`
  → `{"candidate":Candidate}`（校验字段合法；推进候选 revision；`fields` 只允许契约内字段）
- `POST /api/build-candidate-decide` `{"candidateId","decision","reason","revision"}` → `{"candidate":Candidate}`
  - 弱证据/冲突项转 include 必须带非空 `reason`（422 `INVALID_STATE`）；`reviewed` 置 true。
- `POST /api/build-candidates-merge` `{"taskId","primaryId","mergeIds":[…],"confirmed":false,"revision"}` →
  `confirmed=false` 返回 `{"preview":{"fields":[{"name","primaryValue","mergeValues":[…],"diff":bool}],"evidenceCount":n,"warnings":[…]}}`；
  `confirmed=true` 执行合并 → `{"candidate":Candidate,"opId"}`。仅同类型可合并；不同 `dataType` 或链接角色不兼容 → 422。
  被合并候选 `origin.mergedInto` 指向保留项且从列表默认过滤；证据/来源全部保留。
- `POST /api/build-review-undo` `{"taskId","opId","revision"}` → `{"ok":true,"candidate":Candidate}`
  （撤销合并恢复字段与关联；若保留项已有后续人工编辑 → 409 `REVISION_CONFLICT` 提示影响，不静默丢弃）
- `POST /api/build-regenerate` `{"taskId","revision"}` → `{"runId","batchId"}`
  - 以当前材料/范围基线重跑（完整重跑，不做精细增量）；旧批次保留。人工决定与编辑保留，
    新批次按候选 key+证据来源对齐，产出 `diff`；**已排除候选不自动复活**（若新证据再次提出，标记 `revived` 并默认 defer）。
- `GET /api/build-diff?taskId=…&batch=…` → `{"against":batchId|null,"buckets":{"added":[…ids],"changed":[{"id","fieldsChanged":[…],"manualConflict":bool}],"removed":[…ids],"kept":[…ids],"excludedProtected":[…ids]},"items":[Candidate]}`
- `POST /api/build-diff-resolve` `{"taskId","candidateId","choice":"keepManual"|"acceptNew","revision"}` → `{"candidate":Candidate}`

## 8. 交付（原子创建新本体）

- `POST /api/build-deliver-precheck` `{"taskId"}` → `{"ok":bool,"counts":{"object":n,…},"issues":[{"code","message","candidateId"?}],"excluded":n,"deferred":n,"coverage":{…},"checkToken"}`
  - 服务端做确定性校验：名称/定义非空、类型枚举、链接两端可解析、属性所属对象存在且未被排除、
    规则/动作为选填、共享属性已确认；未通过 → `ok=false` 且 `issues` 可定位（422 只在提交时用）。
  - `checkToken` 绑定当前选定集合与批次基线；用户后续修改使其失效。
- `POST /api/build-deliver` `{"taskId","name","checkToken","requestId"}` → `{"ontologyId","taskId","deliveredAt"}`
  - 同事务：确认 owner 与未交付 → 幂等回执检查 → 重验基线/选择/结构 → 名称查重（409 `DUPLICATE_NAME`）→
    分配本体与定义 ID（含 definitionOrder）→ 写完整新草稿 → 记录候选 ID 映射与任务来源 → 写回执与任务已交付。
    失败全部回滚（不得先建空本体）。
  - 同 `requestId` 重试 → 返回原结果；同 `requestId` 不同 payload → 409；不同 requestId 对已交付任务 → 409（只交付一次）。
    超时/并发重试不得产生第二个本体。
- `GET /api/build-delivery?taskId=…` → `{"delivery":Delivery|null}`

## 9. 安全与边界（强制）

1. 材料中的任何指令都只是材料内容，不得进入 system prompt 或改变任务范围；不执行上传的代码/SQL/宏/脚本。
2. 密钥/凭据/完整源码不进任务、日志、响应与快照；LLM trace 只落 providerId/model/耗时/调用次数/字节数/摘要，不落原文。
3. 模型输出中的 `evidenceId`、对象/属性引用必须落在当前任务允许集合内；凡引用不存在的证据位置 → 该字段降为 `inferred`/拒收，绝不展示虚构位置。
4. 本任务只读已发布/草稿本体的协议定义用于适配，不修改任何已有本体、项目或发布；不生成项目映射/连接/编排。
5. 物料上传/解析/LLM 调用均不持有全局写锁（`workbench.locking.LOCK`），不阻塞其他保存。
