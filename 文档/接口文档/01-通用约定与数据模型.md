# 01 · 通用约定与数据模型

本文定义接口层共享的数据结构。**分册中的字段说明若与本文冲突，以本文为准**；若实现与本文冲突，按 README §1.5 处理。

---

## 1. 三类核心状态

系统有三条**完全独立**的数据线，各自有独立的草稿、发布与并发令牌，互不携带对方数据：

| 数据线 | 状态结构 | 保存线 | 发布 |
| --- | --- | --- | --- |
| 本体区 | `OntologyState` | `/api/save` | `/api/publish`（语义化版本 + 变更分类） |
| 项目区 | `ProjectState` | `/api/project-save` | `/api/project-publish`（`v1`、`v2`… 递增） |
| 编排区 | `FlowState` | `/api/flow-save` | 一期无发布（仅草稿 + 软删除） |

## 2. OntologyState（本体状态）

### 2.1 传输形态（重要）

接口边界上 `state.ontology` 是 **JSON schema 形态**（自有格式，非 Foundry 导入格式），后端 `model_format.decode_state` 解码为内部 JSON-LD（`@graph`）处理，`encode_state` 再编码回 schema 形态返回。

- 前端协议层：`frontend/src/ontology/modelFormat.ts`（与 `workbench/model_format.py` **镜像**，改一处必须改两处）。
- schema 版本：`ontology.schemaVersion = 1`；不为 1 直接拒绝。

### 2.2 结构

```jsonc
{
  "workspaceId": "storage",
  "ontology": {
    "schemaVersion": 1,
    "namespaces": { "mg": "https://example.com/microgrid/" },
    "objectTypes": [],        // owl:Class
    "linkTypes": [],          // owl:ObjectProperty
    "properties": [],         // owl:DatatypeProperty
    "sharedProperties": [],   // mg:SharedProperty
    "valueTypes": [],         // mg:ValueType
    "metadata": [],
    "definitionOrder": ["<稳定 id>", "..."],   // 必须与各组记录一致，改 schema JSON 时同步维护
    "extensions": {}
  },
  "workflow": {
    "objective": { "name": "" },
    "functions": [],
    "actions": [],
    "interfaces": [],
    "release": { "note": "", "reviewer": "" }
  },
  "metrics": { "metrics": [] },
  "rules": { "rules": [] },
  "layout": { "positions": {}, "zoom": 1, "pan": { "x": 0, "y": 0 } },
  "sourceGraph": {},     // 导入图谱（可选）
  "learning": {}         // 可选
}
```

### 2.3 关键约束

- 所有引用（契约签名、属性来源、输入绑定）使用**稳定 id**，改显示名不断链。
- 字段映射表（`id/displayName/description/aliases/apiName/...` ↔ `@id/rdfs:label/...`）见 `model_format.py` 的 `FIELDS`/`REFS`/`JSON_FIELDS`。
- 直接改 schema 形态 JSON 时必须同步维护 `definitionOrder`，否则保存报错。
- 空 `metrics` / `rules` **不写入**发布快照。

## 3. ProjectState（项目状态）

```jsonc
{
  "projectId": "a1b2c3d4e5f6",
  "name": "创智储能项目",
  "ontologyId": "storage",           // 引用的本体
  "ontologyVersion": "1.2.0",        // 引用的已发布版本
  "connections": { "connections": [ /* ConnectionConfig */ ] },
  "bindings": {
    "notice": "",
    "object_bindings": [],           // 对象映射
    "observation_binding": {},
    "source_candidates": [],
    "actionBindings": [],
    "mappingDescriptions": {},       // 四类项目说明（2026-09-19 新增，见 §3.4；缺省=无说明）
    "catalogs": {}                   // 【服务端派生】见下方红框
  },
  "implementations": [],             // 计算实现（含 queryRule v1/v2、calculationFunction）
  "parameters": {},
  "projectMeta": {}
}
```

### 3.1 属性取值来源（`object_bindings[].properties[apiName]`）

每个已映射属性挂一个来源对象，以 `kind` 区分取值方式：

```jsonc
// kind='flow'  函数编排取值（2026-09-18 新增；前端卡片「函数编排」）
{
  "kind": "flow",
  "flow": "d7ac770c7149",        // 编排 id，引用编排工作区，必填
  "output": "out_power",          // 编排级 outputs[].id，必填
  "inputs": {                     // 键为编排级 inputs[].id，值见下；无输入的编排可为空对象
    "in_code":   { "from": "property",   "property": "deviceCode" },
    "in_factor": { "from": "constant",   "value": 1.5 },
    "in_key":    { "from": "instanceId" }   // 仅可绑文本输入
  }
}
```

`inputs[*].from` 取值：

| from | 附加字段 | 约束 |
| --- | --- | --- |
| `property` | `property`：当前对象内的属性 apiName | 属性必须存在、已配置来源、非时间序列，且 `rdfs:range` 与编排输入类型相容 |
| `constant` | `value`：字面量 | 按输入类型校验；**`0` / `false` / 空字符串均为有效值**，不得按「假值缺失」处理 |
| `instanceId` | — | 仅文本输入可用；要求对象已配置实例身份（`primary_key` 或 registered 身份） |

编排输入/输出类型与本体属性 `xsd:range` 相容表（前后端镜像，见 `project_validation._FLOW_RANGE_COMPAT` 与 `PropertySources.vue` 的 `FLOW_RANGE_COMPAT`）：

| 编排类型 | 允许的 `rdfs:range`（去 `xsd:` 前缀） |
| --- | --- |
| `number` | `double`、`decimal`、`integer` |
| `text` | `string` |
| `boolean` | `boolean` |
| `datetime` | `dateTime` |
| `object` / `list` | 不可绑定标量属性（校验阻断） |

约束与行为：

- **只读引用**：项目侧只存 `flowId` + 输出 + 输入绑定，不复制编排定义；编排改名/改签名不影响存储，但校验会提示重新选择。
- **编排删除**：按「不存在」处理，校验报阻断错误（`引用的函数编排不存在或已删除`）。
- **单值语义**：编排输出为单值，不能绑定 `mg:valueShape = timeSeries` 的属性。
- **循环依赖**：属性 A 的编排输入引用属性 B、B 又（直接或间接）引用 A，保存校验阻断（`属性来源存在循环依赖`）。
- **校验时机**：保存/发布校验（`POST /api/project-validate`、`POST /api/project-publish`）在服务端执行；前端 `PropertySources.vue` 做同构的前端预检（类型相容、绑定齐全），两者规则必须保持一致。
- **取值预览**：本期未打通编排执行，预览不运行编排；`kind='flow'` 的属性在预览中的行为见 `03-项目区接口.md`。

> 历史 `kind='computed'`（直接 SQL / 引用规则 / 计算函数）**保留只读兼容**：已存配置继续校验与展示，前端不再提供新建入口（新建统一走 `flow`）。

### 3.4 `bindings.mappingDescriptions` —— 项目说明（2026-09-19 新增）

对象/属性/链接/动作四类「项目说明」：当前项目对本体元素的实现描述（自然语言原文），与具体映射配置并存、一起保存/发布，不替换也不包装任何既有来源结构。

```jsonc
{
  "schemaVersion": 1,
  "objects":   { "<对象稳定ID>": "对象来源说明" },
  "properties":{ "<对象稳定ID>": { "<对象属性稳定ID>": "该对象该属性的取值说明" } },
  "links":     { "<链接类型稳定ID>": "两端共用的关联说明" },
  "actions":   { "<对象稳定ID>": { "<动作稳定ID>": "该动作在该对象上的实现说明" } }
}
```

**键规则（一律稳定 ID，禁止显示名称/字段名做键）**

- 对象键 = 本体对象类型稳定 `@id`（统一含 `mg:` 前缀，与 `object_bindings[].object_type` 同域）。
- 属性键 = 二级结构：外层对象稳定 ID，内层为该对象**实际属性节点**的稳定 ID（共享引用用引用节点自身 ID，不是共享库根定义 ID）——同一共享属性挂到两个对象时说明互不影响。
- 链接键 = 本体链接类型稳定 ID；同一链接两端共用一个键，反向入口不复制第二条。
- 动作键 = 二级结构：对象稳定 ID → 动作稳定 ID；同一动作挂到多个对象时说明互不覆盖。

**文本规则**：单项上限 20,000 Unicode 码点（前后端一致）；纯文本原样存储与返回，不执行 Markdown/HTML，展示由调用方转义；换行统一 LF；纯空白按清除处理。

**缺省 / 清空 / 旧客户端（写路径统一语义，CAS 与写锁边界内完成）**

- 旧数据没有该键：视为无说明，不做迁移、不生成空文本。
- 请求 `bindings` **省略** `mappingDescriptions` 键：沿用当前已存说明（不删除）。
- 请求携带完整块：按完整块提交；显式清空某项 = 删除对应键，其余保留。
- `schemaVersion` 高于服务端支持版本：只读保留；对它的写入明确拒绝（不自动降级）。
- `null` / 非法结构：保存拒绝（400），不当作空内容清理。

**失效引用**：说明键指向的元素在引用本体版本中已不存在时，草稿原样保留原文；`project-validate` / `project-publish` 列出并阻断发布，直到显式修复或清除。

**消费者边界**：`project-property-preview` 等尚不支持说明语义的执行入口，遇到目标或依赖元素存在非空说明时，在读取数据源之前返回明确"不支持"（见 03 分册）；不能忽略说明只执行旧配置。

### 3.2 `bindings.catalogs` —— 必须由请求体剥除

`catalogs` 是服务端表结构目录缓存（可达数 MB），**不是项目数据**。前端出站请求必须由 `frontend/src/project/api.ts` 的 `stripCatalogs` 剥除（全前端唯一实现点）；后端读写时以服务端缓存为准覆盖。

> 后果：若把 `catalogs` 发回后端，会污染草稿内容与 revision 哈希，导致保存/校验异常。

### 3.3 ConnectionConfig（数据连接）

```jsonc
{
  "id": "conn-xxxx", "name": "生产库", "engine": "mysql",   // mysql | redis
  "host": "127.0.0.1", "port": 3306, "username": "root",
  "database": "db_name",           // mysql 必填
  "dbIndex": 0,                    // redis 专用
  "tls": "none",                   // none | encrypted | verify
  "caPath": ""                     // tls=verify 时有效
}
```

`password` **永不在配置中出现**：单独经 `/api/connection-secret` 写入受保护 vault，永不回传。

## 4. FlowState（编排状态）

```jsonc
{
  "schemaVersion": 1,
  "flowId": "x1y2z3",
  "name": "编排名称",
  "description": "",
  "status": "active",              // active | deleted（软删除）
  "inputs": [],                    // 入参声明
  "outputs": [],                   // 出参声明
  "connections": [],               // 节点连线
  "nodes": [],                     // 处理节点（python | sql | redis | http | calc）
  "layout": { "positions": {}, "zoom": 1, "pan": { "x": 0, "y": 0 } }
}
```

- 保留节点 id：`flow-input`、`flow-output`（边界节点，不得出现在 `nodes`）。
- 节点类型：`python`、`sql`、`redis`、`http`、`calc`。
- 数据类型：`text`、`number`、`boolean`、`datetime`、`object`、`list`。
- 复制编排时服务端重生成**全部稳定 id** 并重映射引用，原编排字节不动。
- 未知字段整体保留（零丢失）。

## 5. 校验报告结构

### 5.1 项目校验报告（`ValidationReport`）

```jsonc
{
  "errors": ["..."],       // 阻断发布
  "warnings": ["..."],     // 提示
  "items": [               // 结构化定位（页面「去处理」按 kind/id 跳转）
    { "kind": "connection|objectBinding|propertySource|implementation|linkMapping|reference",
      "id": "<稳定 id>", "name": "<显示名>", "status": "unconfigured|...", "issues": ["..."] }
  ]
}
```

### 5.2 编排配置检查报告（`CheckReport`）

```jsonc
{
  "errors": ["..."], "warnings": ["..."],
  "items": [ { "kind": "node|flow", "id": "<id>", "name": "<名称>", "level": "error|warning", "issues": ["..."] } ],
  "status": "passed|pending",
  "diagnostics": [         // 精确定位（不存草稿）
    { "code": "CONFIG_ISSUE", "level": "error", "message": "...", "kind": "node", "id": "...",
      "section": "inputs|implementation|outputs|advanced", "field": "...", "parameterId": "..." }
  ]
}
```

### 5.3 本体变更分类（`Classification`）

```jsonc
{
  "type": "breaking|compatible|pending|initial",
  "reasons": [ { "severity": "breaking|compatible|pending", "area": "objectTypes|...", "id": "<id>", "text": "..." } ]
}
```

### 5.4 升级影响报告（`UpgradeReport`）

```jsonc
{
  "classification": "breaking|compatible|pending",
  "reasons": [ /* 同 5.3 */ ],
  "impacts": [ { "area": "objectBinding|propertyMapping|linkMapping|implementation|propertySource|ontology",
                 "ref": "<引用>", "severity": "breaking|compatible|pending", "text": "..." } ],
  "blocking": [ /* impacts 中 severity=breaking 且 area≠ontology 的子集 */ ]
}
```

## 6. 共享枚举

| 枚举 | 取值 |
| --- | --- |
| 连接引擎 | `mysql`、`redis` |
| TLS 模式 | `none`、`encrypted`、`verify` |
| 探测结果分类 | `ok`、`driver`、`dns`、`tls`、`refused`、`timeout`、`auth`、`database`、`permission`、`unreachable`、`config`、`unknown` |
| 属性来源 kind | `field`、`database`、`redis`、`computed`、`flow`、`registered`、`aggregate`、`unknown` |
| 计算函数类型 | `number`、`string`、`boolean` |
| 编排节点类型 | `python`、`sql`、`redis`、`http`、`calc` |
| 变更类型 | `initial`、`compatible`、`breaking`、`pending` |

## 7. 前端调用约定（强制）

1. 一切请求走 `frontend/src/app/http.ts`：
   - `getJson`（GET，默认 15 s 有界读取，可注入 `__WIZ_READ_TIMEOUT_MS`）
   - `postJson`（POST，写操作不套读取超时）
   - `postBlob`（导出 ZIP）
2. 非 2xx 一律抛 `SaveRequestError`，携带 `status` / `currentRevision` / `data` / `failure`（`timeout|aborted|network|http`）。
3. 409 处理：取 `currentRevision` 换基线后重试（由 `app/saveCoordinator.ts` 统一实现，页面不得自写重试）。
4. 结果不明的失败（`failure !== 'http'`）不得断言「未写入」，UI 必须提示刷新核对。
5. 页面禁止自写 `fetch` / 自写错误解析（架构红线，见 `AGENTS.md`）。
