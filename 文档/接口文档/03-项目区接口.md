# 03 · 项目区接口

项目区共 17 个接口：项目资产与草稿、发布、升级预检、数据连接探测、凭据、目录缓存、公式试算、取值预览。
项目区与本体区是**两条独立的数据线**：`/api/save|publish` 只管本体，`/api/project-*` 只管项目。

> **出站请求强制**：所有把项目状态发给后端的请求必须先 `stripCatalogs`（`frontend/src/project/api.ts`），剥除 `bindings.catalogs`。

## 1. 项目资产与状态

### 1.1 查询项目清单

```http
GET /api/projects
GET /api/projects?ontology={ontologyId}
```

**筛选契约**（2026-09-18 批次 B 显式化，废除「带任意 query 串即过滤」的隐式语义）：

| 请求 | 行为 |
| --- | --- |
| 不带 `ontology` 参数 | 返回**全部**项目（其他任何参数都不改变范围） |
| `?ontology=<有效本体ID>` | 仅返回该本体的项目 |
| `?ontology=<不存在的ID>` | `404 NOT_FOUND` |
| `?ontology=`（空值） | `400 INVALID_ARGUMENT`（查询全部时应省略该参数） |

**响应** `200`

```json
{ "items": [ { "id": "a1b2c3d4e5f6", "name": "创智项目", "ontologyId": "storage",
               "ontologyVersion": "1.2.0", "hasDraft": true, "latestVersion": "1.3.0" } ] }
```

> `latestVersion` 为该本体最新已发布版本（读取失败时为空串）。
> 前端约定：无筛选时**省略** `ontology` 参数（`project/api.ts` 的 `listProjects` 已如此实现），不要传空字符串。

## 2. 项目写操作（4 个端点共用一个入口）

服务端 `project_routes.post_project_write` 按路径分派，四个端点共享「规范化状态 → 覆盖服务端目录 → 校验 revision」前置。

### 2.1 保存项目草稿

```http
POST /api/project-save
```

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `state` | ProjectState | 是 | 完整项目状态（含 `projectId`） |
| `revision` | string | 是 | 并发基线 |

**响应** `200`

```json
{ "revision": "r-<uuid>" }
```

| 状态码 | 场景 |
| --- | --- |
| 400 | 项目标识非法 / 状态结构非法 |
| 409 | revision 过期（带 `currentRevision`） |
| 500 | 草稿保存失败（存储层错误，绝不返回成功） |

**说明**：保存**不要求**绑定本体版本，也不做配置校验（配置校验是独立接口）。

**保存边界保护（2026-09-20 v2 冻结）** —— 普通保存允许未完成草稿，但以下两类「删除他人配置 / 切换引用」动作在保存边界受保护，命中即**零写入**拒绝：

| 场景 | 状态码 | code | 说明 |
| --- | --- | --- | --- |
| 本次保存删除了连接，且提交的 state 中仍有对该连接的引用 | 422 | `REFERENCE_IN_USE` | 响应附 `references: [{kind, id, name}]` 列出引用位置（对象来源/身份/属性来源含 inline SQL 与 redis/实现）。连接与其全部引用在同一份 state 中一并移除 = 显式删除，放行 |
| 本次保存**变更**了引用的本体版本（ontologyId/ontologyVersion 与已存不同）且目标版本不存在或未发布 | 404 | `NOT_FOUND` | 目标必须是已发布版本；引用未变（含历史遗留失效引用）沿用原行为保存 |

> 保存边界不套用完整发布校验（草稿允许未完成）；失效中间态（换表后字段不存在等）允许保存，由 `/api/project-validate` 报错并在发布时阻断。

**`bindings.mappingDescriptions`（2026-09-19 新增，模型见 01 §3.4）**

- 保存仅做结构与长度检查：非法结构 / 非法 `schemaVersion` 写入 / 单项超 20,000 码点 → `400`，不修改已存草稿。
- 请求 `bindings` **省略** `mappingDescriptions` 键：在同一 CAS/写锁边界内沿用当前已存说明；携带完整块则按完整块提交（显式清空某项 = 删除对应键）。
- 只填说明不创建任何绑定/实现；说明不算可执行配置。

### 2.2 项目配置校验

```http
POST /api/project-validate
```

请求体：`{ state, revision }`（`revision` 仅透传，本接口不校验版本）

**响应** `200`

```json
{ "errors": [], "warnings": [],
  "items": [ { "kind": "objectBinding", "id": "mg:xxx", "name": "...", "status": "...", "issues": ["..."] } ],
  "baseline": { "projectId": "...", "revision": "r-<uuid>", "ontologyId": "storage", "ontologyVersion": "1.2.0",
                "flows": [ { "id": "<flowId>", "revision": "r-<uuid>" } ],
                "catalogs": [ { "connectionId": "...", "fingerprint": "<sha256>", "generation": 3 } ] } }
```

未绑定本体版本时返回 `200` + 单条 `reference` item（视为「未配置」而非错误）。

**`baseline`（2026-09-20 v2 冻结）**：本次检查实际读取并参与校验的依赖基线——`flows` 仅含状态中被引用的编排及其不符修订（`wb_asset_heads.revision_token` 不透明令牌），`catalogs` 仅含本项目已有目录缓存的连接（`config_fingerprint` + 代际）。客户端随报告保存，用于判断「报告对应哪次检查」；**发布时服务端仍以提交时刻的依赖独立重验，不依赖此回执**。

**依赖读取失败语义（2026-09-20 v2 冻结）**：
- 编排读取失败（非「不存在」）→ 报告出现 error（文案含指明读取失败与编排 id），发布被阻断；不得按「不存在」处理，也不得跳过检查后放行。
- 目录缓存存在但单条损坏 → 报告出现对应连接的 error「目录缓存读取失败」，发布阻断；连接配置与目录缓存读取失败不可表现为「无目录/零问题」。
- 存储层不可用（`StorageUnavailable`）→ `503` `STORAGE_UNAVAILABLE`（不得降级为 200 + 空结果）。

> 校验规则的权威实现在 `workbench/project_validation.py`；**改规则必须同步更新金样**（`tests/make_validation_golden.py` + `tests/test_validation_split.py`）。
>
> **说明检查（2026-09-19 新增）**：追加 `mappingDescriptions` 结构与失效引用问题——说明键指向的本体元素（对象/属性/链接/动作）在引用版本中不存在 → errors（阻断发布，定位到说明项）；只有说明、未形成可执行配置 → warnings 提示「说明尚未形成可执行配置」。已启用映射缺少表/主键/接口参数的原有阻断不放松。

### 2.3 发布项目

```http
POST /api/project-publish
```

请求体：`{ state, revision, requestId? }`

**响应** `200`

```json
{ "revision": "r-<uuid>", "version": "v2" }
```

幂等回放时追加 `"idempotentReplay": true`。

| 状态码 | 场景 |
| --- | --- |
| 409 | revision 过期（带 `currentRevision`）；`requestId` 复用且内容不同 |
| 422 | 未绑定本体版本；或配置校验未通过（`{"error": "...", "report": <ValidationReport>}`） |

**约束**：持全局写锁；草稿快照 + CAS head + 发布快照 + 发布记录 + 版本引用**单事务**。

**`requestId` 幂等（2026-09-20 v2 冻结，复用 `wb_requests` 回执设施）**：

- 语义与 `/api/publish` 一致：同 `requestId` + 同内容 → 回放既有回执（响应带 `idempotentReplay: true`，不新建版本、不改草稿）；同 `requestId` + 不同内容 → `409 REVISION_CONFLICT`。
- 幂等内容指纹 = **规范化项目状态内容**（`projects.revision` 内容 hash，不含 revision 令牌——成功发布本身会推进 revision，响应丢失后的重试必须仍能回放）；**回执与发布写入处于同一事务**（不存在「已发布未记回执」的崩溃窗口）。
- 回放不要求客户端携带的 `revision` 仍为当前值（首答成功后草稿已推进，重试携带的是新 revision）；只有**内容**变化才触发 409。
- 幂等键归属按账号隔离，跨账号相同 `requestId` 互不可见、不可回放。
- 不带 `requestId` 时行为不变（旧客户端兼容）；保存失败、CAS 冲突不写回执。
- 客户端约定：结果未知（超时/网络中断）的重试复用同 key；**内容变化后必须换新 key**；成功/422 后换新 key。
- 内容等价口径：对象键顺序不影响指纹（服务端按排序序列化）；**数组顺序视为内容差异**（如 `connections[]` 调整顺序会得到 409）——客户端换 key 前不必做数组归一化，但需知悉同一语义不同顺序不会被当作同一请求。

**发布依赖重验（2026-09-20 v2 冻结）**：发布在校验通过后、提交落库前再次核对本次校验实际读取的依赖（编排修订、目录指纹与凭据代际），任何依赖在校验后被改动即拒绝发布（零写入），并返回可重试错误。拒绝不等同于 409 revision 冲突：响应 `409` + `code: REVISION_CONFLICT`（依赖已变场景附 `reason: "DEPENDENCY_CHANGED"`），客户端重新检查后再发布。

### 2.4 本体版本升级预检

```http
POST /api/project-upgrade-check
```

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `state` | ProjectState | 是 | 当前项目状态 |
| `targetVersion` | string | 是 | 目标本体版本 |

**响应** `200`

```json
{ "classification": "breaking", "reasons": [], "impacts": [], "blocking": [] }
```

（结构见 `01` §5.4）

| 状态码 | 场景 |
| --- | --- |
| 422 | 项目尚未绑定本体版本（`{"error": "..."}`） |

**说明**：只读预检，**不自动升级**；前端 `ReferenceNotice` 只做对比展示，升级由用户显式触发。

**比较基线（2026-09-20 v2 冻结）**：请求体 `revision` 为**必填**——项目当前草稿的 revision（`/api/project-state` 返回的不透明 token）。服务端据此把「本次比较基于的项目草稿修订」固定下来：比较期间项目修订被其他页面/客户端改动 → 本次比较结果不再可确认，重新比较；确认升级（`/api/project-save` 变更 `ontologyVersion`）时服务端再次核对草稿 revision 与目标版本存在性，不匹配返回 `409`（带 `currentRevision`），原引用保持不变。`upgrade-check` 未携带 `revision` 时按旧客户端处理（不阻断读取，但结果不可用于确认，前端以本地比较键兜底——服务端不依赖该兜底）。

### 3.3 刷新并持久化目录缓存

```http
POST /api/catalog-refresh
```

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `projectId` | string | 是 | — |
| `connectionId` | string | 是 | 项目内已保存的连接 id |

**响应** `200` —— 同 3.2 的目录结果；迟到结果被丢弃时额外带 `"stale": true`（message 说明未写入缓存，客户端**不得**按成功提示或注入本地目录）。

| 状态码 | 场景 |
| --- | --- |
| 400 | 缺少连接标识 / 项目中不存在该连接 / 连接未配置引擎 |
| 404 | 项目不存在 |

**约束**：从已保存连接 + vault 凭据读取；目录缓存在服务端，**不进草稿与快照**。

**迟到结果保护与落库条件（2026-09-20 v2 冻结）**：

- **技术配置指纹排除显示名称**：仅改连接显示名不使探测结果/目录基线失效；主机、端口、库名/schema、TLS、用户名变化使指纹变化。
- **凭据变化使用安全代际**：连接密码写入递增 `secret_revision`（不导出、不回传密钥本身）；探测期间密码被更换 → 迟到结果丢弃，不落缓存。
- **落库条件更新**：探测完成后的复核与写入之间不留窗口——写库时以「探测前记录的指纹 + 凭据代际 + 目录代际」为条件；条件不满足（期间连接被改/被删/凭据被换/已有更新目录写入）则丢弃本次结果。写入发生在短事务内，探测本身**不持全局写锁**。
- **读取失败语义**：目录缓存读取失败不得返回空目录（见 §2.2 依赖读取失败）；单条缓存损坏按读取失败上报，不静默跳过。
- **删除连接保护**：删除连接时服务端复核完整依赖（对象来源/身份/属性来源含 inline SQL 与 redis/实现）；依赖读取失败按「有引用」fail-closed 拒绝，保存边界见 §2.1。

## 5. 公式试算与取值预览

### 5.1 计算函数公式校验 / 试算

```http
POST /api/calc-eval
```

请求体：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `expression` | string | 公式，语法 `calc-expression-1` |
| `inputs` | array | `[{ "id": "<稳定id>", "type": "number\|string\|boolean", "value": any }]`，最多 50 项 |
| `outputType` | string | `number` \| `string` \| `boolean` |
| `validateOnly` | boolean | true 时仅静态校验 |

**响应** `200`

```json
{ "ok": true, "value": 12.5 }
```
或
```json
{ "ok": false, "error": "参数 p1 不存在（可能已被删除或改名）" }
```

| 状态码 | 场景 |
| --- | --- |
| 200 | 业务失败也用 200 + `ok:false`（纯只读计算，不持锁、不写草稿） |

**公式语法**：字面量（数值 / `'文本'` / true / false）、`{参数标识}`、`+ - * /`、比较 `= != < <= > >=`、白名单函数 `IF/MIN/MAX/ABS/ROUND/ERROR`。禁止 SQL、属性访问、循环、`eval`；长度 ≤ 500、嵌套 ≤ 20、节点 ≤ 200。

### 5.2 项目属性取值预览（受限只读）

```http
POST /api/project-property-preview
```

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `projectId` | string | 是 | — |
| `revision` | string | 是 | 客户端当前项目 revision（**必填**，防读到过期配置） |
| `objectType` | string | 是 | 对象类型 |
| `instanceId` | string | 是 | 已登记实例 id |
| `property` | string \| null | 是 | 属性名；**空串 = 仅成员预览** |

> **说明拦截（2026-09-19）**：该预览是尚不支持说明语义的受限只读执行器。若目标对象/属性在 `bindings.mappingDescriptions` 中存在非空说明，本接口在读取任何数据源之前返回 `200` + `status:'error'`，消息为「不支持当前说明，请使用支持项目说明的执行器」并列出元素；无说明的旧配置行为不变。

**响应** `200`

```json
{
  "status": "ok",                 // ok | empty | incomplete | error
  "value": 12.5,
  "memberCount": 3,
  "missingCount": 0,
  "membersPreview": [ { "id": "...", "label": "...", "value": 4.2 } ],
  "truncated": false,
  "evaluatedAt": "2026-09-18T05:00:00+00:00",
  "message": "..."
}
```

> 冻结契约：**全部字段恒存在**（无值时为默认值）。

| 状态码 | 场景 |
| --- | --- |
| 400 | 参数缺失/非法、项目不存在（协议层错误） |
| 409 | revision 过期（带 `currentRevision`） |

**约束**：短锁读取已保存草稿并核对 revision，**联网查询期间不持锁**；仅支持「登记信息」与「关联聚合（sum）」两类来源，其他来源返回 `status:'error'` + 说明。
