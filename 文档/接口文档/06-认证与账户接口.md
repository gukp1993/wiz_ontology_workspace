# 06 · 认证与账户接口

> 新增于 2026-09-18（登录与账号体系）。本文是认证契约的唯一来源；与 01 分册通用约定冲突处以本文为准。
> 涉及实现的代码：`workbench/auth.py`（口令与会话）、`workbench/auth_routes.py`（HTTP 边界）、`workbench/server.py`（鉴权门）。
> 需求背景：[文档/需求/20260918_登录与账号体系/需求说明.md](../../需求/20260918_登录与账号体系/需求说明.md)。

---

## 1. 总则

1. **除下节列出的免登录接口外，`/api/*` 所有接口都要求登录**；未携带有效会话一律：
   - HTTP `401`，体 `{"error": "请先登录", "code": "UNAUTHENTICATED"}`，带 `X-Request-Id`。
2. **静态资源（`/`、`/index.html`、`/assets/*`）不需要登录**：登录页本身由同一前端承载。
3. **数据完全隔离**：登录后所有接口只读写「当前账号」的数据。其他账号的数据视为不存在（按 id 直连返回 404/空列表），任何响应不泄露其存在与内容。
4. **会话载体是 Cookie**，前端不保存令牌、不读写 Cookie（`HttpOnly`）。

## 2. 免登录接口（白名单）

| 路径 | 方法 |
| --- | --- |
| `/api/auth-state` | GET |
| `/api/auth-login` | POST |
| `/api/auth-register` | POST |
| `/api/auth-logout` | POST（无会话时幂等成功） |

白名单同时登记在 `server.py` 的 `AUTH_FREE_GET` / `AUTH_FREE_POST` 常量；其余接口未登录一律 401。

## 3. 会话与 Cookie

| 项 | 约定 |
| --- | --- |
| Cookie 名 | `wiz_session` |
| 值 | 32 字节随机令牌（URL-safe base64）；库中只保存其 SHA-256 摘要，令牌本身不落盘 |
| 属性 | `Path=/; HttpOnly; SameSite=Strict; Max-Age=2592000`（30 天）；本机 HTTP 不设 `Secure` |
| 续期 | 服务端滑动续期：距上次活动超过 6 小时则刷新到期时间 |
| 退出/吊销 | `POST /api/auth-logout` 删除服务端会话并下发 `Max-Age=0` 的清除 Cookie |
| 过期/失效 | 会话不存在或过期 → 后续业务接口 401；前端回到登录页 |

## 4. 账号规则

| 项 | 规则 |
| --- | --- |
| 用户名 | `strip()` 后 1–32 字符；不得包含空白与控制字符；唯一性按 `casefold()` 比较（`Admin` 与 `admin` 视为同名） |
| 密码 | 4–128 字符（初始 admin/admin 为弱口令，登录后可在设置中心改） |
| 存储 | scrypt（n=2^14, r=8, p=1）哈希 + 随机盐；格式 `scrypt$n$r$p$salt$hash`；明文永不落盘、不回传、不进日志 |
| 初始账号 | 存量数据迁移时创建 `admin`（见 `transfer create-user`）；此后账号由注册页自建 |
| 管理员 | 仅有 `isAdmin` 标记（展示用），本期不引入管理员专属接口 |

## 5. 接口明细

### 5.1 `GET /api/auth-state`（免登录）

返回当前登录态，供页面启动时决定渲染登录页或工作区。

- 请求：无参数。
- 响应 200：
  ```json
  { "user": { "username": "admin", "isAdmin": true, "createdAt": "2026-09-18T12:00:00.000000+00:00" } }
  ```
  未登录：`{ "user": null }`（不报错，便于启动引导）。

### 5.2 `POST /api/auth-login`

- 请求：`{ "username": "admin", "password": "..." }`
- 响应 200：`{ "user": { ...同 auth-state... } }` + `Set-Cookie: wiz_session=...`
- 失败：
  - 401 `{"error": "用户名或密码不正确", "code": "UNAUTHENTICATED"}`（用户名不存在与密码错误同一文案；失败路径有 200ms 固定延迟，抑制暴力枚举）
  - 400 `{"error": "...", "code": "INVALID_ARGUMENT"}`（缺字段/类型错误）
- 说明：登录成功会顺带清理该账号已过期的会话行。

### 5.3 `POST /api/auth-register`（开放注册）

- 请求：`{ "username": "...", "password": "..." }`
- 响应 201：`{ "user": { ... } }` + `Set-Cookie: wiz_session=...`（注册即登录）
- 失败：
  - 400 `INVALID_ARGUMENT`（用户名/密码不符合 §4 规则，消息说明具体原因）
  - 409 `{"error": "用户名已被使用", "code": "DUPLICATE_NAME"}`
- 说明：新账号数据空间为空（无本体、无项目、无编排、无连接与模型配置）。

### 5.4 `POST /api/auth-logout`

- 请求：`{}`
- 响应 200：`{ "ok": true }` + 清除 Cookie（`Max-Age=0`）
- 无会话时同样返回 200（幂等）。

## 6. 既有接口的认证语义（对所有分册生效）

1. 未登录调用 → 401（§1.1）；**不再**返回业务数据。
2. 已登录时，所有查询按当前账号过滤；写入自动落归属。
3. 以其他账号的 id（本体/项目/编排/连接/提供方）发起请求 → 一律按「不存在」处理（404 或空列表），不得泄露他账号数据存在性。
4. 原来的「本地模式无登录会话」占位行为（设置页提示退出登录不可用）随本变更废弃。

## 7. 迁移与运维

```bash
# 在服务停止后执行（真实库）。备份 → 升级 schema → 建 admin → 存量数据归属 admin
python3 -m workbench.storage.transfer backup --out <备份目录>
python3 -m workbench.storage.transfer init                      # 幂等升级到最新 schema
python3 -m workbench.storage.transfer create-user --username admin --password admin --admin
python3 -m workbench.storage.transfer assign-owner --username admin
```

- `create-user`：用户名已存在时不覆盖密码（需 `--reset-password` 显式重置）；密码经参数传入，不回显、不写日志。
- `assign-owner`：把 `owner_user_id` 为空的全部资产、模型配置、用户级设置、LLM 凭据归属到指定账号；可重复执行（只填空白，不改已归属数据）。执行前后建议 `transfer verify` 核对内容。
