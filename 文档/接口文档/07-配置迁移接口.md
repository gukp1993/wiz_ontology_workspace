# 07 · 配置迁移接口（本体与项目配置打包导入导出）

需求：[../需求/20260919_本体与项目配置迁移/需求说明.md](../需求/20260919_本体与项目配置迁移/需求说明.md)。本文是 7 个配置迁移接口的正式契约（2026-09-19 登记，与实现同批交付）。数据模型沿用 [01](01-通用约定与数据模型.md)；本体/项目/编排资产语义见 [02](02-本体区接口.md)/[03](03-项目区接口.md)/[04](04-编排与LLM接口.md)。

## 0. 产品规则（契约级，实现不得放宽）

- 每次用户主动导入都创建**新的**本体/项目/编排/模型配置副本：不覆盖、不合并、不复用已有资产。同名自动追加「（导入）」「（导入2）」后缀，预览可改名。
- 导入原子：全部新资产、草稿、发布、引用、索引、模型配置、待补声明与成功回执写入**同一事务**；任一故障整体回滚。
- 幂等：导入以 `requestId` 为键（绑定账号+包hash+最终命名）。同 requestId 重试返回同一结果；同 requestId 改参数 409。新的主动导入必须换新 requestId。
- 包内**不含任何受管理凭据**（连接密码/API Key/模型 Key/根密钥）；不含目录缓存、运行结果、账号会话、自动保存修订。
- 导入不执行 SQL/Python/HTTP/模型调用，不测试连接，不自动发布。
- 上传/预检/压缩不持全局写锁；仅最终导入短事务持 `LOCK`。

## 1. 通用约定

- 全部接口要求登录；资源/token 归属当前账号，跨账号按不存在处理（404）。
- 技术上限（调整须先改本文）：原始分片 512 KiB；压缩包 ≤ 20 MiB；解压合计 ≤ 100 MiB；条目 ≤ 2000；单文件 ≤ 10 MiB；token/暂存 TTL 30 分钟；每账号同时最多 2 个导出预览 + 2 个上传暂存。
- token（exportToken/uploadId/previewToken）为服务端随机串，仅内存有效（服务重启后 410，需重新预览/上传）；导入结果以 `requestId` 回执持久化，**查回执先于 token 有效期判断**。
- 错误码：400 `INVALID_ARGUMENT`；401 `UNAUTHENTICATED`；404 `NOT_FOUND`；409 `DUPLICATE_NAME`/`IDEMPOTENCY_CONFLICT`/`CHUNK_CONFLICT`；410 `TOKEN_EXPIRED`；413 `PAYLOAD_TOO_LARGE`；415 `UNSUPPORTED_FORMAT`；422 `PACKAGE_INVALID`；500 内部。错误带可定位的资产/文件/字段信息，不回显原始秘密。

## 2. 导出（配置包生成）

### 2.1 POST /api/config-package-export-preview

请求：

```jsonc
{ "modelIds": ["<本体 external_id>"], "projectIds": ["<项目 external_id>"], "extraFlowIds": ["<未绑定编排 id>"] }
```

行为：对当前账号做一致性读取，收集根选择及依赖闭包（项目→本体及版本、被引用编排→模型配置→凭据声明），冻结一份只读快照。**不写任何业务数据**；不自动包含未选择的项目。

响应：

```jsonc
{
  "exportToken": "<随机串>", "expiresAt": "<ISO>", "snapshotAt": "<ISO>",
  "assets": {
    "models":   [{ "packageKey": "m1", "id": "<external_id>", "name": "储能本体", "releaseCount": 2, "includeReason": "根选择" }],
    "projects": [{ "packageKey": "p1", "id": "...", "name": "创智园二期", "releaseCount": 1, "includeReason": "根选择" }],
    "flows":    [{ "packageKey": "f1", "id": "...", "name": "采样值取值规则", "usedBy": ["p1"], "shared": true, "includeReason": "项目引用" }],
    "modelConfigs": [{ "packageKey": "c1", "id": "llm-xxx", "name": "GLM", "referencedBy": ["f1"], "missingApiKey": true }]
  },
  "dependencyEdges": [{ "from": "p1", "to": "m1", "kind": "ontology-version", "detail": "3.2.0" }],
  "warnings": ["<未完成字段/待补提示>"], "blockers": ["<强依赖缺失，阻断下载>"]
}
```

- `blockers` 非空时 `exportToken` 仍返回用于展示，但 2.2 下载会 422。
- 预览与下载使用同一份冻结快照；预览后源数据变化不混入下载，重新生成预览才取最新。

### 2.2 POST /api/config-package-export

请求 `{ "exportToken": "..." }`。响应 `application/zip` 二进制（`Content-Disposition: attachment`）。复用 HTTP 层 `postBlob`；二进制分派与旧 `/api/export` 相互独立。blockers 非空 → 422；token 过期/不存在 → 410/404。

## 3. 上传暂存与导入预检

### 3.1 POST /api/config-package-stage

`action=begin`：`{ "filename": "x.zip", "bytes": 12345, "sha256": "<hex>" }` → `{ "uploadId": "...", "chunkSize": 524288, "totalChunks": N }`。bytes 超限 413。

`action=chunk`：`{ "uploadId", "index": 0, "base64": "...", "chunkHash": "<hex>" }` → `{ "received": index, "totalChunks": N }`。同 index 同 chunkHash 重复提交幂等成功；同 index 不同内容 409 `CHUNK_CONFLICT`；base64 严格解析且解码后不得超过 chunkSize。暂存目录 `DATA_ROOT/tmp/config-packages/<uploadId>/`（0700/0600），绑定账号，TTL 到期清理。

### 3.2 POST /api/config-package-import-preview

请求 `{ "uploadId" }`。行为：校验全部分片 → ZIP 有界安全解析（拒绝穿越/特殊文件/重复路径/未登记条目，不 extractall）→ manifest 格式/版本/能力/逐文件 SHA-256 校验 → 依赖闭包与强依赖检查 → **计算命名计划（不创建任何资产）**。

响应：

```jsonc
{
  "previewToken": "...", "expiresAt": "...", "packageHash": "<sha256>",
  "assets": [{
    "kind": "model|project|flow", "packageKey": "m1",
    "sourceName": "储能本体", "suggestedName": "储能本体（导入）",
    "renameReason": "当前账号已有同名本体", "releaseCount": 2,
    "dependencyNote": "项目历史版本依赖"          // 可选：自动补齐的本体标注
  }],
  "modelConfigs": [{ "packageKey": "c1", "sourceName": "GLM", "missingApiKey": true }],
  "warnings": ["..."], "blockers": ["..."]
}
```

`blockers` 非空（强依赖缺失/版本不支持/包损坏）时预检仍返回 200 供展示，但 3.3 提交 422。

## 4. 导入提交与结果

### 4.1 POST /api/config-package-import

请求：

```jsonc
{ "previewToken": "...", "requestId": "<客户端生成的唯一串>",
  "nameOverrides": { "m1": "自定义名称" } }   // 仅顶层资产名；空/超长/重复 400
```

行为（单事务，持 `LOCK`）：requestId 幂等检查 → 名称权威复查（并发同名 409 `DUPLICATE_NAME` + `conflicts:[{packageKey, suggestedName}]`，不静默改名）→ 生成资产级新 ID（本体 uuid / 项目、编排 12hex / 模型 provider `llm-*`）→ 映射重写跨资产引用 → 写入全部资产/草稿/发布/引用/索引/模型配置/待补声明 → 写成功回执。

响应：

```jsonc
{
  "receiptId": "...", "requestId": "...",
  "assets": [{ "kind": "model", "packageKey": "m1", "newId": "<新 external_id>", "newName": "...", "sourceName": "...", "releaseCount": 2 }],
  "pendingCredentials": [{ "declarationId": "...", "name": "...", "kind": "api|connection|model", "usage": ["<资产/位置>"] }],
  "warnings": ["..."]
}
```

- 业务稳定 ID（本体定义 `mg:*`、编排节点/输入/输出、连接 ID、apiName、登记实例 id 等）**恒等保留**；跨资产引用（项目→本体、项目→编排、编排→模型 provider）重写为本次新 ID。映射矩阵见开发计划实施记录。
- 来源账号默认模型的显式化转换：原「使用默认模型」的编排节点在导入后固定指向本次导入的对应 provider，并在 warnings 说明；接收账号自身默认项不变。
- 预览阶段已列 blockers 时提交 422；previewToken 过期 410。

### 4.2 POST /api/config-package-import-result

请求 `{ "requestId" }`。返回当前账号该 requestId 的回执：

```jsonc
{ "status": "none" }                        // 尚无回执（未提交/仍在途/失败回滚）
{ "status": "completed", "receipt": { ...同 4.1 响应... } }
```

**不触发任何新建**；回执查库持久化，服务重启/暂存过期后仍可确认先前结果。

### 4.3 POST /api/config-package-discard

请求 `{ "uploadId" | "exportToken" | "previewToken" }`（至少一项）。删除本账号对应临时数据（上传暂存/冻结导出快照/预检状态），不删除已导入资产。未知/已过期 token 返回 200（幂等清理）。

## 4.5 预检与导入的强校验语义（2026-09-19 修正登记）

- **依赖闭包校验（零写入阶段）**：项目各快照（草稿/每个发布）引用的本体与编排必须在包内存在；`requiredCapabilities` 非空视为版本不支持（本期能力白名单为空）；JSON 重复键拒绝（不做「最后一个生效」静默覆盖）；payload 与 manifest 同样做深度/大小/编码校验。强依赖缺失在 import-preview `blockers` 列出，import 阶段 422。
- **身份一致性**：编排 payload 的 `flowId`/`name` 与资产新 ID 一并重写——导入后的编排可直接读取并保存（新 revision），不再出现 payload 带源 flowId 导致保存 404。
- **逐快照引用**：项目草稿与每个历史发布分别解析源本体与版本、分别映射与登记（`wb_project_refs` 按草稿、发布 manifest 按各发布 payload），历史版本引用另一本体时不沿用草稿引用。
- **M07 副本归属**：`contextProjects` 精确匹配优先（唯一）；无精确匹配时允许恰好一个无上下文共享副本；歧义在预检 `blockers` 阻断，不猜首个。多副本在预检命名即含「（上下文N）」后缀，落库名称与预览逐字一致。
- **敏感值边界（T04）**：剥离范围限定为认证头键（Authorization/Cookie/Set-Cookie/X-API-Key/API-Key/Proxy-Authorization）与字符串值中的 URL 认证段（含模型连接地址）；**不按 token/secret 等泛化键名清空业务字段**。剥离位置进 manifest.pendingItems 并在导入结果 `strippedItems` 返回。
- **默认模型（T06）**：来源账号默认模型作为被依赖配置一并入包（manifest asset `defaultProviderDependency` 标注）；导入时把「未指定模型的节点」显式绑定到该模型的本次副本（warning 说明转换）；来源无默认模型则明确待补，不改接收账号默认。

## 5. 包格式（formatVersion = 1）

`format: "wiz-workbench-config-package"`；UTF-8 JSON；ZIP 存储，路径用包内随机键（`m1/p1/f1/c1`），不用用户名称拼路径。

```text
manifest.json
models/<k>/draft.json                    # workbench-state-1 payload 原样
models/<k>/releases/<version>.json       # release-state-1 payload 原样
projects/<k>/draft.json                  # project-state-1 payload 原样
projects/<k>/releases/<version>.json     # project-state-1 payload 原样
flows/<k>/draft.json                     # flow-state-1 payload 原样
configuration/models.json                # {providers:[{providerId,name,endpoint,model,timeoutSeconds,temperature,defaultInSource}]}
configuration/credential-declarations.json  # [{declarationId,name,namespace,usage}]
```

manifest 关键字段：`formatVersion`、`packageId`、`exportedAt`、`producerVersion`、`requiredCapabilities`（本期 `[]`）、`rootSelection`、`assets[]`（kind/packageKey/sourceId/name/payloadFormat/draftPath/releases[{version,path,changeType,createdAt,releaseOrder}]）、`dependencyEdges[]`、`credentialDeclarations`、`pendingItems`（敏感剥离位置/缺默认模型）、`files{path:{bytes,sha256}}`、`credentialsExcluded: true`。

- payload 原样携带（含未知扩展，零丢失）；只接受 `payloadFormat` ∈ {workbench-state-1, release-state-1, project-state-1, flow-state-1}。
- 来源 hash 仅用于一致性检测，不是签名；导入后重算目标 hash，发布条目附 `originPackageId/sourceVersion/sourceHash` 追溯信息。
- 受管理凭据不出现在任何成员文件；结构化敏感值（Authorization/Cookie/API-Key 头、带密码的连接串）在导出时剥离为空并在 `pendingItems` 记录位置。

## 6. 前端调用约定

经 `app/http.ts`（`postJson`/`postBlob`）+ `settings/transferApi.ts`；分片上传逐片 `postJson` 到 3.1，页面不手写 fetch。提交后至明确结果前不更换 requestId；网络中断显示「结果待确认」并走 4.2；「再次导入此文件」才生成新 requestId 重新预检。
