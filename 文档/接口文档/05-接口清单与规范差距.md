## 2. 与标准 HTTP/REST 规范的差距

按「修复收益 / 改动成本」排序。P0 建议本轮做，P1 下轮，P2 择机。

## 3. 已知设计问题（实现层）

### 3.1 `/api/restore` 引用了未定义函数（**缺陷，需修复**）

`workbench/model_routes.py` 中 `post_restore` 调用 `_server_current(identifier)`，该函数在模块中**不存在**（当前模块只有 `current()`）。触发路径：`POST /api/restore` 写恢复前备份时会抛 `NameError`，经 `do_POST` 兜底 → 返回 400，恢复失败。

**建议修复**：改为 `current(identifier)`，并在 `tests/` 补一条恢复用例（当前恢复路径无自动化覆盖）。

### 3.2 GET 分派的工作区副作用

`server.py.do_GET` 对所有 `/api/*` 先执行 `workspaces.describe(query.get('ontology', ['storage'])[0])`，导致：

- 编排/LLM/存储状态接口与本体工作区耦合；
- 传入非法 `ontology` 时，与业务无关的只读接口也会 404/400。

**建议**：把工作区定位下沉到本体/项目路由内部（G15）。

### 3.3 路由表用 lambda 包装

`POST_ROUTES` 中 4 个 `project-*` 与 2 个 `connection-*` 端点用 `lambda` 包装同一个处理函数并传路径字符串，函数内再 `if path == ...` 分支。可读性差、易漏分支。

**建议**：改为显式注册的 `functools.partial(handler, path=...)` 或拆成具名函数。

### 3.4 导出接口的二进制特判

`/api/export` 在 `POST_ROUTES` 中值为 `None`，靠 `do_POST` 内 `if path == '/api/export'` 特判。表格语义被破坏（值 `None` 却代表"已注册"）。

**建议**：注册真实 handler，返回 `(bytes, content_type)` 二元组，由 `respond` 按类型分派。

## 5. 演进路线（建议）

**P0（不影响调用方，纯健壮性）**
1. 修 `_server_current` 缺陷 + 补恢复用例；
2. `do_POST` 兜底分支拆为「已知业务异常 → 400」与「未知异常 → 500 + 日志」，禁止回传原始异常文本；
3. 错误响应增加 `code` 字段（保留 `error` 字符串兼容）；
4. `GET /api/projects` 改为显式过滤参数（保留旧行为一版）；
5. 增加 `X-Request-Id` + 结构化访问日志。

**P1（路由层规范化，双轨过渡）**
1. 新路由按资源注册：`/api/v1/ontologies/{id}/draft`（GET/PUT）、`/releases`（GET/POST）、`/api/v1/projects/{id}/draft`（GET/PUT）、`/releases`、`/api/v1/flows/{id}`（GET/PUT/DELETE）等；
2. 旧路由保留并标记 `Deprecated`，前端按区逐步切换，切换一个删一个；
3. `/api/releases` 响应体统一为 `{items}`（前端同步改）；
4. 拆开 GET 工作区副作用。

**P2（治理增强）**
1. `If-Match` / `Location` / `OPTIONS` / `Idempotency-Key`；
2. `GET /api/health`、`GET /api/ready`；
3. 全量接口契约测试（请求/响应 schema 快照），纳入 CI。
