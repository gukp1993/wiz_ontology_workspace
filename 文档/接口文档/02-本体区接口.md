# 02 · 本体区接口

本体区共 23 个接口。本体资产 / 草稿 / 版本 / 发布 / 校验 / 预览 / 探索 / 导出与恢复。

> **通用前置**（GET 除 `/api/ontologies` 外全部适用）：服务端先按 `ontology` 参数定位工作区，标识非法即返回 404（本体不存在）或 400（标识格式无效）。缺省 `ontology=storage`。
> **通用请求体**（POST 除创建/导出外）：`{ "state": <OntologyState>, ... }`，其中 `state.ontology` 为 schema 形态，服务端 `decode_state` 解码。

## 1. 本体资产

### 1.1 查询本体清单

```http
GET /api/ontologies
```

**响应** `200`

```json
{ "items": [ { "id": "storage", "name": "储能本体" } ], "defaultId": "storage" }
```

> 默认本体 `storage` 仅在已持有草稿后出现（资产行随首次保存建立）。

```http
POST /api/ontologies
Content-Type: application/json
```

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 是 | 1–80 字符 |

**响应** `201`

```json
{ "id": "<uuid>", "name": "新本体" }
```

| 状态码 | 场景 |
| --- | --- |
| 400 | 名称缺失或超长 |
| 409 | 已存在同名本体（`DuplicateName`） |

**约束**：持全局写锁；创建时即写入空白草稿状态。

## 2. 草稿读写

### 2.1 读取本体草稿

```http
GET /api/state?ontology={ontologyId}
```

| Query | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `ontology` | 否 | `storage` | 本体标识（`storage` 或规范 UUID） |

**响应** `200`

```json
{
  "state": { /* OntologyState（encode_state 后，ontology 为 schema 形态） */ },
  "revision": "r-<uuid>",
  "saved": true,
  "ontology": { "id": "storage", "name": "储能本体" },
  "latestVersion": "1.2.0"
}
```

- `saved`：是否已存在草稿（false 表示空白状态）。
- `revision`：无草稿时为「空白状态内容 hash」一次性基线。

### 2.2 保存本体草稿

```http
POST /api/save
```

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `state` | OntologyState | 是 | 完整状态（含 `workspaceId`） |
| `revision` | string | 是 | 客户端并发基线 |

**响应** `200`

```json
{ "revision": "r-<uuid>", "errors": ["..."], "ontology": { "id": "...", "name": "..." } }
```

- `errors` 为**校验提示**，非空**不阻断保存**（草稿允许带错保存；发布才阻断）。
- **例外：新引入的悬空引用阻断保存**（2026-09-20 需求 11～13）。保存边界只拦截「本次保存把此前有效的稳定引用改坏」：
  - 检查范围（与前端依赖检查 `frontend/src/ontology/editorModel.ts` 的 `graphReferenceEntries` 对齐）：
    - 图内引用：`rdfs:domain` / `rdfs:range`、`mg:sharedProperty`、`mg:valueType`、取值函数 `mg:valueSource.functionId`、嵌套值类型 `mg:constraint`（`elementValueType` / `fields[].valueType`）；
    - 契约签名：计算/动作/接口三类定义的 `inputs[]` / `outputs[]` 的 `ref`（`kind=object|property|base`；`base` 只在带稳定 id 时按图内引用核对，正常 `base` 引用只有 `dataType`）；
    - 计算/动作/接口三类定义的字段级引用：`object_types` / `object_type` / `applicable_objects`（适用对象类型）、`output_property`（属性）、`relation_ref`（链接类型）、`function_ref` 与 `steps[].function_ref`（计算契约）、`interface_ref`、`property_bindings`（`object_type` / `property_ref`）、`inputs[]`（`object_type` / `property_ref` / `value_type(_ref)` / `interface_ref`）；
    - `properties`（必需共享属性）与 `implementations`（实现对象类型）清单：三类定义同样遍历（实际数据主要在接口定义 `interfaces[]` 上）；
    - 关联与存量定义：动作/规则关联的 `objectTypeId` / `ruleId` / `actionId`、指标 `metrics[].rule_ref` / `applicable_types`、旧 `rules.rules[].member_type`（id 取自旧规则集合，不再误报存在规则）。
  - 不在本检查范围（前端另有保护，但语义不同）：接口实现完整性（删除实现对象上最后一条满足接口要求的共享属性实例，属发布校验提示）；项目映射 `state.bindings` 引用（属项目区 `/api/project-save` 与项目校验）。
  - 比较口径：与当前 head 草稿逐条比较，**只阻断本次新产生的失效引用**；历史遗留的失效引用允许继续保存（不能把草稿永久锁死，需求 §6）。
  - 图内引用目标（`rdfs:domain` / `rdfs:range`）按稳定身份核对，同时接受 `mg:` 前缀与裸名写法（`o1` 与 `mg:o1` 同判；`xsd:`/`http:` 等外部前缀不按图内引用处理）——与前端 `matches` 同口径（2026-09-20 v2 修正）。
  - 比较键只由稳定 ID 组成（来源稳定 id + 引用字段/槽位稳定身份 + 目标 id），业务名称仅用于展示文案：**改显示名不产生新条目**（既有失效引用改名可继续保存），**改目标 ID 一定产生新条目**（同名同文案但身份不同的新失效引用不会被去重放过）。契约签名槽位无稳定 id 时，槽位身份取「引用类别 + 目标 id + 同目标出现序号」（不取所在序号）：删除/重排前置槽位不改写既有悬空引用的比较键，新增同目标槽位仍产生新键（保护不放松）。
  - 响应 `422` `code=BROKEN_REFERENCE`，`errors` 列出具体引用与被引用对象；前端显示原因且不落盘；首次保存（无基线可比）不阻断；
  - 「未填写完整」（缺名称/缺必填）不受影响，仍按上面的 200 + errors 保存。

| 状态码 | 场景 |
| --- | --- |
| 400 | state 结构非法 |
| 409 | revision 过期，响应带 `currentRevision` |
| 422 | 本次保存新引入悬空引用（`BROKEN_REFERENCE`） |
| 503 | 存储不可用 |

**约束**：持全局写锁；CAS 原子提交。

### 2.3 从历史快照恢复

```http
POST /api/restore
```

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `state` | OntologyState | 是 | 当前客户端状态（用于定位本体） |
| `revision` | string | 是 | 并发基线 |
| `release` | string | 是 | 快照文件名（`*.zip`，由 `GET /api/releases` 返回，不接受路径分隔符） |

**响应** `200`

```json
{
  "revision": "r-<uuid>",
  "state": { /* 恢复后的 OntologyState */ },
  "ontology": { "id": "...", "name": "..." },
  "errors": [],
  "backup": "20260918T050000123456Z-r-<8位>.json",
  "release": "xxx.zip",
  "note": "快照中的项目配置未恢复到项目草稿；项目数据由项目绑定区独立维护。"
}
```

| 状态码 | 场景 |
| --- | --- |
| 400 | 快照名非法、快照不属于当前本体、缺少本体定义文件 |
| 409 | revision 过期（带 `currentRevision`） |

**约束**：持全局写锁；恢复前自动写一份当前状态备份（附件表）；**只恢复本体部分**，项目配置不回灌。



### 3.4 发布预检（变更分类建议）

```http
POST /api/publish-check
```

**请求体**：`{ "state": <OntologyState> }`

**响应** `200`

```json
{
  "suggested": "compatible",
  "reasons": [ { "severity": "compatible", "area": "objectTypes", "id": "mg:xxx", "text": "新增对象类型 mg:xxx" } ],
  "latest": "1.2.0",
  "canCompatible": true
}
```

- `suggested`：`initial`（首个版本）/ `compatible` / `breaking` / `pending`（需人工确认）。

### 3.5 发布本体版本

```http
POST /api/publish
```

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `state` | OntologyState | 是 | 待发布状态 |
| `revision` | string | 是 | 并发基线 |
| `changeType` | string | 条件 | `compatible` / `breaking`；`suggested=pending` 时必填 |
| `changeNote` | string | 否 | 变更说明（缺省取 `workflow.release.note`） |
| `reviewer` | string | 否 | 审核人 |
| `requestId` | string | 否 | 幂等键 |

**响应** `200`

```json
{ "revision": "r-<uuid>", "errors": [], "version": "1.3.0",
  "changeType": "compatible", "reasons": [], "ontology": { "id": "...", "name": "..." },
  "idempotentReplay": true }
```

| 状态码 | 场景 |
| --- | --- |
| 409 | revision 过期（带 `currentRevision`）；或 `requestId` 已被不同内容使用 |
| 422 | 校验未通过（响应体为 `{"errors": [...]}`）；或破坏性变化被标为兼容；或存在待确认变更未选类型 |

**约束**：持全局写锁；草稿快照 + head CAS + 发布快照 + 发布记录**单事务**；版本号按数值递增（breaking → 大版本 +1，否则次版本 +1）；`requestId` 幂等回放。
**规则**：引用失效的结构变化**禁止**人工改标为兼容。

### 4.9 业务规则与动作字段定义（2026-09-20 精简）

规则与动作是本体语义定义，均以「名称 + 业务定义」为最小完整定义；适用范围、例外与作用边界写入业务定义，不新增字段。

| 类型 | 显示名 | 存储字段 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| 规则 | 规则名称 | `name` | 是 | 必填检查按 `trim()` 后判空 |
| 规则 | 业务定义 | `description` | 是 | 规定什么、适用什么情形 |
| 规则 | 规则内容 | `content` | 否 | 具体公式/判断逻辑；空值、`null`、空串均按未填处理 |
| 动作 | 动作名称 | `name` | 是 | 动词表达的业务操作 |
| 动作 | 业务定义 | `description` | 是 | 操作目的与含义 |
| 动作 | 预期效果 | `effect` | 否 | **仅显示文案变化**（原「业务效果」）；存储键不变，不新建 `expectedEffect` |

约束：

- 非空值必须是文本；不得把对象/数组静默转字符串。
- **字段类型边界（2026-09-20 验收修复 A01）**：名称与业务定义必须是**文本**（去首尾空白后非空）；`content`/`effect` 为合法选填文本——缺失、`null`、空串、纯空白按未填处理；对象/数组/数值/布尔值等非文本一律受控报错（文案含字段名与当前类型，如「规则 X 的规则内容必须是文本（当前为对象）」），不得用 `str()`/`String()` 掩盖成合法内容，也不得静默清洗原值。后端 `definition_errors` 与前端 `recordFields`/`businessRuleModel`/`actionModel` 同一口径；规则库、动作库与图谱保存入口共用该口径（图谱显式保存不再绕过必填）。`description` 为 `null` 时返回定位到记录与字段的可读文案（不再是 `'NoneType' object has no attribute 'strip'` 类泛化错误）。
- **`POST /api/save` / `/api/validate` / `/api/publish`（本体）拒绝边界**：非文本必填/选填字段经正式发布路由返回 `422` 且**零新增版本**（快照不含非法值）；合法空值（缺失/`null`/空串/纯空白）仍可保存与发布，不补键、不清洗；单条编辑只校验该记录，历史另一条不完整定义不锁死无关草稿保存（发布仍检查全部定义）。
- **旧规则 `output` 零丢失**：读取、编辑、保存、JSON↔schema 转换、发布快照、配置迁移全程透传；有值时仅作「历史补充说明（原输出结果）」只读展示；不自动拼入 `description`/`content`，不清空、不批量迁移。后端不得再将 `output` 空值视为阻断。
- 文案调整本身不构成业务破坏性变更；实际语义变化仍按现有变更分类处理。
- 单条保存只校验该记录；历史其他不完整定义不阻断无关草稿保存。发布检查全部定义；导入沿用整批预检失败不写。
- 动作历史旧格式（参数/权限等）只读兼容与显式转换边界不变，不静默删除其他旧字段；转换后的新格式不强制填写 `effect`。

### 4.10 本体 Excel 导入协议（2026-09-20 表头精简）

四页表述与导入规则。表头按**名称**识别（不按列号硬编码）；规则/动作必须包含「名称 + 业务定义」表头；选填列缺失可接受，模板仍提供。

| Sheet | 新表头（按顺序） | 必填 |
| --- | --- | --- |
| 对象 | 对象名称、业务定义 | 前两项 |
| 属性 | 属性名称、业务定义、数据类型、观测值类型、显示格式 | 前三项（沿用） |
| 规则 | 规则名称、业务定义、规则内容 | 前两项 |
| 动作 | 动作名称、业务定义、预期效果 | 前两项 |

兼容解析（新旧文件都能导入）：

| 输入 | 处理 |
| --- | --- |
| 规则新三列 | 按新定义导入 |
| 旧规则四列（含「输出结果」） | 正常解析；输出结果写入兼容 `output` 保留，预览提示「旧输出结果将保留为历史补充说明」 |
| 动作「预期效果」列 | 写入 `effect` |
| 动作旧「业务效果」列 | 作为 `effect` 别名，与新列同等支持 |
| 新旧效果列同时存在 | 逐行处理：一侧空取另一侧；`trim` 后相同取一份；**都非空且不同报冲突并阻断该批**，绝不择一丢弃。两列并存是合法的逐行合并场景，**不**计入「表头重复」 |
| 待导入规则/动作缺业务定义 | 定位 Sheet、行、列，提示「请填写业务定义」；不按名称自动补齐 |
| 公式 / 错误值 / 非文本 | 沿用严格解析；**旧别名与旧 `output` 同样检查**；公式单元格即使没有缓存值（openpyxl 等工具写出 `t='z'` + `f`）也按公式阻断，不得当作空单元格跳过；未知非空列不可静默忽略 |

其他边界（不变）：四页与隐藏 H 列枚举区、属性下拉与时间序列联动（仅约束新选择，不自动清除残留观测值，导入仍校验）、同名跳过与随机后缀策略、1000 业务行上限、整批预检失败零写入、属性默认进共享属性库、关联仍由页面维护。

模板文件：`frontend/public/templates/ontology-import-rule-action-v1.xlsx`（2026-09-20 起为下载入口指向的上线模板，浅灰 11pt 加粗表头、冻结首行、隐藏 H 列枚举与属性下拉/时间序列联动保留、无样例业务行）；旧 `ontology-import-v1.xlsx` 仍保留在仓库作为旧文件回归输入，不再作为下载入口。

## 6. 定义索引与存储状态

### 6.1 只读定义查询

```http
GET /api/model-definitions?ontology={id}&version={v}&kind={k}&owner={o}&q={kw}&limit={n}&cursor={offset}
```

| Query | 默认 | 说明 |
| --- | --- | --- |
| `ontology` | `storage` | 本体标识 |
| `version` | 当前草稿快照 | 指定已发布版本 |
| `kind` | 全部 | 定义类型过滤 |
| `owner` | 全部 | 所属对象过滤 |
| `q` | — | 关键字 |
| `limit` | 50 | 1–100 |
| `cursor` | 0 | 偏移量 |

**响应** `200`

```json
{ "items": [ { "kind": "objectTypes", "id": "mg:xxx", "name": "...", "owner": "..." } ],
  "cursor": 50, "snapshot": "<snapshotId>", "version": null }
```

- 无下一页时 `cursor` 为 `null`；**快照切换后游标失效**。
- 索引缺失时自动按完整文档重建投影（不写快照/head）。

| 状态码 | 场景 |
| --- | --- |
| 400 | 分页参数无效 |
| 404 | 指定版本不存在 |

### 6.2 存储健康状态

```http
GET /api/storage-status
```

**响应** `200`

```json
{ "ready": true, "schemaVersion": "20260918-01", "backend": "sqlite" }
```

> 仅返回就绪状态、schema 版本与后端类型，**绝不含 DSN 与密钥**。

```http
POST /api/export

```
