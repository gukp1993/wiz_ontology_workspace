# 项目映射：说明与配置 · v2

日期：2026-09-19；版本：v2.1 完整交付稿。当前仅交付需求，正式产品未实施。

本期实施包：四类说明维护、与已有配置共同保存、随项目读取与发布、向后续消费方提供完整上下文，以及不支持说明的执行入口明确拦截。大模型自主查询和设备动作执行另列后续范围，本期不宣称已可自动执行说明。

当前视觉及交互基准：[交互原型_v2.html](交互原型_v2.html)。配套：[开发计划.md](开发计划.md)、[执行指令.md](执行指令.md)。v1 文件仅用于历史对照；不得继续按其模式标签、编号分区及流程条开发。

## 1. 本次修正

最终交互要求：每个对象、属性、链接和动作都能填写描述，同时继续使用已有配置能力。UI 不需要解释“普通模式”“严格模式”“组合使用”，也不需要把“自然语言”作为一种特殊功能突出。

产品呈现改为：**写说明，需要时再补充具体配置。**

这不是增加一个无效备注栏：项目说明应作为未来理解和取值/行为实现的依据之一，与已配置的字段、关联或接口一起保留。产品中不再标识填写采用了哪种机制。严格定义的结构化能力仍保留，位置更收敛。

说明属于当前项目对本体元素的实现描述，不覆盖本体的业务定义。编辑页通过「查看本体定义」按需查看只读内容，避免两种描述混淆。

## 2. 范围与页面结构

对象映射保留左侧对象选择，右侧四个页签：

| 页签 | 说明描述什么 | 需要时补充的配置 |
|---|---|---|
| 对象 | 实例来自哪里、唯一身份、哪些记录有效、多表如何补充 | 数据来源：连接、表、实例主键、原有登记身份及补充来源 |
| 属性 | 从哪里取值、怎样计算、异常如何处理 | 取值配置：字段、Redis、函数编排等原有能力 |
| 链接 | 两端对象在当前项目如何关联 | 关联条件：两端已登记来源表及字段、现有成员关系等 |
| 动作 | 本项目怎样完成动作、接口含义和结果确认方式 | 接口配置：已有请求方式、地址、参数和凭据引用 |

项目页签名称采用对象/属性/链接/动作；既有路由和链接定位保持兼容。不改变主导航或添加新的规则工作区。

## 3. 列表

- 对象页签直接展示来源说明，下方数据来源摘要折叠，提供一个「编辑」入口。
- 属性、链接、动作采用同一三列表格：**名称、项目说明、操作**。
- 名称下方显示现有类型或关系方向，不增加配置模式列、模式标签或 AI 状态。
- 项目说明最多显示两行。若已有字段/关联/接口配置，可在下方以灰字显示其真实摘要，便于定位已有配置。未填说明显示「暂无说明」，不把缺少说明当作无配置。
- 搜索名称与说明；名称点击和「编辑」进入同一表单。原型样例量较少，不展示分页；正式版保留现有大量列表能力。
- 来源始终是项目固定引用本体版本；失效/未知配置仍需原样保留并提示，不能因原型省略而隐藏或删除。

## 4. 统一编辑页

从上到下只有五部分：

1. 返回入口、当前元素名称及必要的类型/对象信息。
2. 「查看本体定义」只读折叠内容。
3. **说明**：默认展开，可收起；一个多行文本框，按元素类型给一句填写提示。没有编号、模式选择器和规则命名要求。
4. **具体配置**：对象叫「数据来源」、属性叫「取值配置」、链接叫「关联条件」、动作叫「接口配置」。默认折叠，标题旁显示当前摘要或「需要时补充」。展开后复用原有表单。
5. 底部「保存」「取消」。不提供测试/执行动作按钮，不展示理解演示或配置流程图。

说明提示按对象、属性、链接、动作分别使用业务语境；不要求用户填写技术上的函数签名或重复属性数据类型。

### 说明输入区（本轮简化）

对象、属性、链接、动作的说明区都只保留一个 textarea，外层「说明」标题继续支持折叠。填写提示仅放在 placeholder 中，不另设提示栏。

不展示插入变量按钮、连接选择、连接标签、字数统计或底部工具栏。用户直接描述对象、字段、实例 ID、时间范围和步骤，不需要先学习变量插入。

下方已有配置及其中的数据连接选择仍然保留。本轮不新增“说明专属连接范围”表单或参数绑定。未来理解说明若无法确定数据库、实例或其他必要信息，需返回具体缺失项，不能猜测；如何解析相关上下文需在执行协议阶段明确，不在 textarea 周围重新增加未经确认的辅助控件。

### 折叠与保存

- 折叠只改变展示，不表示禁用配置，不清空文字，不触发保存或撤销记录。
- 同一次编辑重绘保留折叠状态，重新进入说明默认展开，具体配置默认折叠。
- 说明可空，已有配置也可独立使用；无需强迫用户为简单字段重复写一段说明。
- 两部分一次保存同一项目草稿；取消恢复原值，未保存离开有提示，失败保留输入，409 使用既有保存协调器。
- 移除具体配置需确认；说明保留，依赖失效需提示。清空全部映射仍按原来的显式清除流程，不因空表单自动清掉旧配置。
- 仅保存说明不等于配置可执行或发布通过。说明结构与引用校验在本期实现；模型理解和实际执行另行建设。

## 5. 四类示例

### 对象：储能簇

> 储能簇来自 m_storage_cluster_phase，每条记录表示一个储能簇。id 是唯一编号，name 是显示名称。仅使用 del_flag 为 0 的记录。

下方数据来源保留业务库、表和主键；对象身份必须唯一稳定，多表补充不能重复产生实例。

### 属性：额定功率／采样 SOC

> 额定功率读取当前储能簇记录的 rated_power 字段。

> 使用当前实例 ID 查询 s_attr_scada，取得 scada_table 与 scada_id；查询对应配置表，取得 sample_table_name 与 sample_field_name；按本次时间范围读取采样表的 record_time 和采样字段，返回时间和值组成的序列。

单字段可仅配置字段，不填说明。复杂规则可先写说明，不必先建规则或搭节点。数据类型继承本体，采样输出必须包含时间与观测值。

### 链接：所属设备

> 储能簇的 storage_id 对应储能设备的 id，通过这个关联找到所属设备。

同一链接在两端共用说明及配置，反向入口不复制第二条定义。反向编辑时提示两端都会更新。关系字段选择只能使用两端对象已配置来源，不能随意填未知表。

### 动作：停止充放电

> 调用设备功率设置接口，storageId 使用当前储能设备实例 ID，power 固定为 0。接口受理仅表示请求提交，停止完成以设备反馈为准。

作用于储能簇时，如果项目只有设备级接口，不能简单拿所属设备 ID 代替：这可能停止同设备下其他簇。原型中的簇级动作只保留说明，等待匹配接口；设备级动作展示模拟接口。原型绝不发送请求。

## 6. 解释与执行边界

这些是后台实现要求，不以“模式”标签堆在填写页面：

- 明确配置是确定依据，说明补充业务条件与步骤；两者冲突不能静默选一方或覆盖。
- 说明由大模型理解时必须通过授权工具真实读数/计算，不能用模型生成值替代实际数据。
- 保留连接权限、稳定身份、输出类型、时间范围、超时/数据量/步骤限制，不能绕过现有 dbdrivers 固定探测边界。
- 只读映射的解释不授权动作写入。动作页本期与现有 ActionBindings 一样只配置、不执行；未来执行应单独设计参数解析、权限、确认和结果反馈。
- 保存、发布及尚不支持说明的执行入口按第 10 节处理；配置发布成功不代表说明已通过语义验证或可以执行。
- 旧客户端或执行器若不支持说明语义，应明确提示不支持，不得忽略说明只跑旧字段映射。
- 用记录集合做中间输出再加工成属性值属于后续协议设计，不能擅自放宽现有输出类型校验。

## 7. 非目标

不改本体字段、共享语义、现有链接定义及动作参数模型；不新增设备控制能力；不改工作台存储；不提供自然语言自动生成 SQL/编排的强制流程；不增加模式徽标、AI 检查示例、流程条、多个重复保存入口。

## 9. 数据设计（本次开发建议基线）

以下是按现有项目完整状态接口提出的最小扩展方案，不是当前已存在的 API。执行者应先写入接口文档，再实现。若源码已有同等机制，优先复用，避免两份说明并存；如调整字段命名，必须同步记录最终协议。

### 9.1 独立于原来源结构保存

在项目 `bindings` 中增加 `mappingDescriptions`，不把旧字符串字段映射包装为另一种来源，不替换原 `kind`，不改变 HTTP 动作配置版本。

```json
{
  "mappingDescriptions": {
    "schemaVersion": 1,
    "objects": {
      "<对象稳定ID>": "对象来源说明"
    },
    "properties": {
      "<对象稳定ID>": {
        "<对象属性稳定ID>": "当前对象的该属性取值说明"
      }
    },
    "links": {
      "<链接类型稳定ID>": "两端共用的关联说明"
    },
    "actions": {
      "<对象稳定ID>": {
        "<动作稳定ID>": "该动作在该对象上的项目实现说明"
      }
    }
  }
}
```

`projectId` 由状态本身提供，不再重复。ID 示例是占位说明，不能原样写入真实数据。

- ID 格式与现有项目映射规范一致，通过统一适配器处理 `mg:` 前缀，不能混用两个键表示同一记录。
- 对象属性使用对象实际属性/共享引用节点的稳定 ID，不使用名称、数据库字段名，也不能只用共享库根属性 ID。相同共享属性用于两个对象时，其项目取值说明独立。
- 链接说明按一份本体链接定义定位，反向入口读取同一个键；不同 linkTypeId 即使同名也不合并。
- 动作按对象与动作组合定位：储能簇与储能设备可引用同一动作，但项目说明互不覆盖。
- 不新增“模式”“组合标识”“启用自然语言”或独立说明连接字段。界面摘要由当前配置派生。

### 9.2 文本规则

单项说明建议上限 20,000 个 Unicode 码点，前后端一致；保留段落与原文，不经过 Markdown 执行或 HTML 注入，不通过模型自动重写。展示时按纯文本转义。换行统一为 LF；纯空白按清除处理，有内容的首尾空格不随意修剪。

上限仅在超限时给出错误反馈，不重新添加字数工具栏。仍服从原 HTTP 2MB 请求上限，超限不得截断后假保存。

### 9.3 缺省、清空、旧客户端与未知结构

- 旧数据没有 mappingDescriptions：视为没有说明，无迁移动作，不批量生成空文本。
- 旧客户端提交整个 bindings 时省略 mappingDescriptions：后端在同一 CAS/写锁边界内沿用当前已存说明，而非删除。
- 新客户端携带完整 version=1 块时，按完整块提交；显式清空某项由删除对应键表达，其他说明必须保留。界面只编辑一项，但通过统一项目状态保存。
- `null`、非法类型、非法版本结构不能当空内容清理；当前服务不认识的更高版本只读保留。对其不支持的写入明确拒绝，不能自动降级。
- 非空引用的元素已删除或不属于对象：草稿保留原文并列为失效，允许查看和显式清理；不自动挂到同名元素。
- 清除具体来源不隐式清除说明；删除对象映射若连带清除说明，必须明确显示影响并经原删除确认。否则原样保留为未绑定说明。

### 9.4 存储、升级与接口触点

草稿和发布都进入现有 SQLite 项目状态/快照；JSON 文档新增字段一般无需新增表。若实施确实改变 schema，按 AGENTS 新增 Alembic 迁移，不能服务启动时隐式建表。

本期复用并更新文档中的现有接口：

| 接口/能力 | 本次要求 |
|---|---|
| GET /api/project-state | 返回说明原文，与同一 revision 的具体配置一致 |
| POST /api/project-save | 结构/长度检查、CAS、旧请求省略保留、完整块提交语义 |
| POST /api/project-validate | 追加说明结构与失效引用问题，不伪装成自然语言语义校验 |
| POST /api/project-publish | 原发布规则不放松，事务快照包含说明 |
| POST /api/project-upgrade-check | 识别说明所指对象/属性/链接/动作消失或失效，不静默丢失 |
| 既有导出/备份/恢复 | 与项目状态一起往返，原文保留，不改已发布快照 |
| 既有取值预览/演示执行 | 见第 10 节，不能忽略说明按旧配置执行 |

无需仅为单个说明另开 save-description 接口。不新增模型检查和设备测试接口。前端继续通过 app/http + project/api，后端检查在业务层，不把业务塞进 server.py。

## 10. 保存、发布与消费约定

| 状态 | 保存草稿 | 发布 | 本期执行/预览 |
|---|---|---|---|
| 只有原配置，没有说明 | 沿用原有行为 | 原有校验 | 原有已支持能力不受影响 |
| 只有说明，未启用具体映射 | 可以；不自动创建缺少主键的 object_binding/空接口实现 | 可随项目发布文档内容；给出“说明尚未形成可执行配置”警告，不算映射完成 | 明确不支持，不实际读库或执行动作 |
| 原配置完整，并有说明 | 两者一起保存 | 原有校验 + 引用校验；提醒说明未做语义验证 | 本期消费方未理解说明时拒绝执行，不能只执行原配置 |
| 已启用映射但缺少必需表/主键/接口参数 | 保留现有草稿能力 | 仍按原有错误阻断；不能用说明掩盖 | 不执行 |
| 说明指向失效元素 | 保留原文以便修复 | 阻断并定位说明，直到显式修复/清除 | 不执行 |
| 说明过长、非法结构 | 拒绝该提交，不修改已保存草稿 | 拒绝 | 不执行 |

警告放在已有校验/发布结果中，不新增每行模式徽标。若纯说明项目缺少本体版本、必需项目元数据等原有条件，仍按原规则阻断。

### 10.1 后续大模型如何读取（本期必须可取得内容）

项目状态接口、发布快照和既有导出必须能同时提供：项目与引用本体版本、元素稳定 ID、说明原文、原有具体配置。本期可封装纯函数组装映射上下文，供后续消费者复用；不要为了本次页面改动新造问答入口、聊天系统或执行引擎。

说明不是自动生成的注释，不丢弃，不只存于浏览器，也不导出到一个与项目无关的文件。

### 10.2 既有执行入口的边界

在现有已支持的消费入口增加能力检查：如果目标本身或执行依赖的对象/链接/属性有非空说明，而该消费者没有解释说明能力，返回明确“不支持当前说明，请使用支持项目说明的执行器”以及对应元素，且检查发生在工具调用之前。不得只靠 UI 按钮禁用。

只有无依赖说明的旧配置可以沿用原执行。无法确定依赖范围时宁可报告不支持，不偷偷忽略。缺少依赖、循环引用等原有检查不取消。

这个防护只约束本次能修改的官方入口，无法让用户独立运行的旧版本程序自动理解新协议；实施文档须标明最低支持版本与回退限制，不承诺所有外部旧程序都安全兼容。

### 10.3 后续执行迭代（不混入本次工单）

大模型解释、授权只读取数、动态表字段查询、结果计算与类型校验、实际步骤追踪作为下一迭代。动作执行另行设计业务确认、权限和结果反馈。本期完成不等于该迭代完成。

| D01 | 四类分别保存多行说明，刷新/重启后读取 | 原文、稳定 ID 和具体配置全部保留 |
| D02 | 两对象共用同一共享属性但填写不同说明 | 各自独立；共享库定义未修改 |
| D03 | 链接从反向入口改说明 | 正向同步，只有一个说明键，物理关联方向不变 |
| D04 | 同一动作关联两对象，分别改说明 | 互不覆盖，接口和参数不丢失，不发送请求 |
| D05 | 旧状态缺字段、新客户端清空一个键、旧客户端省略整块 | 分别无说明、显式清空、原值保留，不混淆 |
| D06 | 旧 revision 保存，或存储故障 | 409/真实错误，输入保留，无假成功和部分保存 |
| D07 | 发布后改草稿说明 | 历史快照不变；导出再恢复能往返 |
| D08 | 升级本体使某属性/动作关系消失 | 预检提示具体对象与说明，保存不丢原文，发布定位失效项 |
| D09 | 描述含脚本标签、超限文字、非法 JSON 结构 | 转义显示；非法/超限拒绝且不截断旧内容 |
| D10 | 只填说明不创建字段/接口配置 | 可保存并读取；不自动伪造身份、空规则或动作请求 |
| D11 | 未支持说明的预览入口遇到目标/依赖说明 | 在读库/调用前明确拒绝；无说明的旧行为继续通过 |
| D12 | 对象仅说明，或已启用但缺主键 | 前者描述记录不当成映射完成；后者仍保持原发布阻断 |

最终验收覆盖 V01–V11 和 D01–D12；视觉验收不能用 DOM 测试或类型检查替代。
