## 2. 建议的最小公共层

复用优先，不为本期引入大型表格库或页面配置 DSL。

- `OntologyListToolbar`：搜索、筛选插槽、结果数、操作插槽；不访问 API、不保存模型。
- `OntologyListTable` 或等价样式/组合：语义 table、列插槽、空态、分页外壳。业务行值和操作由页面提供，禁止抽成巨型万能组件。
- `DefinitionPeek` 或等价小容器：只读详情面板，负责遮罩、关闭、焦点和窄屏；各类型内容用插槽复用。
- 已有 RowMenu/AppSelect 直接复用；通用视觉变量统一，不复制四套 CSS。

若现有组件已经能承担上述职责，允许复用而不新增同名文件。公共层只处理显示与事件，不获取 props.state 全量本体并自行增删记录。

## 3. 实施顺序

### T0：基线与映射确认

读取四份交付物，打开 HTML 交互，列出八处区域的现有入口、可执行操作和保留项。确认共享删除是私有化、业务规则无删除、动作历史转换仍存在。记录本次涉及文件与他人未提交修改。

产出：在本文末尾追加实际基线和范围，不新建一堆状态报告。

### T1：统一容器和视觉

建立最小工具栏、表格与只读详情外壳；先用对象属性页签验证视觉、名称/编辑区别、更多菜单和分页。确认未改 API/保存逻辑后复用到其他区域。

完成标准：至少一页真实数据接入；搜索与分页只是视图；原有表单保存/取消保持。

### T2：对象建模五处列表

对象导航调整样式并保留键盘/分页/收藏/画布入口；统一属性、链接、动作、规则。链接卡片改表格，真实方向不反转；关联移除仍调旧函数；悬空引用仍可见。

完成标准：U03–U06、U09 的对象页部分通过隔离验收。

### T3：三个资产库

共享属性、业务规则、动作定义接同一表格；动作列表态不再使用额外窄列；各编辑器继续复用。引用数/对象数分开统计；跨菜单定位和返回恢复工作。

完成标准：U07/U08 通过；原有低频能力未丢失，不出现空“更多”菜单。

### T4：响应式与状态验收

对齐 1440/1024/768px 页面；验证无结果/空/异常/历史/大量数据；确认菜单不被表格滚动容器裁切，详情焦点不跑到遮罩后。

### T5：回归、记录、交付

相关既有测试 + npm run build + 隔离页面验收。将完成项、未测项、截图位置及命令结果追加本文；更新共享上下文并只提交本次文件。

## 4. 可并行边界

先完成 T0/T1 统一接口，之后对象建模与三个资产库可以按文件分工。公共组件、style.css、App.vue/导航由同一负责人集成。不要让多个执行者同时改 ObjectWorkspace 或共享样式，不以并发数量为目标。

## 5. 测试计划

本次不要求全后端回归，因为不改协议或服务。若实施中发现确需后端变更，应先报告原因、更新需求/接口文档，再扩大验证范围。

2. 新测试仅覆盖新增风险：分页前全量过滤、跨菜单返回、链接真实方向、更多菜单不改删除语义。不要写只断言 CSS 文本或重复模板结构的机械测试。

4. 真实页面验收用临时数据根/隔离数据库/独立端口；同时处理 WIZ_DATABASE_URL，不能让临时根服务连到真实库。

6. 用隔离夹具验证删除/移除影响，不在用户储能本体上做破坏性验证。
