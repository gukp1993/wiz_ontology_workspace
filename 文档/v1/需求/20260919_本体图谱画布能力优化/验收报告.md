## 2. 必须修复

### C01 · P1：链接端点改变，图上的线仍指向旧对象

**对应 G03。** `OntologyGraph.vue:584–586` 只用 `el.data(edgeData(e))` 更新边。Cytoscape 的结构端点不能通过普通 data 更新。

复现：保持链接 ID 和数量不变，将“站 → 设备”的终点改为“簇”，触发真实组件增量同步。

- 投影模型的 target 已是 `obj:mg:cluster`。
- Cytoscape 实际 `edge.target().id()` 仍为 `obj:mg:device`。
- 用户会看到与定义不一致的关系，详情和实际连线可能各说各话。

修复要求：端点变化使用 Cytoscape 支持的结构更新方式（如 `move({source,target})`）；保留边 ID、选中状态与现有节点坐标，不整图重建。同步检查普通边与自关联互转。

复验：改 source、改 target、普通边→自关联→普通边，分别断言 **实际渲染图的 source()/target()**，不能只断言纯模型 diff。

### C02 · P2：环形邻域跨页面返回后无法恢复全图位置

**对应 G10/G12/G13。** `initCy` 在 `OntologyGraph.vue:463–464` 从缓存恢复 scope 后直接环形排布，没有重建 `scopeBackup`；`exitScope` 因无 backup 无法恢复全图，下一次保存把临时坐标作为基础位置。

浏览器步骤：搜索储能设备 → 查看关联 → 环形展开 → 打开对象定义 → 返回图谱 → 退出关联查看。结果仍保留环形位置，无法恢复原全图排列。

控制器精确证据：进入前设备坐标 `{x:700,y:900}`，卸载/重挂载、退出邻域后变成 `{x:0,y:0}`。这不是正常的视口调整。

另外，当前缓存记录全图基础坐标，却只记录邻域当前 viewport，缺少全图进入前视口；需一起修复，不能只补一个空 backup。

修复要求：分别保存全图基准（位置、视口、原选择）与邻域参数；重挂载先恢复全图基准并建立可退出的 backup，再派生临时图；环形拖动、页面切换、刷新、pagehide 都不得覆盖基准。退出后恢复原选择和视口。缓存结构变更提供兼容/降级。

复验：普通邻域/环形分别做“进入→退出”“进入→刷新→退出”“进入→定义→返回→退出”，重复两轮，逐节点坐标与全图视口一致，缓存不含临时坐标污染。

### C03 · P2：有效链接返回图谱时被误判为已删除

**对应 G13/G04。** `go` 传回链接 definition ID，但 `focusDomain` 在 `OntologyGraph.vue:664–666` 只检索节点，不检索边；共享引用的对象属性 ID 也不是共享定义节点 ID。

浏览器步骤：储能设备详情 → “包含 → 储能簇” → 打开链接定义 → 返回图谱。

实际：链接仍存在，却提示 **“目标定义已不存在，已清除画布选择。”**，边详情与选择丢失。

修复要求：返回上下文携带准确的类型和图元素身份，覆盖节点、对象链接、共享引用边，不仅携带无类型 domainId；按图元素类型恢复。规则/动作与其他类型业务 ID 相同时不能取第一个命中。返回已有视图应恢复原视口，不强制放大到 100%；需要显式定位时另走定位行为。

复验：对象、私有属性、共享属性、业务规则、动作、对象链接、共享引用边全部往返；未删除不报不存在，实际删除才清空。共享引用保留具体对象属性定位。

### C04 · P2：键盘事件执行两遍

**对应 G17。** 同一 `onStageKeydown` 同时绑定在根元素 `@keydown` 和 window 捕获阶段（`OntologyGraph.vue:1004`）。加减缩放仅 preventDefault，未阻止事件第二次抵达根处理器。

浏览器实测：画布聚焦，比例 100%，只按一次 `+`，变成 **144%**（1.2×1.2），不是预期约 120%。Esc 等分层处理也存在同一事件重复消费风险，应补实测，不能仅改缩放。

修复要求：只保留一个有效键盘处理入口或明确去重；保留输入框让行、系统快捷键让行、业务撤销隔离。

复验：真实浏览器一次 + 为120%，一次 - 回约100%；一次 Esc 只退出当前一层；搜索框/编辑框不触发布局撤销，画布 Ctrl/⌘+Z 只撤销一步。不能用“直接调用一次 handler”代替 DOM 传播验收。

### C05 · P1：默认选择模式拦截画布内按钮点击

**对应 G08/G11。** `onStagePointerDown` 在 `OntologyGraph.vue:860–871` 对所有冒泡到 stage 的 pointerdown 进行捕获，未排除右下角缩放工具栏等交互控件。

浏览器实测：

1. 比例 20%，选择模式点击“放大”：仍为20%；点击“适应窗口”也不响应。
2. 切换移动模式，点击“放大”：变为约25%；适应窗口正常工作。

修复要求：框选仅在真正空白区域开始；控件点击不设置指针捕获，不夺焦点，节点/边交互交给正确的 Cytoscape 路径。捕获必须配对释放/取消。不能通过默认切换移动模式来掩盖问题。

复验：选择/移动两种模式的 +/-/100%/适应窗口都能点击；单击节点、拖节点、多选拖动、Shift框选、Space平移逐项真实指针操作，不出现框选与拖动互抢。
