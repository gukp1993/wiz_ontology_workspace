## 3. 最新明确确认：保存一次就落草稿

用户指出：每一步点击保存就应该是保存草稿，不应该再点顶部保存。

**已确认的新规则：**

| 操作 | 应有行为 |
| --- | --- |
| 表单保存 | 调用所属工作区 API，直接持久化草稿；成功后刷新／重启仍保留 |
| 表单取消 | 放弃本次未提交编辑，保留先前草稿 |
| 顶部状态 | 显示有未保存修改／保存中／已保存／保存失败／冲突 |
| 顶部“保存草稿”按钮 | 删除，不保留第二次提交步骤 |
| 发布版本 | 将已保存的完整草稿修订生成不可变版本，与日常保存分开 |

实现不能只移除按钮：需要局部编辑副本、请求失败保留输入、revision 更新、同资源保存串行化、过期响应保护和 409 冲突处理。表单多步向导在最终“保存”时提交整份配置，不在每次“下一步”时发布或提交半成品。

画布等没有独立表单的完整操作结束后持久化，不按鼠标移动／每个字符产生修订。保留撤销与重做；它们不能改写历史发布版本。具体要求见整体开发指令第三区域。

**已落实到正式界面（2026-09-15，zcode 实施）。** `frontend/src/saveCoordinator.ts` 每区一个 Saver（串行队列/revision/409 currentRevision 重试/900ms touch 合并/beforeunload）；顶栏无保存与发布按钮，仅五态状态条；发布在两区「校验与发布」页且强制先落盘。

## 5. 已有通用属性来源协议摘要

完整编码以 [数据契约与实施设计](文档/交付物/通用属性来源配置_数据契约与实施设计_20260914.md)、[实施说明](文档/交付物/通用属性来源配置实施说明_20260914.md) 和实际代码为准。不要按原型的临时对象结构重新设计生产格式。

- 本体属性 `valueShape` ↔ `mg:valueShape`。缺省按 scalar，timeSeries 才通常落盘；每个观测值的基础类型仍来自 `dataType`。缺省单值与显式单值等价，单值与序列互改属于破坏性变更。
- 共享属性继承结果形态，引用方不能用本地覆盖改变共享类型。SOC 单值与 SOC 序列不能共用一个完整共享定义。
- 新数据库来源：`{kind:'database', connection, table, lookup, result}`，直接从项目连接目录选择表／视图，不依赖对象 `sources[]` 白名单。
- `lookup.match` 使用 AND 等值条件；比较值支持 identityKey、identityField、property、constant、parameter。公共表至少有当前实例匹配，另加对象类型／指标过滤。
- 序列映射有值字段、时标字段、时间编码／时区与上下文时间范围；不能只保存一个 value 字段，也不能把任意多选字段当作已定义的结果结构。
- Redis 仍是 `kind:'redis'`，直接 `connection` 与已登记 `source` 互斥；支持 `{from:'identityField', field}` 参数。普通 GET／HGET 不接收序列目标。
- computed 引用已有实现及输出；`outputDeclarations[].valueShape` 声明形态，与目标属性一致。
- 等价的身份表直接字段可以编码为旧字符串；有额外条件、时间、处理策略等不能压缩丢失。未知 kind 原样保留并提示不能识别，不兜底转成 computed。
- 链接仍为两端对象已配置来源中的表／字段关联，不随属性选表范围一起放开。
- `merged()` 仍只向旧演示引擎放行支持的字符串来源，其余通过 `bindings.unsupportedSources` 等提示未支持。

用户实际提供过储能簇表 `m_storage_cluster_phase`，包含 id、name、company、create_time、update_time、del_flag、storage_id、cycle_life、internal_resistance、battery_capacity、capacity、rated_power。

- 名称、额定功率／容量等可作为普通业务属性。
- id 主要用于实例身份绑定，不必为了匹配而强制建一个业务属性；不能把全部数据库字段照搬为本体属性。
- storage_id、指向单位的 company 优先用于链接映射；删除标识和技术审计时间不默认等于业务属性或采样时间。
- 实时 SOC 示例来自 Redis，用户给过 `m_storage_cluster-{id}-soc`；更早会话也出现过其他模板。具体真实项目 Key 以当前用户配置为准，不能擅自统一替换。
- 采样 SOC 可能在公共长表（对象、指标、时间、值）或宽表（对象、时间、多个指标字段）中，均可使用同一匹配＋结果映射机制。
- 五分钟采样不等于五分钟平均值。单位、口径和结果形态属于本体要求；来源表、时间戳编码、Redis Key 和实现步骤属于项目映射。
- 不能将原型中的 telemetry_sample、cluster_sample_wide、模拟连接和示例值写入用户真实项目。

## 8. 架构、安全与文件职责

完整边界见 AGENTS.md，尤其注意：

- Vue3＋TypeScript＋cytoscape＋Vite；Python 标准库 HTTP 服务，PyYAML／rdflib，可选 PyMySQL／redis。
- `App.vue` 持有工作区状态；`model_format.py` 与 `frontend/src/modelFormat.ts` 是镜像协议层；`bindingModel.ts` 负责项目来源视图适配。
- 本体：ontology/workflow/metrics/rules/layout；项目：bindings/implementations/connections/parameters/project。保存和发布必须分区。
- 本体定义保存到 ontology.json；计算契约由 workflow 等现有文件管理，并非所有内容都塞入一个本体 JSON。
- 项目：bindings.yaml 存映射，implementations.yaml 存实现，connections.yaml 存非明文凭据连接，parameters.yaml 存参数，project.yaml 存身份与版本引用。
- 编辑通过 API 写 `ontology/drafts/{models,projects}/<id>/revisions/`，原子切换 current.json；发布到不可变 `ontology/releases/{models,projects}/`。
- `ontology/models/`、`ontology/projects/` 基础文件仅作初始化输入，不回写；ontology/ 下所有用户数据禁止手改、清理或填入测试样例。
- 目录缓存由服务端 `ontology/catalogs/` 管理，不进草稿、快照或修订哈希。凭据由 vault 管理，不回传、不进文档或日志。
- 不降低 LOCK、Origin、POST 白名单、2MB 请求限制和 revision 检查。网络探测不持全局写锁。
- 测试必须使用 `WIZ_WORKBENCH_ROOT=<临时目录>` 和独立 `WIZ_WORKBENCH_PORT`；禁止对真实 18765 实例执行写入式自动化验收。
- 保持稳定引用和 definitionOrder。新类型／字段必须进入协议、共享继承、契约校验、发布分类和项目升级影响分析。

本上下文不包含任何用户 API Key、数据库密码或凭据原文；后续也不要补入。
