# 共享上下文自动交接

本次是开发协作设置，交付脚本、配置、使用说明和 zcode 指令，不新增工作台页面或交互原型。

## 机制

Codex 写需求、zcode 实施，两边会话都可以一直打开。触发单位是一轮对话或阶段交付，不是关闭窗口。

1. 开始一轮：读取最新摘要，获得本轮 ticket。
2. 交付前：AI 根据实际工作生成结构化交接，通过 record 追加。
3. 脚本加锁更新 session_context.md，保存双方各自结论；不调用大模型、网络或数据库。
4. Codex Stop Hook 发现未交接时让当前 AI 补写一次；第二次仍缺失则警告，避免无限续跑。
5. 下轮 UserPromptSubmit 再注入最新摘要；实施和验收之前也主动读取，防止持续会话保留旧状态。

这是“事件自动触发 + 当前 AI 总结 + 脚本确定性写入”，不是后台自动理解任意聊天。脚本不读取完整会话日志，也不会把整个最终回复直接复制到 Git。

## 文件及范围

| 路径 | 用途 |
| --- | --- |
| `.codex/hooks.json` | 项目级 Codex SessionStart / UserPromptSubmit / Stop 配置 |
| `.collaboration/context.py` | 标准库脚本，读取、追加、去重、加锁、汇总、Hook 适配 |
| `.collaboration/baseline.md` | 稳定基线，重大架构变化时人工维护 |
| `.collaboration/entries/*.json` | 不可覆盖的交接记录；同一任务按执行者分别保留最新声明 |
| `session_context.md` | 自动生成的基线及最近 12 个“执行者 + 任务”状态 |
| `.runtime/context-*` | 本机 ticket、锁、Hook 检查状态，不进 Git |
| `tests/test_context_sync.py` | 临时目录中的并发、幂等、Hook 等回归测试 |
| `历史共享上下文_截至20260915.md` | 旧文件原样保留，仅作历史参考 |

摘要不是全部历史；更早记录（包括未解决问题）仍在 entries。继续旧任务时按 task 检索，不因摘要窗口滚动就认为任务已完成。双方不同结论均保留，不自动裁定哪方正确。

## 正常使用

在项目根目录执行：

```bash
python3 .collaboration/context.py read --actor codex
```

zcode 改成 `--actor zcode`。返回 ticket、revision、context。当前轮已有 Hook ticket 时，重新读取用 `read --actor codex --ticket <已有ticket>`。

交付前写入（用实际 ticket 替换示例）：

```bash
python3 .collaboration/context.py record <<'JSON'
{
  "ticket": "替换为read或Hook提供的ticket",
  "task": "属性映射优化-v2",
  "status": "ready",
  "summary": "需求已确认并输出文档，尚未实施。",
  "decisions": ["属性取值在单页配置并保存"],
  "verification": ["仅完成方案核对，未运行应用测试"],
  "next": ["zcode 按执行指令实施"],
  "references": ["文档/需求/实际需求目录/执行指令.md"]
}
JSON
```

上述为格式示例，不得把示例路径和状态当作真实交付。JSON 从 stdin 输入，避免 shell 插值；禁止使用未转义拼接的命令传递摘要。

| status | 含义 |
| --- | --- |
| decision | 已确认业务或技术决定 |
| ready | 需求/方案已交付，待实施 |
| in_progress | 实施中；用于长任务阶段记录 |
| implemented | 代码已改，待验收 |
| verified | 已完成明确列出的验证，不代表所有功能均验收 |
| blocked | 阻塞原因及下一步 |
| no_change | 本轮纯问答、无新决定或改动；仅完成本机检查，不追加共享历史 |

同 ticket 重试同内容幂等；不同内容禁止覆盖。中间阶段需要追加时重新 read 获取 ticket。Hook 场景中也要在最终交付时完成 Hook 提供的本轮 ticket，不能只写另一个阶段 ticket。

record 返回 context_advanced=true 表示期间对方写过新记录，应重新读取、核对新决定；本次记录仍保留，不会覆盖对方，也不自动改变当前任务范围。

## Codex 启用及当前会话

本机核对：Codex CLI 0.154.0-alpha.6.2，hooks feature 已开启，项目 trust_level=trusted。新增配置仅在本仓库生效，不修改全局 notify 或其他项目配置。

**项目受信任不等于每个 Hook 已受信任。** 官方要求新增/变更的非托管 Hook 审查后才运行。需要用户在 Codex 的 `/hooks` 中审查并信任本项目的三个 Hook；本方案不伪造信任状态，也不使用跳过信任检查的参数。

若桌面客户端没有显示 `/hooks`，使用该客户端提供的 Hook 管理入口或在本项目的 Codex CLI `/hooks` 中查看。不同客户端能否即时重载配置须以实际事件为准，不能承诺刚写文件就已注入正在进行的轮次。

不需要关闭当前会话来继续协作：当前轮先主动 read/record。配置加载且信任后，在同一聊天发送下一条正常请求，检查是否实际出现 Hook 注入与结束检查；如仍未加载，先保持主动交接方式，再处理客户端配置重载。

```bash
python3 .collaboration/context.py status
```

status 显示收到过的事件及未完成提醒。手动调用也会产生计数，因此只有真实客户端触发的新增事件才能证明加载成功。本次自动测试全部使用临时根，不会伪造真实项目的 Hook 触发计数。

## 测试与恢复

```bash
python3 tests/test_context_sync.py
python3 .collaboration/context.py render
```

- 第一条使用临时目录测试，不触碰工作台用户数据。
- 第二条从基线和记录重新生成摘要，适用于摘要丢失或进程在写入后退出。
- record 先持久化记录，再更新本机 ticket 和摘要；途中退出可使用同 ticket 同内容重试，避免重复记录。
- 使用 macOS/Linux 的 fcntl 文件锁，不承诺 Windows 原生可用；独立 worktree 有各自文件，需要通过 Git 同步，非跨机器实时服务。
- 常见密钥形态会被拒绝写入，但过滤不能识别所有秘密；执行者必须主动脱敏。
- Hook 不读写工作台业务数据，不自动提交 Git，不执行 SQL 或模型 API；业务测试仍由执行者显式运行。

官方依据：[Codex Hooks](https://developers.openai.com/zh-Hans/docs/hooks)。配套：[zcode 接入指令](zcode接入指令.md)。
