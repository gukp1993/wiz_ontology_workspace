### Origin 排查结论

- 服务端白名单＝`{无 Origin, http://127.0.0.1:<服务端口>, http://localhost:<服务端口>}`（`workbench/server.py`），未改动任何安全边界。
- 标准本机地址（页面与 API 同端口）POST 正常；异端口或外部 Origin 一律 403。因此评审中「Origin 被拒绝」不是服务端缺陷。
- 确认存在一处**开发代理配置不一致**：`frontend/vite.config.js` 原为字符串简写代理，开发时页面在 vite 端口上，
  POST 的 Origin 不是服务端自身端口 → 必然 403。已做最小修复：代理转发时把 Origin 改写为后端自身地址
  （实测：直连后端带 vite 端口 Origin → 403；经修复后的 vite 代理 → 400 业务错误，已通过来源校验）。
  该改动只影响 `npm run dev`，生产仍由服务端直接托管 dist，不放宽校验、不扩展远程部署。
