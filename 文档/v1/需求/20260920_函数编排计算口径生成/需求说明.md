## 1. 已确认与待确认

### 已确认

- 智能问数向未来 MCP 查询“储能设备 SOC 的计算口径”，MCP 提供定义与规则，不返回真实 SOC，不提供数据库/Redis 连接信息。
- 计算口径来源于工作台已有函数编排，需要编辑完成后生成规范内容。
- 先交付交互原型、需求说明、开发计划、执行指令，由用户评审后交其他工具实施。
- 内容应说明业务含义、输入输出、来源与步骤、实现、条件、版本与完整性。不能只有画布坐标和节点列表。

### 本版建议，尚待确认

**第一版生成可读说明＋结构化规则 JSON，包含各节点已有 SQL、公式、Python 代码或 LLM 指令；不拼接为整段可执行 Python。**

理由：用户尚未选定文档或脚本；当前 Python 节点是 LLM 求值，编排还含 SQL 模板、Redis 行模式和 HTTP，消费端代码运行约定未冻结。强行生成统一脚本会引入新的执行语义。先形成不丢实现信息的口径，便于评审；没有否定未来完整脚本能力。

这不是两个互斥生成模式：说明与 JSON 由同一次转换生成，是同一份口径的两种视图。原始节点实现是 JSON 的一部分，并在界面单独展示。全部可下载，但不得宣传为“可执行函数包”。

待用户确认：是否采用该首期范围；是否保留带“待补充”提示的说明导出。本方案建议允许，便于交接，结构损坏和敏感信息阻断除外。

## 2. 范围与边界

新增编排编辑页入口“生成计算口径”，打开独立内容页，保留返回设计路径。不是 MCP 服务建设，也不是现有“测试调试”页的扩展。不新增主菜单，不改本体属性/项目绑定结构，不要求一个通用编排必须绑定某个对象。

纳入：当前编排整体的输入输出、节点与依赖、查询/计算正文、参数绑定、逻辑来源、配置中的异常行为/执行约束，以及说明缺项与生成状态。

不纳入：实际查询、模型调用、代码执行、编排调度、生成新的业务算法、整段 Python 编译器、MCP 服务接口、运行环境适配、设备控制、本体或项目自动发布。

不得输出主机、端口、账号、连接串、数据库/Redis密码、凭据、模型提供方连接配置、测试输入结果、运行日志、账号信息、画布坐标。表名、字段、Key模板、SQL方言是规则内容，允许输出。HTTP具体服务地址以逻辑服务引用＋路径表达，保留方法、参数与响应提取规则；认证仅声明需要消费端提供认证能力。

## 3. 交互

### 3.1 编辑页入口

在现有页头“检查配置”“测试调试”旁增加次按钮“生成计算口径”。不抢占测试主入口，不重做编排画布。

点击顺序：提交编辑中的表单与编排保存 → 获得已确认 revision → 服务端读取该修订生成。保存失败/冲突不继续，用户输入保留。不能把未保存前端状态冒充已保存来源。

### 3.2 生成结果页

沿用当前白色侧栏、蓝色按钮、浅灰背景、白色内容区风格。内容区全高，正文独立滚动，避免结果挤在画布下方。

顶部：返回编排、编排名称、来源修订（可折叠技术信息）、生成状态、重新生成。

信息条：**“此内容用于解释计算口径，未查询数据，未执行编排；本期不生成完整可执行脚本。”**

页签：

1. **口径说明**：结构化排版；包含用途/口径、输入、逻辑来源、按依赖顺序的步骤、输出、限制与待补充项。缺失值显示“未声明”，不自动编造。
2. **处理步骤**：可展开节点。展示类型、输入来自哪里、依赖、输出与节点原始实现。前序引用用稳定 ID 绑定，名称辅助阅读。
3. **规范内容**：只读 JSON，供后续 MCP/工具消费。显示协议版本及完整脚本状态。

右上“复制”复制当前页签所对应的完整文本：说明=完整Markdown，步骤=完整步骤JSON，规范=完整口径JSON；提示“已复制口径说明/步骤JSON/规范JSON”，失败提示用户手动选择复制，不能假成功。

“下载说明 .md”“下载规范 .json”下载同一次生成快照，不在点击时偷偷重新读取最新配置。第一版无需 ZIP。

不允许直接编辑生成正文。缺项点击“去补充”回到相应编排基础信息/输入/输出/节点并定位；复用现有字段。对于现有UI没有专用字段的业务口径、单位或缺失策略，指向相应说明字段并显示具体提示，不擅自增加一套大型参数表单。本期不把自然语言拆解成已验证的结构化策略。

### 3.3 状态与失败

| 状态 | 展示 | 导出 |
|---|---|---|
| 未生成 | 点击按钮开始 | 不可 |
| 保存/生成中 | 明确当前阶段，防重复提交 | 不可 |
| 已生成 | 内容结构完整，说明已具备 | 可；不等于执行通过 |
| 已生成，有待补充项 | 列明缺失说明、逻辑来源绑定等 | 建议允许，文件内保留同一提示 |
| 原配置已变化 | 原产物显示“来自旧修订”，提醒重新生成 | 可显式导出旧快照，文件与提示一致 |
| 生成阻断 | 成环、引用失效、缺实现、未知节点、敏感内容等定位信息 | 不输出残缺正式产物 |
| 保存/接口失败 | 保留原页面/上次结果，提示重试 | 不把旧产物标为本次成功 |

生成页不新增业务撤销步骤；返回保留原设计/测试上下文。刷新第一版可重新生成，不要求在DB存独立产物历史。已有产物内含来源版本可追溯；不把浏览器内存结果当作服务端长期资产。

## 4. 规范内容 v1（建议契约）

统一名称 `flow-calculation-rule`，`schemaVersion: 1`。这是工作台自有口径格式，不是 MCP 协议本身，也不是行业标准。

| 字段 | 必需性与含义 |
|---|---|
| format / schemaVersion | 固定格式名与版本 |
| rule | 编排稳定ID、名称、原始说明、sourceRevision；不造新业务ID |
| context | 可选项目ID/修订、本体ID/引用版本、具体对象属性适用关系；只包含明确选定且有依据的上下文，不能按名称猜测 |
| inputs | 现有输入稳定ID、技术名、显示名、类型结构、说明；required/default 只有原协议真实存在时写入，不凭空默认 |
| outputs | 同上；包含最终取值绑定。单位/范围仅来自明确配置或保留在原始说明，未声明不推断 |
| resources | 编排局部稳定逻辑来源ID、kind、SQL方言或服务能力、用途。没有地址和凭据 |
| steps | 节点稳定ID、名称、说明、kind、dependsOn、完整输入绑定、输出签名、原始实现、执行约束 |
| outputBindings | 最终输出如何从节点结果取得，使用稳定ID及原字段路径，保留常量或入口透传等已有语义 |
| execution | 本期 mode=definitionOnly，standaloneScriptAvailable=false；列出所需能力、已知写操作/未知副作用，不宣称只读或可运行 |
| checks | 生成检查状态、errors/warnings、未声明项；runtimeValidation=notPerformed，不把旧节点测试自动归为本产物已验证 |
| provenance | generatorVersion、生成时间、源内容摘要、产物内容摘要；项目上下文适用时纳入来源摘要 |

### 4.1 输入绑定与顺序

保留原有四类输入来源的全部语义：编排输入、前序节点输出（含字段路径）、常量，以及当前协议支持的其他来源。实施前逐类核对 flowModel/flows，不按显示名称重建绑定。

依赖由绑定推导，不从画布箭头位置或坐标推断。拓扑序稳定，同级节点按源声明顺序作为展示顺序，但**同级展示先后不冒充新增业务依赖**。保留不影响最终输出的独立节点，明确“未被最终输出引用”，不能擅自裁剪可能有作用的步骤。

空编排、重复ID、成环、悬挂引用、类型不兼容、缺少节点实现、未知节点种类属于结构阻断。名称/业务说明不完整、未注明单位/范围等为待补充，原文必须保留。

### 4.2 节点实现

| 节点 | 必须保留 | 执行语义说明 |
|---|---|---|
| SQL | 方言、模板原文、参数引用、动态表字段绑定、结果模式、行数/超时 | 不执行SQL，不改写模板成猜测的SQL |
| Redis | 命令、Key/参数模板、行模式、元素绑定、输出转换 | 不丢行模式；SET等写命令标记为写操作 |
| 公式计算 | 表达式语言版本、每个输出对应公式、参数稳定ID | 保留现有计算语义，不转换成普通Python算术替代 |
| Python | 代码原文、输入输出 | 当前执行是LLM求值，标注 executionMode=llmEvaluation；不称为经过验证的Python执行 |
| LLM计算 | 指令原文、输入输出 | 标注需要LLM推理；不导出提供方ID/地址/密钥，不生成虚构确定性代码 |
| HTTP | 逻辑服务、路径、方法、参数/正文模板、非敏感头、响应提取、超时 | 请求方法不等于业务只读保证；未明确副作用记为unknown |

当前节点的实际字段以接口契约及实现核对为准。未来未知字段不能悄悄丢弃：若影响实现且无法安全表达，阻止生成并定位，而不是原样泄漏或忽略。保留原编排数据，不因导出校验修改它。

### 4.3 数据来源与上下文

编排本身可以通用，不强制选项目或对象。默认生成通用口径，以编排内逻辑来源槽位标识引用，不把真实连接ID当作外部稳定身份。

如果当前选了运行项目，可选择“包含当前项目适用信息”（默认不选），此时必须使用已保存项目、核对projectRevision和访问权限。未选择时不读取或依赖项目连接详情。一个编排被多个属性使用，不自动声明适用全部项目；通用产物不附用户可访问项目列表。

项目说明与编排说明冲突不能由本生成器裁决；本期只保留明确输入的描述并提示未做语义验证，不调用LLM理解或修正。

### 4.4 信息保护

采用明确的可导出字段表，而非直接序列化完整state。生成不调用任何密钥读取接口。连接对象、provider、credentials、layout、测试记录不进入投影。

代码/SQL/说明中的硬编码密码或内网URL不能靠删除几个键就保证安全。已识别的敏感值与无法安全分离的连接片段阻断并给节点位置，不回显完整秘密；普通业务字段 token、password 等名称不能一刀切删除。说明和代码保真与脱敏冲突时阻断，不能改坏实现后称完整。自动扫描只是辅助，界面提示导出前核对原文，不宣称能识别所有秘密。

### 4.5 版本

本期不创造编排发布版本。用 sourceRevision（不透明token）标识生成来源，内容摘要用于一致性，不当作revision。生成产物可重复下载同一快照；最新编排变动后不自动替换旧结果。布局变化即使不影响口径语义，也不得错标来源修订；语义内容摘要可独立于布局计算。

## 5. 说明的生成规则

使用确定性模板，不调用LLM、不自动推理业务结论。依次输出：身份/适用上下文、原业务说明、输入、资源、处理步骤、输出与绑定、异常/限制原文、未声明项、版本和未执行声明。

公式和SQL按实际配置展示；长实现折叠，不截断导出文件。文档中没有的“del_flag=0”“SOC范围0～100”“容量统一kWh”“缺失值报错”等均不能自动补上。原型演示含这些口径时明确写在模拟源数据里。

## 6. 接口方向（实施前冻结）

建议新增 `POST /api/flow-rule-generate`，请求 flowId、revision，及显式可选 projectId/projectRevision。不接收浏览器完整编排state，不接受连接/凭据覆盖，不接受执行参数。

服务端鉴权后短时读取一致快照，比较revision；过期409携带当前revision，不生成新旧混合内容。项目上下文过期需标明冲突资产及currentProjectRevision，不能被flow保存器误用。读取完后转换不持全局锁，不联网。不存在/跨账号404，非法请求400，结构或敏感内容阻断422且返回结构化issues，意外失败500。

成功返回规范JSON及由它生成的Markdown文本。节点源码嵌在steps，实现页不另外保存一份。返回值中不包含“函数已执行”结果。下载由当前返回快照形成，不为下载新增执行或再次读取接口。接口细节需先写文档、README记录、05清单、server白名单；本需求不授权跳过契约流程。
