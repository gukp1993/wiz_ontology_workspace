配套：[交互原型_v1.html](交互原型_v1.html) · [开发计划.md](开发计划.md) · [执行指令.md](执行指令.md)。

## 1. 目标与确认范围

用户的工作台运行在本地，需要将自己建设的本体和项目交给他人在另一台工作台或另一个账号继续编辑。迁移对象是工作台的配置数据，不是业务数据库的设备记录或采样数据。

已确认的产品规则：

1. 每次用户主动导入都创建新的本体、新的项目，不覆盖、不合并、不复用已有资产。
2. 同一个文件可以多次主动导入，每次得到相互独立的新副本。没有“更新原本体”“覆盖同名”“回传合并”选项。
3. 重名自动追加“（导入）”“（导入2）”等后缀，预览可改名；未重名保留原名。
4. 新项目必须引用本次导入的新本体及对应发布版本；包内共用的本体/编排仍共用本次创建的同一份副本。
5. 接收者导入后可继续编辑；没有发布、尚未完成配置的草稿也能交接。

下面的包格式、入口、历史范围、传输与凭据方案是本版设计建议和实施基准，并非声称用户逐项指定了技术方案。重大调整须先更新本文件与接口契约。

## 2. 本期范围与数据边界

“全部配置”指被选资产及其依赖的完整配置。不能只按菜单当前可见字段重组一份简化JSON，导致隐藏的旧规则、扩展字段或说明丢失。

| 类别 | 本期纳入 |
|---|---|
| 本体 | 当前已保存草稿，以及该本体全部已发布版本；对象、属性、共享属性、链接、规则、动作、接口/历史契约、值类型、显示格式、顺序与关联等完整配置 |
| 项目 | 所选项目的当前已保存草稿及全部已发布版本；实例识别/登记实例、补充来源、属性/链接/动作映射、取值说明、连接元数据、参数、旧implementations、projectMeta等 |
| 函数编排 | 被项目任一纳入快照引用的编排当前已保存配置；节点、实现、输入输出结构、绑定、布局、执行选项等；可额外勾选尚未绑定的编排 |
| 模型设置 | 被上述编排明确引用的模型配置元数据；隐式默认模型依赖见§5；不导出无关账号设置 |
| API凭据声明 | ID、名称、用途/引用位置；不包含凭据值 |
| 必需附件 | 已纳入配置通过已知附件引用机制引用的内容，如source.jsonId来源参考；按白名单类型带入，不能扫描任意磁盘路径 |

不纳入：自动保存的全部历史修订、撤销栈、软删除资产、运行/测试输入输出及日志、账号口令与会话、浏览器偏好、数据库文件和根密钥、表字段目录缓存与连通性结果、业务库记录/采样数据。

工作台内“登记实例”是项目配置的一部分，必须带入；它与查询业务表返回的实例记录不同。

已发布快照迁移后仍只读。源版本标签/顺序保留，目标生成新的存储标识与校验hash；不调用正常“发布”去重新判版本，不触发业务执行。草稿与发布快照分别导入，不能把草稿冒充某个历史发布版本。

编排目前独立存储且仅有草稿，历史项目对编排的引用不等于冻结了当时编排代码。本包携带导出时的编排配置，预览必须说明此现状，不宣称重现历史运行环境。

## 3. 入口与页面结构

主入口：左下角“设置” → 数据管理 → **配置迁移**，页面两个页签“导出配置”“导入配置”。无需先选本体或项目也能进入。沿用现有浅色侧栏、灰底、白面板、蓝色主按钮，不新增工作区。

快捷入口：本体工作概览提供“导出配置”，预选当前本体；项目概览提供“导出配置”，预选当前项目并带入其依赖本体。可放现有更多操作内，不抢占创建/编辑主操作。返回工作区复用现有设置返回机制。

Excel导入用于填写本体定义，现有本体快照ZIP另有格式；两者继续保留，不能被本功能覆盖或误识别。

### 3.1 导出配置

1. 选择本体，可搜索；选择一个或多个本体。
2. 展示相关项目，可多选，默认不全选；从项目快捷入口进入时勾选该项目。无项目也可导出纯本体。
3. 已被项目引用的编排自动纳入，不能单独取消；“额外编排（可选）”折叠区用于未绑定草稿，不增加独立编排管理功能。
4. 点击“查看导出内容”。保存当前正在编辑的相关表单/草稿后，由服务器读取权威配置并收集依赖。不能导出尚未提交的浏览器对象冒充已保存配置。
5. 预览列出本体、项目、编排、模型配置、版本数、凭据待补项，以及“为什么被包含”。显示快照时间。显示草稿未完成项与不能解析的依赖。
6. 点击“下载配置包”。文件名例如“储能本体_配置包_20260919_183000.zip”。成功文案“配置包已生成并开始下载”，不声称知道浏览器已保存到磁盘。

导出预览与下载必须是同一份冻结快照。预览后其他编辑产生的新内容不偷偷混进包；用户可“重新生成预览”取最新数据。新版本/新的隐含依赖引起数量变化要重新展示。

当前表单未保存：沿用现有保存/放弃/取消离开流程，不直接读取控件绕开保存器；已保存草稿的业务校验失败不阻止迁移。

### 3.2 导入配置

1. 上传本功能生成的ZIP，显示文件名/大小；可以取消、更换。
2. 自动上传并预检，显示“正在检查配置包”，禁用提交；预检不会创建任何本体/项目。
3. 预览按本体、项目、编排、模型配置分组列出“原名称 → 导入后名称”；显示归属关系、版本数量、重命名原因和待补配置。
4. 固定提示“本次将创建新的本体和项目，不会覆盖已有内容”。不提供覆盖/合并策略。
5. 可修改顶层资产名称；包内对象/属性等内部定义不批量改名。不支持在导入时拆包勾选部分依赖，本期完整导入已上传包。
6. “确认导入”后禁止重复点击；显示真实等待状态，不伪造逐资产成功进度。
7. 成功页显示最终新名称、实际创建数、待补凭据与“打开本体”“打开项目”“查看编排”。多项目逐行提供入口。
8. “再次导入此文件”开始新的主动导入操作，重新预检/生成名称/使用新的请求ID，再创建一套。返回成功页、网络重试、双击都不是新的主动导入。

关闭预览前无配置写入；提交已发出后离开页面不等于取消事务。回到页面应能通过原请求ID确认结果，不能直接发新请求制造重复副本。

## 4. 同名、身份与引用规则

### 4.1 命名

同名判定沿用当前账号、资产类型范围内的trim + casefold。模型配置用其既有作用域；项目内连接名称仅在新项目内处理，不与其他项目做名称关联。

若原名“N”不冲突则保持；否则尝试“N（导入）”，再“N（导入2）”递增，考虑本次包内重复与库内既有名称。名字长度须预留后缀并按现有上限截短主体；不随机丢字，不超长保存失败。

手工改名为空/超长/重复即时提示，提交前服务端复查。预览后出现并发同名时返回409 NAME_CONFLICT及新建议，让用户看到更新后再确认；不能暗改用户已确认的名称。已有记录不改名。

### 4.2 新身份与关联重建

所有本体/项目/编排/模型配置均生成目标端新ID、asset_uid、快照ID、revision token；不沿用来源账号或外部资产ID做upsert。

定义、节点、参数、输出、连接/来源等稳定ID采用**有作用域的映射表**：同一个源定义跨草稿/版本只分配一个目标ID，不同资产中相同文本的ID不能误合并。可复用已有编排复制遍历，但不能让它自己提交事务或漏掉项目侧flow/output/input引用。

映射表至少覆盖：

| 引用族 | 要同步的位置 |
|---|---|
| 本体/版本 | workspaceId、项目ontologyId、发布manifest及项目版本索引；version标签保持 |
| 本体定义 | graph/schema定义ID、共享属性引用、对象归属、链接两端、动作/规则关联、类型引用、definitionOrder、布局索引、项目对象/属性映射 |
| 项目 | projectId、明确的项目引用、连接/来源及参数引用、动作接口凭据声明 |
| 编排 | flowId、输入/输出/节点/字段ID、nodeField路径、输出绑定、layout/派生connections、项目flow/output/inputs |
| 模型配置 | providerId；默认模型按§5显式处理 |
| 附件 | 已知source.jsonId等附件标识及引用 |

保留：业务表名/字段名、apiName/技术名、SQL模板、代码、说明、业务实例主键/登记编号、固定业务参数、外部URL、标准词汇IRI与枚举、flow-input/flow-output保留边界标识。**禁止在序列化字符串上全局替换UUID、名称或id字段。**

包内同一源资产只导入一次；两个项目引用同一本体、同一编排时共享这次的新副本。每次主动导入映射表重新生成。目标库已有同名、同来源甚至同内容资产均不复用。

在代码/SQL/自由文本中手写源工作台资产ID，不进行猜测替换；预览给可定位的可移植性提醒，用户导入后自行修正。未知扩展数据原样保留，若声明需要本程序不支持的引用能力，则阻止并提示版本不兼容，不能悄悄删字段。

## 5. 依赖完整性、版本与凭据

### 5.1 依赖闭包

收集根本体与所选项目的草稿、发布版本。项目任一纳入快照引用的本体及版本必须存在于包中。若历史项目曾引用另一本体，自动补充该本体及其配置/版本，在预览标明“项目历史版本依赖”；不因此导出该本体的所有其他项目。

遍历项目全部配置而不是仅“启用映射”：旧规则、未绑定但已登记的实现不能丢；已引用编排自动递归收集已支持的显式依赖，按kind+作用域+ID去重，检测非法循环。编排内引用项目连接时使用项目上下文。

同一编排被多个项目使用但连接/凭据ID相同、实际资源不同：分别保留各项目资源。由于复制后连接/凭据ID可能不同，若一个编排副本无法同时表达这些上下文，按兼容的运行上下文分组复制编排，重写各项目引用，并在预览列明；不能选第一个项目的连接覆盖其他项目。

未绑定额外编排无法推断运行项目时，可在导出选择其运行项目作为依赖上下文；没有关联资源则允许无项目导出。不能扫描同名连接猜归属。此项只服务迁移，不改变编排正式资产归属。

源草稿中“尚未填写”字段保持空并列警告；存在非空但已删除/无权访问的强依赖时，阻止导出，定位到资产/字段。导出不能从接收方已有资产补齐包缺失依赖。历史/当前定义本来就未完成的业务校验问题允许迁移，不与归档破损混淆。

### 5.2 模型默认项

显式providerId自动带元数据。节点使用来源账号默认模型时，导出记录当时的默认模型依赖；导入时将这些节点固定指向本次导入的对应模型，预览说明“原默认模型已转换为明确引用”。不修改接收账号默认模型，也不悄悄切到接收者另一个模型。

若来源没有默认模型，保留为待补配置并在该节点显示缺失提醒；接收端不能无提示用本地默认冒充迁移成功。实施时以已有缺失引用机制承载，必要新增字段须先登记协议。

### 5.3 凭据与可编辑性

本版采用普通ZIP，**不导出受管理的密码、API Key、令牌、密文、根密钥或登录信息**；不提供“包含凭据”开关，加密凭据交接留待单独需求。预览/下载区清楚说明此边界。

连接保留host/port/database/username等非秘密配置；API凭据保留名称与声明。导入后连接/模型密钥显示“待配置”，不沿用“已连接/已测试/已配置密钥”。API凭据缺失必须能按原声明的新ID补填，不要求用户重新找每处引用。

缺失凭据声明须持久化，在重启后仍能定位并补填；补填使用既有只写凭据接口，不能用空字符串伪造已存在密钥。目录缓存不导入，保留配置里已有表/字段选择，只提示需要刷新目录；不能因缓存为空把已有映射清空。

工具只保证受管理凭据和明确敏感结构字段不进入包；不宣称能识别SQL/代码/说明/任意JSON中手写的所有秘密。下载说明提醒检查手写内容。明确Authorization/Cookie/API-Key头、带密码的连接串/URL等结构化敏感值须剥离并记录字段位置的待补项；日志不打印原值。不得用通用关键词删除正常业务字段。

导入不测试连接、不执行SQL/Python/HTTP、不调用模型、不自动发布新版本。迁移完成与配置可运行是两种状态，成功页按实际列待补项。

## 6. 归档格式（目标契约）

使用ZIP承载UTF-8 JSON，不以SQLite整库拷贝作为产品迁移格式。外层manifest与内部payloadFormat分开版本化，便于后续MySQL继续使用同一包。

建议结构（路径使用包内随机/稳定键，不用用户名称拼路径）：

```text
manifest.json
models/m1/draft.json
models/m1/releases/1.0.0.json
projects/p1/draft.json
projects/p1/releases/v1.json
flows/f1/draft.json
configuration/models.json
configuration/credential-declarations.json
attachments/a1.json
```

manifest必须记录format="wiz-workbench-config-package"、formatVersion=1、packageId、exportedAt、producerVersion、requiredCapabilities、根选择、资产清单、依赖边、每个文件路径/字节数/SHA-256、凭据排除与转换/待补清单。资产记录kind、packageKey、sourceId、name、payloadFormat、草稿路径、发布版本及路径。来源ID仅供映射和追溯，不授予目标访问权；不写本机绝对路径、原账号口令或会话。

发布条目保留原版本标签、顺序、来源时间与变化类型；导入的新版本是复制后的独立快照，保存originPackageId/sourceVersion/sourceHash便于说明，重新计算目标hash。原已发布内容和目标旧快照均不改写。

来源manifest中的内容hash用于一致性检测，不等于真实性签名。只接受支持的包版本/payload格式/能力，不能仅凭zip扩展名通过。

## 7. 目标接口与传输设计

以下是新增接口建议，尚未实现。实施前登记接口文档01/02/03/04相关引用、05清单、README，可新增“07-配置迁移接口.md”收口，不在本轮直接修改正式契约。

| 接口 | 请求与主要响应 |
|---|---|
| POST /api/config-package-export-preview | modelIds/projectIds/extraFlows及上下文；返回exportToken、expiresAt、snapshotAt、资产/依赖/版本清单、warnings/blockers |
| POST /api/config-package-export | exportToken；返回application/zip，复用http层postBlob能力 |
| POST /api/config-package-stage | action=begin/chunk；begin含filename/bytes/sha256返回uploadId与分片上限；chunk含uploadId/index/base64/chunkHash，幂等确认 |
| POST /api/config-package-import-preview | uploadId；验证所有分片、解压预算与依赖，返回previewToken、packageHash、命名建议、清单、warnings/blockers |
| POST /api/config-package-import | previewToken、requestId、nameOverrides；原子创建，返回receiptId、新资产ID/名称/归属/待补项 |
| POST /api/config-package-import-result | requestId；返回该账号已提交回执或尚无回执，不触发新建 |
| POST /api/config-package-discard | uploadId或exportToken/previewToken；只清理本账号尚未提交的临时包，不删除导入资产 |

命名覆盖以包内packageKey寻址，不能传任意目标资产ID/owner/覆盖模式。服务端创建新ID。结果中只有当前接收账号可见的新资产。

为保留其他POST的2MB限制，采用有界JSON分片，不整体base64大包、不全局调大server上限。建议：原始分片512KiB、压缩包≤20MiB、解压合计≤100MiB、条目≤2000、单文件≤10MiB、TTL30分钟、每账号最多2个暂存包；实施可按测量调整这些技术上限，但须先统一接口文档与提示。临时目录权限0700、文件0600，存放在DATA_ROOT专用临时目录，随机文件名、到期/取消清理，不作在线存储回退。限制总磁盘占用与解压/JSON深度。

导出下载用独立已注册二进制分派，不破坏原/api/export；路由保留鉴权、Origin校验、请求上限。大包失败明确提示限制，不悄悄截断数据。

响应：400请求非法、401未登录、404资源/token不存在或不属于本账号、409重名/幂等参数冲突、410本人token过期、413大小超限、415包格式不支持、422结构/强依赖损坏、500真实写入失败。错误返回可定位项目/本体/文件/字段，不能只显示UUID。

## 8. 原子性、幂等和保护

- 上传/预览只有受限临时文件，不创建业务资产；不能将未验证包内容直接写入正式表。
- 导入事务同时写所有新资产、草稿、发布、索引/项目版本引用、模型元数据、缺失凭据声明及成功回执。任一点故障整体回滚，不使用逐个create/save后补偿删除。
- 同一次确认产生一个requestId；requestId与账号、包hash、最终名称等规范化请求hash绑定。双击/超时重试同ID返回同一结果；同ID换参数返回409。成功回执与数据同事务写入。
- 同一个包新的一次主动导入使用新requestId，创建新副本。不能用packageId/hash做全局去重而阻止再次导入。
- 查询已成功回执应先于临时token有效期判断，上传文件过期/服务重启后仍可确认先前已提交结果。查不到回执不能自动换requestId重试。
- 每次导入生成新revision，不复用包里的CAS token；本次资产归属当前登录账号，不信任包里的owner。
- 预检/压缩/解压在写事务和全局LOCK之外；最终短事务内复查名称、分配ID和写入，用现有并发护栏/唯一性保护。没有网络探测持锁。
- ZIP拒绝绝对路径、..、反斜杠穿越、重复规范化路径、符号链接/特殊文件、异常压缩膨胀、未登记条目；逐项有界读取，不直接extractall。JSON禁止重复关键键、非法数字、过深嵌套；导入预览名称与说明按文本渲染，不能执行脚本。
- 不执行包内代码或连接；解压失败、解析失败、依赖缺失、版本不兼容均不能留下半套资产。
- 上传进度与业务导入状态分别展示；不生成不存在的逐条提交进度。
