## 3. 共享属性修改（11）


沿用现有共享属性编辑器。引用属性只读并提供“编辑共享定义”“转为私有”。

编辑器显示引用对象数与查看明细。点击保存时：
- 无变化不产生新修订。
- 仅名称/显示格式变化：已有引用提示可见，正常保存。
- 数据类型/值类型/业务定义等影响含义的变化：打开影响确认，展示前后字段、引用对象→属性清单；说明只改当前草稿、发布版本不变。需要勾选已查看影响后提交。
- 当前编辑或引用关系变动使确认失效，不能仅复用旧“已确认”布尔值。

共享保存只确认当前草稿修改范围；发布继续沿用现有流程，本期不新增发布审核或变更分类。用户可取消；如只想改当前对象，返回选择“转为私有”，不得悄悄替其解除共享关系。

## 4. 统一操作语义（12、13）


| 内容 | 操作 | 统一含义 |
|---|---|---|
| 私有属性 | 删除属性 | 删除当前对象上的定义，有依赖则阻断并列明 |
| 共享引用属性/引用边 | 移除对象属性 | 删除当前对象的引用属性，共享库定义保留；不转为私有 |
| 共享引用属性/引用边 | 转为私有 | 保持对象属性ID及生效内容，解除共享；对象仍拥有属性 |
| 共享库定义 | 删除共享定义 | 有引用阻断；无引用确认删除 |
| 对象链接/边 | 删除链接 | 删除这一份稳定ID的链接定义，两端同步消失 |
| 对象中的动作/规则 | 移除关联 | 定义保留，其他对象不受影响 |
| 动作库/规则库 | 删除定义 | 有对象或历史契约等当前草稿依赖则阻断，无引用确认删除 |
| 对象 | 删除对象 | 本期保留阻断式删除，完整列出属性/链接/规则等依赖，动作关联按统一明确提示处理；不新增一键级联清理 |

规则库补齐和图谱一致的安全删除入口，这是本次对历史“暂不做规则删除”的明确建议：图谱底层保留删除逻辑，且规则库需要完成无引用定义的清理；当前已移除的图谱删除按钮不恢复。对象一键清理、通用批量编辑暂缓。

每个阻断条目显示业务名称、依赖原因、定位入口；转到依赖时保留返回目标。任何入口（含图谱批量、快捷键、关联边删除、旧编辑器）使用同一判断。批量预检全量通过才一次写入；一项失败整批不变。前端提示与后端草稿边界校验必须一致，不可只在按钮里防护。

## 5. 交互与失败处理

- 共享编辑沿用现有整页表单，新增影响确认采用弹窗。原型为便于演示用弹窗压缩编辑器，不要求另造正式编辑器。
- 编辑前的对象引用与属性生效内容是比较基线。弹窗显示字段名称、旧值、新值和对象名称，不只列UUID或数量。
- 取消确认不落库，返回表单时保留未提交编辑；取消整个表单遵守已有离开守卫。
- 有引用的删除显示原因及“去处理”，定位后保留返回上下文；不能提供强制删除。
- 保存失败保留表单，提示真实原因；409后重新取得当前基线和影响再确认，不能静默复用旧确认。
- 当前草稿或引用变化、表单修改使影响确认失效。用户正在确认时其他标签页修改，也不能覆盖其更新。
- 保存结果未知沿用现有保存协调器处理，不能假报成功或对用户断言肯定未写入；不为此引入延期的恢复操作状态系统。
- 批量命令即使入口当前隐藏，调用时仍需全量校验，一项失败整批不变。正常操作保留现有撤销能力。

## 6. 数据与兼容边界

稳定ID不变，未知字段完整保留；共享属性转私有保留当前生效内容和对象属性ID。解除对象关联不删除其他对象的定义或关联。

本期仅维护当前本体草稿，不改已发布版本，不切换任何项目引用。删除依赖检查针对当前草稿；历史版本中的合法引用不因此失效，也不能据此把草稿定义永远锁死。

前端复用唯一HTTP层、保存协调器、表单守卫和反向引用能力；后端对保存结果维持引用完整性和CAS/owner边界。不能只在某个按钮做保护，也不为这三项建设全新依赖管理平台。

如接口确有变化，先更新接口文档及README/白名单，再实现。原则上不需要新增持久化审核记录：影响确认是本次草稿保存前的交互，不新增归档状态、版本差异、检查点表。若现状暴露必须改变存储协议的原因，先说明，不借机实施延期模块。

测试隔离WIZ_WORKBENCH_ROOT和数据库URL；不手改真实ontology/、SQLite、凭据。旧格式兼容引用、私有/共享属性、规则/动作关联不丢失。项目与发布接口作为必要回归检查，不作为新功能开发对象。
