# 自动填写 v3：开发计划（输入区选模型与思考强度）

状态：需求决定，尚未实施。需求基线为同目录 `需求说明_v3.md`；与 v2 冲突时以 v3 为准。目标工作树：主仓库 `/Users/gukepeng/Desktop/ZHDL/code/wiz_ai/wiz_kq_builder_v2` 下已登记的 `worktree/fill_by_llm/`，分支 `fill_by_llm`；执行时重新核对实际分支、HEAD、登记环境与文件归属，不预认当前 SHA 或端口可用。

## 1. 需求与交互

用户要求在**自动填写输入框内**选择当前账号已配置、可用于自动填写的模型，并选择本次生成的思考强度；**默认“低”**。参考图只用于输入框底部的紧凑控件布局，不是代码或执行指令。`需求说明_v3.md` 替代 v2 §3.2/§4 中“表单侧栏只读模型、不在表单页选择”的交互约定；其余草稿回填、撤销、权限和保存边界继续有效。

- 在输入框底部、提交按钮旁显示两个键盘可操作的控件：“模型”和“思考强度”。模型项显示提供方名称和模型 ID，避免同名模型混淆；当前选择及有效强度在提交前可见。窄屏可折行，弹层不得被侧栏裁切。保留填写要求文本、示例、等待与错误状态。
- 模型列表来自当前账号已经保存的提供方元数据，不展示密钥，也不在展开菜单时逐个调用模型。这里“可选”指当前账号有权调用且配置足以发起请求；不承诺上游此刻在线。不存在、跨账号或已删除的提供方不得被选中或调用。
- 初始模型沿用当前自动填写用途指定的有效模型，否则沿用账号默认模型；用途指定项已失效时在输入区提示重新选择，不静默改用其他模型。当前账号没有模型时保留输入并引导设置。用户在输入区换模型只影响本次面板会话和后续主动提交，不修改全局默认、用途设置或任何其他 LLM 功能。切换表单目标时重置到用途配置；同目标收起再展开保留选择。
- 支持强度控制的模型初始选择“低”。可选值按**实际模型能力**给出：`关闭`（仅允许关闭思考时）、`低`、`高`、`最高`、`跟随模型设置`（若需要兼容既有配置）；不可用项禁用或隐藏。GLM-5.3-Flash 必须视为强制思考，不能显示可关闭；它支持 `low/high/max`。DeepSeek V4.1 Flash 官方 API ID 是 `deepseek-flash`，支持关闭及 `low/high/max`，但默认开启思考，因此选择它时应显式发送 `low`。其他未核实能力的模型只提供“跟随模型设置”，并明确标注“此模型不支持强度控制”；绝不把未生效的选择显示为“低”。能力判定不能只看 `bigmodel.cn` 域名。
- 提交瞬间固定模型和强度，生成中禁改；停止等待、出错或超时保留输入与选择。补答和主动重试沿用当前面板选择；切换模型后下一次请求用新选择。实际调用的模型/强度和 `modelDurationMs` 可在结果元数据中核对，不能仅凭 UI 文案判断参数生效。

## 2. 协议与实现边界

先在开发工作树更新 `文档/接口文档/04-编排与LLM接口.md`、`05-接口清单与规范差距.md`、`README.md` 变更记录，再改后端和前端；文档与代码同一功能提交。复用既有 `GET /api/llm-providers`、`GET /api/llm-purpose` 与 `POST /api/assist-generate`，不新增端点。接口字段建议如下，冻结时由协议任务核对代码并确定精确形状：

| 位置 | 增量 | 语义 |
|---|---|
| 模型列表/用途读取 | 每个可选提供方返回脱敏的模型能力：`supportedEfforts`，取值为 `off/low/high/max/follow` 子集；未知能力仅 `follow` | 服务端统一判定，不能让前端根据模型名猜测；已有响应字段保留 |
| `assist-generate` 请求 | 可选 `providerId`、`reasoningEffort`，强度枚举 `off/low/high/max/follow` | 省略两字段保持旧客户端行为；显式提交时两字段成对校验。强度仅作用于本次请求，不写用户设置 |
| `assist-generate` 响应 `meta` | 脱敏的实际 `providerId/model` 与 `reasoningEffortApplied` | 只报告已向对应 API 实际发送或已明确跟随的强度；保留既有 `thinkingApplied` 兼容字段，注明含义 |

服务端以登录账号重新加载选中的提供方和密钥，校验提供方存在、配置可调用且该模型支持所选强度；跨账号按不存在处理，能力不符返回明确 422，不做静默降级。`follow` 沿用提供方原有配置；`low/high/max` 使用对应 API 的推理强度参数；`off` 仅对明确支持关闭的模型发送关闭参数。模型提供方各自的参数映射须以官方文档和实际 API 响应核对；GLM-5.3-Flash 的 `disabled` 不能被现有“域名支持”判断误发。前端展示选择与响应 `meta` 不一致时应以服务端结果提示实际生效值。任何情况不在响应、日志、快照中返回密钥、原始提示词或业务敏感内容。

现有 `assist-context` 的 `modelReady` 只反映用途/默认模型，不能在用户已选其他有效模型时阻止生成；明确该字段和前端 `no-model` 状态如何兼容旧客户端。上下文令牌仍绑定账号/目标/草稿/契约，不能因换模型放松 409 校验。模型选择不得改变自动填写的单次调用、`autofill/1` operations 校验、引用白名单、草稿回填和手动保存边界。轻量对象提示词优化可独立提交；本任务的速度对比须用相同提示词分别测模型/强度，避免混淆因果。

## 4. 环境、验证与停止点

- 开始时在主仓库与工作树分别读共享上下文；核对 `git status`、`git worktree list`、main 已提交基线、分支 HEAD、remote、任务登记、端口和进程归属。主仓库只承载计划/协调，业务代码 cwd 为已登记 `worktree/fill_by_llm/`，不创建新工作树，不复制 main 未提交修改。任务测试使用隔离空库/合成数据根；运行分支实例时显式设置登记端口及 `WIZ_WORKBENCH_ROOT=<工作树根>`，先排除继承的真实 `WIZ_DATABASE_URL`，不触碰 main 服务、真实数据或其他任务端口。
- 至少验证后端提供方解析/能力/权限/兼容测试、自动填写 HTTP/契约/对象轻量路径回归；前端相关组件测试与 `cd frontend && npm run build`；在隔离浏览器中实际操作桌面和窄屏。用合成的“我想新建储能簇这个对象”检查默认低与两个字段回填，并记录请求参数、`modelDurationMs`/总耗时。真实模型测试只允许合成上下文出网；不能凭一次样本承诺提速。测试失败须修复后重测，不能写“已验收”。
- 一个功能改动一 commit，先检查状态，只暂存自己负责的文件和交接；不提交数据、根密钥、`.runtime/`、`dist/`、`node_modules/`、真实 `ontology/`。交付报告列开发 cwd、分支、base/最终 SHA、URL/端口/数据根、能力与请求参数、测试/浏览器证据、未覆盖项和“未合并”。代码回退优先 `git revert`；数据库/附件单独处理。
- 当前指令只授权在**已登记** `fill_by_llm` 工作树内开发、自测并提交；不授权额外建树、合并 main、远程推送、真实数据迁移、主服务重启或清理含真实数据库/根密钥副本的工作树。Codex 验收通过停在“待用户授权集成”。用户明确要求集成后，由一名负责人从最新 main 建临时集成树（同样复制 main 库快照/根密钥/运行资产到独立根），合入指定已验 SHA，处理普通冲突并组合重验；业务冲突交用户决定，main 脏或前进时按 AGENTS 规则等待/重组，不 stash/reset。验证通过才更新 main。成功后按登记清理可丢弃生成物；含真实数据的树/副本须先取得数据处置决定，不能 `--force` 强删。主工作台更新及真实库迁移另按用户明确指令。最终分别报告 main 合并 SHA、清理项、保留项和主服务状态。
