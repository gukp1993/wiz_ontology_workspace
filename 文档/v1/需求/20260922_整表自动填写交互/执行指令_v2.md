# 给 harness 的执行指令：自动填写 v2

## 必读与环境

依次读主仓库 `AGENTS.md`、同目录 `需求说明_v2.md`、`交互原型_v2.html`、接口文档 `01/04/05/README`，再核对当前代码和交接。v2 优先于冲突的 v1；旧原型只作历史。已登记开发树为主仓库下 `worktree/fill_by_llm/`（观察时分支 `fill_by_llm`），**执行前重新核对** owner、HEAD、工作树状态、端口、数据根；所有业务改动只在获授权的任务工作树。另有 `worktree/model_setting/`，设置页/协议文件由协调者确定唯一写入 owner，禁止跨树覆盖正在进行的改动。

若已登记工作树不可用，停止并等待用户明确授权创建；不能改在 main 实施。获授权创建时从最新已提交本地 main 建 `worktree/<任务名>/`，登记 base SHA、独立端口与环境；`WIZ_WORKBENCH_ROOT` 设为该树根，按 AGENTS 使用 transfer backup 取得 main 的 WAL 一致库快照并复制根密钥及运行资产，不直接复制活库、不建空库。含真实数据副本登记为不可自动丢弃；自动化测试另用空库/合成数据隔离根。

## 实施顺序

1. 先冻结协议：更新接口文档及 README 变更记录，再改后端和前端。按 `需求说明_v2.md` 给契约增加字段生成策略；通用提示词按契约组织，保留受限 operation、服务端白名单、候选归属和现有 check/explain 兼容。对象“储能系统”必须能生成定义草稿，严格字段不能被放宽。
2. 在**模型设置**增加当前账号的“自动填写”用途配置，复用已存模型/密钥，支持仅该用途的思考覆盖及兼容回退；更新读取/保存协议、鉴权和设置 UI。自动填写侧栏只展示生效配置，不加页面级模型选择。协调 `model_setting` 文件归属后实施，不直接改另一工作树。
3. 按原型调整当前侧栏、等待状态、字段级结果、撤销和补问；复用现有表单适配器，不能把原型关键词/固定结果写入产品。回填只改本地草稿，保存走原页面校验、共享影响确认及 revision/CAS。
4. 用合成数据补回归：短词生成名称＋定义；无依据连接/字段不猜；已有值保留；联动与未知字段保留；用途配置选择/关闭思考只影响该侧栏；模型缺失、失效、超时、迟到响应；无自动保存和真实业务执行。

把任务按契约、用途配置后端、设置 UI、填写引擎/侧栏、测试拆给互不写同一文件的 owner；共享接口、迁移、构建和 Git 提交由协调者串行收口。接口或依赖不稳定时先冻结再并行，不把模拟测试冒充真实联调。

## 验证、交付与停止点

在隔离测试根运行相关测试及 `python3 tests/run.py all`；改前端必须 `cd frontend && npm run build`。用任务自身端口与独立浏览器上下文实测“储能系统”完整流程、严格字段缺信息、设置用途切换、停止等待、保存前后数据；采集 console/error 与实际耗时。没有浏览器权限则如实标未覆盖，不绕过策略。不得测试真实用户库、发送业务数据到模型、执行 SQL/Python/动作接口；密钥不输出、不入库。

仅暂存本任务文件，按 AGENTS 提交并报告：开发树/分支/基线与最终 SHA、改动文件、接口变更、测试与浏览器证据、未覆盖项、服务 URL、数据根、模型是否真实调用。结束按 `.collaboration/context.py` 交接。停在“待 Codex 独立验收”；**不合并 main、不重启主工作台、不推送**。验收失败在同一树修复并交新 SHA；验收通过仍须用户明确要求集成。集成授权后由单一负责人从最新已提交 main 建临时集成树、处理普通冲突并组合重验；业务冲突交用户决定，main 脏则等待，不 stash/reset。主环境更新与真实数据库迁移另需明确指令；代码回退用 revert，数据另处置。含真实库和根密钥副本的工作树不可自动强删，清理前须按 AGENTS 核对数据归属并取得处置决定。
