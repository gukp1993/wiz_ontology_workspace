# 整表自动填写：需求说明 v1

日期：2026-09-22。状态：需求交付，待执行与验收；未实施本次改版。

## 1. 目标与适用基线

用户默认手工填写。需要帮助时在当前表单页头打开“自动填写”，输入一段要求，系统根据当前表单结构、当前值与业务上下文生成合法的字段变更，直接填入编辑草稿，用户检查后沿用原保存流程。

本期替代旧方案“生成建议卡→逐项勾选→采纳”的主流程。不是把勾选框隐藏后自动调用旧adopt：旧方法的选择策略、同字段后项覆盖、跨字段依赖和撤销范围均需重审。

基准：
- 本目录 `交互原型_v1.html`，原型提交 `576bd9a`；两页分别演示本体属性定义、项目数据库字段取值。原型仅为预置内存示例，未做本轮浏览器独立验收。
- 当前实现位于 `worktree/assist-fill-production`，分支 `codex/assist-fill-production`，编写本需求时HEAD为 `544f6c8`；未提交改动为空。该SHA是观察基线，不保证执行时仍最新。
- 旧 `20260920_本体与项目辅助填写` 需求保留历史；本文件优先定义新交互和契约。未改变的业务权限、保存、引用保护继续保留。

两页原型不代表仅实施两页：本期覆盖既有11类辅助场景，共用一个填写引擎；按本文件矩阵逐类接入。

## 2. 范围和不做事项

范围是“当前编辑表单”，不是整个页面所有资产，更不是全本体/项目批量生成。对象详情的属性列表不是可自动创建多条属性的表单；需打开对应新建/编辑表单再使用。

本期不自动创建对象关联、不新增编排、不查询业务记录、不执行SQL/Python/接口、不保存、不发布、不升级引用。认证凭据和系统字段不由模型填写。

不新增AI菜单、聊天历史、知识库、提示词管理后台或独立表单设计器。不为实现自动填写重写全部现有页面。开发者维护契约，业务用户只输入自然语言。

原型的固定SOC响应、内存SAVED/BUFFERS、例句关键词判断、固定连接不移植到生产。生产使用已有模型配置和实际可访问元数据。

## 3. 页面和字段覆盖

| 场景 | 入口所在表单 | 可自动填写 | 边界 |
|---|---|---|---|
| O1 对象 | 新建/编辑对象 | 名称、业务定义 | 不自动创建层级及关联资产 |
| O2 属性/共享属性 | 新建/编辑属性、维护共享定义 | 名称、定义、数据类型、观测类型、现有显示格式 | 类型联动、共享影响确认保留；只读引用不能通过填写越权修改 |
| O3 链接 | 新建/编辑链接 | 既有起终点、正反向名称、数量关系、定义 | 不自动创建不存在对象 |
| O4 业务规则 | 规则编辑 | 名称、定义、选填规则内容 | 不添加旧输出字段，不把项目SQL塞入本体 |
| O5 动作 | 动作定义编辑 | 名称、定义、选填预期效果 | 不增加本体参数、提交条件或自动关联对象 |
| P1 实例识别 | 对象映射实例识别 | 说明、已有数据库来源配置；登记实例模式的说明 | 不凭id名称推断唯一性；不批量生成登记实例 |
| P2 数据库属性取值 | 属性来源编辑 | 连接、表、字段、匹配条件、说明；时间序列时的时间字段 | 依据当前目录、保留属性结果类型约束 |
| P3 Redis属性取值 | Redis来源编辑 | 已有连接、用户提供的命令/模板、参数来源、明确的转换要求、说明 | 不猜Key、GET/HGET或0～100换算 |
| P4 编排属性取值 | 已有编排绑定编辑 | 兼容编排、输出、输入绑定、说明 | 只绑定已有能力；不存在/不支持的运行时输入待补充 |
| P5 链接映射 | 链接映射编辑 | 两端来源、字段、说明 | 字段同名不等于业务等价 |
| P6 动作接口映射 | 接口绑定编辑 | 已提供的方法/URL、请求体格式、参数映射、说明 | 不执行接口，不编造域名或凭据 |

显示格式必须使用当前正式编辑器结构和枚举，不因原型用一句文本演示而退化为另一个格式字段。现有历史字段及未知扩展不得因自动填写消失。

本期属性来源kind仍以当前表单选定类型为边界。用户要求Redis但当前编辑数据库来源时，提示切换来源后再填，不能在模型响应中隐式切换并清除整份已有配置。实例来源mode如既有契约支持修改，切换整组必须经过依赖校验和丢弃影响检查。

## 4. 交互要求

### 4.1 默认页面

- 默认显示现有表单，不显示提示词输入区、建议卡、教程或占位AI大面板。
- 页头右侧一个次要按钮“✦ 自动填写”，保存仍为页面主要操作。
- 无模型时仍可手填；点击入口后显示未配置提示及设置入口，不在整个页面弹阻断。
- 只读表单不提供可写入口；可复用已有查看/解释能力，但不能伪装成可自动填写。

### 4.2 打开面板

点击入口打开右侧面板；显示明确目标、一个textarea、可选简短示例、主按钮“自动填写”。内容独立滚动，操作按钮可达。

宽屏可并排且表单不挤成狭窄列；空间不足用带遮罩的侧层。关闭按钮、Esc、窄屏遮罩可关闭。焦点进入输入框，关闭回到入口；遮罩态键盘焦点不能落到背后表单。

用户输入当前目标内存保留，刷新可丢弃；不持久保存prompt。切目标不复用另一目标的输入/答案/结果；同目标重新打开可保留输入，但必须校验草稿和契约是否仍一致。

“检查当前内容”和“解释怎么填”降为面板里的次要入口（如更多帮助），不占三等分主tab；可复用旧能力。检查只定位问题，不自动改值；解释只显示帮助。若用户采用检查中的修改意见，转为显式“自动填写”任务后再执行同一受控写入路径。

### 4.3 生成与回填

点击后显示“正在填写”，禁重复提交，可取消。网络失败、超时、无有效变更均保留表单和输入，面板保持打开，提示具体原因，不假称成功。

有合法变更且无待补问题：一次填入当前draft，面板收起，聚焦改动摘要。页面提示“已填写N项，尚未保存”，修改字段高亮，可查看修改、撤销。N是实际改变的表单字段/顶层复合组数，不是模型建议条数。

有独立合法内容和待补信息：先填独立内容，面板保留，说明“已填写N项，另有M项待补充”，只问当前必要的1～3个问题。缺信息不得靠模型随机补齐。补答后继续完成，全部解决再收起。

模型输出非法/已过期时不写入。存在一组非法内容但另有独立合法内容，允许只填独立合法组，同时清楚列出未填写项及原因；禁止整页宣称完成。

### 4.4 已有值策略

不增加“普通/严格/覆盖模式”切换。统一规则：
- 空字段：有依据且合法即填入；没有依据保持空。
- 已有字段：用户明确要求该字段修改时可直接替换，写回后高亮并支持撤销；仅“帮我完善”默认补空，已有值的争议修改提出一次具体问题。
- 未涉及字段保持原样；字段未返回不等于清空。缺失键表示不修改；null只在契约显式允许nullable时为合法值；空字符串/空数组按字段结构校验，不能绕过clear和删行授权。
- 清空须用户明确要求且字段可空，使用独立clear操作；空字符串不自动等于删除。
- 系统派生字段由业务转换计算，不让LLM生成；内部ID/只读字段/密钥禁止修改。

“明确要求”不能仅以模型自报true绕过保护。模型须返回所依据的原话片段或已答问题ID，程序校验该依据确实来自本次输入；这只能验证来源，无法机械证明全部语义正确。对含糊指代、破坏性清空和来源切换引发的额外丢弃，仍必须追问具体变更，不自动覆盖。高亮+撤销不替代这一约束。

### 4.5 依赖、手改和保存

- dataType/obsType等按依赖组在草稿副本上校验后原子写回。
- 改连接需处理表/字段，改表需重新校验字段，不能保留旧连接下的合法假象；若会清除未提及的已有配置，先显示丢弃范围补问。
- 生成中手改表单、切目标/版本、参考目录或契约变化：作废当前请求，迟到结果不写入。不得只是隐藏旧结果。
- 回填不是保存：不触发touch/changed自动保存，也不调用form-save/commit-now。等待超过自动保存窗口仍不得落盘。
- 正常保存维持必填/引用/共享影响/权限/CAS。共享影响确认取消，数据库不变。
- 完整一轮（初次填写+继续补答）作为一次可撤销操作。未手改时撤销恢复本轮开始前草稿；若期间有手改，禁止整轮撤销并说明，不覆盖用户改动。后续再次点击自动填写形成新的撤销单元，只需支持最近一轮。
- “取消修改”沿用原页面语义恢复已保存内容；关闭AI面板不撤销已经填入的draft。关闭生成时只取消待处理结果，不承诺供应商停止计费。

## 5. 通用架构与页面解耦

采用“共享表单契约＋上下文提供器＋通用填写引擎＋薄页面适配”。不扫描DOM推断字段，不让模型操作浏览器，不以提示词维护另一套字段定义。

### 5.1 单一表单契约

在仓库中维护不含业务数据的声明式契约（建议JSON格式）。它是字段定义唯一来源，后端装载、前端生成类型/消费元数据，页面通过同一字段描述取枚举和条件；接口文档描述该协议。构建/测试检查生成物漂移，不允许运行时由任意客户端提交schema扩权。

| 契约信息 | 内容 |
|---|---|
| 身份 | formId、schemaVersion、schemaDigest |
| 字段 | 稳定fieldId、标签、业务含义、类型、嵌套结构、必填/长度/枚举 |
| 条件 | visibleWhen、editableWhen、requiredWhen；受限声明式表达，不是eval脚本 |
| 联动 | 依赖字段、原子组、清理影响、合法转换 |
| 候选 | 受控provider名称及参数依赖，如表候选依赖connection |
| 权限 | 只读、敏感、不出网、是否允许AI填写、是否可清空 |
| 转换 | 已注册codec/业务setter标识，不携带可执行任意代码 |

JSON Schema可表达类型和结构，但不能单独承担权限、动态候选和业务语义；这些由元数据及已有验证器补充。别把所有业务校验重新写一遍。

### 5.2 上下文提供器

按用户权限、当前目标及草稿提供有限候选：对象、属性、数据连接、表字段、已有编排签名等。项目仅用固定引用版本；权威数据由后端重取。目录缺失提示刷新/人工补充，不在生成时自动探测业务连接。

分级取候选：先连接/表，再取选中表的字段；多义候选补问，不让LLM从裁剪后的列表断言资源不存在。发送前摘要说明范围；密钥、认证头、密码与业务记录不出网。LLM公共层原始trace不能泄漏prompt或凭据。

### 5.3 通用引擎和适配层

引擎只认识契约、当前标准化draft、上下文及用户要求；不引用Vue组件名、DOM位置或某个业务对象名称。

页面适配层提供读取标准化draft、预检合并、应用合法patch、快照/恢复、字段定位。复用现有 `AssistHostBinding` 与业务setter，抽取页面重复的开关/请求代际/指纹通知为公共宿主逻辑。

JSON-LD属性类型转换、Redis来源编码、接口参数行ID等保留专用codec；普通字段使用声明式映射，避免每页再手写一份可编辑白名单。

重复行必须有稳定本地rowId；明确append/update/remove及定位目标。不接受模型生成持久ID。不明确修改哪行则提问，不默认替换整个数组；整组替换必须明确覆盖范围并验证未丢失未知内容。

## 6. 输出协议与校验

T0必须先更新接口文档，再改实现。优先在现有assist接口上增加明确的新协议版本与fill响应；旧check/explain保留兼容，禁止静默改变旧suggestions语义。

填写结果包括：requestId、formId、schemaVersion/digest、target、draftFingerprint、contextFingerprint、operations、questions、unresolved、summary。operation含fieldId/稳定rowId、set/clear/受限行操作、typed value、basis、atomicGroup；不提供任意JSON路径或apply代码。

- 后端按自己的契约白名单验证类型、引用、权限、原子依赖和依据来源。
- 前端核对目标/草稿/契约/上下文指纹；模型回显的版本不能替代服务端绑定。
- 在副本上合并并调用现有转换/校验，合法组一次写回；拒绝同字段冲突操作而不是后项覆盖前项。
- 异常结构、超限、截断、未知schema明确报错；有效但无变更明确empty。错误不得200+空数组假成功。
- 问题ID由服务端稳定绑定会话/生成轮次，答案须有归属；旧问题答案不得因q_1复用串到新问题。自动回填已改变draft，补答前必须刷新contextToken与指纹；手改后的字段不能被续填按旧值覆盖。
- 服务返回前后本体/项目存储修订不变；模型请求不持全局写锁，取消/超时不会触发延迟写入。

字段版本变化：布局/文案可不变更语义版本；类型、枚举、权限、依赖等需更新digest并使在途结果过期。增删字段后契约、页面绑定、校验的覆盖测试必须发现遗漏。新增普通字段通常不用改引擎，复杂新控件/codec仍需适配，不承诺零代码。

| 编号 | 操作 | 合格条件 |
|---|---|---|
| A01 | 初次进入两区各编辑表单 | 默认可手填，无AI区占顶部、无需滚动越过AI |
| A02 | 页头打开、关闭、Esc、窄屏遮罩 | 目标准确，输入保留，焦点合理，关闭不自动撤销已回填内容 |
| A03 | 空属性输入采样SOC的完整说明 | 合法字段直接填入，联动正确，面板收起，高亮+摘要，无逐项勾选 |
| A04 | 仅要求改名称 | 只改名称；其余字段逐字保持 |
| A05 | 已有rated_power，明确要求capacity | 更新取值字段，未提及内容保留；不能仍是rated_power却提示完成 |
| A06 | 表存在于两个连接 | 独立说明先填；连接补问，无猜测；答后继续填，不重置已填值 |
| A07 | 暂不确定/资料不足 | 保留待补项，普通表单可继续手填，不能补造默认口径 |
| A08 | 改连接/类型/来源导致依赖变化 | 同组合法更新；未知影响先问，不产生旧表旧字段/残留obsType |
| A09 | 生成时手改、切目标/版本、关面板 | 旧响应零写入，加载和按钮状态可恢复 |

| A11 | 补问后撤销／回填后手改再撤销 | 前者恢复整轮起点，后者禁直接撤销；取消编辑恢复已保存值 |
| A12 | 共享定义保存确认取消/409 | 未落盘；错误清楚，未假成功 |
| A13 | 复杂参数列表及未知历史字段 | 修改只落指定行/组，未涉及行及未知字段不丢失 |
| A14 | 无模型、超时、响应错误、empty | 不改表单，保留输入，可重试，无无依据成功提示 |
| A15 | 越权、伪造schema/候选、非法patch/XSS | 程序阻断，文本安全渲染，无真实业务执行、密钥泄漏 |
| A16 | 修改契约/新增枚举/删除字段 | 旧响应失效；契约覆盖检查发现遗漏，已支持普通字段无需改引擎 |
| A17 | 11场景及非储能例子 | 每类可完成填写→检查→保存，非关键词预置输出 |
| A18 | 1440×900、1280×800、768×1024 | 表单/侧栏可用、长内容独立滚动、按钮可达、键盘可操作 |

现有旧版D1～D7作为业务语义回归继续执行，但操作替换为本期自动填入流程，不能因旧用例要求勾选而保留强制建议卡。模型桩验证是功能测试；真实提供方联调另记，不能混称。
