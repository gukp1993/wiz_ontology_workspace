## 1. 背景与用户诉求

用户实测发现：`.json` / `.jsonId` 等本属**结构化定义**的物料因无专用解析器，事实质量与溯源精度不足：
`.json` 现归 code 类，在 code 解析器内部按文本线索降级（quality=low、partial，`protocol.py` 后缀映射 +
`parsers/code.py` docstring 所列未适配语言降级）；`.jsonld` / `.jsonId` 等未登记后缀走
other → LLM 兜底（配模型且未超限时）→ 文本线索（quality=low）。

用户明确：`.json`、`.jsonld`、`.yaml`、`.yml`、`.properties`、`.csv` 都是常见格式，要求全部支持；
并经互联网检索核对常见格式共识（配置类：**JSON / YAML / TOML / INI / Java Properties / .env**，
其中 `.env` 属凭据密钥硬黑名单——见 §4；数据交换类：**CSV / TSV / JSONL**；语义类：**JSON-LD** 为 W3C 标准）。

## 2. 支持范围（第一批）

| 后缀 | kind / 解析器 | 抽取设计与定位粒度 | 质量级别 |
|---|---|---|---|
| `.json` / `.jsonld` | `json`（纯标准库 `json`） | 键路径遍历：每个叶子标量产出一个事实，定位 `文件+JSON路径（$.a.b[0].c）`；数组产出摘要事实（长度+元素类型+首元素键）；**JSON-LD 识别**：存在 `@graph` 时按节点产出高质量事实（`@id`/`name`/`rdfs:label`/`definition`/`skos:definition`/`@type`/`nodeType`，定位=节点 `@id`）——用户储能 jsonId 物料直接受益 | JSON-LD 节点=high；键路径=high |
| `.jsonl` / `.ndjson` | `json`（逐行模式） | 每行一个对象（键路径同上），定位 `文件+行号` | high |
| `.yaml` / `.yml` | `yaml`（`yaml.safe_load`，PyYAML 已是工作台核心依赖，零新增） | 解析后**复用 JSON 同一树遍历器**；锚点/别名展开后按普通节点处理并在 coverage 注记 | high |
| `.properties` | `properties` | `key=value` 逐条（点号视为层级提示记入 data），定位 `文件+行号`；注释行计入说明不计事实；编码复用 textline 既有探测链（utf-8/gbk），`\uXXXX` 转义按 Java 规范解码——避免中文值乱码进事实 | high |
| `.csv` / `.tsv` | `csv`（stdlib `csv`，分隔符嗅探） | 表头列名 + 每列统计（非空计数、≤3 样本值、推断类型）+ 总行数；定位 `文件+行号`；**超过 100 行仅采样前 100 行并注记截断范围** | high（采样如实标注） |
| `.ini` / `.cfg` / `.conf` | `ini`（stdlib `configparser`） | 节名+键路径、值，定位 `文件+行号`；重复节/解析错误进 failedSegments | high |
| `.toml` | `toml`（**自写最小子集解析器**：Python 3.9 无 stdlib tomllib，不引入新依赖） | `[table]`、`key = 标量/数组/内联表` 同 JSON 键路径；**不覆盖语法**：多行字符串（`"""…"""`）、日期时间类型、`[[数组表]]`、虚键（dotted keys）→ 逐条进 failedSegments（诚实降级，quality=medium） | medium（子集解析，注明） |

统一约束：复用既有 Fact 协议与上限（`MAX_FACTS_PER_MATERIAL`、snippet 截断）；新增**深度上限常量
（默认 32 层）**：超深的子树产出一条摘要事实（路径+类型+规模注记），不递归展开、不静默丢弃；
**坏文件显式失败**：损坏 JSON/YAML/TOML → 解析失败（failedSegments 含语法错误位置）、可单物料重试、
**不回退 LLM 兜底或文本线索**（避免把语法损坏当低质量线索继续）；解析纯只读（不执行、不连网、
不计算公式）；**不新增第三方依赖**（PyYAML 既有）。

## 3. 三级分派中的位置

`detect_kind` 将上述后缀映射到六个新 kind（`json` / `yaml` / `properties` / `csv` / `ini` / `toml`），
各注册专属解析器（登记表 kind→解析器一对一）。此后这些后缀进入三级分派第①层（专用解析器），
**不再进入 LLM 兜底或文本线索降级**。既有路径精确基线（现状，供对照）：
`.json` 现归 code 类内部降级；`.jsonld`/`.jsonId` 等未登记后缀现走 other → LLM 兜底 → 文本线索；
新 kind 上线后两者改走专用解析层。其余未登记后缀仍走 other → LLM 兜底 → 文本线索，行为不变。

## 4. 明确不做与排除（第一批，如实告知）

- **`.env` 不在支持范围**：`.env*` 属既有**硬黑名单**（凭据密钥，v2 §5.4 / G20，安全边界不可配置），
  上传层即被排除并进排除清单——本需求不将其纳入解析，也不提出边界修订；
- **二进制格式**（Parquet / Protobuf / Avro / MessagePack）：列入**软黑名单默认项**
  （后缀为主、魔数可读性探测为辅——Protobuf/MessagePack 无固定魔数；`PAR1` 等非文本前缀直接判不可解析），
  进排除清单可查看，不进 LLM 兜底。旧版 .xls 不在此组：维持既有「建议转 .xlsx」路径（不改既有行为）；
- **通用 XML**：已有 MyBatis 专项；泛化 XML 维持现状（语句级），专项化列入待定项；
- **OpenAPI / GraphQL / Proto**：OpenAPI 本质是 YAML/JSON（新解析器自然覆盖其结构与路径），
  专用语义抽取列入待定项；GraphQL/Proto 第一版不做；
- **执行类**：任何格式均不执行其中的代码/宏/公式（既有安全边界不变）。

## 5. 解析器支持矩阵与前端展示（本批新增展示项）

下表为本批定义的解析器支持矩阵（实现后应作为**能力页新增的矩阵展示项**呈现给用户——
当前能力页只有限额与版本号，矩阵为本批新增内容，不是既有结构）：

| 后缀 | 解析层 | 定位粒度 | 说明 |
|---|---|---|---|
| .json / .jsonld | 专用（json） | JSON 路径 / 节点 @id | JSON-LD 语义模式 |
| .jsonl / .ndjson | 专用（json 逐行） | 行号+键路径 | |
| .yaml / .yml | 专用（yaml） | 键路径 | PyYAML |
| .properties | 专用（properties） | 行号 | |
| .csv / .tsv | 专用（csv） | 行号+列统计 | >100 行采样注记 |
| .ini / .cfg / .conf | 专用（ini） | 节+键路径 | |
| .toml | 专用（toml 子集） | 键路径 | 不支持语法诚实降级 |
| .env* | **硬黑名单排除** | — | 凭据边界（G20），不可配置 |
| Parquet 等 | **软黑名单/魔数排除** | — | 不可解析如实报告 |

同步项：`KIND_LABELS` / `KIND_LOCATOR_LABELS` 增加新类型中文名；上传控件 accept 追加新后缀；
`parsers/__init__.py` 既有「纯标准库」安全边界表述与能力页依赖说明需随 PyYAML 使用同步修订。

## 6. 验收条

| 编号 | 条件 |
|---|---|
| S1 | `.json/.jsonld/.jsonl` 键路径事实可定位原文（路径回放可取到该值）；JSON-LD `@graph` 节点产出高质量事实（用真实储能 jsonId 样本回归） |
| S2 | `.yaml/.yml` 嵌套结构与 JSON 同一遍历口径；锚点/别名展开有注记 |
| S3 | `.properties/.ini/.conf/.toml` 键路径事实可定位行号；TOML 不覆盖语法（多行字符串/日期时间/`[[数组表]]`/虚键）各产出 failedSegments 样例；坏 JSON/YAML/TOML 显式失败 + failedSegments + 可单物料重试 + 不回退兜底 |
| S4 | `.csv/.tsv` 列统计与行数正确；>100 行采样有截断注记 |
| S5 | 深嵌套超 32 层的子树产出摘要事实（含路径与规模），上限值在能力页可见；不静默丢弃 |
| S6 | 新类型在三级分派中进入专用解析层（不再进 LLM 兜底/文本线索）；`.env` 被硬黑名单排除；二进制后缀被软黑名单/魔数排除；既有格式回归不退化 |
| S7 | §5 支持矩阵作为能力页新增展示项实现；`KIND_LABELS`/`KIND_LOCATOR_LABELS`/上传 accept/「纯标准库」表述与依赖说明同步更新 |

## 7. 待定项（不作为本批承诺）

- 通用 XML 专项化、OpenAPI 语义抽取、GraphQL/Proto 支持：待用户逐项拍板后另立增量；
- 二进制格式（Parquet 等）：依赖第三方库且非文本物料，暂不做，需求不做承诺。
