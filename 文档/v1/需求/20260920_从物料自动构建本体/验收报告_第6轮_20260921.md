## 2. 整改复核

`finish_success()` 现在在同一写事务中核对 run 归属、lease、取消标记与当前状态；只有 running 可成功收尾，实际转换成功后才推进任务阶段。`_finish()` 不覆盖已有终态。

真实扫描、生成、对话三条管线均会先通过 `runner.stage()` 进入 running，限制 queued 直接成功不会破坏现有调用。

| 场景 | 结论 |
| --- | --- |
| 最后内容写入后、成功收尾前取消 | 保持 cancelled，取消标记保留，任务不被收尾推进 |
| 成功后取消 | 保持 succeeded |
| 取消后重试，旧 worker 收尾 | 旧执行权不能覆盖新运行 |
| 正常及重复成功收尾 | 正常推进、重复幂等 |
| 取消后异常收尾 | 不覆盖 cancelled |
| queued 直接成功 | 拒绝推进 |
| 独立补测 failed / interrupted / running+cancel_requested | 状态保留、任务不推进 |

额外只读检查：自动构建适配器产生的规则、动作字段符合 main 已更新的名称/业务定义必填文本、content/effect选填协议，未发现集成语义冲突。
