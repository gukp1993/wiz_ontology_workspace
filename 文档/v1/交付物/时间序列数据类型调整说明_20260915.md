# 时间序列数据类型调整

## 填写方式

属性统一填写名称、业务定义、数据类型。数据类型选择“时间序列”时，再选择每个时刻记录的“观测值类型”。删除独立的“结果形态”选项，不再同时维护“数值 + 时间序列形态”。填写顺序为名称、业务定义、数据类型；数据类型与观测值类型在宽屏同一行联动显示，窄屏自适应换行。

| 储能簇属性举例 | 数据类型 | 观测值类型 |
| --- | --- | --- |
| 额定电压 | 数值 | 不填写 |
| 实时 SOC | 数值 | 不填写 |
| SOC 采样序列 | 时间序列 | 数值 |

SOC 的业务定义均应说明电池剩余电量百分比，再分别说明最新值或按时间记录的历史观测值。上述是填写示例，本次没有向真实本体添加这些属性。

时间序列表示带时标的观测值集合。具体数据连接、对象定位、时间字段、值字段、筛选条件仍在项目映射维护；不会因为选择时间序列而自动规定五分钟采样或某种数据库。

## 工作台联动

- 对象属性、共享属性库统一展示数据类型，例如“时间序列（数值）”。共享引用继承共享定义的数据类型。
- 计算契约引用属性时继承该属性的类型；直接选择基础类型时也支持时间序列及观测值类型。
- 计算实现不再另选输出结果形态。新实现根据契约输出类型判断与属性来源是否匹配。
- 项目属性取值依据属性数据类型显示时间字段和值字段等配置；原有数据库、Redis、函数来源继续使用。

## 格式与兼容

新保存的本体 JSON 使用以下类型描述：

```json
{"dataType": {"type": "timeSeries", "valueType": "double"}}
```

普通数值仍为 `{"dataType":{"type":"double"}}`。`valueType` 在这里表示观测值的数据类型，不是值类型约束库的引用。

旧 `valueShape` 格式仍可读取，保存时按新数据类型规范输出；前端既有 JSON-LD 编辑模型通过适配层兼容，内部旧标记不是新的用户配置项。旧计算实现中已经保存的输出声明保留兼容读取。未直接重写用户草稿或已发布版本。

这属于本工作台的自有文件格式，不是 Palantir 官方导入格式。

## 验证范围

覆盖前后端格式往返、旧格式兼容、共享属性继承、契约类型及变更分类、计算输出与属性匹配、项目映射校验、API 保存重启与并发冲突。浏览器交互在独立临时本体中验证，未向真实本体添加测试数据。
