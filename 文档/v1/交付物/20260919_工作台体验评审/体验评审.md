# 工作台体验评审

日期：2026-09-19。性质：产品体验与优化建议，尚不是授权实施的需求。

## 1. 结论与体验边界

目前本体定义、项目配置、函数编排、配置迁移的基本结构已成型。最值得投入的是把「配置完成 → 验证当前绑定 → 解释结果 → 重复验证」连接起来，同时统一状态与术语。不建议再进行一次全站布局重写。

本轮在 Chrome 实际浏览 18765 工作台，查看了：

- 35kV 本体的对象列表、对象属性/规则列表、共享属性及引用位置抽屉。
- 创智园二期的项目概览、数据连接、储能簇属性映射与采样 SOC 编排绑定、储能设备动作绑定。
- 函数编排列表、采样值取值规则编辑页、独立测试工作区。
- 模型设置与配置迁移入口。

采用只读体验；未保存配置、未测试真实连接、未运行 SQL/Redis/HTTP/模型调用，未发布或导入。本报告不等于执行结果正确性、接口安全或完整回归验收。部分判断另用源码核对，下面分别说明。

工作区另有本体图谱画布优化的未提交改动，本轮不把旧画布问题重复列为新需求，也不对在途实现作验收结论。未修改这些文件。

## 2. 建议保留的设计

1. **本体与项目分区、项目固定引用发布版本。** 项目页已经说明当前 3.2.0 与本体未发布修改的区别，具备查看变化和更新引用入口；不应再认为「没有版本提示」。
2. **对象列表＋详情、库列表搜索筛选分页。** 现有共享属性列表支持类型筛选、引用定位与复制私有属性；不需要重新设计卡片系统。
3. **说明在前、结构化配置可折叠。** 符合已确认需求；保留一个 textarea 的简单输入，不重新增加模式切换、模板插入或连接选择。
4. **独立测试工作区。** 输入与结果并排展示，整条/单节点/片段测试已经有现有实现；本轮没有执行测试，不宣称这些执行路径重新验收通过。
5. **配置迁移导出/导入分开，导入创建新资产。** 符合本地应用交接编辑的场景；不建议扩成覆盖合并系统。

## 3. 优先改进清单

### R01：补齐属性绑定后的取值预览（高优先级，功能缺口）

**实测：** 储能簇采样 SOC 显示「已配置」，编辑时已经绑定模型名、属性名、实例编号，输出已映射采样值/时间戳。但表单没有针对该属性的测试入口。进入函数编排测试页后，模型名、属性名、模型标识需要再次填写。

**源码核对：** `workbench/project_property_reader.py::_preview` 已有受限预览，仅允许项目登记实例并支持登记信息/旧关联聚合；明确不执行 flow 来源。不能表述为「完全没有预览接口」。`frontend/src/tools/InstanceExplorer.vue` 是模拟数据浏览，也不能当作真实通用属性浏览。

**建议：** 在属性配置旁增加「预览取值」，先选择真实实例；时间序列增加时间范围。自动解析已保存的属性输入绑定，展示最终值/序列、实际输入、来源、耗时、空值或失败原因。SQL、Redis、编排来源复用同一入口，底层逐项接通，不假装全部可执行。说明参与取值但尚无解释器的配置，明确说明执行边界。

首先交付一个储能簇采样 SOC 的完整链路，再扩展为对象实例详情展示多个属性及各自失败状态。预览运行只由用户明确点击触发，不因打开页面自动查询业务数据。

### R02：区分未检查、错误、警告和运行结果（高优先级，状态表达）

**实测：** 两条编排在列表显示「待完善」，打开编辑页又显示「尚未检查」。属性映射同时显示「已配置」。这些状态并非一定矛盾，但缺少说明和对应问题入口。

**源码核对：** `workbench/flows.py::check_flow` 在有警告但无错误时同样返回 pending；`FlowList.vue` 把非 passed 统一显示为待完善，只展示 errorCount，不显示 warningCount。零错误有警告时就没有可见的问题数量。

**建议：** 分开表达配置状态与运行验证状态：未检查／配置有误 N 项／配置通过·有 M 项提示；运行侧单列未测试／测试成功／测试失败／配置已变化需重测。状态可点击并定位到具体节点或字段。不要将「已保存」「已配置」「可执行」「已发布」合并成一个绿色状态。

### R03：把计算方式讲清楚（高优先级，能力边界）

**实测：** 编排列表和模型设置写明 Python 由大模型代为求值，但节点类型仍然叫 Python，用户容易按通常含义理解为运行解释器。

**源码核对：** `workbench/flow_executor.py::_exec_python` 做语法解析后调用 LLM；`_exec_calc` 已有确定性公式计算，也有 LLM 模式。因此不是「缺少公式引擎」。

**建议：** 节点选择和结果上直接标明「公式计算」「模型推理」「Python 描述·模型求值」。额定容量求和、SOC 比例优先引导已有公式能力。结果保留使用的模型或计算方式。真正 Python 沙箱属于独立后续能力，只有现有公式确实无法满足时再设计；不要为了改名称就引入执行平台。

### R04：收敛旧入口与当前术语（高优先级，轻量优化）

**实测：** 项目侧栏是「函数编排」，概览却仍写「属性与链接的派生取值在计算实现中配置」「全部计算实现」。编排列表说明还提到「与项目取值规则库相互独立」。

**建议：** 以当前主要流程为入口：属性取值 → 函数编排；需要保留的旧实现明确标为历史配置并保留兼容访问，不继续让新用户在三套术语中选择。仅改文案不能偷偷迁移旧规则或删除引用。

### R05：删除与解除引用用准确的操作名（中优先级，轻量优化）

**实测：** 对象规则列表按钮叫「删除规则」，页尾却解释仅移除当前对象引用。对象共享属性已使用「移除引用」，同类操作不统一。

**建议：** 对象中的规则/动作/共享属性统一使用「移除关联」或「移除引用」；库中删除定义才使用「删除」。引用位置抽屉目前显示对象名加 `p_…` 技术标识，优先展示「对象名称 → 属性名称」，标识放到可复制详情中。已有反向引用功能继续复用，不重建一套。

### R06：统一资源范围和当前上下文提示（中优先级，文案与导航）

**实测：** 函数编排位于项目侧栏，但列表是可复用编排，并通过编辑页的「运行项目」决定连接；模型设置称「部署级共用」。切换到项目后浏览器标签仍显示此前选择的 35kV 本体，而页内实际是创智园二期、引用储能本体。

**源码核对：** `workbench/llm_providers.py` 按账号隔离模型配置和凭据，因此「部署级共用」不准确。

**建议：** 模型设置文案改为「当前账号下的本体、项目和函数编排共用」。编排列表明确复用范围，编辑/测试持续显示运行项目。标签标题按当前页面显示项目名/编排名，避免复制地址或多标签时混淆。URL 是否同时完整恢复项目/编排状态需单独验证，本轮未重载，不能据此断言深链失效。

### R07：保存测试用例，减少反复填参数（中优先级，新增能力）

**实测及源码：** 当前测试页明确写结果不落盘；`FlowTestWorkspace.vue` 的输入与结果仅在页面内存。返回编排可保留，不代表跨会话可复用。

**建议：** 支持命名测试用例，保存输入、测试范围及可选预期值/容差，绑定编排修订和运行项目。修改计算逻辑后可手动复跑，展示期望值与实际值差异。先做用户主动保存的少量脱敏样例，不默认保存大批业务输出，不引入自动定时执行。与 R01 共用结果展示。

### R08：逐步增加配置依赖与影响定位（后续增强）

共享属性已能查看对象引用，项目已有本体版本差异提示，这些基础不应重做。

建议下一步补足「该编排被哪些项目/对象/属性使用」「某输出字段变化影响哪些绑定」，让用户从编排定义跳到具体使用处。最终以依赖链解释结果，例如：储能设备 SOC → 簇 SOC 与额定容量 → Redis/数据库 → 公式。此项是产品增强建议，本轮未逐接口核实全部反向依赖覆盖，不列为已确认缺陷。

## 4. 动作与未来功能的取舍

储能设备动作页明确说明本期只做 HTTP 接口配置校验、不发送请求；当前引用版本没有关联动作，也给出本体关联、发布、项目升级路径。这是明确的阶段边界，不能将未配置数据当作产品 Bug。

如果下一阶段目标包含真实设备控制，需要独立设计动作执行、实例选择、请求预览、用户确认、幂等和结果记录。这不应顺带塞进本次 UI 优化。当前优先打通只读属性验证；调度平台、多用户实时协作、复杂权限、自动推理建模都不建议立即扩充。

## 5. 推荐迭代顺序

| 顺序 | 范围 | 可见收益 | 实施约束 |
|---|---|---|---|
| 1 | R04、R05、R06 中的文案与上下文；R02 状态表达 | 降低理解和误操作成本 | 小范围前端调整；状态字段有变化须先更新接口文档 |
| 2 | R01：从一个实际属性绑定预览开始 | 能确认配置取到了正确数据 | 对照真实绑定解析；独立数据根验收，不写真实设备 |
| 3 | R03 节点能力呈现、R07 命名用例 | 精确计算与模型推理有明确选择，迭代可复测 | 复用已有公式引擎；不默认新建 Python 沙箱 |
| 4 | R08 依赖定位、多个属性的实例详情 | 复杂项目更容易排查与复用 | 先核对现有接口，按实际缺口补足 |

本报告只提出建议。若选择其中一项实施，再按仓库约定产出该项原型、需求、开发计划和独立执行指令，不将整份评审自动扩成一次大改。
