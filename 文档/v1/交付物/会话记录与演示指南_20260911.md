## 二、最终交互形态（本体空间 / 项目空间）

左栏顶部一个**工作空间下拉框**，两个空间并行独立：

| | ◈ 本体空间 | ▤ 项目空间 |
| --- | --- | --- |
| 处理 | 本体建模相关工作 | 项目绑定相关工作 |
| 当前对象 | 当前本体（下拉切换 + ＋新建本体） | 当前项目（下拉切换 + ＋新建项目） |
| 菜单 | 对象类型 / 链接类型 / 属性管理 / 计算定义 | 项目管理 / 对象与链接绑定 / 项目校验 |
| 顶部工具栏 | 保存草稿 / 校验模型 / 发布版本 | 保存项目草稿 / 校验项目配置 / 发布项目版本 |

关键规则：

- **两条管道并行**：没有本体也可以先建项目（引用本体可后补）；本体建模菜单在有本体后才露出；未选择项目时只显示"项目管理"菜单
- 本体空间的菜单在无本体时隐藏，内容区显示"创建第一个本体"卡片
- 两个空间各自独立保存、独立撤销，互不影响

## 三、核心概念问答（FAQ）

### Q1：计算定义（契约）只定义输入输出，不定义实现？

比这多一点：**契约定义"算什么、口径是什么"，不定义"怎么算出来"**。契约 = 输入签名 + 输出签名 + **业务约定**（口径、单位、缺数据语义）。实现（Redis/SQL 取数步骤）在项目空间的"计算实现"里。

### Q2：业务约定（口径）为什么放在本体，不是项目？

切分线是**口径改变的是"输出的含义"还是"取得输出的方式"**：

- 改变含义的（SOC 是 0~100 百分数、剩余电量=额定电量×SOC÷100、无数据不用 0 冒充）→ 本体契约，所有项目必须一致，否则跨项目数据不可比
- 只影响取数的（读哪个 Key、查哪张表、阈值 300 秒还是 600 秒）→ 项目实现 / 项目参数

项目真的需要不同业务口径时，走**本体版本变更**（破坏性 + 语义确认），不允许项目通过绑定悄悄改含义。

### Q3：不同项目用不同算法算 SOC 怎么办？

允许且预期。契约锁定"所有项目的 SOC 必须是同一个东西"，项目放开"各自用最合适的方法"：项目 A 读 Redis、项目 B 查数据库、项目 C 估算——只要满足契约签名和约定。**算法路子不同没问题，输出含义不同才是问题**（那是新属性或本体版本变更，不是改实现）。

### Q4：约定的实际作用是什么？

1. 约束项目实现（实现描述不得违反，如"查不到就返回 0"违反约定）
2. 发布时判断变更性质：改约定（如 0~100 改 0~1）即使只动说明文字也是**破坏性变更**
3. 开发实现后的业务验收依据

分寸：约定宁缺毋滥——"所有项目都必须遵守才说得通"的才写进本体。

### Q5：适用对象、输入类型是什么关系？

- 输入类型描述**调用所需信息**，不等于能力所属对象
- 适用对象（可选多选）只用于对象详情的展示筛选，**选择适用对象不能替代输入绑定**
- 正确性由项目侧结构化输入绑定保证

### Q6：标题属性是什么？

决定对象实例**在界面上显示成什么名字**。默认"名称属性"兜底；主键管身份、标题管显示，互不影响。

## 四、文件结构导览（演示用）

### 总览

```text
ontology/
├─ models/                              空目录。旧版遗留的初始化种子位置，新架构不再使用
├─ drafts/                              ══ 草稿区：编辑落点，每次保存生成一个修订目录 ══
│  ├─ models/<本体id>/
│  │  ├─ current.json                   指针：指向当前生效修订（原子替换，防写坏）
│  │  └─ revisions/NNNN-哈希/           一次保存 = 一个完整修订
│  └─ projects/<项目id>/                同构的项目草稿
├─ releases/                            ══ 发布区：不可变快照，项目引用的就是这里 ══
│  ├─ models/<本体id>/
│  │  ├─ index.json                     版本注册表（号、类型、说明）
│  │  └─ <版本号>/                      一次发布的完整快照
│  └─ projects/<项目id>/v<N>/
├─ projects/<项目id>/                   项目"出生证明"（初始文件，之后以 drafts 为准）
└─ workspaces/<本体id>/workspace.json   本体登记（id、名称、创建时间）
```

### 本体版本目录（releases/models/<id>/1.0.0/）

| 文件 | 内容 | 备注 |
| --- | --- | --- |
| manifest.yaml | 版本档案：版本号、变更类型（兼容/破坏性）、变更说明、验收人、父版本、时间 | 项目升级预检、版本历史的数据源 |
| ontology.json | 本体结构：对象类型、链接类型、属性、共享属性 | 建模区三个页面的成果 |
| workflow.json | 计算契约：结构化签名 + 业务约定 | 计算定义页的成果 |
| layout.json | 画布布局（位置/缩放） | 纯界面状态 |

（metrics.yaml / rules.yaml 为历史兼容文件，为空时不再生成——发布逻辑已改为"有内容才写入"）

### 项目文件（drafts 或 releases/projects/<id>/vN/ 下的 5 个 yaml）

| 文件 | 一句话 | 关键内容 |
| --- | --- | --- |
| project.yaml | 项目身份证 | project_id、name、ontology、ontology_version |
| bindings.yaml | 映射核心 | 对象映射（表/主键/标题属性）、属性来源（数据字段或计算结果）、链接映射（关联字段） |
| implementations.yaml | 计算实现 | contractId、rule（自然语言规则）、inputBindings（输入来源）、outputDeclarations（输出承诺） |
| connections.yaml | 数据连接 | id / adapter / path（凭据在受保护配置） |
| parameters.yaml | 项目参数 | 键值对，如 soc_max_age_seconds: 300 |

演示串词：**project.yaml 是身份；bindings + implementations 是干活的两本账（数据从哪来、算出的值给谁）；connections + parameters 是环境配置**。

### 三组版本线关系

```text
本体版本线：  1.0.0 ──→ 1.1.0 ──→ 2.0.0     （本体空间发布）
                    ↑          ↑
项目版本线：  v1 ──────┴──────────┘        （项目空间发布，各自引用某个本体版本）
```

草稿随便改，发布即封存；项目引用的本体定义永远来自 releases/ 下的不可变版本。

## 五、属性来源与输入绑定（配置模型）

属性来源（每个属性值从哪来）两种方式：

```yaml
properties:
  soc:              # ① 计算结果：指向某实现的输出
    kind: computed
    implementation: <实现id>
    output: <契约输出签名id>
  rated_power: rated_power_column   # ② 数据字段：直接写列名
```

计算实现的输入绑定，来源四种：

| kind | 含义 |
| --- | --- |
| object | 当前对象本身（最常用：算谁的 SOC 就传谁） |
| field | 某对象已映射的字段（含**主键 ID**，已支持直接选择） |
| constant | 常量（禁止放密码密钥） |
| output | 其他计算的输出（可串联，禁止循环） |

链接映射：按链接的**起点对象**配置，column 填"本表里存对方主键的字段"。

## 六、发布与校验机制

### 本体发布

1. 系统对比当前草稿与上一版本的**结构差异**，给出分类建议
2. 检测到引用失效的结构变化（删改标识、改类型/口径、改契约签名、增必需输出）→ **禁止标记为兼容**
3. 人工确认变更类型 → 生成不可变版本目录 + manifest

### 项目校验（配置校验 ≠ 执行验证）

- 配置校验：引用版本、对象与属性归属、契约与实现匹配、输入绑定完整性、输出声明覆盖、循环依赖
- **不证明**自然语言规则会正确执行——执行验证需要执行器（首期未包含）
- 发布项目版本 = 配置快照，页面明确标注"未执行验证，发布不等于上线"

### 常见校验错误对照

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| 输出「X」未声明返回 | 实现没勾"本实现返回 X" | 全部计算实现 → 输出声明勾选 |
| 属性来源：引用的计算实现不存在 | 属性来源指向的实现已被删除/重建 | 属性来源里重新选实现 |
| 所选输出未在该实现中声明 | 同"未声明返回"的连带 | 补输出声明 |
| 输入绑定引用的字段尚未配置 | 数据字段来源指向了未映射字段 | 映射属性下拉现在含主键 ID 与已配置属性 |
| 该项目尚未绑定本体版本 | 项目创建时选了"暂不绑定" | 项目信息 → 绑定本体与版本 |
