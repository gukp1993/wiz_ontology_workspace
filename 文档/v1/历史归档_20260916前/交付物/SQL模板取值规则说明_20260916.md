# SQL 模板取值规则

入口：项目映射 → 取值规则库 → 新建查询规则 / 编辑规则实现。

填写规则名称、数据连接、输入参数、SQL 模板和返回列。无需逐项填写查询步骤。

## 示例

```sql
-- @step point one
SELECT scada_table AS scadaTable, scada_id AS scadaId
FROM s_attr_scada
WHERE model_name = :model_name
  AND attr_name = :attr_name
  AND model_id = :model_id;

-- @step storage one
SELECT sample_table_name AS sampleTable, sample_field_name AS sampleField
FROM {{point.scadaTable}}
WHERE id = :point.scadaId;

-- @step samples many
SELECT record_time AS timestamp, {{storage.sampleField}} AS value
FROM {{storage.sampleTable}}
WHERE record_time >= :startTime AND record_time < :endTime
ORDER BY record_time ASC;
```

- `-- @step 名称 one/many` 为工作台模板约定，不是数据库执行指令。one 约定唯一记录，many 约定多条记录。
- `:参数` 表示输入值，`:步骤.别名` 表示前段查询值。
- `{{步骤.别名}}` 表示动态表或列名，需由未来执行器校验，不能简单拼接执行。
- 每段一条 SELECT，可编写 JOIN、表达式、聚合等查询文本。当前不支持以 WITH 开头的段。
- 最后一段作为返回结果，配置返回类型、值类型、时间列及值列（SELECT 的输出别名）。

## 存储与兼容

保持 queryRule schemaVersion 3，新增 mode=sqlTemplate、sqlTemplate。旧结构化规则在打开编辑时转换成文本；保存前不修改用户数据。原步骤留在 extensions.structuredRuleBeforeSql 作为历史参考，新的模板是唯一生效定义。规则 ID、属性绑定保持不变。旧结构化规则仍可读取和校验。

## 当前验证边界

检查名称、连接、输入声明、查询段、前置步骤引用、单值/多条匹配。保存和发布不执行 SQL。检查不是完整 SQL 解析器，不证明语法正确、输出别名存在、字段存在或语句执行安全。执行器尚未实现，不应将保存成功理解为取值测试成功。
