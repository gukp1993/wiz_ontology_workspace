## 1. 协议（V4 sqlSteps，冻结）

```json
{"kind":"queryRule","schemaVersion":4,"mode":"sqlSteps","id":"...","name":"...","connection":"...",
 "inputs":[{"name":"model_id","type":"string|double|boolean|dateTime","description":"可选","source":"binding|runtime"}],
 "steps":[{"id":"稳定系统id","key":"技术引用名","name":"中文名","cardinality":"one|many","sql":"单条SELECT模板"}],
 "result":{"step":"steps[].id","type":"scalar|timeSeries","valueType":"...","value":"列名","timestamp":"列名(时序)"},
 "extensions":{"sqlTemplateBeforeSteps|structuredRuleBeforeSql":"旧格式原文留档，未知扩展原样保留"}}
```

SQL 内引用：`:参数名`=输入值；`:key.列`=前置 one 步骤的值；`{{key.列}}`=动态表名/字段名。key 匹配 `^[A-Za-z_]\w*$` 且唯一，UI 不提供改技术名操作；result.step 用步骤 id（旧规则 id=key 保持不变）。属性绑定侧（kind:'computed' 的 implementation/output:'series'/inputs）零变化。

## 3. 旧格式迁移

- V1/V2/V3 结构化 → 每步生成 SQL（别名/引用/排序原样，`:x`/`:k.c`/`{{k.c}}` 映射与旧 toSqlTemplate 一致）；V1/V2 无显式 inputs 时按旧语义合成默认五参数；原结构留档 extensions.structuredRuleBeforeSql；policies 等顶层字段保留。
- V3 sqlTemplate → 词法定位行首 `-- @step key one|many`（字符串/块注释内的不算）切段；标记行后首行中文注释成为步骤名；原文留档 extensions.sqlTemplateBeforeSteps；段名重复/无段/非 SELECT/首段前有内容 → 转换失败，展示原因并保留旧模板编辑回退。
- 打开仅内存转换不落盘；保存才写项目修订。V4 落盘后旧发布快照与初始化目录不回写。

## 4. 校验（前后端一致）

名称/连接/输入参数；步骤中文名、key 唯一、SQL 非空、单条 SELECT（WITH 明确不支持）；`:参数` 已声明、`:key.列`/`{{key.列}}` 为前置 one 步骤（消息含中文名，如「步骤『定位采样存储』：引用 point.scada_id，但『定位测点』不存在、返回多条或尚未执行」）；result.step 存在、scalar↔one、timeSeries↔many、时间列≠值列；输出步骤非最后仅为界面提示（不阻断保存与发布，实施中修正了初版将其计为阻断错误的问题）。输出列存在性/字段真实类型只标未验证。字符串/注释内伪引用、伪分号不误判（词法剥离后扫描）。
