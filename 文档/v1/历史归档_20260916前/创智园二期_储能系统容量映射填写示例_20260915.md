### 成员关系

先在本体定义“储能系统包含储能设备”链接：起点储能系统，终点储能设备。按当前一个设备只属于一个系统的场景，数量关系为一对多；如果实际允许跨系统共享设备，应另行调整这一假设。

| 字段 | 填写值 |
|---|---|
| 当前系统 | 创智园二期储能系统 |
| 成员对象类型 | 储能设备 |

### 系统额定容量

| 字段 | 填写值 |
|---|---|
| 目标属性 | 储能系统 → 额定容量 |
| 取值方式 | 关联属性聚合（待实现） |
| 关联路径 | 当前系统 → 包含 → 储能设备 |
| 输入属性 | 储能设备 → 额定容量 |
| 聚合操作 | 求和 SUM |
| 输入来源 | 复用设备已配置的 m_storage_phase.capacity |
| 统一单位 | 按现有共享属性说明为 kWh；执行前应确认实际来源单位一致 |
| 输出 | 数值，单位口径 kWh |
| 缺失值策略（本例建议） | 有成员容量缺失时返回“不完整”，不静默当成 0 |
| 空集合策略（本例建议） | 返回空值并提示“未匹配到成员设备”，不默认显示 0 |

业务表达：系统额定容量 = 当前系统有效成员设备额定容量之和。

示意：设备 A 为 200 kWh，设备 B 为 300 kWh，则系统为 500 kWh。这两个数值只是演示，不是项目实际查询结果。不要再叠加储能簇容量，否则可能重复统计。

## 3. 当前为什么不能直接保存为可用映射

1. 实例识别表单与校验要求 connection、table、primary_key，尚不能保存项目登记实例。
2. 当前本体引用缺少系统与设备链接，无法引用不存在的关系。
3. 属性取值没有通用关联 SUM 聚合配置和执行能力；现有采样查询规则不能替代它。
4. 设备实际归属范围需要确认；没有已确认的 park 值时不能直接对整表求和。

因此，本次没有提交假表绑定，也没有把未实现的 kind 写入草稿。设备和簇已有映射保持不变。

1. 增加本体“系统包含设备”链接，按现有流程发布新版本并更新项目引用；不能直接修改 3.0.0 发布快照。
2. 项目实例来源增加“项目登记”，保存系统实例编号和显示名称。
3. 项目链接映射增加按成员条件建立关系，确认园区范围和有效记录条件。
4. 属性来源增加关联聚合，按稳定对象、属性和链接标识引用，执行 SUM。
5. 验证空成员、缺失容量、重复成员及统一单位，再启用实际查询。

若暂时不开发上述功能，可由项目数据库维护方提供系统视图和设备归属视图，现有表／视图映射可用于登记配置。该替代方案也需要明确成员过滤，不能在没有授权及过滤条件时自动创建数据库视图。
